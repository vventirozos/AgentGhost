memory / graph.py — GraphMemory

SQLite-persisted knowledge graph mirrored into NetworkX for spreading-activation retrieval. Temporal triplet versioning handles belief updates.

Storage

  • SQLite at memory_dir/knowledge_graph.db.
  • In-memory networkx.MultiDiGraph rebuilt at startup via initialize_graph().

Schema

ColumnTypeNotes
subject / predicate / objectTEXTUNIQUE composite key. Subjects/objects lowercased; predicates uppercased.
timestampREALLast-touched epoch.
weightREALReinforcement counter.
valid_fromREALCreation time.
valid_untilREAL nullableNULL until superseded.

Indexes on subject and object.

It also DROPS the self-loop minted from an edge that ran BETWEEN the two merged nodes (would otherwise duplicate the merged node's whole neighbourhood in every activation chain), while a genuine old→old self-loop still migrates to new→new. get_neighborhood(words, global_limit)Spreading-activation BFS retrieval.

Spreading-activation retrieval

  1. Word-to-node fuzzy match: exact → substring → difflib.get_close_matches. The candidate node list is now a cached snapshot (_nodes_snapshot, invalidated on any edge mutation) instead of list(nodes()) rebuilt per query word — the graph is the only uncapped tier, so that O(nodes) rebuild ran per-turn (2026-07-07). Fragment guard (2026-07-22): the substring tier only seeds a node that is a FRAGMENT of the query word (ai from aiohttp, user from username) when it is ≥ 4 chars AND ≥ 75% of the word's length (_seed_containment_ok); the fuzzy tier drops stoplist hubs. That direction re-seeded generic ego hubs from unrelated words and blew the ego graph into every turn's context — now gone. The opposite direction (word inside a longer node, germ → germany) narrows rather than widens and stays unrestricted.
  2. 3-hop BFS from each seed.
  3. Score paths by sum of edge weights.
  4. Format winners as (subject)-[PREDICATE]-> (object) -[P2]-> (target).

Functional vs. non-functional predicates

_FUNCTIONAL_PREDICATES are SINGLE-valued: a new object supersedes the old one (which gets a valid_until stamp) instead of accumulating a contradiction. Every entry MUST be one-to-one for any subject — a multi-valued predicate in the set silently expires real knowledge on every new extraction.

  • Biographical: WORKS_AT, LIVES_IN, DRIVES, MARRIED_TO, BORN_IN, STUDIES_AT, LOCATED_IN, EMPLOYED_BY, HAS_AGE, HAS_LOCATION.
  • Operational (agent-written, single-valued by construction — a process has one status / one pid at a time): HAS_STATUS, STATUS, HAS_PID.

Everything else — LIKES, KNOWS, the HAS_* family, OWNS, IS — is multi-valued and accumulates.

OWNS / IS removed from the functional set (2026-07-22). Both were wrongly listed here and are MULTI-valued (you own many things; X is many things), so every new extraction expired a real prior fact: 19 of 21 live expired rows were OWNS — the operator's ownership history was silently lost, since restored. HAS_PET / HAS_TASK / HAS_FEATURE / HAS_NAME (written with the generic subject project) and HAS_STATE / HAS_FEN (position logs) are likewise deliberately absent. Conversely the genuinely single-valued operational predicates HAS_STATUS / STATUS / HAS_PID (and HAS_AGE / HAS_LOCATION) were MISSING and had been accumulating mutually-exclusive contradictions — now added. Every expiry is instrumented: logger.warning records subject predicate old → new on every supersession (write-time and merge-time), so an expiry is never silent. Covered by tests/test_graph_dataloss_fixes.py.

Forgetting — decay for the only uncapped tier (2026-07-07, #27c)

Owner life facts are exempt since 2026-10-03 — see below.

Unlike vector (5000-cap), episodes (500) and skills (50), the graph had no bound: every non-functional predicate accumulated forever, and weight-1 edges (one-off extractor noise) diluted retrieval as the graph grew. prune_stale_edges(max_age_days=45, keep_min_weight=1) deletes currently-valid edges whose weight ≤ keep_min_weight AND whose timestamp is older than the age threshold — from both SQLite and the mirror. Reinforced edges (weight > threshold) survive regardless of age: weight IS the decay signal, previously stored but never used for forgetting. It runs from the dream cycle (best-effort, never fails a dream) and reports the count in the Dream-Complete line. Covered by tests/test_graph_forgetting.py. (A persistent token→node inverted index — replacing the substring/difflib scan entirely — remains a further optimization.)

Archive-before-delete (§4M, 2026-08-08)

Every destructive path now appends the doomed triplets to graph_pruned_archive.jsonl (fsync'd, one JSON object per row with archived_at + reason) before deleting — the invariant the skill playbook learned the hard way, applied to the tier that suffered the July data loss (884 live rows vs 1407 in the 07-22 backup, unattributable precisely because no archive existed). Failure semantics differ by intent: prune_stale_edges (unattended, dream-driven) fails closed — no archive, no prune; delete_by_target falls back to recoverable soft-expiry (valid_until) when the archive write fails; wipe_all (explicit operator reset) archives best-effort and proceeds. Pins: tests/test_learning_stack_audit.py (§4M block).

Concurrency

threading.RLock guards both SQLite and the networkx mirror. initialize_graph() rebuilds the entire mirror from disk.

Audit fixes (2026-07-26)

Malformed triplets can't abort the batch: t.get("subject") ran OUTSIDE the per-triplet try, so one list/tuple-shaped LLM triplet raised out of add_triplets — at the smart-memory call site that aborted the whole consolidation INCLUDING the turn's fact embed and profile write (graph runs first). Non-dicts are now skipped with a debug log; relation is accepted as a predicate-key fallback; the per-triplet except logs instead of pass. Generic-subject expiry guard: functional-predicate expiry (HAS_STATUS/STATUS/HAS_PID) is skipped for aggregate subjects (_EXPIRY_GENERIC_SUBJECTS: project/task/app/service/…) — live rows like project HAS_STATUS done|active|needs_user are three DIFFERENT projects' facts, and a new write would have expired every sibling. Same rationale that kept HAS_NAME out of the functional set. Tests: ::TestGraphTripletRobustness.

prune_stale_edges skips edges about the owner (subject or object user) and family, ownership, residence, name and work relations — stated once and never reinforced, they were due to be deleted after 45 days. delete_edge removes one archived edge (used when a profile field is deleted). get_connected_entities follows only identity edges (_IDENTITY_PREDICATE_RE; aliases both ways, a class link thing → class only), anchored on the exact node.

Re-review 2026-10-03 re-review

Decay keeps a durable relation (whole predicate tokens: family, birth, ownership, residence, home, address, pets; plus HAS_NAME/NAMED/WORKS_AT/WORKS_FOR) whoever its subject, and any user HAS_* field; the owner's chatter (user GREETED, ASKED_ABOUT) decays again. forget_entity replaces the word match for forget; is_owner_family tells a family member. Forget preview, folded matching, health facts 2026-10-03 §4KX r8

  • preview_forget_entity(entity) — what forget_entity would do, deleting nothing: (doomed, kept). The forget preview lists both; a kept fact can be picked by number.
  • Kept by forget_entity: _is_owner_life_fact — a durable fact with user at one end. A public person's WORKS_AT or parents are not the owner's and go.
  • _node_is folds case and accents and treats hyphen/underscore as space; _entity_candidates scans every live row for a non-ASCII entity (SQLite's lower()/LIKE fold ASCII only); is_owner_family compares folded names.
  • delete_edge deletes exactly the live rows it archived (by rowid) — never an expired history row. count_edges() feeds the reset_all preview.
  • Decay: health and profession predicates are durable (CONDITION, MEDICATION, DIAGNOSIS, ALLERGY, HEALTH, DISEASE, PROFESSION, COMPANION), and LOCATED_IN; a trip (IS_AT, LOCATED_NEAR) still decays. forget_project(project_id, title, forget_title) 2026-10-06

The graph leg of a project hard delete (see manage_projects). Deletes every row, current and expired, where a node holds the project id as a whole token (project:<id>, project <id>, a bare id under project HAS_ID; a longer id that contains it is not matched), every edge of the task:<tid> nodes the project owned via HAS_TASK, and, when forget_title, the generic project HAS_TITLE <title> edge (folded comparison). Shared concept nodes (technique:bayesian) lose only this project's edge. Input that is not an 8+ char hex id deletes nothing. Rows are archived to graph_pruned_archive.jsonl (reason forget_project) before deletion; if the archive write fails they are soft-expired instead (recoverable, like delete_by_target). Blocked on ReadOnlyGraphMemory.

Review round 1 (same day). The extractor's main way to record a project is a node named by its title (ai self awareness exploration TESTED self-awareness emergence, webos HAS_STATUS active); the id-only version left it live. When forget_title, the node whose key equals the title's key is now matched too, but only for a title of two or more words (a one-word title such as "Chess" is also a topic the owner talks about), and an owner life fact on that node is kept. Title comparison is one function, GraphMemory.project_title_key (folded case and accents, hyphen/underscore as space), used by both forget_project and the caller's "is the title still used" check (the caller had used .lower(), so deleting "Café" removed a live "Cafe"'s title edge). Trade-off: a multi-word title that is also general knowledge is forgotten with the project. The 2026-10-06 backfill kept youtube transcription USES whisper/yt-dlp/tor for that reason; deleting a future project titled "YouTube Transcription" would remove it.

Review fixes 2026-10-03 §4KX r8

owner_field_edges(entity): live user HAS_<…> edges whose predicate names the entity. Entity matching reads every live row and ignores a trailing dot. Decay: LOCATED_IN is durable only with user as subject (other places' LOCATED_IN was research chatter kept forever).

owner_facts_matching(query) — the owner's facts by predicate and category, for recall (see memory_tools → "recall: the owner's facts by their kind").

One predicate per fact, presence vs home, newest wins 2026-10-03 §4KZ

  • _CANONICAL_PREDICATES: spouse, birth-date, residence and medication synonyms are written as ONE predicate (MARRIED_TO, HAS_BIRTHDATE, LIVES_IN, HAS_MEDICATION…). Ages (AGE/HAS_AGE) are not stored — the birth date is the fact.
  • LIVES_IN is home (single-valued); LOCATED_IN / LOCATED_AT / STAYS_AT / IS_AT / VISITING are PRESENCE — not single-valued, not durable (a weekend in Kyllini replaced the owner's home on 08-15).
  • add_triplets(as_of=…): a single-valued edge stated EARLIER than the live one does not replace it (a re-queued journal item expired "lives in Patras" back to Athens). Journal items carry ts.
  • owner_edges_naming(value, predicate): a correction removes only that kind of fact; a removal verb (sold, gave away) removes every owner edge naming it.
  • owner_facts_matching: newest first with "(as of …)", wife/husband/sons categories, short plurals; also feeds the bus hydration graph tier.

§4MI (2026-10-08)

  • execute_graph_compression now archives every row it rewrites (reason=compress:<old>-><new>) and logs the pair at INFO; it used to be the one destructive path with no record.
  • propose_merge_candidates never pairs two names whose digit sequences differ (qwen3.5…/qwen3.6…, 1.10/1.1.0); the same numbers written differently (ubuntu 22.04/ubuntu-22-04) still pair. In the safe tier each variant pairs with the first earlier variant it is not digit-distinct from.
  • Seeding: a query word reaches a LONGER node only as a whole token of it (Unicode word boundaries), or as the start of a token when the word is ≥4 characters and at least half that token ("germ" → germany). "back" no longer seeds xtrabackup. When every substring hit is refused, the word does NOT fall to the fuzzy tier (that turned "tool" into pool); a plain typo with no substring hit still does.
  • sync_owner_mirrors keeps the mirror of an ON-DEMAND profile field (the address, a *_description) EMPTY, which also removes an edge written before this.

§4MM (2026-10-08): moving-target world facts are never stored

TRANSIENT_WORLD_PREDICATE (VERSION, LATEST, CURRENT, NEWEST, PRICE, COST, STOCK, RATE, SCORE, RANK, RANKING as whole _-separated words) is defined here and applied in add_triplets, the single writer path. A triplet with such a predicate is refused unless the owner is one end (user …), it is a durable relation (_is_owner_fact: family, work, residence…), or it is a raw profile mirror. A known limit of the word list: stable world facts with these words (INTRODUCED_IN_VERSION, HAS_SAMPLE_RATE) are refused too. RELEASED_IN 1996 is stable and stays.

§4MR: the object's shape counts too. is_moving_target_world_fact(predicate, object) is applied at both writers (add_triplets and the agent's extraction filter). It is true for the predicate words above, for a version-shaped object under a release-ish predicate (postgresql HAS_RELEASE 18.4), and for any money amount (bitcoin TRADES_AT $61,000, PRICED_AT 1199 eur). The word list alone had let those through. A year is not a version: RELEASED_IN 2008 is kept.

Why: postgresql HAS_VERSION 18.4 (July) sat beside 18.6 and outranked it, and "what is the latest version of postgresql?" was answered 18.4 twice. Before this, §4ME F3 gated only the smart-memory writer. Had the stale row stayed, the 45-day prune_stale_edges would have deleted the newer weight-1 row first, leaving the wrong value alone.

scripts/memory_repair_4mm.py archived and deleted the seven live rows of this kind (agent stopped).

§4MN (2026-10-08): archived edges keep their validity window

_archive_rows records valid_from and valid_until. Without them, a restored expired edge came back as current.
