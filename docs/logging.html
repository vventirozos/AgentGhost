Logging & monitoring

The agent is monitored by watching its live log stream. Every operationally-important event — and every failure — appears there in one aligned, per-request, icon-tagged format. This page is how to read it, and what the May-2026 overhaul changed.

pretty_log per-request tags failures visible distinct icons
The model. pretty_log(title, content, icon, level) in utils/logging.py writes the monitored console stream. Standard library logger.warning/error calls are now routed through the same renderer, so a failure never appears as a bare, easily-missed plain line interleaved with the pretty output. The on-disk file (system/ghost-agent.log) keeps a plain, grep-friendly format (now stamped with the logger name).

Reading the log: archive vs operator view

The log file is a complete record by design — _mirror writes every pretty_log call at full length, DEBUG included, because a turn must be reconstructible after a restart and several instruments count mirror lines. That completeness is also what makes it hard to read: measured 2026-08-09 on a 4000-line window, 1652 lines (41%) were the single string critic compute — Routing verification to Critic Node (Nova), while only 6 lines carried a verdict. The log announced an intent 275 times for every outcome it reported.

The fix is a level change, not mirror-collapse (collapsing the mirror would break the instruments that count it). Background plumbing — self-play, REM, failure-dimension tagging — routes verification constantly while idle and nobody reads it; a real user turn is exactly what the operator IS watching. request_id_context already distinguishes them ("SYSTEM" = not request-scoped), so those two routing lines now log at DEBUG when background and INFO when request-scoped. Node failures were untouched: they are WARNING and always were — making them visible is the point. Measured effect: the INFO view halves, 3783 → 1900 lines.

Read it with scripts/ghostlog.py: INFO+ with repeats collapsed for ambient health, --req <id> for one request in full, --all when you want the raw archive back.

Two sinks, and the durable narrative mirror (2026-07-24)

There are two physical destinations, and they are NOT the same content:

SinkPathWhat it is
Pretty streamstdout → ~/Data/AI/Logs/ghost-agent.logThe aligned, iconed, per-request, truncated view a human watches. Redacted. Rewritten each boot (launchd stdout).
Durable log$GHOST_HOME/system/ghost-agent.logPlain HH:MM:SS - name - LEVEL - msg, append-only, survives restarts. The log you grep or hand to another reader to reconstruct a turn.

The problem it fixed. pretty_log historically wrote to stdout only (the durable mirror was gated on DEBUG_MODE, off in prod), while logger.info/debug wrote to the durable file only. So the entire turn/tool/cognition narrative — thinking, tool calls + results, verifier verdicts, what was learned — lived only on the ephemeral stdout stream, and the durable log held only failures + repetitive noise. An audit measured 0 turn narratives / verdicts / tool results in the durable log, and it was 56% one repeated line. Neither log alone could reconstruct a turn.

The fix — _mirror(). pretty_log now emits its full, untruncated content to a dedicated file-only logger (GhostStream, propagate=False, carries only the file handler so it never double-prints on stdout) on every call — normal lines and BEGIN/END/SECTION frames — regardless of DEBUG_MODE. Result: the durable log is now a complete, plain-text, restart-surviving record of everything the agent did, while the pretty stream stays the truncated, curated live view. The stream truncates a long line to 60 chars (240 for WARNING+); the durable mirror always keeps the whole thing.

Companion changes. (1) Noise: the top repeated durable lines were demoted to DEBUG or de-duplicated — the Semantic Routing line dropped its redundant logger.info twin (it was 56% of the log) and now names the injected skills; watchdog start/cancel and composed-skill re-register → DEBUG; the PRM serve-inert and journal-recovery lines → INFO so they leave the operator's WARNING+ stream. (2) Content, not counts: verifier verdicts now carry their reasoning (a CONFIRMED says what); SKILL ACQUIRED names the fix, not just the trigger; belief revision (was debug-only) names the dropped facts; file writes report size; circuit-breaker recovery is now logged (symmetric with the trip), so a node healing is visible. (3) Escaped warnings: transformers + py.warnings (e.g. the context-overflow token indices … longer than …) are now captured into both sinks instead of vanishing to raw stderr.

Idle loop reconstructable. The nightly biological tick now emits one durable idle cycle: ran dream, self-play (idle 42m) summary per cycle that did work (INFO, so durable-only; frequent all-cooldown ticks stay silent). Self-play's 20% dice roll — previously ANDed with the cooldown so "never fired" looked identical to a crash or a lost roll — is split so each outcome (cooldown-skip / dice-miss / ran) is logged distinctly.

Live-stream philosophy. Because completeness now lives in the durable log, the pretty stream is kept clean: routine per-turn diagnostics stay at INFO (durable-only), and only actionable events reach the WARNING+ pretty channel. Running the launcher without --verbose keeps the stream truncated and free of raw thinking tokens while losing nothing (the durable log has it all).

Repeat-collapse and verify purpose tags (2026-08-05)

The burst problem. One idle cycle printed 33 byte-identical Routing verification to Critic Node (Nova) lines in a row — reflection verifying its lesson batch, self-play validating, counterfactual re-judging, each verdict two stage-calls — with zero information distinguishing any line from its neighbours. Two fixes:

Console repeat-collapse. Consecutive identical lines (same request, icon, title, content, level) print once; when a different line arrives, the swallowed run closes with one dim summary — critic compute ⤷ repeated ×33 in 240s. Console only, by hard rule: the GhostStream mirror records every occurrence, because instruments grep-count mirror lines (the escalation-overturn counter once double-counted precisely because two loggers carried the same event — the mirror stays the single complete ledger). Frame markers (BEGIN/END/sections) are exempt; a pending summary flushes on the next normal line. Kill switch: GHOST_LOG_COLLAPSE=0.

Verify purpose tags. The routing log sites sit several call layers below the code that knows why a verdict is being requested, so the purpose rides a ContextVar (verify_purpose_context, set via the verify_purpose("…") context manager in utils/logging.py). The turn-loop gate tags turn gate; reflection's plan judge tags reflection plan-verify; untagged callers render unchanged. A tagged line reads Routing verification (turn gate) to Critic Node (Nova) — so even an uncollapsed burst is legible as "which subsystem is asking." Covered by tests/test_log_beautify.py.

Reading a line

Each line has a fixed anatomy — once your eye learns the columns, a busy multi-request stream is scannable:

│  A7  💭  +0.42s  thinking            128 tokens · 0.9s
^   ^   ^    ^        ^                    ^
│   │   │    │        │                    └── content (one line; ERROR/WARNING get a larger budget)
│   │   │    │        └── title (lower-cased, bold, level-coloured)
│   │   │    └── elapsed since the request began
│   │   └── icon — picks itself per event type
│   └── 2-char request tag (deterministic colour; groups concurrent requests)
└── left frame edge

Requests are framed by ┌─ … request started / └─ … request finished +12.3s markers. These now fill the terminal width with a ─ rule, so each request is a visually distinct block even in a busy interleaved stream. The boot and shutdown sequences are framed by 🌅 System Boot … 🚀 System Ready … 💤 System Shutdown.

Guaranteed column alignment. The icon sits in a fixed 2-cell field, so the delta / title / content columns line up on every line. This holds because every registry glyph is East-Asian wide-base (renders as 2 cells on any terminal). Narrow-base or bare variation-selector symbols (⚠️ 🗣️ 🛡️) are terminal-dependent — 2 cells on some, 1 on others — and were the cause of columns drifting on certain lines; they are now banned from the registry (test_every_registry_icon_is_wide_base). _icon_cell still pads any stray narrow glyph as a backstop, and the content column is derived from one layout formula (_CONTENT_COL) so it can't silently drift.

May 2026 overhaul

An audit of all ~700 log sites surfaced three problem classes; all are fixed (with unit tests). See the audit page for the companion bug-fix work.

1 — Orphaned loggers (logs going nowhere)

Five first-party loggers — GhostSelfhood, GhostWorkspace, GhostOptim, GhostDistill, GhostReflect — were never given handlers; setup_logging only configured GhostAgent. Their debug/info was discarded and warning/error leaked to bare stderr — never the file, never the stream. setup_logging now configures all of them.

2 — Failures off the monitored stream

~150 logger.warning/error calls printed as un-iconed plain lines (or, for the orphaned loggers, nowhere). A new _PrettyLogHandler renders every WARNING+ record through pretty_log (⚠️/❌, with the request tag), so failures land in the channel you're already watching. Where an event had no log at all it was added with a semantic icon: API auth rejections (🛡️), proxy failures (❌), browser / sandbox-exec / Postgres failures, context compaction escalation (✂️, so you can see when answers start degrading from dropped context), a shutdown frame (💤), and profile-corruption resets (👤, which previously reverted the user's identity silently).

3 — Readability

  • Failure content survives. WARNING/ERROR lines get a larger content budget, so the exception text (the why) isn't truncated off the live stream.
  • Distinct icons. De-collided glyphs that were double-bound (📚/📓, ✂️ vs split, ⚡ boot vs edge-node) and gave the browser/image/PDF/worker/edge events their own icons instead of borrowing 🐚/literals.
  • Distinct titles. The 8-way overloaded Sandbox boot title was split into Sandbox Provision / Image / Chromium / Tor / Cache / Ready; node-failover messages that were crammed into the 18-char title (losing the error) are now a short title + full content; a failed verifier no longer renders a green ✅.

Beautification pass — alignment & icon accuracy

A follow-up pass took the stream "a step further" for the monitoring operator: aligned by construction, each request cleanly separated, and every icon accurately matched to its event.

  • Fixed-width icon column. The layout always assumed a 2-cell icon; a narrow or variation-selector glyph would shift every following column on that line. Icons now pass through _icon_cell, and the content column is computed from one formula (_CONTENT_COL) rather than a hard-coded constant.
  • All icons are wide-base. A real-terminal report showed lines like 💬 llm request and 📈 metacog conf drifting right — their old glyphs (🗣️, 🌡️) were narrow-base + VS16, whose width is terminal-dependent. All 17 such glyphs (registry + metacog) were swapped for East-Asian wide-base emoji that render as 2 cells everywhere: ⚠️→🔶 warn, 🛡️→🔒 shield, 🗣️→💬 llm, ⬇️→📥 download, ⚙️→🔧 worker, 🛰️→🛸 edge, ✂️→🔻 cut, ⛓️→🔗 constraint, ♟️→🎮 game, and more. A test now fails the build if any narrow-base glyph re-enters the registry.
  • Full-width request frames. ┌─/└─ markers fill the terminal width, turning each request into a clearly delimited block in an interleaved stream.
  • No more registry-bypassing icons. 18 inline emoji literals (e.g. icon="💤") across dream.py, skills.py, acquired_skills.py, vector.py were replaced with named Icons constants. Literals silently collided — dream was reusing 💤 SYSTEM_SHUT; it now has its own 🌙 DREAM. A guard test (test_no_inline_emoji_literal_icons_in_source) fails the build if any reappear, now catching single- and double-quoted literals (the 🌡️ metacog icon had slipped through as a single-quoted one).
  • Icon accuracy fixes. New constants 🌙 DREAM, ⏩ SKIP, 💪 MEM_REINFORCE; the previously-orphaned 🎓 SKILL_GRADUATE is now wired to the graduation call sites; skill reinforcement (was 🔄, read as "retry") and skipped/deduped work now read at a glance.

Covered by tests/test_logging_framework.py (registry-hygiene guard, icon-width normalization, derived content column, adaptive frames, new-icon presence/distinctness).

Verbosity knobs. --verbose lifts the content truncation entirely (full payloads on the stream); --debug drops the file/console threshold to DEBUG and mirrors every pretty_log into the file. --daemon suppresses the console handler (file only). NO_COLOR / a non-TTY sink disables ANSI so piped logs stay clean.

Thinking is never filtered — and never truncated (2026-07-08). Streamed 💭 thinking blocks used to be swallowed before they reached the logger unless --verbose was set. The emit/flush closures are no longer gated on VERBOSE_MODE, and the three thinking call sites pass pretty_log(..., no_truncate=True) — a per-call exemption from the content budget (newline flattening, redaction and column wrapping still apply, so the line format is identical). Result: the full reasoning stream is visible in EVERY mode; all other lines keep the standard 60-char budget in non-verbose. The post-stream 🧠 summary line is unchanged in both modes. Covered by tests/test_logging_thinking_nonverbose.py.

Stream redaction (anonymity)

The operator monitors this stream live, which made it the single largest cleartext sink in the system — redaction historically ran only at the JSONL trajectory boundary, never at the log boundary, so secrets, .onion addresses, full URLs, and absolute home paths reached the console verbatim. pretty_log now routes content through distill.redact.redact_text before rendering (post-truncation, so the regex cost is bounded to the visible line), and the WARNING+ auto-render path inherits it. On by default; --no-redact-logs opts out for debugging. redact_text only rewrites known sensitive patterns, so ordinary log lines stay byte-identical and readable. Covered by tests/test_quick_wins.py.

Fire-and-forget: spawn_bg (2026-07-07)

Background work that must not block a turn — memory writes, lesson retraction, PRM online updates, graph-triplet extraction, reflection — is scheduled through one primitive, utils.logging.spawn_bg(coro, *, name). It composes the three guarantees that four earlier ad-hoc conventions each had only some of:

  • contextvars propagation — the task logs under the spawning request's id (same as spawn_task).
  • strong reference — held in a process-wide registry (_BG_TASKS) until completion. asyncio keeps only a weak ref to a bare create_task, so an un-stored task can be garbage-collected mid-flight and the work silently never lands; two real sites (lesson retraction, PRM online update) were doing exactly this in violation of the codebase's own documented rule.
  • exception logging — a done-callback logs any non-Cancelled failure via logger.warning (auto-renders on the live stream). Previously a dying background coroutine vanished into an except: pass body — the root of the "built-but-silently-not-happening" pathology.

drain_background_tasks(timeout) awaits the registry at lifespan shutdown (bounded) so in-flight writes get a chance to land. The three superseded variants (bare spawn_task for fire-and-forget, the module-local _GRAPH_EXTRACT_TASKS set, and GC-unsafe bare create_task) are removed; the remaining legitimate strong-ref sites (the biological daemon task, the swarm task registry, the context _pending_background_tasks set, the self-play loop) are allow-listed. A grep-based regression guard (tests/test_spawn_bg.py::test_no_bare_create_task_in_hot_modules) fails the suite if a new bare create_task appears outside that allow-list.

Timing: what the numbers mean 2026-08-12

Two operations had no visible cost, and one number was being read as something it never measured.

The request frame closes at FIRST TOKEN, not at done

└─ B7 request finished +23.0s is emitted from handle_chat's finally — and on the STREAMING path that function returns a generator the client drains afterwards. So the banner measures time-to-first-token. Observed live: a turn whose frame said +23.0s handed the terminal back about two minutes later, and every second of that generation was logged nowhere.

The frame's number is KEPT — it is when output starts appearing, and three clients parse that frame (uConsole turnstatus.py, Slack, web). A second line now reports the number it was being mistaken for, from the drain's own finally so a client that disconnects mid-stream still produces it:

└─ B7  request finished  +23.0s
│  **  🏁  +0.2s  stream drained   b72d9978 · TOTAL 140.2s · first token 23.0s · 2,317 chunks · 178 KB

Ordered for the console, which truncates content at LOG_TRUNCATE_LIMIT: total and first-token survive; size and rate fall into the durable mirror, which keeps the full line.

** lines now carry a duration

SYSTEM-scoped lines had six blank spaces where a request line has +12.3s, because _format_delta measures from a request's BEGIN and background work has none. That made post-turn and idle work — metacog, hippocampus, dream, the job reaper, the stream drain — the only part of the agent whose cost was invisible in the stream the operator actually watches.

The reading is time since the previous ** line, i.e. how long the step that just finished took. "Since process boot" would be useless on a daemon that runs for weeks, and there is no request start to measure from. A request OPENING resets the anchor, so the first background line after a turn shows blanks rather than reporting the turn's own length as if it were a background step.

The semantics live in a pure _delta_from(prev, now) — split out because the anchor is process-global and any background thread that logs can advance it between two statements, which is exactly how the first version of its test passed alone and failed in a full run. A clock that goes backwards renders +0.00s, never a negative: the column is a fixed six characters and every line after it is aligned from that width.

Tests: tests/test_log_timing_visibility.py.

The 2026-08-20 stream audit (§LOG)

A two-lens audit (716 pretty_log sites inventoried; 16 days of live mirror measured) confirmed the mechanics — zero alignment breaks in 6,967 real lines, frames balanced 748/748, repeat-collapse caught every burst — and found seven semantic gaps, all fixed:

  • Origin on the frames (LOG-4). 45 of one week's 87 turns were self-play wearing a user turn's clothes — origin was mirror-only. Both frame lines now end with a dim · user / · sim / · bench marker, placed after the rule so the three frame parsers (uConsole, Slack, web) are untouched. END reads the origin stashed at BEGIN.
  • The final reply is logged (LOG-3). A Final Reply 🤖 line lands beside Turn Outcome: 60-char head on the console, full text in the mirror — the mirror's "reconstruct a turn" contract was false for the answer itself.
  • Mirror deltas are the console's (LOG-2). _mirror used to re-call _format_delta; the second STATEFUL read advanced the SYSTEM anchor, so every SYSTEM step-duration in the durable record was ~+0.00s. The delta is now computed once and passed through.
  • Dispatch-level tool line (LOG-5). One Tool Call 🎬 line per executed call (name + compact args) — before, a tool was visible only if it self-logged; a successful yt_download appeared nowhere. Unknown-tool rejections warn instead of silently striking, and the three strike lines (Execution Fail/Transient Fail/Tool Warning) are WARNING so their error previews get the 240-char budget instead of dying at 60.
  • Idle liveness (LOG-6a). The once-per-cycle Idle Cycle 📡 summary now reaches the console (it was logger.info → file-only), so a quiet night and a wedged event loop no longer look identical.
  • Stale-process backoff (LOG-6b). The staleness warning gained a per-file 1h cooldown on top of per-digest dedup — on a dev box every save minted a new digest and re-warned (95 near-identical warnings in 16 days, the #1 WARNING).
  • Icon registry hygiene (LOG-7). The metacog icons are registered in Icons (three glyph collisions resolved: arbiter 🧮→🥇, replan 🔀→🚦, default 🧠→🫧) and added to both client ICON_CLASS maps; bridged stdlib warnings title as agent·module instead of the anonymous agent; Schedule/Watch Error got ❌ instead of the unclassified 🔹; benign Auto Memory Skip moved off 🛑 to ⏩; deferral lines use ⏳ (waiting, not skipping); the pre-frame-era bare print() thinking dump — which bypassed the stdout lock, the mirror and redaction — is deleted (LOG-1).

Tests: tests/test_logging_stream_fixes.py.

§4EH — coverage + icon-sense pass (2026-09-03)

The stream is a monitoring tool, so severity must read at a glance and meaningful events must appear at all. Icon severity: an ERROR/CRITICAL line now always renders the failure glyph ❌ (or 🔒 SHIELD for a deliberate fail-closed security refusal) — 17 lines that used a soft amber 🔶, a halt 🛑, or a cheerful tool glyph on an ERROR were corrected, and tests/test_4eh_log_icons.py lints the invariant over the AST. Coverage: the per-turn router decision (label/confidence/escalation, gates MCTS and the planner) and the memory hydration verdict ("N/M recalled memories used") now reach the live stream instead of only the file mirror; foresight predict/resolve failures surface at WARNING. Consistency: level="WARN"→"WARNING", the dark-web breaker line uses the onion 🦥 not the clearnet globe 🌐, and the Verifier Gate line uses the flask 🧪 not a thought bubble. Phase 4: a dedicated tool-dispatch glyph 🧰 (so a tool call no longer borrows the 🎬 "request started" clapperboard; added to both client icon maps), and the title collisions where two different events shared one rendered name — "Service" split into Sandbox/Project, the research summarizer's "Worker Compute" → "Research Compute", boot "Memory Bus" → "Memory Bus Init". The "verifier" stream (one coherent flask-iconed class) and a few sub-event icon varieties were left as-is.
