core / entropy.py — token-level Shannon entropy

Pure-function entropy math + a streaming-friendly rolling tracker. The objective-calibration half of the composite confidence score.

Public API

SymbolPurpose
compute_token_entropy(top_logprobs) -> floatShannon entropy (nats) of one token's top-K logprobs. Re-normalises the truncation, ignores non-finite inputs.
normalise_entropy(h, k=5) -> floatMap raw entropy into [0, 1] by dividing by log(K). K=1 is coerced to 2 to avoid divide-by-zero.
EntropyTracker(window=32, top_k=5)Rolling-window accumulator. observe(top_lps) per token; reading() returns an EntropyReading (raw mean, normalised, n).
extract_top_logprobs(chunk) -> list[float] | NonePulls top-K logprobs out of an OpenAI-compatible streaming chunk. Recognises both logprobs.content[*].top_logprobs and llama.cpp's flat logprobs.top_logprobs. Lenient on shape; returns None on mismatch.
request_logprobs(payload, top_k=5, native_nprobs_ok=True) -> boolShapes a chat payload so the upstream returns token logprobs, picking the field set it will accept: no tools → portable OAI logprobs/top_logprobs; tools attached → the llama.cpp-native n_probs sidestep (llama-server 400s the OAI flag on tools+stream but its formatter emits logprobs whenever the slot sampled with n_probs>0 — verified live + master source, 2026-07-27). Kill: GHOST_ENTROPY_TOOLS_NPROBS=0; callers pass native_nprobs_ok=False after a live rejection (the agent latches context._nprobs_rejected).

Invariants

  • Reading on an empty window: raw=0, norm=0, n=0. Callers can use n == 0 as the "no calibration yet" sentinel.
  • Uniform top-K → norm ≈ 1.0; peaked top-K → norm ≈ 0.0.
  • NaN / inf / non-numeric inputs are skipped, not propagated.
  • Logprobs are clamped to [-50, 0] before exp to prevent overflow.

Why no library?

SciPy's entropy would force a numpy dependency on every chunk parse — too expensive on edge. The pure-Python implementation is sub-microsecond per token and dependency-free.

Consumers (updated 2026-07-27)

Two trackers now feed the confidence/calibration spine: the client-SSE stream's (since phase 2.2) and one on the agent's INTERNAL upstream stream — the path every sim/self-play/CLI turn takes, previously logprob-blind, which left calibration entropy degenerate at 0.5 (see calibration). The live MTP upstream emits logprobs only on target-sampled tokens (~1 chunk in 7); both consumers observe whatever arrives and read the mean over observed tokens. Since the same day's request_logprobs n_probs sidestep, tool-attached streamed generations — the overwhelming majority of main-loop generations — observe entropy too, closing the coverage gap that kept w_entropy pinned at 0 (details in calibration).
