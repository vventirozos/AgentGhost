core / evidence_gate.py — the EVIDENCE CHECK steer

One pure function reads the turn's tool results and answers "did any call this turn return substantive evidence?". When every evidence-bearing call came back empty, weak or errored, the loop tells the model so before it answers. Shipped 2026-09-07 (journal §4FD), under the live experiment arm evidence_gate.

Why it exists

The largest real failure class in six weeks of live turns (~30 of 124 labelled failures, and most of the human 👎) was a confident answer produced after every retrieval came back empty or unrelated: recall returned rows about pg_stat when asked for a project codename and the agent invented a name; browser extract_text returned LENGTH: 1 and the agent answered "around 4 hours"; web search returned nothing usable 54 times and the agent defined a Greek dessert anyway. arXiv 2606.21409 measures the mechanism — unreliable retrieval is worse than none (44.8 → 4.7 F1 on shuffled context) — and this model abstains readily when it is told the evidence is empty. Nothing told it.

What it does

FunctionBehaviour
assess_turn_evidence(tools_run)Walks the turn's recorded tool results (synthetic loop-minted rejections excluded). Only EVIDENCE_TOOLS count (searches, recall/knowledge_base, browser, file_system reads, execute, fact_check, news, system_utility). Returns an EvidenceAssessment: consulted, substantive, and one reason per empty call.
EvidenceAssessment.firesTrue only when the turn consulted evidence and got none of it. A chat turn with no retrieval never fires; one good result among empties never fires.
render_evidence_steer(assessment)The steer text: names up to four reasons, forbids stating facts that were not retrieved, and allows exactly three moves — one more targeted attempt, or say plainly what was not found, and stop.

The empty shapes

Each shape is the tool's own wording, and this module is the single place they are recognised — a tool that rewords its empty result reddens the shape pin in tests/test_evidence_gate.py rather than silently disarming the gate.

Loop wiring and the arm

GhostAgent._evidence_gate_block(tools_run_this_turn, req_id) is called at the volatile-state assembly site, right after the explicit-constraints block, and its text rides the volatile block (never a tool result — the corpus stays what the tool returned, the §4K lesson). It is arm-gated: experiments.arm_for(ctx, "evidence_gate", req_id); the trigger is marked on both arms (evidence_gate_fired: True on treatment, False on control) so the report can condition on turns where it would have fired; the text ships on treatment only. The key is registered in TRIGGER_KEYS and CONTEXT_MUTATING_KEYS. Kill switch: GHOST_EVIDENCE_GATE=0; an unregistered arm is inert.

Tests: tests/test_evidence_gate.py — every real shape both ways, the fires-only-when-all-empty rule, synthetic exclusion, bounded reasons, the arm gating executed on both arms and the kill switch, an AST pin that the production loop calls the method with the turn's tools and appends its result to the volatile state, and the registry keys. Mutation battery §4FD: all gate mutants killed.
