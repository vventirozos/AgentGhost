core / confidence.py — CompositeConfidence

Fuses token-level entropy (one-shot generation signal) and per-domain competence (long-term capability prior) into one tunable confidence score.

The one thing this score is licensed to do (2026-09-04, §4ER)

Measured over 209 metacog summaries: confidence computed 865 times, below_threshold fired 118 times, arbitrations — its only consumer, hard-gated off by _METACOG_ARBITER_ENABLED — zero. The number was computed, recorded, calibrated and acted on by nothing.

§4EO/§4EP settled what it may be read as. It is not a probability (beats_base_rate=indistinguishable, and confirm-carrying coverage cannot make that resolvable at this corpus). It does order turns (ranks_outcomes=yes, AUC 0.634 [0.564, 0.712]). So it gets exactly one use: CalibrationTracker.lowest_confidence_turns() — "the shakiest answers of the week", rendered on introspect learning.

  • The licence gates the use. Only an affirmative yes unlocks it — in NOT_INFORMATIVE would fail OPEN on a typo or a future verdict word.
  • Absent is not withheld. It returns (rows, refusal): a refusal string when the ranking may not be shown, so the report can say why instead of printing an empty list that reads as "no shaky turns this week".
  • Ranked on the RAW stored composite — one stable scale across refits. The Platt map would rank identically (it is monotone) while implying the probability reading the licence refuses.

Asking where the corpus is blind

The human channel was never the bottleneck: the web console carries 👍/👎 on every reply, the ghost CLI has /good//bad with retries, Slack has thumbs. Thirty-nine days produced 7 labels, because nobody is ever asked.

So the agent asks — on a turn that ranks in the bottom quintile, has no verdict, and has not been asked about in 20 hours. The middle condition is the point: a verified turn already has a label, so asking there buys a duplicate, while an unverified low-ranked turn is exactly a row that would otherwise enter the corpus as the _UNVERIFIED_PRIOR placeholder. The wording never quotes the number (GHOST_LABEL_ASK_HOURS=0 disables it).

Formula

C = w_e · (1 - e) + w_c · p, with w_e + w_c = 1 enforced and both clamped to [0, 1]. When the competence cell has fewer than five observations, p is shrunk toward the neutral 0.5 by a coefficient n / (n + 5). A fresh agent never radiates overconfidence in a brand-new domain.

Why additive, not geometric?

The two signals are asymmetric: entropy is per-generation; competence is historical. Weighted additive lets operators tune the balance per deployment — an edge build with a thin model raises w_c because token entropy is noisier there.

Fusing the verbalised-uncertainty track

Historically the objective score (entropy + competence) and the agent's own "I'm not sure" flags (core.uncertainty) were disjoint. score() now accepts uncertainty_pressure ∈ [0,1] (from UncertaintyTracker.pressure()) and applies a multiplicative penalty × (1 − λ·pressure). The default λ = 0 is a no-op, so this is byte-for-byte back-compatible — the calibration spine only raises λ if the agent's hedges actually predict failure on logged turns.

Fusing the objective outcome signal (2026-06-07)

score() also accepts outcome_penalty ∈ [0,1], applied as a final un-discounted multiplicative penalty × (1 − outcome_penalty). Unlike entropy (per-generation) and competence (historical prior), this is ground truth about the answer just produced: it is set when the verifier REFUTED the response or the turn finalised on an unverified file mutation.

Why it was needed. The finalize reading uses a neutral entropy term, and once the calibration refit collapses the entropy weight toward zero, composite ≈ competence. So a domain the agent is historically good at (e.g. fs, competence ≈ 0.96) reported high confidence even when the verifier had just rejected the work — the observed "C=0.92 below=no on a REFUTED build" and "C=0.96 on an untested write" failures. A REFUTED/unverified verdict now drives outcome_penalty = 0.8, which reliably pulls a 0.92–0.96 reading below the 0.89 threshold so below_threshold flips true and the turn is recorded as a failed outcome. Default 0.0 is a no-op, fully back-compatible. Covered by tests/test_verifier_gate_teeth.py.

Self-calibration

apply_fitted(params) hot-swaps the threshold τ, weights, and λ from a calibration fit — at startup (loading a persisted fit) and from the idle refit phase (2.7c). A long-running agent's confidence becomes empirically calibrated against realized outcomes instead of the hardcoded τ = 0.55 / 0.5–0.5 defaults, with no restart.

Calibration composite-leak (bug-hunt 2026-07-26b)

ConfidenceReading gained pre_penalty_composite: the composite BEFORE the outcome_penalty multiply. The calibration spine records THAT, not the penalized composite — the penalty is a function of the turn's outcome label, so recording the penalized value made Brier/ECE read optimistically on exactly the negative samples the loop exists to catch (a refuted turn's stored confidence was pulled to ~0.18, so its Brier contribution looked tiny). The below_threshold DECISION still uses the penalized composite. Defaults to composite for positionally-built readings. Tests: tests/test_bughunt_fixes_2026_07_26b.py::TestConfidencePrePenalty.

2026-07-27 — entropy_observed and missing-feature renormalisation

ConfidenceReading gained entropy_observed. Passing normalised_entropy=None to score() means "no logprobs were observed": the reading is still produced (neutral entropy term, unchanged behaviour) but is FLAGGED, so calibration can exclude it from the entropy-weight fit instead of recording a fabricated measurement.

The composite is now computed per-sample according to what is actually available:

  • entropy observed → w_entropy·entropy + w_competence·competence;
  • not observed → competence alone (the weights sum to 1, so this is the renormalised form).

Blending in the 0.5 stand-in dragged every logprob-less reading toward 0.5 in exact proportion to w_entropy — which is precisely why the weight could only ever be fit to 0 while those turns dominated. Splitting the cases lets the weight be learned from turns that DO carry entropy without degrading the ones that don't.

2026-07-27 (later 5) — turn-effort: the first per-TURN feature

Every input to the composite was dead (see the section above): entropy had 2 distinct values, uncertainty pressure had 1, and competence — the only one that varied — separated success from failure by −0.0008. Competence is a per-DOMAIN historical average, so it is near-constant within a domain and structurally cannot discriminate individual turns. The fix is not better calibration; it is an input that varies per turn.

What was measured first

296 labelled trajectories (246 passed / 50 failed) were scanned for turn-shape signals before any code was written:

The last row is the strongest raw correlate and is deliberately excluded: "a tool errored" is literally a term of the calibration label (execution_failure_count > 0), so feeding it back would predict the label from the label and add no information — the same circularity that made the earlier AUC 0.679 measurement an artefact.

The feature

confidence.effort_component(tool_names) averages two saturating struggle signals — sprawl (call count, saturating at 12) and spin (longest same-tool run, saturating at 6) — into [0, 1] where 1.0 is a short, clean turn. Averaged rather than min()'d so one extreme signal cannot slam the term to zero alone; the measured AUC is within noise of the best single signal (0.670 vs 0.678) while depending on both.

Result end-to-end: replaying the labelled corpus through the real feature and the real fit, w_effort is earned at 0.5, the probability map is adopted (a = 5.91), and Brier lands at 0.123 against a base rate of 0.140 — the model beats the base-rate predictor by 12%, where before it lost to it by 75%. This is the first time the confidence score carries information.

Design rules carried over

  • No fabricated neutrals. A turn that ran no tools passes effort=None, not 0.5 — absence of evidence about effort, not a measurement. Recording it as observed would poison the weight fit exactly as fabricated entropy neutrals did.
  • Weight earned, not assumed. w_effort stays 0 until at least _MIN_EFFORT_SAMPLES (30) samples measured turn shape with BOTH outcome classes present — the same evidence gate as w_entropy.
  • Renormalisation generalised to three components. Only observed components contribute and the blend is divided by their weights, so a missing feature never spends its weight on a stand-in. With entropy absent and effort present, competence + effort renormalise to 1 instead of leaving 40% of the mass on a neutral.
  • _composite_for in the fit mirrors score() exactly, including the three-way renormalisation — the fit must optimise the formula the agent actually evaluates.
