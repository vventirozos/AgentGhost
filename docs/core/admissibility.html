core / admissibility.py — who may consume origin=bench (§4BF Track 1c)

The per-consumer policy matrix for bench-bank outcomes — one declarative table, enforced at every read/write seam. Tests: tests/test_admissibility_1c.py.

Why

Track 1b (eval/banks) generates mechanically-graded outcomes in an isolated corner: a separate trajectory root, task_kind="bench", no learning-store writes. That answered "how do we get graded volume without contaminating anything". This module answers the operator-decided follow-up: which consumers may read that volume, and in what form — so admission is a written policy, not an accident of file paths. The §4AQ denominator rule generalizes here: bench volume must never inflate (or grade) a real-turn instrument.

The four policies

policymeaning
real_onlyreads real turns only — the default for any consumer without a row (fail closed).
bench_featureadmits bench-labeled examples WITH origin attached as an explicit feature/field; every floor, gate and holdout stays real-only. (One accepted deviation: the tool-description runner's SUPPLY gate counts bench positives — ship safety is recovered by its real-only resolution gate, which refuses when the real private tier is too thin.)
bench_taggedadmits bench-derived WRITES tagged with provenance (source="bench") so they stay auditable and retractable.
bench_scopedbench-only VARIANTS: bench data feeds bench-scoped instances exclusively (experiment arms).

Access helpers

  • iter_bench_trajectories(consumer, args=None) — THE way to read the bench corpus: withholds everything for non-admitted consumers (fail closed + debug line), filters to task_kind=="bench" even inside the bench root, degrades to empty on a bench-less box, and (R4) empties under a --no-bench boot when the caller passes the runtime args — the full_no_bench ablation arm must ablate consumption, not just generation. What the flag CANNOT undo: lessons already minted (source=bench) and calibration rows already recorded (origin=bench) — see scripts/ABLATION.md for the arm's honest scope.
  • bench_corpus_fingerprint(args=None) — fold into any corpus-unchanged skip gate, or new bench data never triggers a refit; None under --no-bench so a disabled corpus can't force refits either.
  • selfhood row (R4 CRIT): the first-person diary was an UNDECIDED consumer — bench turns were writing lived-experience entries to the production autobiographical store. Capture is origin-gated (at all three write sites) and dream's bench isolate nulls self_model. The activity digest got the same user-origin gate as the project digest (its ungated sibling was eating notify events — including bench experiment verdicts — every idle night).
  • The finalize doctrine (R5): 1b/1c flipped bench turns from "no collector, everything downstream returns early" to "full collector, full finalize" — every side effect whose only protection was that early return had to be re-decided. User-origin gates now cover: the two digests, the selfhood writes, the METACOG confidence stash (a bench solve's reading was arming/disarming the arbiter on the next REAL turn), the hydrated-lessons trajectory stamp (bench rows were stamped with the last real turn's lesson set), and the promotion-nudge footer. Every copy.copy-shared LRU ring the finalize writes through is rebound on the bench isolate — the full six-ring inventory is pinned behaviorally AND as a source twin (tests/test_bench_solve_loop_1c.py / test_admissibility_1c.py).
  • Report populations (R5-R7): the bench report carries its own title, denominator (coverage["admitted_turns"]) and an items-vs-attempts label; all four live-view surfaces and both announce passes DENY the names DECLARED in the other scope (never an allow-list of this scope's enabled names — that erased a disabled spec's history; never an enabled-only deny — that resurrected stale stamps on re-scope-then-disable); the bench verdict computation itself honors --no-bench via the chokepoint.
