core / calibration.py — Calibration Spine

Closes the loop on confidence: pair each turn's composite confidence with the realized outcome, measure Brier / ECE, and re-fit τ + weights + λ to the data. Roadmap phase 2.5.

The problem it closes

The composite confidence was computed every turn but never checked against what actually happened. The threshold τ = 0.55 and the entropy/competence weights 0.5 / 0.5 were asserted constants — so "the agent is 80 % confident" had no demonstrated relationship to the turn succeeding 80 % of the time. The calibration spine turns that assertion into a measured, self-correcting loop.

The three jobs

  1. Measure. Every metacog turn produces a confidence reading paired with the realized outcome, appended to $GHOST_HOME/system/calibration/calibration.jsonl; from that we compute a rolling Brier score mean((C − outcome)²) and an Expected Calibration Error over a 10-bin reliability table.
    • Logprob-optional confidence. The composite is computed at turn finalization for every full-loop metacog turn — not gated behind the streaming is_final_generation+stream_response branch (which many turns never enter) nor behind a populated token-entropy window. The entropy term is used when the per-token window observed tokens and is neutral (0.5) otherwise, so on speculative-decoding / MTP / no-logprobs upstreams (where the per-token logprob stream is sparse or absent) competence + verbalised-uncertainty drive the score and a sample is still recorded. Verified live on the MTP llama-server: samples land with entropy_component=0.5, competence driving C.
    • Outcome signal. A turn is a negative (0.0) on a structural tool failure, a verifier REFUTED verdict (≥0.7), or a next-turn user-correction promotion (the strongest "confidently wrong" signal — recorded against the prior turn's stashed confidence); otherwise 1.0. Real negatives are what stop the fit from bailing single-class on free-form chat (which is otherwise almost all "clean").
  2. Self-tune. Once ≥ 40 samples (both outcome classes present) accumulate, an idle-time grid search re-fits the entropy/competence weights, the verbalised-uncertainty penalty λ, and the decision threshold τ to minimise Brier. The threshold is then chosen to maximise Youden's J on the "predict success when C ≥ τ" decision.
  3. Unify. The recorded sample carries the verbalised-uncertainty pressure alongside the objective entropy/competence components, so the formerly-disjoint "the agent said it was unsure" track and "the generation/domain was uncertain" track are fit together.

Design non-negotiables

  • Local-only, pure stdlib. math + json only — no numpy, no hosted scorer, no outbound traffic.
  • JSONL / JSON on disk. Append-only history, atomic param writes (.tmp + os.replace), schema-versioned (ghost.calibration.v1).
  • Fail-safe. A recording or fit failure is logged at debug and never breaks a turn; load_params returns None on any problem so a corrupt file degrades to the hardcoded defaults.
  • Bail-on-thin-data. Below 40 samples, or with only one outcome class present, fit returns None and writes no params — a confidently-miscalibrated threshold is worse than the neutral default (same posture as prm.trainer).

Observability

Refits emit metacog calib log lines (📐 icon) with the fitted threshold/weights/λ/Brier. tracker.stats() exposes {samples, brier, ece, fitted, threshold, w_entropy, lambda_uncertainty} for introspection.

Entropy de-degeneration (2026-07-27)

1179 of 1180 recorded samples carried entropy_component=0.5 — the finalize fallback hardcoded neutral entropy, and the only path observing real logprobs (the client-SSE stream) rarely runs: every sim/self-play/CLI turn takes the agent's INTERNAL upstream stream, which never requested logprobs. With 2 distinct entropy values, w_entropy was unfittable (the fit's own DEGENERATE flag). The logprobs opt-in is now hoisted to cover the internal stream — FINAL generations only: llama-server hard-rejects logprobs on tools+stream payloads (live 400 caught on the post-deploy probe), and tools are attached exactly on non-final turns, so tool turns keep neutral entropy by design. The final-generation stream observes chunks into an EntropyTracker (sparse MTP logprobs — ~1 chunk in 7 on the live upstream — are fine; the reading averages observed tokens) and stashes a req-id-tagged _entropy_norm_pending that _record_calibration_safe consumes in place of the old hardcoded 0.5.

Coverage is structurally sparse — root cause established by live probes: with --native-tools ON (default since 2026-07-17) the server withholds logprobs on every tool-attached turn, and most interactive answers land ON a tools-attached turn (the model answers directly rather than transitioning to a forced final generation). The lone real-entropy sample in the corpus is dated 2026-07-18 — the native-tools toggle window. Real entropy therefore flows only on forced final generations, truncation continuations and SSE final streams. Watch entropy_distinct_values; if still <3 by ~2026-08-10, retire w_entropy (already 0-weighted — no behavioral change either way). Tests: tests/test_calibration_entropy_wiring_2026_07_27.py.

2026-07-27 — the entropy signal was structurally unfittable

Measured live: 1200 of 1201 stored samples had entropy_component exactly 0.5 and the fitted w_entropy was 0.0 — the confidence composite had been running on competence alone.

Root cause (confirmed by instrumenting the running agent): llama-server rejects logprobs on tools + stream payloads (HTTP 400, re-confirmed against the live server), and the turn loop attaches tools on every non-final generation. The probe showed final=False tools_in_payload=True → request_logprobs=False for an ordinary turn, so the overwhelming majority of turns observed no token logprobs at all. Those turns recorded the neutral 0.5 stand-in as though it were a measurement. With zero variance in the entropy column, any w_e > 0 could only drag composites toward 0.5 — so the grid search was guaranteed to pick 0 forever. It was not a tuning problem; the data made the parameter unlearnable.

  • Readings and samples now carry entropy_observed, separating "the model was genuinely 50/50" from "no logprobs came back". Legacy records default to False, which is the truthful reading of what they were.
  • Missing-feature renormalisation. A sample with no observed entropy is scored on competence ALONE rather than blended with the stand-in — see _composite_for, which mirrors CompositeConfidence.score exactly so the fit optimises the same formula the agent evaluates. This is what lets a weight learned from the observed minority coexist with a logprob-less majority: an earlier version that fit on the subset and applied it to everything drove Brier from 0.075 to 0.219.
  • The weight only moves with evidence. Below _MIN_ENTROPY_SAMPLES observed samples of both outcome classes, w_entropy stays pinned at 0 and the reason is logged, rather than a weight being "fit" on fiction. FittedParams gained n_entropy_observed so the state is visible.
  • Logprobs are now requested whenever the payload carries no tools — the previous gate also required is_final_generation, which is strictly narrower than the server's real constraint and cost coverage for tool-free non-final generations.

Verified across four regimes: all-neutral → w_e=0 (no regression); observed+informative → w_e=1.0 (previously impossible); observed-but-noise → w_e=0 (declines to use noise); mixture → w_e=1.0 with Brier 0.093 instead of 0.219. Tests: tests/test_calibration_entropy_observed.py (15).

2026-07-27 (later 4) — probability recalibration, and the diagnosis it produced

The composite was measured against the only baseline that matters — always predicting the base rate:

PredictorBrier
Raw composite0.0656
Always predict the base rate (0.961)0.0374

As a probability, the confidence number was worse than a constant. The weight search decides how to COMBINE signals but cannot set their level, so a two-parameter Platt stage (p = sigmoid(a·composite + b)) now runs after the weight fit, with the raw and base-rate Briers persisted alongside it so the comparison can never be lost again.

On the live corpus the map is REJECTED — and that is the finding

An initial measurement suggested the composite had real ranking ability (AUC 0.679) and that recalibration would beat the baseline by 18%. That was an artefact: it was computed on the stored composite, which mixes two scoring regimes. Recomputed leak-free from the stored components, AUC is 0.473 — below chance. The optimiser therefore converges to a ≈ −0.08: a negative slope that would INVERT the agent's confidence ordering, and a near-flat one that would collapse every turn onto the base rate, leaving below_threshold permanently inert. Calibrating noise is not an improvement, so the guard refuses any fit with slope below 0.5 and logs why. The machinery engages the moment a predictive feature exists — pinned by a test using an informative-but-compressed corpus, where it is adopted and beats the base rate.

Feature health: 0 of 3 inputs are alive

Recalibration cannot fix a score with nothing in it. Measuring each input for whether it varies AND separates the outcome classes:

This is now reported every run by learning-health telemetry (features: 0/3 live — NONE discriminate), so a dead input is visible immediately rather than inferred from a bad Brier months later. Note that "few distinct values" is NOT the death test — a two-valued feature that splits the classes cleanly is useful, whereas competence has 270 values and separates by −0.0008. Separation is what counts.

Consequence: the binding constraint on this subsystem is feature quality, not label supply and not calibration. Competence is a per-DOMAIN historical average, so it is nearly constant within a domain and cannot discriminate individual turns. A useful confidence score needs an input that varies per TURN.

Fitting notes

  • Newton/IRLS, not gradient descent. GD was still at a = 1.28 after 4000 steps and only reached its optimum near a = −0.08 after ~60000 — values on opposite sides of the safety guard, so an under-converged run would have adopted a map the converged fit rejects. The answer must not depend on the iteration budget. IRLS converges in under 20 iterations (0.04 s on 1208 samples).
  • Unweighted. Class-balancing was tried first, on the theory that 96% positives would drown the minority; but balancing optimises a reweighted distribution, so the probabilities describe a 50/50 world that does not exist and the unweighted Brier got worse. Imbalance is handled by the threshold search (Youden's J), which weights sensitivity and specificity equally regardless of prevalence.
  • The threshold is selected on the CALIBRATED scores, so it lives on the same scale below_threshold compares against.
  • domain is finally recorded on each sample — it was computed for the competence lookup and then dropped, so all 1208 stored samples carried domain="" and per-domain reliability was impossible.
