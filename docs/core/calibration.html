core / calibration.py — Calibration Spine

Closes the loop on confidence: pair each turn's composite confidence with the realized outcome, measure Brier / ECE, and re-fit τ + weights + λ to the data. Roadmap phase 2.5.

The problem it closes

The composite confidence was computed every turn but never checked against what actually happened. The threshold τ = 0.55 and the entropy/competence weights 0.5 / 0.5 were asserted constants — so "the agent is 80 % confident" had no demonstrated relationship to the turn succeeding 80 % of the time. The calibration spine turns that assertion into a measured, self-correcting loop.

The three jobs

  1. Measure. Every metacog turn produces a confidence reading paired with the realized outcome, appended to $GHOST_HOME/system/calibration/calibration.jsonl; from that we compute a rolling Brier score mean((C − outcome)²) and an Expected Calibration Error over a 10-bin reliability table.
    • Logprob-optional confidence. The composite is computed at turn finalization for every full-loop metacog turn — not gated behind the streaming is_final_generation+stream_response branch (which many turns never enter) nor behind a populated token-entropy window. The entropy term is used when the per-token window observed tokens and is neutral (0.5) otherwise, so on speculative-decoding / MTP / no-logprobs upstreams (where the per-token logprob stream is sparse or absent) competence + verbalised-uncertainty drive the score and a sample is still recorded. Verified live on the MTP llama-server: samples land with entropy_component=0.5, competence driving C.
    • Outcome signal. A turn is a negative (0.0) on a structural tool failure, a verifier REFUTED verdict (≥0.7), or a next-turn user-correction promotion (the strongest "confidently wrong" signal — recorded against the prior turn's stashed confidence); otherwise 1.0. Real negatives are what stop the fit from bailing single-class on free-form chat (which is otherwise almost all "clean").
  2. Self-tune. Once ≥ 40 samples of the current epoch (both outcome classes present) accumulate, an idle-time grid search re-fits the entropy/competence/effort weights, the verbalised-uncertainty penalty λ, and the decision threshold τ. Candidates are scored on the Brier the pipeline will actually deliver — i.e. after the Platt stage, under the same acceptance rules — and a weight may only leave zero if its feature both has enough observations and measurably separates the outcome classes. The threshold is then chosen to maximise Youden's J on the "predict success when C ≥ τ" decision.
  3. Unify. The recorded sample carries the verbalised-uncertainty pressure alongside the objective entropy/competence components, so the formerly-disjoint "the agent said it was unsure" track and "the generation/domain was uncertain" track are fit together.

Design non-negotiables

  • Local-only, pure stdlib. math + json only — no numpy, no hosted scorer, no outbound traffic.
  • JSONL / JSON on disk. Append-only history, atomic param writes (.tmp + os.replace), schema-versioned (ghost.calibration.v1).
  • Fail-safe. A recording or fit failure is logged at debug and never breaks a turn; load_params returns None on any problem so a corrupt file degrades to the hardcoded defaults.
  • Bail-on-thin-data. Below 40 samples, or with only one outcome class present, fit returns None and writes no params — a confidently-miscalibrated threshold is worse than the neutral default (same posture as prm.trainer).
  • One epoch per fit. Rows from an older label scheme or feature set are never blended with current ones. See Corpus epochs — this is the constraint whose absence silently inverted the fit for 26 days.

Observability

Refits emit metacog calib log lines (📐 icon) with the fitted threshold/weights/λ/Brier, the sample count n (current epoch) and excluded (older-epoch rows skipped). tracker.stats() exposes {samples, samples_all_epochs, epoch, brier, ece, fitted, threshold, w_entropy, lambda_uncertainty, map_status, beats_base_rate} — a debug/test surface with no production caller, despite what its docstring claimed until 2026-08-30.

Four surfaces report the verdicts, and they must agree (§4EB): the startup 📐 line (main.calib_startup_fields), the idle-refit 📐 line (core.agent._biological_tick), the warning from fit itself (since 2026-09-04 at WARNING only when the verdict changes, at DEBUG while it persists), and introspect learning (learning_health collector → renderer). Each carries both beats_base_rate and ranks_outcomes; the refit line reads refit=ok/no_prob:<v>/no_rank:<v>, and the report prints an AUC … — the score RANKS outcomes line under the Brier sentence. An AST enumeration in tests/test_calibration_rank_verdict.py fails if any function reports one verdict without the other — the first cut of §4EB added the rank verdict to fit and the agent line only, which is the “both ends but not the collector” mistake this module already carries a warning about.

A placeholder is not a label (2026-09-04, §4EO)

grade_turn_outcome returns _UNVERIFIED_PRIOR (0.83) for “nothing was checked and nothing visibly broke” — a stand-in for a measurement that never happened, exactly as the neutral 0.5 is for unobserved entropy. This module already refuses to let the entropy stand-in vote (entropy_observed gates w_entropy); the outcome stand-in had no such gate, and on the live store it is 63% of the fit population (672 of 1074, measured 2026-09-04). Both verdicts were computed over it:

  • beats_base_rate compares the model against always predicting the base rate — and the base rate IS the placeholder (0.838 against a constant 0.83), so two thirds of the rows were asking the model to reproduce the comparand. The fitted map obliges: slope 1.958 / intercept 0.013 returns 0.837 at the placeholder, and the whole corpus maps onto [0.700, 0.867]. “Indistinguishable from a constant” was not a finding about the score; it was the corpus describing itself.
  • ranks_outcomes binarises at 0.5, so every placeholder entered the AUC as a positive — 672 of 1017 (66%) of the “successes” the score was credited with ordering were turns nobody checked.

label_is_verdict is now the single authority on which rows may judge a fit, and verdict_pairs the single filter (one implementation per shape, as with the supersession and cap twins). Placeholders are still fitted on — this narrows what measures the scorer, never what the scorer is. The weights, the Platt map and the threshold are untouched.

“Indistinguishable” hides two opposite states

The word covers “we measured a tie” and “we cannot measure”, and the live store is the second. delta_halfwidth — the half-width of the cross-validated delta CI — is the smallest difference these rows can resolve: ±0.00607 against an observed effect of 0.00369, so the comparison is 1.6× too coarse to find what is there. The warning and introspect learning both state it. This is the same unknown-versus-measured distinction the module already refuses to blur on beats_base_rate, one field over. Scaling estimate: roughly double the verdict rows (~6 weeks at ~10/day) before the comparison could resolve either way.

The bench exclusion now explains itself

The direction gate had been dropping rows since 2026-08-31 saying only “they rank backwards”, so the question it raises — why do these rows invert? — took a bespoke script to answer. The answer was worth having: on the 309 excluded rows competence_component ranks at 0.189 against effort_component at 0.755. Competence is a per-domain prior, so on a population whose domain mix is degenerate it is a near-constant that cannot track per-turn outcomes — and it carries the largest weight. The gate now returns that per-component measurement and the message names it (Driven by competence_component 0.189; …), so an exclusion is a diagnosis rather than a verdict.

What this is not. The bench population also showed 7 of its 19 failures with no per-turn component observed at all — composite collapses to the domain prior (0.88–0.92) and reports it with the authority of a measurement. That looked like the finding, and it does not replicate on real turns: P(bad | effort unobserved) is 0.024 against 0.066 when observed, i.e. the opposite direction. It is a bench-harness pattern, and nothing was changed on the strength of it.

Pins: tests/test_calibration_verdict_population.py (22). Mutation battery 17/17 killed, no-op control survived, known-bad control died.

Warnings fire on CHANGE, not per refit (2026-09-04)

The three per-refit warnings in fit — the backwards auxiliary population, the map not in force, and the base-rate verdict — each describe a property of the corpus, not an event. The refit runs hourly (_CALIB_REFIT_COOLDOWN, agent idle phase 2.7c) over an append-only store, so the same rows re-announced the same verdict about eleven times a day. Measured on the live operator log: 99 INDISTINGUISHABLE lines and 80 bench-EXCLUDED lines over five days, identical but for the fourth decimal. That is the alarm channel spent on a fact that has not moved, which trains exactly the habit these warnings exist to defeat.

Each site now picks its level through announce_level(previous, current): WARNING when the verdict is new or has changed, DEBUG while it merely persists. The message text is untouched, so a log grep still finds the state; only the severity moves. The transition is the event.

  • The verdict is the trigger, never the count. n_bench_misaligned climbs with every nightly bench solve (253 → 309 over five days), so gating on it would re-announce a standing exclusion under a new number — the same noise in disguise.
  • One decision serves both base-rate branches. no and indistinguishable are two values of one verdict logged from two branches; deciding per branch would let a no → indistinguishable flip — a real change in what the score may be used for — read as steady state.
  • The baseline is the params file, not process memory. A restart therefore does not replay every standing warning, and there is no second record of “what did we last say” to drift from the file every other consumer reads. Consequence, stated because it is real: a fit that bails writes no params, so a verdict that changes and then bails re-announces until a fit succeeds and records it — the honest direction, since the change is genuinely still unrecorded.
  • One cold-start baseline, shared. NOTHING_RECORDED is a FittedParams whose verdicts are None — in no vocabulary, so an unrecorded condition always announces. It replaced three per-site if prev is not None guards after a mutation battery proved one of them unpinnable: at cold start _apply_bench_direction_gate has no instrument, so it excludes nothing and the bench warning never runs, making that site’s cold-start branch unreachable and its mutant equivalent — one gate change away from silently swallowing the first announcement. test_the_bench_line_cannot_fire_before_a_first_fit pins the reachability that argument rests on.

The steady state does not go dark: it stays a field on the stored params (beats_base_rate, bench_verdict, map_status), rides the per-refit 📐 CALIB line at INFO as no_prob:<v>/no_rank:<v>, is written to the activity ledger, and is queryable via introspect learning. The verdict is asked once and published; this only stops the log from re-announcing the answer.

Pins: tests/test_calibration_log_on_change.py (17). Mutation battery 10/10 killed — always-WARNING, always-DEBUG, inverted comparison, count-as-trigger, wrong field, per-branch decision, per-site cold start, a sentinel carrying a vocabulary word, an instance-memoised baseline, and the map line deciding from itself — with a no-op control that survived and a known-bad control that died.

beats_base_rate — the licence (2026-08-30)

FittedParams.beats_base_rate answers “may anything treat this score as informative?” and takes one of four values: yes, no, indistinguishable, unknown. The last three are grouped as NOT_INFORMATIVE.

Consumers test != BEATS_YES, not in NOT_INFORMATIVE. The membership form fails open: a value outside the vocabulary — a typo, a hand edit, a verdict from a future version — is not in the set, so it reads as licensed. NOT_INFORMATIVE remains as the grouping the vocabulary is defined by; the guard consumers use is the affirmative one.

It is decided from the 95% paired-bootstrap CI of the cross-validated Brier delta, not from the point estimate: hi < 0 ⇒ yes, lo > 0 ⇒ no, straddling zero ⇒ indistinguishable. Malformed intervals (wrong arity, non-finite, inverted, booleans, strings) all yield unknown — yes is unreachable from anything but a well-formed interval strictly below zero. Until this landed, the decision sat ~45 lines above the only evidence that could inform it and could consult only the in-sample point estimate, which read the live store's 0.00108 wobble as a win.

A rejected map withholds the licence — at every caller, for stored and derived verdicts alike. The rule lives in calibration.downgrade_for_map(verdict, map_status), and it has three callers: fit(), load_params(), and the learning-health renderer — the last on both its paths, the verdict it derives for a legacy file and the verdict it reads from a file that already has one. Each was added a round after the previous one shipped alone; the loader was the third reader, and while it did not ask, one params file told the startup 📐 CALIB line and introspect learning different stories. The second was added 2026-08-30 after the first shipped alone — protecting files where the field is absent while trusting files where it is wrong, which is exactly the shape every params file written by the previous build carries (rejected_inverted together with beats_base_rate: "yes"). It lived only in fit() until 2026-08-30, so a params file written before the field existed — every one of them, the live one included — was re-granted the licence at render time even when its map had been rejected. map_applied() is the single answer to "is the map in force?": absent means a file older than map_status and reads as applied; anything else unrecognised (including "", which was previously read three different ways) fails closed.

On all three rejection paths the shipped predictor is the raw composite, while the CV interval measures the calibrated model — so the verdict is downgraded to unknown, never to no or indistinguishable, which are measured words for a comparison that was never run. The learning-health renderer reports that refusal verbatim, naming the cause it can actually observe — a rejected map, or a fit with no usable interval, which are different situations that both produce unknown. Only a params file with the key genuinely absent (written before this existed) falls back to deriving a verdict from the stored interval, and the rendered line is then tagged DERIVED at render time. That tag was claimed here before it existed: until 2026-08-30 a derived verdict rendered byte-identically to a stored one.

“NOT IN FORCE” (2026-08-30)

The learning-health report reads calibration_params.json directly, so it could render a full CALIBRATION section — base-rate licence included — for a fit load_params refuses, while the agent ran on hardcoded defaults. It now asks load_params itself rather than re-implementing one clause of its policy: the loader returns None on bad JSON, a non-dict, a schema mismatch, and any unusable required numeric, and a first version of this flag checked only the schema. When the loader refuses, the section is prefixed ⚠ NOT IN FORCE rather than blanked — the numbers are still the last fit's and worth seeing, they simply are not running.

Absent is not null. A params file with no map_status predates the field and reads as applied; an explicit "map_status": null is a malformed value and fails closed. map_applied() takes a value and so treats None as the null case; map_applied_in_params() takes the dict, where absence is observable. Every number read off this file is guarded the same way — a bool, a string or a missing key in brier or brier_cv used to raise out of the renderer, and introspect turned that into Learning health unavailable, losing lessons, episodes, PRM and router reporting to one malformed calibration field.

Nothing read off the file is trusted

Every value in calibration_params.json is attacker-shaped as far as this code is concerned — a partial write, a hand edit, a future producer. The rules, all learned the hard way, each after a guard was applied to one site and not its neighbour:

  • Absent is not null. A missing key means a file older than the field and may be derived from; an explicit null is malformed and fails closed. This holds for map_status (map_applied_in_params) and for beats_base_rate (beats_base_rate_present) — the second got the rule a round later, during which null was the single most permissive value the field accepted, more permissive than a typo.
  • Bools are ints, and NaN is neither positive nor negative. Every numeric read goes through a guard rejecting bool and non-finite values. A pair of predicates that were not complements (< 0 / >= 0) let NaN vanish eight lines of the report with no notice.
  • Omissions are announced. ⚠ NOT IN FORCE when load_params refuses the file, ⚠ NO USABLE BASELINE when the verdict and ablation table are dropped, a counted warning when feature-ablation entries are unusable. A section that disappears silently is worse than one that reports a problem.
  • The report never raises. introspect turns any exception into Learning health unavailable, so one malformed calibration field would cost the lesson, episode, PRM and router sections too.

An unrecognised value — a typo, a hand-edited file, a verdict from a future version — is not a verdict. load_params coerces anything outside the four words to unknown, because consumers testing in NOT_INFORMATIVE fail open on a word they do not know; the log lines now test != BEATS_YES instead, which fails closed.

Reading n: it counts the current epoch only. When epochs landed it dropped 1709 → 541 in one refit; excluded sits beside it precisely so that reads as a filter rather than as data loss.

Corpus epochs (2026-08-02)

The history is append-only and max_history (4000) exceeded the whole file, so every refit pooled the entire corpus. That is only valid while the label scheme and the feature set hold still — and they had not. The result was ~291 warning lines, one pair per hourly refit for 26 days, reporting that the composite was "anti-correlated with outcomes" and that the fit was "WORSE than always predicting the base rate". Both were true of the pooled corpus and false of the signal.

Pooled, the score rises exactly as the labels fall — a textbook Simpson's paradox that forces a negative Platt slope, so the map was rejected as inverted on every refit and Brier stayed on the raw scale. Measured both ways on the same 1709 rows with the same code:

So CURRENT_EPOCH gates the fit, and every row carries an epoch tag. Untagged legacy rows get theirs derived from ts (epoch_for_ts), never defaulted to the current value — silently promoting them is the contamination the field exists to prevent. The boundary check validates the ISO shape before comparing, because "not-a-timestamp" > "2026-07-27" lexicographically would promote garbage. Retro-negatives (task_reopened) inherit the closing turn's epoch, since they reuse that turn's stored features.

Bumping CURRENT_EPOCH is not bookkeeping — it is what keeps the fit valid. Any label-scheme or feature-set change must bump it. Expect the loop to go quiet afterwards until the new epoch clears the 40-sample floor; that is correct, because no fit beats a fit on incomparable rows. Every read path — brier_score, ece, reliability_table, stats, and the learning_health telemetry — is scoped the same way, or the report would describe a population no fit ever sees.

Selecting on the delivered Brier (2026-08-02)

The grid search scored candidates on the raw Brier while the pipeline delivers a Platt-mapped one. On the live corpus the raw-best point (0.054164, slope −0.077 → map REJECTED) beat the runner-up (0.054204, slope +0.388 → map ACCEPTED) by 4e-5 — a coin flip in the fourth decimal decided whether the agent got a probability map at all, and 321 of the 396 grid points had a positive slope. Candidates are now scored on what the pipeline actually delivers: the calibrated Brier when the map passes the same acceptance rules applied downstream, the raw one when it does not. This cannot do worse, since a rejected point simply scores its raw Brier as before.

Two guards keep that honest:

  • Tie-break toward the simpler model (_BRIER_TIE_TOL = 1e-4). A strict < over floats hands the decision to the last decimal place — which is exactly how the inverted map won. Complexity is compared on the integer grid indices, not the divided floats, since 0.1 + 0.2 ≠ 0.3 in binary would otherwise rank two equally simple points by a rounding artefact.
  • A separation gate (_MIN_SEPARATION_SIGMAS = 2.5). Scoring on the delivered Brier removes the level penalty that used to suppress a useless column, so without this the grid buys w_entropy = 0.2 for a 4.9e-5 in-sample gain on a corpus of pure noise. A tolerance cannot fix it: the spurious gain is heavy-tailed (median 0, tail ~1e-3) and does not shrink as 1/n, so any tolerance large enough to absorb the tail also eats most of a real feature's contribution. Instead a weight may only leave zero when |mean(ok) − mean(bad)| reaches 2.5 standard errors — the module's own "a feature must VARY and SEPARATE" rule, applied in the fit rather than only in the report. Measured over 1000 pure-noise corpora spanning n = 40…800 it false-admits 4.9 % (2.0σ admits 8.8 %), while the live effort feature separates at 3.64σ and is never in danger.

    The zero-denominator case is two cases. A feature with no within-class spread has standard error 0, and the first version returned 0.0σ for it — which pinned the single best feature obtainable. A column that is constant within each class and different between them is a PERFECT separator (→ inf); only a column constant across both classes is undecidable (→ 0.0, pinned). Note that a real corpus rarely hits the branch exactly: values like 0.9 and 0.2 leave ~1e-18 of float residue and take the ordinary path to a huge finite σ, which is equally correct.

The telemetry's entropy_learnable verdict and _feature_health's live/dead call both invoke calibration._separation_sigmas directly and apply both halves of the gate. Reporting only the sample floor is how that line once printed "LEARNABLE" while the fit was pinning the weight to 0; keeping a local abs(sep) < 0.02 cut is how feature_health came to mark entropy [live] (0.0421 > 0.02) in the same report where the fit pinned it (0.63σ < 2.5σ). One function, one verdict.

Two questions, two verdicts (2026-08-31, §4EB)

The hourly warning used to end on “nothing may treat this score as informative”. On this corpus a Brier comparison cannot support that sentence. With a base rate of 0.855 and 71 negatives in 1274 rows (5.6%), the achievable improvement over a constant is a fraction of a percent — measured R² 1.7% — so the test is nearly powerless for ordering. Measured on identical rows the same day:

Both are now measured, both are recorded, and both are interval-driven — _rank_verdict reads the bootstrap CI against 0.5 exactly as _base_rate_verdict reads the delta CI against zero, so this cannot become a second licence granted on a point estimate (the §4DZ defect). They reuse one frozen vocabulary; for a rank statistic no means orders them backwards. AUC is computed on the RAW composite deliberately: it is invariant to a strictly increasing Platt map, so raw and calibrated agree whenever the map is applied, and on the rejected_inverted branch the raw column is what actually ships.

Consequence for consumers: a ranking use — flagging the lowest-confidence turns — is supported by ranks_outcomes; a probability claim still needs beats_base_rate, and does not have it. The operator line reflects the split: refit=ok/no_prob:indistinguishable instead of the old undifferentiated no_signal:.

Auxiliary rows must rank the same way (2026-08-31, §4EB)

_apply_bench_mass_cap admits bench-origin rows to the fit under an equal-mass cap, on the premise that they are exchangeable with real turns. It bounds how many enter; nothing tested the premise. Measured on the live store:

Bench rows ranked outcomes backwards — fit alone they produce a Platt slope of −12.8 — and being under the cap (252 ≤ 1022) every one was admitted, dragging pooled AUC to 0.577. This is the same lesson corpus epochs encode one axis over: no fit beats a fit on incomparable rows.

_apply_bench_direction_gate tests the premise. It is deliberately conservative — it excludes only on a confident inversion (the whole CI below chance); an auxiliary population that merely ranks weakly, or not at all, is still admitted, because dropping real data on noise is the worse error and the operator decision that admitted bench (§4BF 1c) stands until there is evidence against its premise. Measured false-exclusion rate under a true null: 2.25–3.25% against a nominal 2.5%, pinned as a test. The auxiliary rows are scored with the previously fitted weights — the instrument actually in production, which also keeps the decision independent of the fit it feeds — so on a cold start there is no evidence and everything is admitted; the exclusion costs one refit. The decision is recorded as bench_verdict / n_bench_misaligned, so a corpus that oscillates is visible rather than silent.

One builder. fit, _load_epoch and stats each assembled the population chain by hand, and this module already carries two bugs from that (§4L R2 NEW-4 averaged superseded duplicates; §4BF 1c reported over uncapped bench rows) — a metric describing a population the fit never consumed. All three now call _fit_population, and an AST enumeration fails if a fourth filter is added to one caller and not the others.

Known asymmetry

The λ (verbalised-uncertainty) grid is not gated by the separation test — only the entropy and effort weights are. In practice uncertainty_pressure is 0.0 on essentially every sample (2 distinct values, mean 0.0003, max 0.067), so the multiplicative term (1 − λ·pressure) can move a composite by at most ~3 % and only on the handful of rows that carry any pressure. If that tracker ever starts producing real signal, gate λ the same way before trusting a fitted value.

Entropy de-degeneration (2026-07-27)

1179 of 1180 recorded samples carried entropy_component=0.5 — the finalize fallback hardcoded neutral entropy, and the only path observing real logprobs (the client-SSE stream) rarely runs: every sim/self-play/CLI turn takes the agent's INTERNAL upstream stream, which never requested logprobs. With 2 distinct entropy values, w_entropy was unfittable (the fit's own DEGENERATE flag). The logprobs opt-in is now hoisted to cover the internal stream — FINAL generations only: llama-server hard-rejects logprobs on tools+stream payloads (live 400 caught on the post-deploy probe), and tools are attached exactly on non-final turns, so tool turns keep neutral entropy by design. The final-generation stream observes chunks into an EntropyTracker (sparse MTP logprobs — ~1 chunk in 7 on the live upstream — are fine; the reading averages observed tokens) and stashes a req-id-tagged _entropy_norm_pending that _record_calibration_safe consumes in place of the old hardcoded 0.5.

Coverage is structurally sparse — root cause established by live probes: with --native-tools ON (default since 2026-07-17) the server withholds logprobs on every tool-attached turn, and most interactive answers land ON a tools-attached turn (the model answers directly rather than transitioning to a forced final generation). The lone real-entropy sample in the corpus is dated 2026-07-18 — the native-tools toggle window. Real entropy therefore flows only on forced final generations, truncation continuations and SSE final streams. Watch entropy_distinct_values; if still <3 by ~2026-08-10, retire w_entropy (already 0-weighted — no behavioral change either way). Tests: tests/test_calibration_entropy_wiring_2026_07_27.py. Superseded the same day — see the n_probs sidestep below: the tools-attached gap is closed, so the ~2026-08-10 check flips its expectation: coverage should CLIMB (entropy_observed_pos/neg in the learning-health report), and a flat 0 now means the probe broke again, not that the corpus can't produce entropy.

2026-07-27 (later) — n_probs sidestep: tool-attached generations observe entropy

The server constraint was re-read at the source (llama.cpp master server-common.cpp / server-task.cpp, matching the live b10090 build): the 400 guard fires only on the OAI logprobs flag, while the streamed chat formatter attaches OAI-shaped logprobs to a chunk's last delta whenever the slot sampled with n_probs > 0 — it never re-checks the request flag. The llama.cpp-native n_probs field rides the server's pass-through parameter copy straight to the sampler, so n_probs + tools + stream streams logprobs chunks. Verified against the live server: the chunks parse through extract_top_logprobs → EntropyTracker unchanged (probs/delta alignment is imperfect under tool parsing — irrelevant for entropy, which needs only the top-K distributions, not their text alignment).

  • entropy.request_logprobs(payload, top_k=5, native_nprobs_ok=…) owns the field selection: no tools → portable OAI logprobs/top_logprobs; tools attached → native n_probs. The OAI flag is NEVER set alongside tools — that 400 breaks the generation, not just entropy.
  • Self-healing: if a future upstream rejects n_probs, the stream-abort handlers on BOTH stream paths latch context._nprobs_rejected, so it costs one generation, not every one. Kill switch: GHOST_ENTROPY_TOOLS_NPROBS=0.
  • MTP sparsity is unchanged: probs arrive on target-sampled tokens only; the tracker reads over observed tokens.

2026-07-27 — the entropy signal was structurally unfittable

Measured live: 1200 of 1201 stored samples had entropy_component exactly 0.5 and the fitted w_entropy was 0.0 — the confidence composite had been running on competence alone.

Root cause (confirmed by instrumenting the running agent): llama-server rejects logprobs on tools + stream payloads (HTTP 400, re-confirmed against the live server), and the turn loop attaches tools on every non-final generation. The probe showed final=False tools_in_payload=True → request_logprobs=False for an ordinary turn, so the overwhelming majority of turns observed no token logprobs at all. Those turns recorded the neutral 0.5 stand-in as though it were a measurement. With zero variance in the entropy column, any w_e > 0 could only drag composites toward 0.5 — so the grid search was guaranteed to pick 0 forever. It was not a tuning problem; the data made the parameter unlearnable.

  • Readings and samples now carry entropy_observed, separating "the model was genuinely 50/50" from "no logprobs came back". Legacy records default to False, which is the truthful reading of what they were.
  • Missing-feature renormalisation. A sample with no observed entropy is scored on competence ALONE rather than blended with the stand-in — see _composite_for, which mirrors CompositeConfidence.score exactly so the fit optimises the same formula the agent evaluates. This is what lets a weight learned from the observed minority coexist with a logprob-less majority: an earlier version that fit on the subset and applied it to everything drove Brier from 0.075 to 0.219.
  • The weight only moves with evidence. Below _MIN_ENTROPY_SAMPLES observed samples of both outcome classes, w_entropy stays pinned at 0 and the reason is logged, rather than a weight being "fit" on fiction. FittedParams gained n_entropy_observed so the state is visible.
  • Logprobs are now requested whenever the payload carries no tools — the previous gate also required is_final_generation, which is strictly narrower than the server's real constraint and cost coverage for tool-free non-final generations.

Verified across four regimes: all-neutral → w_e=0 (no regression); observed+informative → w_e=1.0 (previously impossible); observed-but-noise → w_e=0 (declines to use noise); mixture → w_e=1.0 with Brier 0.093 instead of 0.219. Tests: tests/test_calibration_entropy_observed.py (15).

2026-07-27 (later 4) — probability recalibration, and the diagnosis it produced

The composite was measured against the only baseline that matters — always predicting the base rate:

PredictorBrier
Raw composite0.0656
Always predict the base rate (0.961)0.0374

As a probability, the confidence number was worse than a constant. The weight search decides how to COMBINE signals but cannot set their level, so a two-parameter Platt stage (p = sigmoid(a·composite + b)) now runs after the weight fit, with the raw and base-rate Briers persisted alongside it so the comparison can never be lost again.

On the live corpus the map is REJECTED — and that is the finding

An initial measurement suggested the composite had real ranking ability (AUC 0.679) and that recalibration would beat the baseline by 18%. That was an artefact: it was computed on the stored composite, which mixes two scoring regimes. Recomputed leak-free from the stored components, AUC is 0.473 — below chance. The optimiser therefore converges to a ≈ −0.08: a negative slope that would INVERT the agent's confidence ordering, and a near-flat one that would collapse every turn onto the base rate, leaving below_threshold permanently inert. Calibrating noise is not an improvement, so the guard rejects a map whose slope is ≤ 0 (anti-correlated) or above the _MAX_SLOPE = 50 step backstop, and logs why. The machinery engages the moment a predictive feature exists — pinned by a test using an informative-but-compressed corpus, where the map is adopted.

“Adopted” is not “beats the base rate” (2026-08-30). This page used to run the two together. They are different questions with different evidence: was the Platt map applied? compares the calibrated score to the raw composite, while does the score carry any information? compares it to a constant. A map can legitimately improve on the raw composite while the result is still statistically indistinguishable from always predicting the base rate — which is the live store today (map_status: applied, 95% CI of the Brier delta [−0.00187, +0.000354], straddling zero).

The rejection is now visible in every status surface (2026-07-29): FittedParams.map_status records what happened to the map — applied | rejected_inverted (slope ≤ 0) | rejected_step (slope > 50 backstop) | discarded_worse (calibrated Brier no better than raw) — persisted in calibration_params.json (legacy files load as applied) and threaded into the idle-refit metacog line (previously refit=ok in the very cycle whose map was REJECTED — now refit=map_rejected_inverted), the boot loaded=startup line (map=…), the activity-ledger record, and tracker.stats(). Tests: tests/test_log_audit_fixes_2026_07_29.py::TestCalibMapStatus.

Feature health: 0 of 3 inputs are alive

Recalibration cannot fix a score with nothing in it. Measuring each input for whether it varies AND separates the outcome classes:

FeatureDistinct valuesSeparation (success − failure)

This is now reported every run by learning-health telemetry (features: 0/3 live — NONE discriminate), so a dead input is visible immediately rather than inferred from a bad Brier months later. Note that "few distinct values" is NOT the death test — a two-valued feature that splits the classes cleanly is useful, whereas competence has 270 values and separates by −0.0008. Separation is what counts.

Consequence: the binding constraint on this subsystem is feature quality, not label supply and not calibration. Competence is a per-DOMAIN historical average, so it is nearly constant within a domain and cannot discriminate individual turns. A useful confidence score needs an input that varies per TURN.

Fitting notes

  • Newton/IRLS, not gradient descent. GD was still at a = 1.28 after 4000 steps and only reached its optimum near a = −0.08 after ~60000 — values on opposite sides of the safety guard, so an under-converged run would have adopted a map the converged fit rejects. The answer must not depend on the iteration budget. IRLS converges in under 20 iterations (0.04 s on 1208 samples).
  • Unweighted. Class-balancing was tried first, on the theory that 96% positives would drown the minority; but balancing optimises a reweighted distribution, so the probabilities describe a 50/50 world that does not exist and the unweighted Brier got worse. Imbalance is handled by the threshold search (Youden's J), which weights sensitivity and specificity equally regardless of prevalence.
  • The threshold is selected on the CALIBRATED scores, so it lives on the same scale below_threshold compares against.
  • domain is finally recorded on each sample — it was computed for the competence lookup and then dropped, so all 1208 stored samples carried domain="" and per-domain reliability was impossible.

2026-07-27 (later 7) — second review pass: six defects in the same day's work

All six were introduced the same session and all were invisible to a 142-green calibration suite, because each needs a corpus shape the tests never built. The theme is worth keeping: every one of these safety mechanisms was written from intuition rather than measurement, and every one was wrong in a way only a numeric probe reveals.

  • The "ridge" was not a regulariser. Added to the Hessian diagonal only, it is Levenberg damping — it changes the step size but not the fixed point. On linearly separable data the unpenalised optimum is at infinity, so the slope grew with the iteration budget (a = 51 → 207 → 233 at 5 → 50 → 200 iterations), directly falsifying the docstring's own guarantee. The L2 penalty now enters the GRADIENT too, making it a MAP estimate; verified budget-independent at a = 20.76.
  • And that diverged map was adopted. brier_cal <= brier_raw is computed in-sample on the very points the two-parameter map was fitted to, so it is nearly always true. Confidence collapsed to the step predicate competence < 0.5499 with a reported Brier of 0.0. A _MAX_SLOPE backstop now rejects it.
  • The slope floor was scale-blind and justified by a false claim. The comment said a flat map "would leave the gate inert"; measured, the below-threshold decision set is bit-identical before and after (412 vs 412), because Platt is strictly monotone for a > 0 and τ is refit on the same scale. Rejecting a = 0.296 threw away a real 0.069 Brier improvement and changed no decision. Only INVERSION (a <= 0) and DIVERGENCE (a > 50) are rejected now.
  • w_effort == 1.0 was silently dropped (the bound was exclusive while the grid reaches exactly 1.0), leaving the scorer on the previous fit's effort weight — evaluating a formula the fit never saw, under a Platt map fitted on different composites.
  • The map's intercept floored the composite. Applying Platt AFTER the outcome penalty made sigmoid(b) an absolute floor: with a fitted b = 0.27, even outcome_penalty = 1.0 bottomed out at 0.566, so below_threshold was unreachable for every possible input — while the comment directly above promised a REFUTED verdict "must pull the reading below threshold regardless". The penalty now applies after the map, on the probability scale, and reaches 0.
  • The stored composite column mixed scales (raw before a fit, mapped after, re-scaled at every refit), so the reliability table, ECE and reported Brier compared different populations — the same turn binned [0.2,0.3) pre-fit and [0.6,0.7) post-fit. ConfidenceReading now carries raw_pre_penalty_composite and both record sites persist that, giving the column one stable meaning. _best_threshold's degenerate fallbacks likewise returned raw-scale constants into a mapped caller; they now return the median of the supplied scores, which is scale-free.

None of these were ACTIVE in production — the map is currently rejected on live data, so they were latent — but they would have activated the moment the turn-effort feature earns its weight, which is exactly when nobody would have been watching. Tests: tests/test_calibration_review_fixes.py (19).

2026-07-27 (later 9) — graded outcome labels and sample provenance

The binary label — 0.0 if (exec failure | verifier REFUTED | budget exhausted) else 1.0 — had two defects. It was 96.1% one class, and it asked "did anything visibly break" rather than "was the answer good": a turn that hit one tool error, RECOVERED, and answered correctly scored 0.0, identical to a refuted answer. That is a mislabel, not a strict label.

Provenance first

Every sample now carries source — turn for the graded proxy, user_correction for ground truth. This landed BEFORE any new signal tier on purpose: without it, mixing tiers is irreversible, because you can never audit which tier is noisy nor drop one without discarding the whole corpus. Legacy rows default to turn, which is what they were.

§4EE (2026-09-02) — two ranks the mirror question found missing. human_feedback (the explicit thumb on this turn, via record_human_label) is now the TOP of the ladder — it was the only corpus label source with no calibration rank at all, so a 👎 corrected the learning corpus and left the fit believing the inline grade. shape_failure (via record_shape_failure, rank just above turn) re-labels a turn the SHAPE heuristics marked FAILED at _SHAPE_FAILURE_GRADE (0.68, the currency of one unverified execution failure): the sample is written before the corpus row exists, so without this tier a selector-thrash turn graded as the prior or, with an inline PASS, as 1.0 while the corpus said FAILED. The full order is turn < shape_failure < verifier_late < task_reopened < failure_report < bench_validator < user_correction < human_feedback, pinned as a chain in tests/test_4ee_label_pins.py.

§4BF 1c — bench population (origin, oracle re-label, equal-mass cap)

Samples additionally carry origin ("user" | "bench"; legacy rows default to user — sim was write-gated, so they were all real turns). Bench-bank solves are the carve-out in the simulation write-gate: they record their per-attempt turn sample with origin="bench", and the bank oracle's verdict then re-labels each attempt via record_bench_validator_verdict at the bench_validator source rank — mechanical ground truth, above verifier_late and below user_correction, same no-leakage re-label contract as every retro tier, joined only to origin="bench" turn rows (bench req_ids are bench--prefixed so a collision with a real join key is impossible by construction). PASS verdicts record immediately; FAIL verdicts are DEFERRED until dream's infra triage has ruled — a sandbox banner or a validator crashing in its own frame must never be written as a permanent ground-truth negative (R1 CRIT; the §4AO label-noise class at the strongest rank). The fit, stats(), the operator metrics (Brier/ECE/reliability) AND the learning-health label/feature gates blend populations through _apply_bench_mass_cap (dict twin apply_bench_mass_cap_rows): at most as many bench rows as real rows (newest first), zero when no real rows exist — bench may feed the starved negative class, it may never become the population the instrument describes (see core/admissibility). learning_health surfaces the mix as label_origins. The user-correction stash is user-origin-only and carries req_id/domain, so the human negative SUPERSEDES the proxy row instead of counter-weighting it.

Grading, with measured constants

grade_turn_outcome() maps a finished turn onto [0, 1]. The numbers are measured rather than chosen: across 302 verdict-bearing trajectories the agent passed 251, so an unverified-but-clean turn scores 0.83 — the observed P(good | checkable) — instead of asserting 1.0. Claiming certainty for a turn nothing checked is precisely the verification theatre this project keeps rediscovering. Verifier PASSED/FAILED remain the hard 1.0/0.0 anchors; execution failures subtract 0.15 each down to a 0.15 floor (0.0 is reserved for "checked and WRONG"); budget exhaustion scores 0.2, since the agent itself flags that reply PARTIAL.

One narrowing of the PASSED anchor (2026-08-04). A verifier passed no longer buys the 1.0 when the turn's SHAPE says the answer cannot be honest — every tool call failed and the reply never said so (outcome_heuristics.unacknowledged_total_failure, the same rule the trajectory corpus applies; kill switch GHOST_UNACKED_FAILURE_GATE=0). Live case req 03b96c28: three failed tools, a fabricated one-character answer, an escalation-overturned CONFIRMED. Grading that a perfect 1.0 teaches the confidence model that a confident answer over three broken tools is what success looks like. Such a turn falls through to the graded execution-failure path instead — the shape says "unverified and something broke", not "checked and wrong", so it is never a hard 0.0. An honest failure report keeps its 1.0.

Two supporting changes were required, and either one missing would have silently defeated the feature:

  • Binarisation removed from BOTH the write and read paths. 1.0 if outcome >= 0.5 else 0.0 would have crushed every graded label straight back to two values — re-creating the exact constant column the grading exists to remove.
  • Class-presence gates generalised to VARIANCE in fit() and _fit_platt. "Are both binary classes present?" is the wrong question once labels are continuous: a graded corpus can carry real signal with every sample above 0.5, and the old gate would have refused to fit it at all. For 0/1 labels the tests are identical (variance is zero exactly when one class is missing), so binary corpora behave as before.

Measured — and it contradicted the hypothesis

Replaying the real production mix (1028 turns, 726 of them unverified) through the real feature and the real fit:

LabelDistinct valuesVarianceBrier vs base rate
Binary20.09860.0666 vs 0.0986 — beats by 33%
Graded80.04460.0395 vs 0.0446 — beats by 11%

Grading gives a far richer target but a smaller edge over the baseline. The reason is that the binary label is partly CIRCULAR with the turn-effort feature: effort counts tool calls and repeats, tool errors drive both the effort signal and the binary label, so the model was partly predicting itself. Grading weakens that near-tautology, which lowers the apparent win — the 33% was flattering and 11% is the honest number. It shipped anyway, because a correct label with a smaller flattering metric is worth more than an incorrect one with a bigger one.

Standing caveat: the graded label is a PROXY for process health, not correctness. If the ground-truth tier (user corrections) ever stops flowing, the agent is calibrating purely against its own notion of a tidy turn — which is what it already over-indexes on. Provenance is what keeps that checkable.

2026-07-27 (later 10) — Tier 2 redesigned from evidence: failure reports

The plan was to loosen this classifier's phrase-plus-rephrase requirement to phrase-only. Measurement killed that design. Across 246 eligible triples in the stored session history the classifier fires on zero — while 20 of them (8.1%) unmistakably report that the delivered work is broken:

"game.js:45 Failed to load frame definitions: TypeError: …"
"Failed to load resource: the server responded with a status of 404"
"it still does the same. the game never starts"

There is no phrase to loosen. A pasted traceback contains no rebuttal and shares no tokens with "build me a game", so neither signal can fire. The classifier is not malfunctioning — it is structurally blind to how corrections actually arrive, which is roughly one turn in twelve of GROUND TRUTH.

The same measurement killed a second idea from that plan: "repeat request = implicit negative". Eleven near-identical re-asks exist and they are dominated by a daily-briefing habit ("hello ghost, what's new today?"). Labelling those negative would have fabricated failures.

classify_failure_report()

Single-signal by design — a pasted traceback is unambiguous in a way a bare "no" is not.

  • Diagnostic: tracebacks, exception classes, HTTP 4xx/5xx, "Failed to load", "is not a function", file.js:NN. Bare error/errors is deliberately excluded — it false-positives on "zero console errors".
  • Breakage, split by strength. STRONG ("doesn't work", "still does the same", "won't start") versus WEAK ("fix it/that/this"), which is genuinely ambiguous: a complaint in "doesn't work, please fix it", but forward-looking instruction in "perfect, fix it exactly like that next time".
  • Praise veto, scoped to WEAK evidence only. This scoping is load-bearing. A first version vetoed on any affirmation and silently ate "the minesweeper right click doesn't work though, but the rest looks good" — a real defect report with a polite softener. Mixed messages are the COMMON shape, and an over-aggressive guard that discards real signal is the same class of bug as a tolerant parser that inverts a verdict. A softener does not cancel a named breakage; a hard diagnostic outranks any amount of politeness.

On the real corpus: 20/246 detected, 0 false positives, 0 vetoes needed — the veto guards only hypotheticals, which is what a guard should do.

Wired calibration-only, on purpose

Unlike an explicit correction this does not mark the trajectory FAILED, because that feeds reflection → lessons → the playbook, where a false positive poisons retrieval (this module's own docstring warns of exactly that). A calibration sample is numeric, provenance-tagged and filterable back out; a bad lesson is not. Recorded at source="failure_report", grade 0.15 — a notch above an explicit correction's 0.0, since the human is reliable that something is broken and slightly less so that THIS turn broke it. The fingerprint stash is consumed, so a report and a correction on one turn cannot double-count.

Two bugs surfaced only in live testing, both invisible to 9584 green tests: the tier sat behind a trajectory-cache lookup that returned first (disabling it on exactly the long tool-heavy turns most likely to draw a complaint), and a stash gate written for binary labels (>= 1.0) stopped matching once the graded label scored clean turns at 0.83 — neither change wrong alone, only in composition.

2026-08-01 — Tier 3: retroactive negatives from reopened work

A task a turn closed DONE being later REOPENED is a delayed negative on that turn — the closing was premature. Both halves of the signal already existed (the reopen transition and the closing turn itself); what was missing was the JOIN. Three pieces close it:

  • Closing stamp. ProjectStore.update_task stamps the closing turn's request id (request_id_context) into a new tasks.closed_req_id column on the transition to DONE (idempotent migration; "SYSTEM" — boot reaper, maintenance — stays blank, and a re-asserted DONE never steals the original close). Calibration samples symmetrically gained a req_id field, populated by the Tier-1 end-of-turn record — that pair is the join key.
  • Reopen hook. The TASK-level DONE → open transition (regardless of project status — a task revived on a still-ACTIVE project is just as much a delayed negative as one that fires project_reopened) logs a task_reopened event and fires ProjectStore.on_task_reopened(project_id, task_id, from_status, closed_req_id) — same outside-the-lock, fully-guarded discipline as on_project_done; wired in main.py.
  • Retro writer. CalibrationTracker.record_task_reopened_negative(closed_req_id) finds the closing turn's source="turn" sample by req_id and re-records its own stored components — the feature side is byte-identical, only the label differs (the no-leakage rule) — at source="task_reopened", grade 0.15 (_TASK_REOPENED_GRADE, same strength as a failure report: attribution equally loose, a reopen can also mean scope growth). Idempotent per closing turn (a DONE→open→DONE→open cycle labels each distinct closing turn once), and skipped when the closing turn's own label was already negative — Tier 2's no-double-counting rule.

Measured supply is deliberately acknowledged as MARGINAL (~7 reopen events / 20 days at design time, §4E) — this tier exists because it costs one column and one hook, not because it moves the fit alone. The durable req_id join also removes Tier 3's dependence on the 32-entry in-memory fingerprint stash: a reopen can arrive days and several restarts after the close. Tests: tests/test_task_reopened_tier.py.
