core / objection.py — arithmetic before opinion

Resolves the judge's objections that are decidable by arithmetic or string search, so the expensive model is spent only on genuine ambiguity — and so proven-real catches can never be overturned away.

Why it exists

Four rounds of escalation policy (rebuttal burden, verdict-tier routing, truncation guard, and two calibrations) all failed the verifier's ship gate, because every one of them was arbitrating opinions: the cheap judge says the claim is wrong, the main model says it is fine, and any rule that trusts one of them loses whatever the other was right about. Measured, those arms traced a single false-alarm-versus-catch trade curve — 0.591, 0.717, ~0.73 balanced — and never crossed it.

The way out came from counting rather than designing. Collecting all 145 distinct false-alarm objections that the completed bench arms produced showed that 43% of them are not opinions at all:

Real objectionWhat settles it
The largest file size is 18,433 bytes, not exactly 18 KB.18433 ÷ 1024 = 18.0 — a unit conversion.
Stated as 396,000, but the evidence provides 396,960.0.24% apart, and the claim is written with fewer significant figures — a rounding.
Humidity around 28% is not in the evidence.Search the evidence: "28" is right there — the judge missed it.

These are precisely the systematic classes the small judge gets wrong, and that two GEPA prompt-optimization rounds failed to fix. They do not need a better model. They need float() and in.

The three proof rules

Each rule was earned by a measured failure, and each decides in only one direction unless it can prove the other.

RuleDismisses (false alarm)Upholds (proven real)

An absence proof is a proof against the session, not the turn (§4HZ, 2026-09-17). Request 30419cf0: the reply said "~149 highlighted points"; 149 was computed one request earlier (the agent's own execute output). This turn's digest was a vision caption and a browser result, so the cheap judge objected "invented number", the absence rule looked in the digest, found no 149, and UPHELD — no escalation spent — and the auto-repair stripped a true figure. resolve_issue/resolve_refute now take prior_evidence: the session's earlier tool outputs and replies (built by agent._prior_turn_evidence, newest first, 60k chars, this turn's outputs excluded; never shown to a judge). If any cited atom is present there under the same canon, the rule returns UNRESOLVED ("carried over, needs judgement") — never DISMISS: present-earlier is not present-now, so the strong judge decides. Both mechanical sites in the verifier (_guard_truncated_absence, _escalate_refute_impl) thread it; the code route passes none by design. Pins: tests/test_objection_prior_turn_evidence.py (the live objection, the blob builder, and an AST enumeration that every resolve_refute / claim-route verify_claim call carries the keyword).

Everything else returns UNRESOLVED, which means "carry on as before": whatever the module cannot prove is handled exactly as it was before it existed.

It does change verdicts — an earlier version of this page claimed it "can only remove work", which is false in both directions and is the whole risk surface. A DISMISS returns CONFIRMED without the main-model call the old path would have made, at a confidence floor of 0.7 (deliberate: a mechanical dismissal is proven, not a soft overturn, so the 0.6 laundering cap does not apply — but no legacy path produced a model-free CONFIRMED). An UPHOLD keeps the cheap judge's REFUTED and suppresses the escalation entirely. Both are the point; both are why every rule decides in one direction unless it can prove the other.

Three discriminators that only measurement could have found

  • Precision, not proximity. A plain 2% tolerance dismissed 26.7°C is not supported; evidence states 26.6°C — which is a fact swap. A genuine rounding loses significant figures, so the coarser value must be written with fewer of them; equal precision plus a small gap is a real difference, however small. Precision also picks which value is the rounded one — deriving that from magnitude recognised only roundings that round DOWN, so 27, not 26.6 and 3, not 2.9 were reported as contradictions and upheld.
  • Quantity, not identifier. The first version compared SN851X with SN850X (0.1% apart → "rounding") and 2025 with 2026. A number counts only when it stands alone as a token. Bare years are excluded lexically; dates, versions, ports and ids are excluded contextually — one such marker anywhere in an objection disables numeric adjudication for all of it, and the exclusion applies only inside the numeric rule. The standalone-token requirement also drops any number glued to its unit, so 18KB and 26.7C parse as no numbers at all: the rule's reach is narrower than the examples suggest.
  • The contrast frame is what makes a mismatch an assertion. Upholding whenever an objection merely names two differing numbers raised protection from 37 to 59 catches — but hardened false alarms from 2 to 7, because 34°C and humidity 28% contains two numbers and asserts nothing. That rule was deleted; the reasoning stays in the source as a warning. Deleting it was not sufficient — the contrast pattern matches a bare not, which every absence complaint contains, so 34°C and humidity 28% are not in the evidence was still adjudicated as a numeric contradiction and upheld, reviving the deleted rule's harm inside the protected no-call path. Absence complaints are now excluded from the numeric rule outright.

What it buys

Measured over every completed bench arm's refutes, the cost of being wrong is 2 hardened false alarms and 1 erased catch. The protection counts are deliberately not quoted: two mid-development figures survive in the record (37 upheld / 41 calls avoided, and 51 / 55), the ad-hoc script that produced them was not kept, and both predate the 2026-08-06 defect fixes above — the confirming re-bench re-derives them. In the shipped pipeline arm that becomes balanced 0.808 against the legacy pipeline's 0.797 — the first arm of five to clear the gate — with catches up (0.705 → 0.778), degraded-evidence false alarms down four-fold (0.242 → 0.061), overturn damage halved (59 → 31), 38 fewer main-model escalations and p50 latency down from 42.5 s to 26.9 s.

The gate is cleared by +0.011 on a tier with ±0.08 documented session noise, and the score decayed across the run (0.837 at 41% → 0.808 final). Read the pass as narrow and the profile as the real argument. GHOST_VERIFY_OBJECTION_CHECK=0 disables the module; the companion policies (GHOST_VERIFY_OVERTURN_QUOTE, GHOST_VERIFY_TIER_ROUTING) ship default-OFF, and v5's measured configuration is objection-check ON with the rebuttal burden OFF.

Two adversarial rounds, thirteen wrong verdicts, one shape

After the first bench pass, two independent adversarial reviews (2026-08-07) executed the module against realistic judge sentences and found 13 CRIT-grade wrong verdicts between them. Every fix is a regression test; the recurring shape is worth stating because it will recur: a mechanical rule earns its verdict only from what is WRITTEN, and every shortcut past the written text was a wrong verdict waiting.

  • Unit conversions need written units. A bare factor list dismissed "3 errors, not 21 errors" as a ×7 "conversion". The unit map now carries bytes, time, distance, mass, percent, speed, data-rate and frequency families — and "13 km/h vs 8 mph" (equal in reality) dismisses by actual conversion instead of convicting.
  • round() is not rounding. Banker's rounding over binary floats convicted "1,500 for 1,450" and "0.4 for 0.35" while dismissing "3 for 2.9". Half-step distance with graded error budgets replaced it; a round-shaped match beyond its budget is GRAY — suspicion, never proof, and one gray pair blocks the whole objection's dismissal exactly as a contradictory one does.
  • Convictions must be anchored asymmetrically. The claim-side figure must be claim-exclusive (a hallucinated "500" that appears in neither text — or in an attacker's page — convicts nothing); the evidence-side figure need only be present, because a real fact_swap usually quotes the evidence number before contradicting it.
  • Who omitted it decides where to look. "The reply omits the 28% that the evidence provides" was dismissed as "the judge missed it" because 28% was in the evidence — backwards: that is what makes the judge right. Claim-side omissions search the claim, and are never mechanically upheld.
  • Presence needs boundaries everywhere. Substring matching found "180" in "1800 rpm", "8 GB" in "18 GB" (through the digit-unit glue), and 256 inside "SHA-256" (through hyphen collapse). Every numeric-edged atom is boundary-matched; identifier glue is refused.
  • Flagged presentation is not leaked noise. Fenced diffs, inline code spans, a truncated opening fence, and the markdown horizontal rule are all how a claim should show these strings.

Uphold-only: the shipping configuration (2026-08-07)

The confirming re-bench put per-direction counters on the mechanical layer for the first time, and they split it cleanly: UPHOLD measured 40 protects / 2 damage; DISMISS measured 3 rescues / 9 damage — net negative. A 12-trial splice re-run (replay scorer, ~7 minutes, zero cheap-verdict drift) then showed dismiss-OFF strictly dominates: balanced 0.829 vs 0.819, five of the nine erased catches recovered by the escalation, and every rescue surviving anyway because the overturner independently rescues the same false alarms the dismissal did. The cost is ~12 extra escalation calls per 340 trials.

So the module ships uphold-only: GHOST_VERIFY_OBJECTION_DISMISS defaults OFF (=1 re-enables; the bench sweeps it). The asymmetry is principled, not incidental: an UPHOLD's failure mode is a hardened false alarm that the rebuttal machinery was already bad at fixing, while a DISMISS's failure mode is an erased catch with no recovery route — and the escalation already does the dismissal's job on genuine false alarms, just more expensively and more safely.

§4IP — the uphold branch convicted absences (2026-09-18)

Of the incumbent's eight clean refutes on the mined pool, five were mechanical upholds — the branch the header calls the module's whole risk surface. Rule 2 upheld any absence complaint whose cited atoms were all missing from the evidence: a derived date ("'Jul 30, 2026' is not explicitly stated" — today plus a week), a computed coordinate, a single status word ("'RECOVERED'"), a task name. Rule 1 upheld a numeric pair on claim-exclusivity alone: "ball x=365 vs plunger x=375" (two records), "18:38 vs 15:36:58Z" (a timezone). The same rule 2 was the module's fabrication catch — and, read closely, it was catching fabrications for the wrong reason: the judge rarely quotes the invented name ("The claim cites Dr. Elin Vasquez, but this name is not present" carried no citable atom), so the trial was convicted on whatever derived figure sat nearby.

Now an absence proves an invention in two shapes only: a name is absent, or the absence is total. A name is a cited atom that has the shape of a name and is one the binder lists for the claim (_name_shaped: after stripping an honorific or possessive, a run of two or more capitalised words with no sentence punctuation, no all-caps token, matching the binder's entity shape; _written_as_a_name: its entity_key is among the entities claim_binding.audit_entities finds in the claim — so a bold lead-in label (**Memory Usage**: 21 GB), a heading, a greeting or a sentence-initial dictionary word is not a name here because the binder does not list it there, and "All Tests Passed" quoted by the judge from "all tests passed" or a name the judge invented is in neither text). Its presence is the binder's test (_name_present: entity_key + _entity_supported, or the squashed spelling — "Dr. Elin Vasquez" is present in "Elin Vasquez led it" and "Chess Coach" in chess_coach). Total means _total_ungrounding: every evidence block a tool failure while the reply does not report one (the turn loop's own response_acknowledges_failure decides what "reports" means — "didn't work, so I couldn't", "crashed", "errored out"), or a reply of at least six Latin content words sharing not one word and not one figure with a digest that itself carries at least six Latin content words (a Greek source or a numbers-only command output shares no word with any English reply by construction). Unquoted names are cited atoms too (the binder's entity regex over the issue, a sentence-opener trimmed, the judge's framing words excluded, a glued closing quote stripped) and are placed before the atom cap. Any other absent figure, date or status is UNRESOLVED and escalates. The competing-figure rule of the first draft is gone: on the judged-fine corpus it fired on 27% of turns with an absent figure, so it was a lexical proxy for "same subject", not a proof.

A numeric pair convicts only when it can denote one quantity (_same_quantity_plausible: neither figure inside a clock or date token wherever it occurs; a figure that cannot be located is unproven; an evidence figure in a dense record needs the claim's sentence to align with it; and a counter-figure the claim itself writes, anywhere, is a second quantity of the reply — the binder's _claim_states rule: "15 tasks total (10 done, 5 pending)", "28°C now, 18°C tonight", a whole two-sentence reply quoted by a judge complaining about length; the projection shape "the evidence says 3 users, so we have 500" escalates to the judge instead of being convicted with no call). Claim-exclusivity — what makes a figure a fabrication — is the binder's agreement rule (_claim_figure_supported = claim_binding.quantities_agree on the quantity at the figure's position in the claim's sentence, within the same unit family): "0.04 seconds" is supported by elapsed = 0.041s, "about 212 KB" by 217,088 bytes, the low end of "between 21 and 25°C" by a forecast of 22°C, and none can be the convicting side; "60 users" is not supported by elapsed: 1 min. Machine noise demonstrably in the claim now decides before the numeric reading of the issue (a reply torn by merge markers was being upheld as "7 vs 1.5"). Measured by re-resolving every cheap REFUTED in the recorded bench runs: mined right upholds 15 → 28, wrong 5 → 0; seed 27 → 29, wrong 2 → 0; and over the 564 cheap refutes in the bench response cache, 95 upholds — 69 of them the bench's own injected names — and none of the fifteen weather-gloss / status-phrase / plan-sentence shapes the consumer review listed. The verdict sidecar now carries the first three issues, so the next review of this branch can replay live refutes instead of pooled ones.

Known limits

  • artifact_leak (0.5) and fact_swap (0.606) remain the soft columns: the machine-noise rule only fires when the judge's wording names the noise, so the rest still escalate.
  • Name shape is the binder's (_ENTITY_RE): particle runs, spaced initials and Greek/Cyrillic names are names since §4IP R7, and a judge's Latin spelling of a Greek name is matched to the reply's (translit_greek); single tokens ("Interpol"), acronym bodies and names with an apostrophe or hyphen-initial ("O'Brien") are not — an invented one escalates to the judge rather than being convicted without a call. A name the request or the active project's title carries is provenance, and a name inside a stated next step is not a fact. Space-grouped thousands ("396 960") are two figures to this tier as they are to the binder. A relative-time figure ("2 hours ago" vs "3 hours ago") is masked as a date on both sides. All of these are the conservative direction.
  • Subjective gloss, semantic drift and domain judgement are deliberately not mechanised — they go to the strong model unburdened, which is where it measurably excels.
  • The module reads the packed digest the verifier received, so a fact the packer cut is invisible to the absence rule; above the severity floor the rule returns UNRESOLVED itself. (The separate truncation guard runs earlier, before the escalation, and only when every issue is absence-shaped — it is not a fallback this rule hands off to.)
  • It runs first among the escalation policies, but only on the claim path: verify_code_output injects its own re-adjudication, and the check is skipped whenever that is set. It also sits behind GHOST_VERIFY_ESCALATE_REFUTE and the cheap-route check, so GHOST_VERIFY_OBJECTION_CHECK is not its only off switch.
  • The packer's truncation marker is not evidence. It carries digits — a random 8-hex nonce and the two byte counts (400 of 5400) — and the absence rule was searching it, so a cited number could be "found" inside the packer's own bookkeeping and a proven catch dismissed. The byte counts made that deterministic for any objection citing them; the nonce added a ~3%-per-process-start random component that surfaced as a flaky unrelated test. Markers are now stripped before the search.
