core / agent_qwen.py — REMOVED

Deleted 2026-07-27. This page is kept only so existing links don't 404.

What was here

A GhostQwenAgent(ReActChat) subclass that ran the conversation through qwen-agent's own ReAct loop instead of the agent's turn loop, with tools supplied by tools/qwen_bridge.py.

Why it was removed

The pair was unreachable dead code: nothing in the repository ever constructed GhostQwenAgent — no import, no instantiation, in src/, scripts/, bin/ or interface/. The live agent runs core/agent.py, which talks to llama-server over the OpenAI-compatible API and never touched this path.

Keeping it was not free. It carried two latent defects that a future user of the variant would have hit immediately — _run_coro_blocking ran each coroutine on a fresh event loop while blocking the caller's loop in join() (freezing the whole agent, and raising cross-loop errors for any loop-bound client), and the system-injected kwargs were not excluded from the model-param pass-through, so a hallucinated sandbox_dir crashed the call with a duplicate-keyword TypeError. It also pulled the heavy qwen-agent dependency tree into every install. Deleting the variant closed all of it at once; qwen-agent was dropped from requirements.txt in the same change.

What replaced it

Nothing — the functionality was never in use. Note that the main agent's handling of Qwen-dialect <tool_call> tags is unrelated to this module and is still very much live: see the syntax healer in core / agent (tests/test_agent_tool_calling_logic.py::test_agent_qwen_syntax_healer).
