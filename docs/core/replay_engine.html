core / replay_engine.py — turning one episode into many graded labels

Takes a recorded turn, changes exactly one thing, re-executes it forward, and grades the result against an executable check. The output is a decision-level credit — "did that lesson matter?" — which live traffic cannot produce at any volume.

The rule the whole phase rests on

Always re-execute forward from the fork. Never splice a changed decision into a recorded suffix. Between 61% and 94% of post-fork actions get rewritten once a decision changes, so a spliced evaluation scores a world that never happens. Every perturbation here is "change one thing at step k, then let the agent run to the end on its own".

The last filter is no_filesystem_checkable_deliverable, and it is not a tightening for its own sake. An episode whose tools only read — list_files, introspect, recall — leaves nothing for a synthesised check to inspect, so its legs can only ever fail. Measured: the rule rejects 6 episodes an earlier census had “successfully measured”, and all six had scored exactly p = 0.00. Those zeros were structural, and counting them made the corpus look more deterministic than it is. The rule discards no signal; it removes rows that were inflating the count.

That is the honest ceiling, and it is an order of magnitude below what the plan's throughput target assumed. At three specs a night a batch produces at most three credit rows, so “≥30 verdicts/night” is ten times out of reach; draining the backlog is roughly 100 nights at one batch, or 17 days at the six batches a day the four-hour cooldown allows. The multiplier is perturbations per episode, not episodes.

Why the network filter is not (only) about safety

A replay of an episode that searched the web is not reproducible: the search returns different results than it did on the day, so the control and perturbed legs both diverge for reasons that have nothing to do with the perturbation, and the paired consistency rule abstains. Non-reproducible episodes produce verdicts about noise. This is a reproducibility filter that happens to also be a safety one.

The allow-list is not the complement of the deny-list

REPLAYABLE_TOOLS and isolation.REPLAY_FORBIDDEN_TOOLS are different lists doing different jobs — containment versus reproducibility — and they differ on exactly the tools that are safe to run but do not return the same thing twice. Crucially, the replay list is an allow-list: an acquired skill is registered at runtime under a name this module has never seen and runs arbitrary code, so a deny-list could not name it. Guard the thing, not a proxy.

Perturbations, applied to the data

KindThe questionPremise it needs

tool_ablatedid that capability matter?the tool was dispatchable

lesson_inject and tool_ablate are implemented but never mined: build_specs emits only the other three. Nothing in a recording says which lesson the episode should have had, or which tool it could not have done without, and guessing would put an ungrounded generator inside a measurement whose whole value is that it is execution-grounded. tool_ablate exists because the seeded-truth gate needs a perturbation whose effect is known in advance — it is a spike-in control, not a sample of the workload.

A spec whose premise is false produces a verdict about nothing, and a corpus of those is how a label source becomes a noise source. So a withhold is only generated for a lesson the episode genuinely hydrated, and a step-deny only where a recorded call actually failed — on a clean episode there is no step-deny spec, which is correct rather than a gap.

The lesson perturbations are applied to the STORE, not to the retrieval code path. Filtering a rendered lesson string, or intercepting one of the two retrieval surfaces, would be a lexical proxy for "this lesson was not available" and would miss whichever surface the interception did not cover. A fork-local playbook that simply does not contain the lesson is the property, and every ranking, dedup and quarantine rule downstream keeps working unchanged.

Two deviations from the plan, both deliberate

  • tool_swap became step_deny. Nothing in a recording says what the alternative call should be, so something would have to invent one — and an invented alternative puts an ungrounded generator inside a measurement whose entire value is that it is execution-grounded. Denying the recorded call asks the same counterfactual with nothing invented.
  • The executor is built on the isolation substrate, not on synthetic_self_play. That method is around 3,200 lines specialised for a different job, and every perturbation would have to be threaded through it as a new branch. The substrate is the part worth reusing, and it is separately tested. Self-play is not touched.
  • The transferability gate is not reused. _is_transferable_challenge asks "can this be re-posed as write a solution.py over the fixture in your working directory" — it exists for the mined-challenge harness, which rewrites the task. A replay re-runs the recorded turn. The safety half is reused, because that one is about what the tools do, which is identical in both.

The validator, and its two-sided self-test

Bench episodes carry executable validators already. A real episode needs one synthesised, and a synthesised check that cannot fail is not a check. Three gates:

  1. Static screen. No subprocess, no os.system, no network, no deletion, no eval, parses, under 6 KB. A check that shells out is not a check — it is a second agent with no supervision. (The first version named subprocess and not os.system: half a class, which reads as a closed door and is not one.)
  2. The negative control. Run the validator against an empty fork with no agent run at all, and require it to fail. This is the half the agreement test cannot do: import sys; sys.exit(0) passes the static screen and then agrees with the recording on every passed episode with probability 1.0 — the majority of the real ones — and would report no_effect for every perturbation of that episode forever. Agreement is exactly what a constant validator gives you.
  3. The agreement test. Run the unperturbed control leg and require the validator to reproduce the episode's recorded outcome. Disagreement means either the world drifted or the validator is wrong, and both mean "not replayable" — never "assume the validator".

LLM-judged validators are not admitted at all; abstain beats opine.

The paired verdict

Every spec runs n control legs and n perturbed legs, and the rule is keep-first / abstain-on-tie, applied strictly:

SituationVerdict
any leg produced no verdict (timeout, infra fault, inconclusive validator)abstain — a missing leg is not a null result
legs within an arm disagreedabstain — that is the stochasticity the pairs exist to detect
the arms agreeno_effect
the arms differ consistentlymattered_pos / mattered_neg

Two failure modes are specifically not charged to the agent: the [SANDBOX INFRA ERROR] banner (docker.execute never raises — it returns that string, and self-play already paid for reading it as a genuine failure), and validator exit 2, which is the validator's own "I cannot check this from the filesystem".

The control arm runs first. If it is already ungradable there is nothing to compare against, and running the perturbed arm anyway would spend the night's budget producing abstains.

The rule has a noise floor, and it is on every row

Unanimity across n legs makes a stochastic flip rarer; it does not make it distinguishable. For a genuinely null perturbation on a task with per-run pass probability p, the rule mislabels noise as an effect at 2·pn·qn / (pn+qn)² of the cases it decides:

At n = 2 the pre-registered specificity bar of 0.90 is unreachable unless the replayed tasks are near-deterministic (p ≥ 0.815), so the default is three legs an arm. That still does not make the floor vanish, and until the A/A census below nothing measured p — so every credit row carries the observed pass_rate and the noise_floor it implies. The census has since measured it, and the corpus turns out to be near-deterministic almost everywhere, which is why the observed floor is small: it is a property of the episodes, not a guarantee about the rule. A consumer reading a mattered_* without them is reading a number whose error bar it does not know, and credit_stats counts those separately rather than folding them into the same total.

The sign of a mattered_pos depends on the kind

“Control passed, perturbed failed” means the perturbed thing helped when the perturbation REMOVED it (lesson_withhold, step_deny, verify_toggle, tool_ablate) and that it hurt when the perturbation ADDED it (lesson_inject). Every row carries the normalised sign, because a consumer summing mattered_pos across kinds without it is adding opposite facts. A kind that nobody classifies falls through to the additive branch and reports the exact opposite of the truth, so the suite fails on any kind that is in neither set rather than waiting for the ledger to show it.

An unapplied perturbation is not a null result

The single most load-bearing field on a leg is applied. Every way a perturbation can silently fail — a withheld lesson that is no longer in the store (88.5% of real withhold targets have been pruned since their recording), a step-deny whose tool the free-running replay never calls, a wrapper destroyed by a dispatch-miss rebuild — produces a perturbed arm byte-identical to the control arm, and therefore a confident no_effect about a counterfactual that never happened. Each of those is now detected and abstains.

The fork the legs run in is part of the measurement

run_spec defaults source_workspace to USE_LIVE_WORKSPACE, so every leg starts from a copy of the live sandbox — the replayed agent has the inputs the original had. The A/A census that measures the rule's noise floor hardcoded an empty fork, and the difference is not cosmetic: probed on one episode, 3 top-level entries against 16. A floor measured in a world the rule never runs in is a number about the wrong regime. The regime is now a flag, it defaults to the engine's, and it is written on every run — a rows file that does not say which world it ran in cannot be compared with one that ran in the other.

The trace must name paths the fork has, not the ones the recording had

isolated_replay_context nulls current_project_id on purpose, so a replayed agent writes at the fork root. The trace fed to the validator synthesiser still carried the recorded locations, so the model wrote checks against projects/<id>/…. In the seeded regime that is worse than a broken check: the fork contains the copied-in original under that exact path, so such a validator passes for free on every leg without the agent doing anything, while still failing the empty-fork negative control — presenting as a perfect reproduction. Four forms leaked before the sweep came back clean: the plain prefix, the tool result channel (SUCCESS: Wrote 5202 chars to 'projects/<id>/x.py'), the mount point with the cd hop, and an absolute host path. content was spared at first because it is the file's text, and that was the last leak — a script the agent wrote held the literal path = "projects/<id>/model.py". One rule for every value now: an exemption becomes the next bypass.

The floor on the corpus is not the floor the engine meets

The census admits an episode when its validator discriminates; the engine admits one only when the control arm also reproduces the recording. Those are different bars, and the gap is most of the corpus — an episode that never reproduces contributes a guaranteed zero false-mattered and is one the engine refuses to run. Reported side by side: the corpus-wide rate, and an engine_admissible stratum weighted by p_admit = p̂n (or q̂n when the episode was recorded failed — agreement means matches the recording, not passes). The weighted number is the rate a consumer of the credit ledger actually meets.

Why episodes fail to reproduce was measured rather than assumed, and it is not the paths and not the seeding: one episode's synthesised check hardcodes the original environment's entry count, which no fork can match; another asks for a multi-step experiment the replay's single constrained turn — no network, verifier ablated, force_final_response — does not finish. Replay is a harder setting than the original turn, and that is a fact about the corpus the engine will run on.

The floor, measured

The A/A census ran the whole corpus in 7.0 hours: 128 episodes seen, 57 measured, six identical control legs each, every 3+3 split put through the engine's own decide_verdict. Every arm is the same condition, so every mattered_* it produces is a false positive by construction.

That is what licenses opening dream_credit conditionally on a row's own noise_floor instead of on a blanket pass — it does not license arming the engine, which still needs the sensitivity gate.

⚠ The entire measured signal is one episode. With six legs a false mattered is possible only at exactly 3-of-6, and exactly one episode landed there ([T,F,T,F,T,F], p̂ = 0.50). The theory behaves exactly as written, and the point estimate rests on a single stochastic episode — which is why the interval is as wide as the estimate. The corpus is overwhelmingly deterministic: 42 always-pass, 13 never-pass, 2 stochastic. Quoting 0.0011 without that sentence is quoting a number whose error bar the reader does not know.

A leg's budget is for many turns, so no one command may spend it

The per-command clamp used to hand a single sandbox command everything left of the leg. A replayed episode ran python3 -m http.server 8080 — a foreground server that never returns — and was handed timeout -k 5s 569s out of a 600 s leg. The leg died ungradable and took the episode with it, and raising the leg cap had raised what one command could waste from 209 s to 569 s.

The execute tool's own guard does not catch this, and should not: _SERVERISH_RE matches http.server, but blocking additionally requires the command to detach (… & / setsid), and the block message says so — "foreground and short-lived commands are unaffected". That is correct for a live turn, where a blocking server is the operator's problem. In a replay leg nobody is watching, so the bound has to come from the budget:

REPLAY_MAX_CMD_S = 120.0

def _cmd_budget(leg_budget, elapsed):
    remaining = leg_budget - elapsed - 30
    return int(max(30.0, min(REPLAY_MAX_CMD_S, remaining)))

Two bounds and the tighter one wins: what is left of the leg (a command outliving its leg blocks an executor thread the leg's cancellation cannot reach) and an absolute cap. 120 s is measured rather than chosen — legs run a p50 of 26 s and a p90 of 127 s for all their commands and LLM turns together — so it is generous for a compile or a test run while leaving a timed-out command most of the leg to recover in, which is what the original turn had. The identity the fix rests on is pinned (REPLAY_MAX_CMD_S * 2 <= DEFAULT_LEG_TIMEOUT_S): a cap that grows past a leg budget stops bounding anything and the defect returns silently.

Raising the leg timeout is not the fix. Re-measuring the eight episodes lost to ungradable_leg at 600 s split them cleanly: some were bounded-but-slow and came back gradable (one at p̂ = 0.17, a genuinely useful stochastic episode), the http.server one stayed ungradable as predicted, and several returned gradable but p̂ = 0.00 — dead weight the engine abstains on forever. Gradable is not usable.

What the census costs, and the two things that made it cost more

Measured on the live corpus, seeded forks, 220 legs: median 26 s, p90 127 s, and only 1.8% at the 240 s cap. Tightening that cap is tempting and wrong — it would reclaim 16 minutes while converting the 10% of legs that finish between 120 s and 240 s into skips. Seeding is the real multiplier: the same legs run 2.3× slower against a copied sandbox (median 53.4 s) than against an empty one (23.6 s). That is the price of measuring the regime that ships, and it is worth paying.

Two defects showed up only once it ran for real, and both were about cost and control rather than correctness:

  • Legs that could not change the answer kept running. An A/A episode needs every leg graded — one ungradable leg skips it whatever the rest do — so the five legs after the first ungradable one are provably wasted. One episode spent 1,052 s reaching a verdict its first leg had already settled: 81% of that run's entire cost, for a row the census then excludes. The abort keys on passed is None and not on not passed — a leg that ran and failed is a measurement, and most of this corpus is p = 0.00, so aborting on it would compute a pass rate from one leg instead of six.
  • The run could not be stopped. kill -INT was a no-op: a shell starting a background job sets SIGINT to SIG_IGN in the child, and CPython preserves an inherited SIG_IGN rather than installing its default handler. The signal arrived, nothing happened, and the census walked on to the next episode — writing no completion footer, which is precisely the case the footer exists for. SIGTERM has no default handler at all and loses it the same way. Both are installed explicitly now, and the footer records how the run ended so it can never claim a completion that did not happen.

Where it runs, and what it costs

Biological phase 3c, deep idle (>60 min), 4-hour cooldown, behind a §4U preflight that refuses on a memory-starved box — a batch spawns a container per leg, and this box runs llama-server at about 22.6 GB wired. It does not reset the idle clock, for the reason bench does not: resetting it closes the deep-idle window and starves self-play for an hour.

Kill switches: GHOST_DREAM_REPLAY (default off — the whole engine is inert until an operator turns it on) and --no-self-play, which suppresses it because an ablation arm that ablates "self-play" must ablate everything riding the same clock or it measures something other than its name.

What it can reach, and what it cannot

network="none" covers the container. It does not cover the agent's own process, and the first version of the deny list claimed to be a superset of self-play's while omitting web_search and deep_research — the two tools self-play has denied since the beginning, for exactly this reason. A replayed episode whose local routes are all denied will reach for a search. The list now covers every host-process egress tool, and self-play's own list was extracted from an inline literal into a constant so the superset claim is testable rather than merely asserted.

What a leg is left holding: file_system, execute, workspace, recall, introspect, scratchpad, report_pdf and a few read-only surfaces — all fork-scoped or inert.

The other escape was subtler. Swapping in a perturbed lesson store handed the isolate a plain SkillMemory, which has no is_read_only attribute — and that single attribute is how the entire repo derives "this turn is not real traffic". Two gates are not backstopped by a nulled handle: the metacog competence write (the per-domain prior the confidence composite reads on real turns) and the foresight predict hook (the live world-model index and its ledger). Lesson perturbations are 43% of all specs, so the majority of every night's legs were writing production learning corpora. The perturbed store carries the marker now, and every kind is pinned against turn_origin.

The gate: seeded truth before any consumer

The engine's output will be read as labels, and this project's two worst label failures were both plausible mechanisms with no sensitivity number attached. scripts/dream_replay_validate.py is that number, built from challenges that carry their own executable ground truth (a setup_script that builds the fixture, a validation_script that runs the artefact) and a recorded stable-pass verdict, i.e. known solvable.

  • The positive ablates file_system and execute for the whole perturbed leg. Every qualifying challenge asks for a solution.py that its validator then runs, so with both tools gone there is no path to that file and the perturbed leg must fail — whatever the model tries. Effect size 1.0, by construction.
  • The null ablates recall and list_lessons, which such a task never touches, through the identical code path — so a specificity number describes the same machinery the sensitivity number came from.
  • Stability re-runs the null spec and counts a flip only where both runs decided.

⚠ What this replaced. The first seeded positive wrapped a validator so its exit code flipped. That is applied downstream of the agent run, so the two arms differed no matter what the perturbation did: the instrument measured the validator-execution path and could not distinguish a working engine from one whose perturbations were all inoperative — which is precisely the defect class three review rounds then found. It was also sign-confounded, scoring a working engine as a miss and a crashing validator as a hit.

Three honesty rules the gate holds itself to, each of which it once broke:

  • The seed's truth is conditional. “If the task was solved, the ablation must break it.” A control arm that ran cleanly and failed is gradable, so the engine correctly reports no_effect — and scoring that as a sensitivity miss charges an engine with the agent's task-failure rate. The control condition is checked before the verdict is read, and the four abstain reasons (control errored / control failed / control split / perturbation did not apply) are counted separately, because they look identical in a ratio and mean opposite things.
  • A bar needs power and a representative sample. 20 decided cases per arm is an absolute floor; an engine that abstains on 90% of seeded positives and is right about the rest clears it with a sensitivity of 1.00. The decided cases are exactly the tasks the agent could solve, so a yield below 50% reports UNREPRESENTATIVE, never PASS. Every ratio is printed with its exact (Clopper–Pearson) interval, and the verdict rule stays the pre-registered point estimate.
  • A partial run cannot certify anything. A run that stood down on the mid-run preflight, hit its wall-clock deadline, or lost a case to an exception reports INCOMPLETE, whatever its partial numbers say. An intermediate version argued that a wall-clock truncation still left a uniform random subsample — the corpus is shuffled, and whole unstarted cases are what a deadline drops. That is wrong, and it is worth writing down why: a uniform random order does not give a uniform random retained set when the stopping rule is duration-dependent. The retained set is the maximal prefix that fits, so a case's chance of completing falls with its duration — and duration is outcome-correlated, because a case the agent flounders on burns n_pairs × leg_timeout per arm. Hard cases are dropped, and hard is exactly “the control arm fails or abstains”.
  • A recovered run says so. Rows stream to disk as each case completes, bracketed by a run header and a completion footer; --rescore rebuilds the scoreboard from them and refuses to certify a file that carries no footer, because a file without one belongs to a run that did not finish. It scores the LAST run's rows only — the scratch path is fixed and the writer appends, so two runs' rows share a file.

Status: the instrument works — seeded pairs come back mattered_pos / no_effect as constructed — and refuses to call the result a result until it is powered. Until it returns PASS, dream_credit stays closed.

Admissibility: two rows, not one

dream_replay reads the corpus and admits bench episodes as a feature — they carry executable validators already, which makes them the cheapest source of seeded ground truth. dream_credit is anything that later reads a replay verdict and acts on it, and it is real_only until the seeded-truth bar is cleared. One row could not express "may read the corpus, may not yet believe the output", and a single permissive row is how an unvalidated label source opens.
