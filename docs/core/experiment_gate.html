core / experiment_gate.py

§4ST (2026-11-02): a task that writes up a model run may close DONE only when a probe_model transcript kept for the project backs it. The gate is judged on the bytes that ran, not on the task's words.

Why it exists

In request b45ec99f (2026-11-01), three "Run Experiment … probe_model runs …" tasks were built by the coding executor. It wrote the transcripts and the scores itself, and all three closed DONE. The §4QA hold that should have stopped them is decided on words (does the goal or the task name a model?). Three review rounds of §4SS showed those words flip-flop: one version held ordinary work, the next missed real experiments.

probe_model keeps a byte copy of every transcript it saves outside the sandbox (core.probe_transcripts). Nothing else can make one: not the coding executor, and not a file write. So "did a model really answer?" has a mechanical answer.

When a close is checked

unrun_experiment_check(store, project_id, description, files=(), result_text="") returns (problem, claimed_files). It applies when either:

  • the words say so: project_advancer.is_model_experiment (the §4QA/§4SS detector) is true for the task; or
  • the output looks like model output: a prose file the close delivers (.md .txt .rst .html .htm .tex) has a Model response/answer/output: label, or has a heading naming transcripts (## Transcripts) or a Transcript: label and names a model or probe_model. The fake b45ec99f files had all of these. Review r1 found that without the model condition, meeting, interview, podcast and court transcripts counted. Without the prose-only rule, a .py comment (# load the transcripts), a typed field or a YAML key counted, and the build's source was quarantined. The bare word probe_model is not a shape, because a protocol that only plans the runs names it too. This half catches a task the detector misses, such as "repeat the ladder on the worker node; scoring via results/analyze.py", once it writes transcripts.

The files read are only the close's outputs:

  • the files passed in (deliverables, the build's files, the research brief);
  • the file the description declares (→ results/x.md);
  • project files the close's result names.

Files the description names are not read. They are usually inputs: in the replay, "Compile the PDF from research/protocol.md" was refused because the protocol it reads has a worked "Model output:" example. For citations, text files (.md .txt .rst .csv .tsv .json .html .htm .tex .yaml .yml) are read, at most 512 KB each and 24 files. A path never leaves the workspace: a link inside it is read like the file it points to, and a link leading out is not read. simulated/ is never searched.

What backs a close

A checked close stands when any of these holds (probe_transcripts.recorded and cites):

  • a delivered file is a kept transcript (probe_model(save_to=…)), byte for byte. A fake written over a kept transcript's path does not count (r1);
  • the result text or a delivered file cites a kept transcript, by its saved path or file name;
  • one hop: a project file the deliverable or the result names cites one (an analysis citing results/exp1.md, which cites the run transcript).

Known limit: citing a different real run of the same project passes. The gate proves that a model ran in this project, not that this write-up came from that run. Closing this gap would mean judging which run a write-up "belongs to", which is a judgment on words.

Otherwise the problem text says why it was checked, how many transcripts are kept, and what to do: run the prompts with probe_model(save_to="results/<new>.md"), write the results from that transcript, and name its path. If the check itself fails, the gate returns no problem, logs a WARNING (production drops debug lines), and the other close gates still apply.

Where it runs

  • Owner's task_update status=done (tools.projects): not on a re-close of a task already DONE. The stored description is judged, and a rewrite's declared file is read too. A refused task is listed in refused with gate model_run (before §4SU Phase 4: unrun_experiments), and the call is REJECTED when nothing else was updated. A false trigger (a protocol that only describes transcripts, a survey of published chatbot studies) can pass override={"model_run": "<why>"} (the old not_model_data keyword is still accepted, no longer in the schema) of at least 12 characters (MIN_WAIVER_CHARS), in a call that closes one task (task_id). In a bulk close the waiver applies to no task (r1: one sentence waived three fabricated runs). The reason is appended to the task's result as [not model data: …]. Only if the task really reaches DONE does the payload list it in experiment_gate_waived and the work log record "experiment gate waived". A waived close that a later gate refuses or demotes records no waiver.
  • Advancer build (_experiment_gate_build, run in a worker thread just before _finalize_coding): a build cannot run a model. The build is failed with the problem as its reason, its transcript-claiming files are quarantined and dropped from its file list, and the log shows a Model Run Gate warning.
  • Advancer research / self-analysis close (worker thread): the brief and the result are checked the same way. Owner-run, the task goes FAILED with the reason. Unattended, it is held NEEDS_USER ("not closed unattended"). Nothing is moved on this path (r1: a moved brief left the declared file missing, so no later close could pass, not even a waiver).

A declared kind replaces the words (§4SU Phase 2, 2026-11-02)

unrun_experiment_problem(..., kind=): a task declared model_run is an experiment whatever its words ("it is declared a model_run task"); any other kind, or none, is judged by its words as before (review r1: a kind that switched the words off let a retype skip this gate), and a file it delivers that reads like model output is still refused (the shape check). See core.task_kind.

Quarantine

quarantine(store, project_id, rels) moves each file to simulated/<rel>, with a .N suffix on the file name (never on a folder) if that path is taken, so no later task reads a written-up run as data. Nothing is deleted (the §4QA-c precedent). Only files the close itself delivered and that claim to hold transcripts move (a transcript heading or Transcript: label). A file the result only names, or the description only declares, is judged but never moved (r1: the owner's input file named in a result went to simulated/). A protocol whose one worked example is labelled "Model output:" is refused at close, but it stays where later tasks read it. A quarantine never follows a link, never leaves the workspace, and never moves a file already under simulated/.

Tests

tests/test_4st_experiment_gate.py covers the trigger, backing, waiver, build, research and quarantine paths, including the b45ec99f shapes. Battery: scripts/mutate_4st.py (coverage-parallel, with no-op and known-bad controls).
