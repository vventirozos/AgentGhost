core / request_scope.py — the request's project and conversation

§4SX B0 (2026-11-04). The project and conversation a request works in are a value carried in a ContextVar, not shared state on the agent's context. The model of conversation focus is described in projects → conversation focus.

What is in it

  • RequestScope(conversation_key, project_id, origin, persist, context). It is mutable on purpose. A switch that runs in a child or gathered task must change the request's project, and a child task's ContextVar.set would not reach its parent.
  • install(scope) / reset(token) / current_scope(context=None). With context, a scope is returned only when it was built for that very object.
  • conversation_key_for_session(session_id) returns session:<id>, keeps a Slack slack:<…> id as-is, and returns "" when there is none.
  • Origins: owner, member, replay, probe, unattended, leaf.

How it is used

  • GhostContext.current_project_id and conversation_key are properties. Inside a request they read and write that context's scope. Outside one (idle loops, startup), or for a context the scope was not built for, they are the object's own value. copy.copy(context) keeps the values in force at copy time as the copy's own.
  • GhostAgent._build_request_scope builds the scope at handle_chat start, right after the origin contextvar. A passed scope (a leaf's) wins. Otherwise it picks, in order: member; replay (probe-fr-/probe-rt-); probe; unattended (sched-/sub-/job-, or any population other than user); owner. Only the owner with a session id gets persist=True. Without a session id, the key is the first-message hash, which still pairs previews and late corrections.
  • tools.projects.begin_request_focus runs inside the turn lock. A persisting scope reads its conversation's focus row, and the shared scratchpad follows the request's project.
  • tools.projects._set_current writes the row (switch/create/resume) or clears it (exit), and only for a persisting scope.
  • The streamed drain runs after handle_chat's finally. It captures the scope and re-installs it, like the other request contextvars.
