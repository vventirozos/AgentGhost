core / project_research.py

Auto-research for long-term projects (any domain, not just code): search → summarise → persist a Markdown brief in the project workspace → index it → surface it in the briefing.

Why

Projects are multi-session efforts of any kind. While working one — on demand or during background auto-advance — the agent should be able to research relevant topics, keep the findings (not just raw search dumps), and stay aware of what it has already looked into. This module turns a web search into a durable, summarised brief inside the project's own workspace_dir, and records it so every later turn sees it.

Entry points

FunctionEffect
async research_topic(context, project_id, topic, *, tool_runner=None, llm_summarizer=None, queries=None, task_id=None)Research ONE topic: run web search(es), summarise, persist the brief. Falls back to the tool registry for search and to context.llm_client for summarisation; with neither it still writes a (sourceless) brief so the topic is recorded.
async research_project(context, project_id, *, topics=None, max_topics=5, ...)Research several topics. When topics is empty, auto-derives them via propose_topics.
async propose_topics(context, project_id, n=5, ...)LLM-derive up to n distinct topics from the project goal + open tasks. Fallback when no LLM: the open task descriptions, then the goal.
async persist_research_from_output(context, project_id, topic, search_output, *, task_id=None)Turn a search output already in hand into a brief — used by the autoadvancer so it doesn't search twice.
get_research_index(store, project_id) -> list[dict]The project's research index (read by the briefing).

What a run produces

  • A Markdown brief at <workspace>/research/<slug>.md — title, ## Summary + ## Key findings (LLM-written, or a heuristic title list when no LLM), a ## Sources section parsed from the search tool's [Source: url] markers, and a timestamp. The slug is alphanumerics + dashes only, so a topic can never escape the research dir.
  • A research index entry in project metadata (metadata.research_index): {topic, slug, path, ts, summary_preview, sources_count}, replace-by-slug (re-researching refreshes rather than duplicates), capped at 50 entries.
  • A research/INDEX.md human-readable mirror of the index.
  • A file artifact (when tied to a task) + a research_added event on the project log.

Triggers

  • On demand — manage_projects action=research (a single topic, or omit it to auto-derive several from the goal) and action=research_list.
  • Automatic during auto-advance — a research-classified task in advance_once that ran a real web_search and got usable output calls persist_research_from_output on that output (no second search), so background ticks leave durable findings, not just a transient tool_call artifact. The synthesised summary becomes the task's result_summary; the brief path is added to the autoadvance_step event and the result summary.

Awareness

build_project_briefing reads the metadata index (no file I/O) and appends a RESEARCH NOTES section listing recent topics → file paths with a one-line preview, so the agent sees what it has already researched on every turn it works the project — and is told to read a brief with file_system before re-researching it. The manage_projects create/switch/resume briefing dict carries a compact research list too.

Directly-written briefs get indexed too (2026-06-22)

The agent frequently saves a research brief with a bare file_system write (during a "Research" task) instead of action=research — and those direct writes never reached metadata.research_index, so the briefing didn't surface them and the agent never re-read its own research (observed live: PetAI/research/transformer-from-scratch.md written once, then ignored while the model rebuilt everything from parametric memory). reconcile_research_dir(store, project_id) walks the project workspace for **/research/*.md briefs anywhere (the agent may nest them under a self-named subdir, not just <workspace>/research/), and indexes any not already present — keyed by path so a brief the research tool already indexed isn't duplicated; the topic is taken from the brief's first Markdown heading. It runs after every manage_projects task_update (closing a task is a natural "I produced something" checkpoint), so the next turn's briefing advertises the brief. Entries carry origin: "direct_write". Covered by tests/test_research_reuse.py.

Research reaches the build (2026-06-22)

Awareness alone wasn't enough — the coding executor never saw the research at all: _gather_project_files skipped the whole research/ tree, so build tasks rebuilt without the design decisions the agent had researched. Now project_advancer._gather_research_briefs reads the briefs (head excerpts, bounded) and passes them to build_coding_task as research_context, rendered in the spec prompt as PROJECT RESEARCH (reference — build consistently with these; NOT files to edit). _gather_project_files now excludes research/ anywhere (not just the root) from the editable file set, so a brief is never mistaken for a build target the model must grow.

Robustness

Every path degrades and never raises into the caller: missing LLM → heuristic summary (the top result titles); missing search runner → sourceless brief; missing workspace → a clean ok=False result. The autoadvance hook is wrapped so a research failure can't break a tick.

The summariser and topic-proposer issue a no-think utility completion (_llm_complete): a plain foreground chat_completion with thinking disabled — the /no_think soft-switch + chat_template_kwargs:{enable_thinking:false} hard-switch + a system nudge, mirroring core.dream. This matters because the upstream runs as a reasoning model under --deep-reason: a utility call with thinking left ON burns the entire token budget inside <think> and returns an empty content (verified live: finish_reason=length, all completion tokens spent on reasoning_content), which silently dropped the summary to the title-list fallback. Responses are still defensively cleaned — _strip_think removes any stray <think> block and _message_text salvages reasoning_content if content is empty. The index summary_preview skips Markdown headings so it reads as a real sentence. Covered by tests/test_project_research.py and tests/test_project_advancer.py.

Idle summariser yields to the user 2026-07-22

_llm_complete (the research-brief summariser) was foreground-marked, but it is reached from the idle autoadvance loop (advance_once → persist_research_from_output) — so an idle research summary contended on the main slot with a live user turn and inflated foreground_tasks. It is now background-aware: the public funnels take background=None (auto-detect) and resolve it once at run start from llm_client.foreground_requests — > 0 means an interactive turn is in flight (stay foreground, no self-stall), 0 means idle/autoadvance (mark is_background=True so it parks politely). A user-invoked manage_projects action="research" therefore stays foreground; the idle backstop degrades. The call stays on the main model (no use_worker), so is_background alone is the fix. Test: test_project_research_offmain.py.

Main-loop research write-back 2026-09-03 · §4EK

Live (request 463111ad): the main loop ran six web searches about the active project and threw the results away — only the conversation saw them, while the coding leaves read the project's research/ files and nothing else. They built from a 3 KB brief that said "talismans and stat allocation are not covered" and shipped wrong facts.

Every relevant main-loop web_search now lands in research/main-loop-findings.md — newest first, the top 5 results of each search with a 200-char snippet and the source URL, a repeated query replaces its own entry, and only the newest MAIN_LOOP_FINDINGS_MAX_SEARCHES (8) survive. Zero LLM calls: the raw results with their URLs are the record. The research index (metadata + INDEX.md) carries a main-loop-findings entry, and _gather_research_briefs — what the coding executor reads — picks the file up unchanged (it sorts before research-*.md and its head is the newest search). The tool output tells the model where the results now live.

Who writes, who does not. The hook sits in tool_search, which the registry now calls with the live context; it writes only when current_project_id is set and the context is not a pinned one — autonomous leaves (autoadvance, the /advance route, the research leaf itself) build tools from _PinnedProjectContext, whose is_pinned_project_context marker excludes them, since their research is already saved as a brief. Error outputs and empty result sets are never recorded.

One authority for "is this about the project". The work-log gate's token-overlap check (request vs. project title/description/task text, or a command naming the project dir) moved out of agent.py into request_relevant_to_project here; the agent method now delegates, and the recorder uses the same verdict — so "get me the news" in a project conversation is neither journaled nor filed as research. Pins: tests/test_main_loop_research_writeback.py (executed delegation, executed registry wiring, the gatherer integration).
