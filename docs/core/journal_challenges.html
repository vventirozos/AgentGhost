Source filter

Only journal entries of type post_mortem or failure are considered. The miner scans for failure markers (error · failed · traceback · assertionerror · timeout · unresolved) and synthesises a tiny deterministic input.txt (typically 4 lines). The validator is intentionally lenient — it accepts any exit-0 output that references the expected file tokens.

Transferability + explicit-shape gates (2026-08-13, §4BE)

The leak. A mined challenge wraps the original request in a FIXED harness: "a <fixture> has been written in your working directory — write a solution.py that opens it and performs the operation the user asked for, applied to that file". _detect_data_shape fell back to a generic input.txt for any request, so "Run the composed skill youtube_transcribe on this URL" became a file exercise. Observed live on 2026-08-12: the solver ran the real macro — 8 Tor exit rotations, twice, genuine network egress from a "synthetic" exercise — then satisfied the validator by printing the fixture's lines, scored passed=True, and the lesson extractor mined "genuine lessons" from a run whose task and grader never agreed. Both halves are label noise: a fabricated PASS enters frontier scoring, and a lesson enters the corpus that retrieval later injects.

Two gates, both fail-safe. _is_transferable_challenge refuses a request that acts on the live world (invoking a macro or the agent's own tools, network fetches, service restarts, browser work, live sessions) or that names no task verb at all — a declarative statement like "I am located in Athens" asks for no operation, so the exercise degenerates to "print the fixture" and its PASS says nothing. Separately, _detect_data_shape now reports explicit: the generic input.txt fallback is marked inexplicit and the mining path refuses it, because a fixture that stands in for nothing the request referenced is exactly what made the harness incoherent. kind and filename are unchanged, so every other consumer behaves as before.

Refusing costs one skipped self-play cycle (the template bank and LLM-gen still supply material); accepting writes a fake label into the corpus and can touch the network — so the gates are deliberately tuned toward refusal. Measured against the live trajectory corpus of 957 distinct requests, mining goes from "almost anything" to 6 candidates end-to-end through _synthesize_challenge (an earlier "15" skipped anonymisation and the pre-existing destructive denylist), and the incident request is refused end-to-end. The live stash's 20 records all refuse — correctly: they are project-continuation turns (4 name Chess Coach), contentless ones like "proceed with all tasks", macro invocations and tool-driving — and record 19 is the incident itself. Tests: tests/test_label_noise_leaks_4be.py.
