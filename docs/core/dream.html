core / dream.py

Idle-time store maintenance. The REM consolidation cycle and the synthetic self-play pipeline that used to live here were removed on 2026-10-11 (§4NM); the idle phase was renamed maintenance the same day (the _idle_ran label, the ledger phase, the liveness row; older dream rows read as maintenance). The module, the Dreamer class and the --no-dream flag keep their names — about thirty files import them. Since §4NN its log lines are tagged Maintenance Digests, Maintenance Manifest and Trajectory Archive (were Dream Projects, Dream Manifest, Dream Mode), the idle scheduler's per-pass line is Idle Maintenance (was Biological Hook), and the return text no longer says (no REM — …).

Responsibilities

  • Run the project digest pass (project_dream_pass): per-project dream_digest events, event-id watermarked, surfaced as LAST DREAM DIGEST in the briefing.
  • Backfill the project manifests (deliverables registered against the files that actually exist).
  • Take the daily verified snapshot of the stores and apply the archive retention (§4MN).
  • Archive trajectories older than 90 days and purge the forget-archive (forgotten episodes, removed profile values, vector_reset_* dumps, the graph archive — one rule, 30 days).
  • Every ~6 h (STORE_MAINTENANCE_EVERY_S): graph upkeep — stale-edge prune and duplicate-node merge — and the cross-store reconcile (orphan skill vectors reaped). (The RRF-weight refit that used to run here is gone; the learned RRF weights were removed in §4NN.)

What runs today (2026-10-11, §4NM)

  • Dreamer.dream() is the maintenance entry point. It runs the daily store care first (a quiet day must not mean "no backup"), then the project digest and manifest passes, then — when the 6-hour stamp has expired — store maintenance. It stamps last_dream_outcome with the phase, whether anything was written, and the one-line summary the idle tick logs and ledgers: N project activity digests written; N project file descriptions written; store backup taken (<file>) / no store backup this pass (one a day) / FAILED; memory graph cleaned: N stale links removed, N duplicate entities merged (or memory graph cleanup not due (every 6 h) / FAILED), then the memory reconcile's repairs when it made any, led by nothing needed — when the pass changed nothing (§4PQ; it read maintenance: project digests N, manifests N, snapshot yes/no, graph pruned N, graph merged N until 2026-10-16). The stamp lives on the agent context, because a new Dreamer is built every cycle (until 2026-10-10 it was kept on the instance and the throttle never held).
  • No part of this phase writes a lesson. Lessons come from exactly two sources (LESSON_SOURCES_ALLOWED, memory/skills.py): learn_skill and operator_repair.
  • The idle self-play slot (phase 3) is not in this module: it replays the owner's real failures (core/failure_replay.py, §4MW) and runs the owner regression suite (core/regression.py, §4NE).

What was removed (2026-10-11, §4NM)

Each of these was measured on real turns in October 2026 (§4MS, §4NC, §4ND) and found not to change an answer for the better. The code and its tests are gone; the project journal keeps the engineering record.

  • REM consolidation — merging auto-memory fragments into syntheses, the heuristics harvest (lessons with source="dream"), trajectory- and self-play-seeded REM, the entropy and idempotency gates, episodic consolidation, failure-cluster distillation (core/failure_distill.py), lesson graduation and utility pruning. 44 dream-written lessons surfaced 3 times in 86 real requests with no relevant hit.
  • Synthetic self-play — synthetic_self_play, the challenge quality gate, preflight and validator self-test, journal-mined challenges, challenge templates and tiers, the adversarial generator, frontier-weighted cluster selection, self-play scoring and solution novelty, the counterfactual replay and the manual self_play / self_play_loop tools. The agent passed 8 of 9 invented challenges at the first try.
  • Macro proposals — mine_recurring_tool_sequences / _propose_macros_sync, which minted proposed composed-skill macros from the trajectory log.
  • The dream replay engine (core/replay_engine.py) and its GHOST_DREAM_REPLAY slot.

Store maintenance

Graph prune and merge

After the stale-edge prune, Dreamer._compress_graph_nodes(model_name, max_merges=8) merges duplicate entities. Candidates come from the read-only, deterministic GraphMemory.propose_merge_candidates: "safe" pairs (punctuation/whitespace variants of one name) are merged directly; "fuzzy" pairs (plurals/typos by string similarity) are merged only when a single batched worker call confirms the names denote the same entity (temperature 0, JSON {"same_entity": [...]} — when unsure, exclude). A worker failure skips the fuzzy pairs but keeps the safe merges; the whole step is best-effort and never fails the cycle; merges are capped per cycle so one bad batch can't rewrite the graph. Every merged row is archived (compress:<old>-><new>) and logged; two names whose numbers differ (qwen3.6…/qwen3.5…, 1.10/1.1.0) are never candidates (§4MI). Reported as "(N duplicate graph nodes merged)". Tests: tests/test_dream_graph_compression_wiring.py.

RRF-weight refit (removed)

Dreamer._refit_rrf_weights fitted the bus's intent weights from the usefulness-observations ledger and persisted rrf/weights.json. It no longer exists: core/rrf_weights.py was deleted on 2026-10-11 (§4NN), and MemoryBus._INTENT_WEIGHTS is the only weight table (see bus).

Reconcile

The cross-store reconcile removes vector rows whose owning record is gone. Since §4MN it also reaps acquired-skill vectors whose skill is gone: the purge used to run only when the owner called manage_skills, and 6 of 8 rows had been orphaned for days.

Daily store care (§4MN, 2026-10-08)

  • _daily_store_care runs first in every cycle. It takes the snapshot and enforces the archive retention: one rule, 30 days, for forgotten episodes, removed profile values, vector_reset_* dumps and the graph archive, applied here rather than only on the next forget. A context whose memory_dir is not a real, existing directory does nothing (a test's MagicMock had made a ./MagicMock folder).
  • _maybe_snapshot takes a snapshot (memory/snapshot.py) when the newest is older than 22 h, in a child process (§4MR). What a snapshot holds:
    • every SQLite database, through the online-backup API;
    • the chroma segment folders together with chroma.sqlite3;
    • the JSON/JSONL stores.
    It also includes the sandbox (project files; any single file over 50 MB is skipped). It leaves out eval, tokenizer, logs, LLM recordings and repair copies. A snapshot that raises (disk full, a locked database) removes its .partial and is logged at ERROR. Each snapshot is written to .partial, verified (every database passes integrity_check, and chroma opens from a copy and its sampled vectors find themselves), then renamed. The newest 7 are kept in system/backups/. A failed verification is logged at ERROR and nothing is published. GHOST_SNAPSHOTS=0 turns it off. By the operator's decision (2026-10-08) snapshots are local only for now. Restore: stop the agent and copy the snapshot's files back, with the whole memory/ folder together (scripts/snapshot_stores.py).
  • The 90-day trajectory archive runs on every cycle (§4MI) — it used to run only after a completed REM call, so a worker outage stopped retention.

Concurrency

Async orchestration, triggered by the lifespan-spawned idle scheduler (biological_watchdog; phase 2, 10–60 min idle, --no-dream disables it). The snapshot runs in a child process; graph merges are in-process and best-effort.

Ledger

The cycle writes one row to the autonomous-activity ledger — the surface introspect action='activity' reads to answer "what did you do while I was away". agent.dream_ledger_summary() shapes the cycle's own return message into the row (whitespace collapsed, length bounded) so a productive cycle and an empty one are distinguishable; a pass that wrote nothing is a heartbeat (idle_attempts.json "declined"), and only a pass that wrote something gets a ledger row (kind maintenance), carrying the pass's own maintenance: … summary. (Before §4NM a skip tick whose side passes wrote got a REM skipped; side passes wrote — … row.)
