Running it

Settings that matter

There are a few dozen command-line flags. About twenty are worth knowing; the rest exist to run experiments. This page is the twenty.

The defaults are the recommended configuration. Almost everything here is already set the way it should be. Change things when you have a reason — a second machine to use, a feature you want off, a problem to diagnose.

Using more than one machine

Ghost can hand different kinds of work to different LLM servers. This is the single biggest change you can make to how it feels, because your main model has one inference slot — every background check competes with your actual conversation for it.

Each flag takes a comma-separated list of url|model pairs:

--worker-nodes "http://192.168.1.20:8088|gemma-4-e4b"
--critic-nodes "http://192.168.1.20:8089|selene-mini"

Worker and critic do not have to be the same model — and there's a good argument they shouldn't be: worker chores (summarising, classifying) want a fast generalist, while the critic's adjudication wants a judge-trained model that applies verification rubrics well. One box can serve both as two llama-server instances on different ports; on a 16 GB machine that takes the dual-residency recipe (raised iogpu.wired_limit_mb, small --ubatch-size on both servers) — see the verifier reference's judge-model selection section. Whatever model serves the critic must return verdicts inside GHOST_VERIFY_WORKER_TIMEOUT (45 s) under real load — a judge that misses the deadline silently pushes its verdicts onto your main model.

FlagSends what to the other machine
--worker-nodesBackground and small jobs: summarising, classifying, compacting the conversation.
--critic-nodesThe self-check. The one worth doing first — it moves an entire extra model call per turn off your main model, and makes the check non-blocking as a side effect.
--coding-nodesCode generation, if you have a model that's better at it.
--visual-nodesImage analysis.
--image-gen-nodesImage generation. Without this, the image tool doesn't exist.
--swarm-nodesParallel fan-out when a task is split across several models.
Use a stable address. Point these at a tailnet address or a hostname that doesn't move, not a DHCP-assigned LAN IP. A node whose address changes shows up as a stream of connection failures, and the circuit breaker will eventually stop trying it. Check nodes and node_health on /api/health to see which are configured and which are actually answering.

Turning background work off

All on by default. Each one is an off switch so you can measure whether the thing is worth its cost. The self-teaching passes that used to have switches here (reflection, post-mortems, the router, the PRM) were removed on 2026-10-11 (§4NM). What each of these does →

FlagEffect
--no-dreamStops the idle maintenance phase: store maintenance (project digests, archive purges, graph prune/merge) and the daily verified snapshot. The lesson-writing consolidation it used to run was removed on 2026-10-11 (§4NM).
--no-self-playStops the idle failure-replay slot: replaying your failures and running your regression tests (the learning loop).
--no-trajectoriesStops recording turns. Also stops failure replay and the regression suite, which read them.
--no-self-modelStops the first-person diary and cross-session continuity.
--no-workspace-modelStops watching your files for changes.

Opt-in subsystems

These are complete features that are off by default because they add cost.

--enable-metacog
Logs each shell or SQL command that the safety checks block (a metacog valid line) and counts them; at shutdown one metacog summary validator_blocks=N line gives the total. At boot it prints metacog boot state=enabled validators="shell, sql". The checks themselves run whether or not this is on. (Host-health monitoring and the re-plan alarms it used to turn on were removed in §4PT, 2026-10-17.)
--metacog-mem-high (and the other host flags)
Removed §4PT — accepted and ignored. --metacog-cpu-high, --metacog-mem-high, --metacog-mem-floor-mb, --metacog-mem-warn-free-mb, --metacog-disk-high and --metacog-host-heartbeat-s set the trip points of the host-health monitor, which no longer exists. They are still accepted so a launcher that passes them keeps starting; the production launcher stopped passing them in §4PV (2026-10-17).
--principle-gate
After each answer, checks it against the operating principles Ghost has written for itself and appends a note if it contradicts one. Never blocks — annotates. One extra model call per turn.
--notify-webhook
--notify-ntfy
Where to push notifications when something needs you. A LAN or tailnet target is reached directly; a public one only over Tor, and skipped if Tor is down.

Environment variables are read at boot only. If you run Ghost under launchd or systemd, they must be set inside the service definition — a background service doesn't inherit your shell profile. The failure mode is quiet and confusing: Ghost starts fine on a brand-new empty memory at the default path, and looks like it forgot everything.

The other flags

Mostly cooldown timings, thresholds for the metacognition stack, and switches that exist to run controlled experiments (--bio-time-scale compresses the idle scheduler's hours-long windows into minutes so its jobs can be tested in an afternoon — never set it in production). They're all documented in the full CLI reference, and every one carries its own help text:

python -m src.ghost_agent.main --help
