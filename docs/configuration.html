Running it

Settings that matter

There are 64 command-line flags. About twenty are worth knowing; the rest exist to run experiments. This page is the twenty.

The defaults are the recommended configuration. Almost everything here is already set the way it should be. Change things when you have a reason — a second machine to use, a feature you want off, a problem to diagnose.

The ones you have to set

FlagDefaultWhat it does
--upstream-urlhttp://127.0.0.1:8080Where your LLM server is. Wrong value here and nothing works.
--modelqwen-3.6-35b-a3The model name to request. Must match what your LLM server actually serves.
--host0.0.0.0What address to listen on. Use 127.0.0.1 unless you need remote access.
--port8000Which port.
--api-keyfrom GHOST_API_KEYThe key clients must send. Required on a non-loopback bind.

Using more than one machine

Ghost can hand different kinds of work to different LLM servers. This is the single biggest change you can make to how it feels, because your main model has one inference slot — every background check competes with your actual conversation for it.

Each flag takes a comma-separated list of url|model pairs:

--worker-nodes "http://192.168.1.20:8088|gemma-4-e4b"
--critic-nodes "http://192.168.1.20:8089|selene-mini"

Worker and critic do not have to be the same model — and there's a good argument they shouldn't be: worker chores (summarising, query expansion) want a fast generalist, while the critic's adjudication wants a judge-trained model that applies verification rubrics well. One box can serve both as two llama-server instances on different ports; on a 16 GB machine that takes the dual-residency recipe (raised iogpu.wired_limit_mb, small --ubatch-size on both servers) — see the verifier reference's judge-model selection section. Whatever model serves the critic must return verdicts inside GHOST_VERIFY_WORKER_TIMEOUT (45 s) under real load — a judge that misses the deadline silently pushes its verdicts onto your main model.

FlagSends what to the other machine
--worker-nodesBackground and small jobs: summarising, classifying, compacting the conversation.
--critic-nodesThe self-check. The one worth doing first — it moves an entire extra model call per turn off your main model, and makes the check non-blocking as a side effect.
--coding-nodesCode generation, if you have a model that's better at it.
--vision-nodesImage analysis.
--image-gen-nodesImage generation. Without this, the image tool doesn't exist.
--swarm-nodesParallel fan-out when a task is split across several models.
Use a stable address. Point these at a tailnet address or a hostname that doesn't move, not a DHCP-assigned LAN IP. A node whose address changes shows up as a stream of connection failures, and the circuit breaker will eventually stop trying it. Check nodes and node_health on /api/health to see which are configured and which are actually answering.

Turning background work off

All on by default. Each one is an off switch so you can measure whether the thing is worth its cost. What each of these does →

FlagEffect
--no-dreamStops memory consolidation.
--no-self-playStops practice sessions.
--no-reflectionStops reviewing failed turns.
--no-trajectoriesStops recording turns. Also disables reflection, which reads them.
--no-self-modelStops the first-person diary and cross-session continuity.
--no-workspace-modelStops watching your files for changes.

Safety

--mandatory-toron Boot fails if Tor is unreachable, and direct connections to public addresses are blocked for the life of the process. Turn off with --no-mandatory-tor — you need this exactly once, on a fresh install, so the embedding model can download.

Opt-in subsystems

These are complete features that are off by default because they add cost or need a trained file to exist first.

--enable-metacog
Turns on the metacognition stack: output validators, host-health monitoring, a competence profile, uncertainty tracking, and a second-solver arbiter for low-confidence answers. Several other flags (all the --metacog-* ones) only do anything when this is on.
--metacog-mem-high
RAM percentage above which a host-health signal fires. Default 97. Ghost always runs alongside a local LLM server, which pins memory as steady state — a lower threshold treats that resting condition as pressure and warns on a box with gigabytes free. Genuine pressure is caught by the free-RAM conjunct (--metacog-mem-warn-free-mb, default 1 GB) and the hard floor (--metacog-mem-floor-mb), which fire on real numbers rather than a percentage. Lower it only on a host that isn't co-resident with the model.
--principle-gate
After each answer, checks it against the operating principles Ghost has written for itself and appends a note if it contradicts one. Never blocks — annotates. One extra model call per turn.
--router-model
Path to a trained request classifier. When set, Ghost routes cheap requests to cheap machines. When unset — the default — every request gets the full pool.
--prm-model
Path to a trained plan-scoring model, used to evaluate partial reasoning paths. Ghost trains this itself during idle time; this flag points at an existing checkpoint.
--notify-webhook
--notify-ntfy
Where to push notifications when something needs you. A LAN or tailnet target is reached directly; a public one only over Tor, and skipped if Tor is down.

Environment variables

VariableDefaultWhat it does
GHOST_HOME~/ghost_llamacppWhere everything lives. The one directory to back up.
GHOST_API_KEYunsetDefault for --api-key.
GHOST_MODELqwen-3.6-35b-a3Default for --model.
TOR_PROXYsocks5://127.0.0.1:9050Where Tor's SOCKS proxy is.
GHOST_SANDBOX_MEM4gMemory ceiling for the sandbox container.
GHOST_SANDBOX_JOBS1A sandbox command still making progress after 90 s is moved to the background instead of blocking the turn, and the model is woken with its result when it lands. Set to 0 to go back to killing it at the 600 s budget. See sandbox.jobs for the promotion threshold (GHOST_SANDBOX_JOB_PROMOTE_AFTER_S), the lifetime cap (GHOST_SANDBOX_JOB_TTL_S, default 45 min), the progress window, and the concurrency cap.
GHOST_EMBED_MODELBAAI/bge-small-en-v1.5The embedding model. Changing this invalidates your entire vector store — Ghost refuses to start until you re-embed.
GHOST_MANDATORY_TOR1Set to 0 to default mandatory Tor off.
Environment variables are read at boot only. If you run Ghost under launchd or systemd, they must be set inside the service definition — a background service doesn't inherit your shell profile. The failure mode is quiet and confusing: Ghost starts fine on a brand-new empty memory at the default path, and looks like it forgot everything.

The other 44 flags

Mostly cooldown timings, thresholds for the metacognition stack, and switches that exist to run controlled experiments (--bio-time-scale compresses hours-long idle windows into minutes so the background loops can be tested in an afternoon — never set it in production). They're all documented in the full CLI reference, and every one carries its own help text:

python -m src.ghost_agent.main --help
