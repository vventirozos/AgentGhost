Maintenance cycle

What idle time is spent on: keeping the stores healthy. (Until 2026-10-11 this page was "Dream cycle & self-play"; until 2026-11-05 it was "Maintenance cycle & failure replay".)

Current state (2026-11-05, §4SZ). No idle phase writes a lesson or proposes a rule. The failure-replay slot (phase 3), the owner regression suite and the reaction judge were removed on 2026-11-05: in the 27 days the slot was live it made 13 replays and proposed 9 rules (5 adopted), nothing in its last 17 days, and the suite held 0 kept tests. Rules are now dictated by the owner (Owner rules, core/owner_rules.py). Earlier, on 2026-10-11 (§4NM), the REM consolidation, the synthetic self-play pipeline (templates, journal mining, the adversarial generator, frontier selection, scoring, novelty, counterfactual replay, the manual self_play / self_play_loop tools), reflection, post-mortems, failure distillation, automatic skills and skill pruning were removed after the October 2026 measurements (§4MS, §4NC, §4ND) found none of them changed an answer for the better. The lesson store itself (memory/skills.py; writers learn_skill and operator_repair, LESSON_SOURCES_ALLOWED) is still present, out of prompts since 2026-10-13, and scheduled for removal.

The idle phases

The idle scheduler (formerly called the biological watchdog; biological_watchdog in code) ticks every 60 s while no foreground request is running. Each phase needs both an idle window and its own cooldown. At boot it logs Idle Scheduler — started; jobs: …, listing the jobs this boot will run (with the production launcher: memory-journal consolidation, maintenance, store-hygiene, workspace tidy, project autoadvance (autopilot projects only), self narrative, workspace narrative, mirror (one I-sentence a day); "stale open questions" was on the list until 2026-11-05, §4TB). Each tick that did work prints one Idle Cycle line, idle Nm — ran <job> (<what it is for>): <what it did> | … (§4PQ, see logging).

Phase 3: failure replay (removed 2026-11-05)

History. This section describes a mechanism that was removed on 2026-11-05 (§4SZ, see the agent page). The code (core/failure_replay.py, core/regression.py, core/owner_seeds.py, distill/reaction_judge.py), the switches GHOST_SELFPLAY_COOLDOWN_S and GHOST_REACTION_JUDGE, and the commands "learn rule N" and "keep test N" no longer exist.

The slot won a 20% roll after a 4 h cooldown (GHOST_SELFPLAY_COOLDOWN_S, default 14400) and ran one stage of one case per slot:

  1. Seed. core/owner_seeds.py listed the owner's own turns that failed: a 👎 (feedback), a next message the reaction judge (judge_reactions, GHOST_REACTION_JUDGE) read as a correction (tool turns only: since §4PM the judge also read no-tool turns, into a separate file the seeds never read; see §4PM), a verifier refute (since §4OW, 2026-10-14, only the mechanical checks produced one) or a run of tool failures. Member, probe and test turns never qualified.
  2. Base. The newest read-only case (searches, pages, files — a request that changed something was never replayed) was asked again twice on an isolated context, labelled as a test: no writes, no messages, no memory.
  3. Diagnose. The main model read the original reply, the replays and what each saw, and wrote the cause and one general rule — or none. A rule that named the case or echoed a web page was discarded.
  4. Test. The question was asked twice more with the rule in the prompt, then the kept regression tests were run with it.
  5. Propose. The owner saw Candidate rule N under "Background activity while you were away" and decided: learn rule N adopted it into the ### OWNER RULES block. The same 👎 drafted a regression-test proposal (keep test N).

Its state was kept in $GHOST_HOME/system/selfplay/failure_replays.json and system/regression/cases.json. Why it went: 13 replays, 9 proposed rules and 5 adopted in 27 days (two the same, three a restatement of "say only what the tool output shows"); nothing new in the last 17 days, because 30 of 30 flagged turns were follow-ups in a conversation or action requests that a replay cannot rebuild; 0 kept regression tests; 1–6 background judge calls a day on the main model.

Isolation boundary of a replay

A replay ran on a detached copy of the real context (core/isolation.py; that module is still in the code and has had no live consumer since the removal). All memory wrappers were read-only:

  • ReadOnlyVectorMemory — add() / smart_update() / delete() are no-ops, and reads are stat-pure: search/search_advanced force record_retrievals=False (a read that bumps retrieval stats is still a write to operator memory), and survivor-credit calls resolve to None through the strict whitelist — a replay earned no production credit by construction.
  • context.simulated — the one flag (§4TD, 2026-11-06; until then is_read_only on the lesson store's read-only wrapper) that makes write-oriented paths and the Perfect-It follow-up call stand down.
  • ReadOnlyGraphMemory, journal = None, profile_memory = None.
  • Tool surface restricted (restrict_tool_surface: schema, dispatch dict and _subagent_allowed_tools; youtube_transcribe dropped wherever knowledge_base is), browser denied, the notify targets and the labs host cleared, the container on network=none, job promotion off (§4MI).
  • A replay could not author the agent's selfhood: the autobiographical store was detached (2026-08-11).

What the ledger says a cycle did

Each phase writes one row to the autonomous-activity ledger (the maintenance pass under the phase maintenance; older rows say dream and are read as maintenance) — the surface introspect action='activity' reads to answer "what did you do while I was away". A skip tick is a heartbeat. maintenance is the only phase expected to leave a periodic heartbeat (PHASE_EXPECTATION, core/autonomous_activity.py); the self_play phase the replay slot wrote is no longer expected and is listed in RETIRED_PHASES, so the liveness table skips its old heartbeat rows; the rows stay readable in the ledger.

History

From 2026-04 to 2026-10 this page described the dream cycle (REM consolidation and heuristics harvest), frontier-aware cluster selection, tier-aware templates, the validator self-test gate, the lesson extraction pipeline and the counterfactual replay. All of it was measured in October 2026 — 44 dream-written lessons surfaced 3 times in 86 real requests; invented challenges were passed 8 of 9 at the first try; 52% of skill-prune victims were decided by label noise — and removed on 2026-10-11 (§4NM). From 2026-10-10 to 2026-11-05 the page also described the failure-replay slot and the regression suite (§4MW, §4NE), removed in §4SZ. The engineering record is in the project journal.
