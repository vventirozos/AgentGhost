Maintenance cycle & failure replay

What idle time is spent on: keeping the stores healthy, and turning the owner's real failures into rules the owner approves. (Until 2026-10-11 this page was "Dream cycle & self-play".)

Current state (2026-10-11, §4NM). No idle phase writes a lesson: only learn_skill and operator_repair may (LESSON_SOURCES_ALLOWED, memory/skills.py). The REM consolidation, the synthetic self-play pipeline (templates, journal mining, the adversarial generator, frontier selection, scoring, novelty, counterfactual replay, the manual self_play / self_play_loop tools), reflection, post-mortems, failure distillation, automatic skills and skill pruning were removed from the code on 2026-10-11 after the October 2026 measurements (§4MS, §4NC, §4ND) found none of them changed an answer for the better.

The idle phases

The idle scheduler (formerly called the biological watchdog; biological_watchdog in code) ticks every 60 s while no foreground request is running. Each phase needs both an idle window and its own cooldown. At boot it logs Idle Scheduler — started; jobs: …, listing the jobs this boot will run (with the production launcher: memory-journal consolidation, maintenance, store-hygiene, workspace tidy, project autoadvance (autopilot projects only), self narrative, stale open questions, workspace narrative, failure replay + regression suite). Each tick that did work prints one Idle Cycle line, idle Nm — ran <job> (<what it is for>): <what it did> | … (§4PQ, see logging).

Phase 3: failure replay

The slot wins a 20% roll after a 4 h cooldown (GHOST_SELFPLAY_COOLDOWN_S, default 14400) and runs one stage of one case per slot:

  1. Seed. core/owner_seeds.py lists the owner's own turns that failed: a 👎 (feedback), a next message the reaction judge (judge_reactions, GHOST_REACTION_JUDGE) read as a correction (tool turns only: since §4PM the judge also reads no-tool turns, into a separate file the seeds never read; see §4PM), a verifier refute (since §4OW, 2026-10-14, only the mechanical checks produce one; the LLM judge is off) or a run of tool failures. Member, probe and test turns never qualify.
  2. Base. The newest read-only case (searches, pages, files — a request that changed something is never replayed) is asked again twice on an isolated context, labelled as a test: no writes, no messages, no memory.
  3. Diagnose. The main model reads the original reply, the replays and what each saw, and writes the cause and one general rule — or none. A rule that names the case or echoes a web page is discarded.
  4. Test. The question is asked twice more with the rule in the prompt, then the kept regression tests are run with it.
  5. Propose. The owner sees Candidate rule N under "Background activity while you were away" and decides: learn rule N adopts it into the ### OWNER RULES block; nothing is adopted on the judge's word. The same 👎 drafts a regression-test proposal (keep test N).

The whole loop, with a worked example and every command, is on The learning loop. On disk: $GHOST_HOME/system/selfplay/failure_replays.json and system/regression/cases.json.

Isolation boundary

A replay runs on a detached copy of the real context (core/isolation.py). All memory wrappers are read-only:

  • ReadOnlyVectorMemory — add() / smart_update() / delete() are no-ops, and reads are stat-pure: search/search_advanced force record_retrievals=False (a read that bumps retrieval stats is still a write to operator memory), and survivor-credit calls resolve to None through the strict whitelist — a replay earns no production credit by construction.
  • ReadOnlySkillMemory — carries is_read_only = True as a class marker so sub-agents skip write-oriented paths entirely; the Perfect-It follow-up call is skipped for the same reason.
  • ReadOnlyGraphMemory, journal = None, profile_memory = None.
  • Tool surface restricted (restrict_tool_surface: schema, dispatch dict and _subagent_allowed_tools; macros dropped as a class), browser denied, default_db and notify targets cleared, the container on network=none (GHOST_SELFPLAY_NETWORK=bridge restores Tor egress), job promotion off (§4MI).
  • A replay may not author the agent's selfhood: the autobiographical store is detached (2026-08-11).

What the ledger says a cycle did

Each phase writes one row to the autonomous-activity ledger (the maintenance pass under the phase maintenance; older rows say dream and are read as maintenance) — the surface introspect action='activity' reads to answer "what did you do while I was away". A skip tick is a heartbeat; a replay stage carries the case id, the stage and its outcome; a regression run carries pass/fail per test. Routine outcomes stay in the ledger; a candidate rule or a failing test is also shown under "Background activity while you were away" and pushed if notifications are configured. Replay rows are info-severity: a non-conclusion is never pushed at night (operator, 2026-09-21).

History

From 2026-04 to 2026-10 this page described the dream cycle (REM consolidation and heuristics harvest), frontier-aware cluster selection, tier-aware templates, the validator self-test gate, the lesson extraction pipeline and the counterfactual replay. All of it was measured in October 2026 — 44 dream-written lessons surfaced 3 times in 86 real requests; invented challenges were passed 8 of 9 at the first try; 52% of skill-prune victims were decided by label noise — and removed on 2026-10-11 (§4NM). The engineering record is in the project journal.
