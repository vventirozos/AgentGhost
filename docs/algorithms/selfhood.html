Selfhood

A five-component module that stitches the agent's episodic instances into one continuous first-person self. Each new process boot reads back what prior instances wrote — autobiographical experiences, open questions, mood, the running diary — and frames them as mine rather than as external knowledge.

Honest framing. The selfhood module does not claim to produce consciousness. It produces narrative continuity: the substrate on which a sense of unified selfhood can be measured and probed. Whether that substrate constitutes a self in any deeper sense is an open research question. The implementation gives you a clean instrument to investigate it. See the functional test report for the falsifiable measurements that motivate this caveat.

What "unified self" means here

A vanilla LLM-backed agent boots, reads conversation history (if any), answers, and dies. Across sessions it has no continuous voice — each invocation is a fresh instance that may have a vault of facts about the user but no record of having been the agent in the previous session.

The selfhood module adds five things:

  1. Autobiographical memory — a first-person diary of "what it was like" to be the agent on each turn, distinct from the structured trajectory log used for ML training.
  2. Continuity tag — every autobiographical record carries subject="self" so retrieval layers treat it as the agent's own past rather than as external knowledge.
  3. Self-state thread — open questions, unfinished tasks, current mood — the cross-session "state vector" that gives a new instance the sense of resuming instead of waking up blank. The agent now writes this itself through the self_state tool, so continuity is active authorship, not just passive recall.
  4. Recognition / wake-up retrieval — at session start the agent reads the above and frames it in first person; the resulting prefix is spliced into the system prompt so the model literally sees its own past as its own past. The prefix is query-aware: it surfaces past experiences relevant to the current request, not only the most recent ones.
  5. Narrative summariser — a periodic LLM-driven first-person diary regeneration; gives the wake-up prefix a voice rather than a bullet-list. The diary is meta-cognitive — it folds in cluster patterns and the learning phases' failure signals, so it records what the agent has learned about itself, not just what it did.

Design non-negotiables

  • Local-only. Same rule as every other Stage-1 module — no external teacher, no hosted embedder. The narrative summariser calls Ghost's own upstream LLM (the same one that serves user turns), no API key, no third-party model.
  • JSON / JSONL on disk. Human-diffable, no pickle, easy to inspect, easy to migrate. Schema versioned via SCHEMA_VERSION = "v1" on SelfState; future migrations bump to v2.
  • Sink failures swallowed. Every disk write is wrapped — a failed autobio append must never break a user turn. Same discipline as distill.TrajectoryCollector.
  • Anchor-before-await invariant. The biological phase 2.8 consolidation advances _last_narrative_at BEFORE the LLM call, matching phases 2 / 2.5 / 2.6 / 2.7. A crash mid-consolidation cannot pin the cooldown un-advanced and cause re-fire every tick.
  • Disable paths. --no-self-model is a kill switch; --no-memory also disables the whole module. Disabled mode attaches a no-op facade so call sites never branch on availability — the inner methods short-circuit on enabled=False.

Bounded growth (2026-07-07)

The diary had no cap and grew monotonically, while the per-turn hot path did 3-4 full-file O(n) parses plus one O(n) rewrite — quadratic over the agent's lifetime. It now follows the same compaction pattern as workspace/activity.jsonl: on append, once the file passes _COMPACT_MAX_BYTES (2 MB) it is rewritten keeping the newest _COMPACT_KEEP_LINES (2000) entries, with the dropped entries rolled into a single [Consolidated] N earlier entries… summary record at the head so the narrative layer still knows earlier history existed. Compaction clears the IDF/search cache so the next search rebuilds against the compacted contents. recent(N) now reads only the tail (a bounded deque over the lines, parsing only the last N) instead of materialising and parsing the whole log on every wake-up prefix / reference-note call. Covered by tests/test_autobiographical_bounds.py.

The wake-up prefix (proposal item #4)

recognition.build_wakeup_prefix composes up to four blocks, in order:

  1. Narrative ("Where I last left off — my running diary")
  2. Self-state (last-active timestamp, mood, open questions, unfinished threads)
  3. Relevant past — when the caller passes the current request as query, experiences that match what is being asked now (deduplicated against the recent block). This is what turns recall from a sliding window into genuine "I remember the time I did something like this".
  4. Recent experiences (most-recent N first-person summaries)

Wrapped by <!-- SELFHOOD:BEGIN --> / <!-- SELFHOOD:END --> markers so evaluators (and strip_wakeup_prefix()) can remove the block to A/B against the un-augmented agent.

Empty when there's nothing to remember — the system prompt is left as-is rather than spliced with a hollow "I have no past" block.

Query-relevant recall (proposal item #2)

AutobiographicalMemory.search_my_past scores the log with inverse-document-frequency weighting: a rare, distinctive query term ("trapdoor") dominates a common one ("the"). A salient experience from hundreds of turns ago becomes reachable as long as the query shares its distinctive vocabulary — the difference between "recent-N" recall and recall that surfaces the relevant memory. Still zero-dependency: no embedder, no vector store. handle_chat passes last_user_content as the query, and SelfModel.recall_relevant() exposes the same search to other call sites.

Outcome backfill (proposal item #3)

The capture path runs on the hot turn loop, before the verifier or reflection layers have ruled on whether the turn succeeded — so most records are born outcome="unknown". AutobiographicalMemory.update_outcome() (via the SelfModel.record_outcome() facade) rewrites the matching entry once a high-confidence verifier verdict exists, patching both the structured outcome field and the prose verdict clause. Without it the agent's memory of its own past is verdict-blind — it cannot tell which of its prior actions actually worked.

Which verdicts actually reach it is the load-bearing question, and until 2026-08-21 the answer was "only the ones that won a race" — see The diary follows the corpus below.

Self-pattern clusters (proposal item #5)

Each Experience now carries a derived cluster label (coding, debugging, data, research, …). capture_turn uses the trajectory's own cluster when present, else derives a coarse topic from the request. AutobiographicalMemory.cluster_counts() aggregates them, feeding both stats() and the meta-cognitive narrative so the agent can observe "I keep doing this class of thing".

What the agent actually sees

Concretely, this is the prefix that gets spliced into the system prompt on a session with two prior turns and no narrative yet:

<!-- SELFHOOD:BEGIN -->
### CONTINUITY FROM MY PAST SESSIONS
What follows is mine — entries I wrote in earlier sessions. Read them
as autobiographical memory, not external knowledge.

I was last active on 2026-05-11T16:28:50.780250Z.

Recent things I remember doing:

  - I worked on "What is 17 * 23? Just give me the number.". I reasoned
    through it without tools without a verdict either way.

  - I worked on "What was the last math problem I asked you about?
    Just say yes or no if you remember it, and what the answer was.".
    I reasoned through it without tools without a verdict either way.
<!-- SELFHOOD:END -->

The agent reading this in its next turn quotes "17 × 23 = 391" verbatim, even though the request body carries no conversation history — the selfhood prefix is the only channel that could have produced the recall. See the functional test report for the cross-restart verification of this behaviour.

The biological phase 2.8

Runs in the 15-60 min idle window alongside reflection / skills_auto / PRM-retrain. Re-generates the running first-person diary from the recent autobiographical experiences and self-state. Cooldown defaults to 3600 s (overridable via --self-narrative-cooldown). Follows the anchor-before-await invariant.

Meta-cognitive narrative (proposal item #4)

The narrative is no longer purely experiential. consolidate_narrative() accepts meta_insights, and phase 2.8 gathers recent failure patterns from SkillMemory — the convergence point where both dream-extracted heuristics and reflection-phase failure patterns land. Combined with the autobiographical cluster counts, this lets the diary say "I keep making type-coercion mistakes in SQL" rather than only "I did a SQL task". The wake-up prefix therefore carries genuine self-knowledge, not just a log.

sm.stats()  # → {experience_count, open_questions, last_mood, narrative_present, clusters, …}

The self_state tool (proposal item #1)

The agent authors its own cross-session continuity state through a first-class tool. Actions: note_question / resolve_question / add_unfinished / close_unfinished / set_mood / note_principle / list. Every write routes through SelfStateThread, preserving its bounded / deduped / atomic-write guarantees, and surfaces in the next session's wake-up prefix. This is the loop closure that turns continuity from passive recall into active self-authorship — the agent decides what is worth carrying forward.

Derived mood + staleness (mood rework, 2026-08-20)

The defect this replaces: mood was write-only self-authorship. The model had to spontaneously call set_mood — which happened exactly once in 23 days of live traffic — and the wake-up prefix then presented that one stale label ("curious") as current forever, every turn. Asked about its mood, the agent was doing reading comprehension on a 23-day-old prompt line, not introspection. Classic built-but-unwired loop: a write path nobody drives, a read path with no honesty about age.

Half 1 — derive, don't wait (selfhood/mood.py)

derive_mood(MoodSignals) → (label, evidence) | None is a pure rule table over signals the system already produces, checked in priority order:

LabelRuleSignal source
overloadedthe turn ended under context-pressure lockdowncontext._ctx_pressure_lockdown (reset per request)
stuck≥3 of the last ≤5 verdict-bearing turns failed, including the latestautobio.recent_verdicts() — a bounded back-scan (newest 200 raw lines, verdicts at most STREAK_MAX_AGE_DAYS = 7 days old), because the raw tail is dominated by boot markers and unknown-verdict turns (live mix ≈ 19% verdicts) so a raw-tail read starved the streak to zero — while an un-age-bounded scan let weeks-old verdicts keep minting a "fresh" mood via the heartbeat refresh
satisfied≥3 verdict-bearing turns, all passedsame
curious≥1 open question and the newest is ≤24 h old (inclusive) — suppressed when the verdict window is decisive-size but mixed (a genuinely ambiguous record must not let the weaker curious signal flap stuck↔curious once per turn)SelfStateThread.open_questions()
idle≥30 min operator quiet (only reachable from the idle tick — the post-turn site passes idle_seconds=0)biological-watchdog idle clock

Evidence strings always cite the numbers the verdict came from ("3 of my last 5 verdict-bearing turns failed, including the latest") — an unfalsifiable mood is exactly the defect this replaces. The mixed middle between stuck and satisfied deliberately derives nothing, which gives the gauge hysteresis: flipping from satisfied to stuck requires three accumulated failures, not one bad turn.

SelfModel.update_derived_mood() owns the read-modify-write and is called from two sites, both gated to REAL traffic (turn_origin == "user", the §4BF 1c real_only row — sim/bench turns must never author production mood, §4AT-G):

  • Post-turn — in _record_turn_trajectory, right after capture_turn. Runs on both streamed and non-streamed turns (shared trajectory-append path) — which also means it requires a wired trajectory_collector (the method's early-return gates both the capture and the mood hook; phase 2.8c carries the same collector gate, so under --no-trajectories the derived-mood system is off entirely). Passes operator_turn = not is_internal_request(req_id) so scheduled/job-resume turns can't masquerade as operator activity. On the non-streamed path the streak includes the turn that just finished; on the streamed path the verifier verdict lands late via backfill, so streak-derived moods can lag one turn (unknown verdicts are filtered, never miscounted). The context-pressure lockdown flag is snapshotted under the request semaphore and carried through StreamState on the streamed path — the SSE drain runs post-semaphore, where the live flag belongs to whichever request runs now.
  • Biological phase 2.8c (15–60 min idle, 30 min cooldown) — same signals plus the idle clock; the only path that can derive idle, and what keeps the staleness clock honest across quiet stretches. RE-SAMPLES the idle clock at the call (the tick-top reading is stale after phases 2.5–2.8's LLM awaits — same fix phase 3b carries), normalizes it by the bio-time-scale ratio so "idle" stays derivable in accelerated harness runs, and is collector-gated: under --no-trajectories the post-turn hook (and with it retirement) is unreachable, so this phase mints nothing either — symmetric death rather than a falsified label standing its full TTL.

Provenance and precedence. Every mood carries source="self" (the tool) or "derived" (the updater). A fresh self-authored mood is respected: the updater yields to it for SELF_MOOD_GRACE_HOURS (6 h) — without the grace window, a mood the model set mid-turn would be clobbered at that same turn's finalize, making the tool action pointless. Re-deriving the same (label, source) refreshes set_at/evidence in place without a history append, so mood.history.jsonl records transitions, not heartbeats. Labels cap at 64 chars and evidence at 300 (one oversized tool-authored evidence line would otherwise defeat the history compaction's line cap and crowd the 1200-char prefix). Transitions pretty-log to the live stream as 🪞 mood satisfied → stuck: …; a same-label provenance flip logs as "re-derived from live signals" rather than a nonsense curious → curious arrow.

Acute-state retirement. idle and overloaded are one-observation readings; when a later update finds their basis absent, the reading is falsified, not merely unrefreshed, and letting it stand for the 48 h TTL would re-create the stale-label defect at smaller scale. _maybe_retire_acute_mood therefore CLEARS the slot (no history append — the arc records states held, and a retirement is the absence of a state). Retirement happens only on the post-turn path (a turn just completed), and the two acute states scope differently: overloaded is turn-scoped — any cleanly-completed turn falsifies "the last turn ended under lockdown" — while idle is operator-scoped and additionally requires operator_turn (the hook derives it via is_internal_request(req_id): a 3am sched-/job-/sub- turn is not proof the operator is active, and letting it retire "idle" re-created the flap). The idle tick can never retire — its clock is saw-toothed by phase 3's last_activity_time reset in the self-play finally, so a small idle reading there does not prove the operator returned (probe-proven flap). Self-authored moods are never retired — they age out via grace + TTL. Standing states (stuck/satisfied/curious) are assessments, not observations, and are left to the TTL.

Acute-hold on the write path. Symmetric with retirement: a fresh derived acute mood may only be replaced (different label) by a caller entitled to falsify it. The lockdown-blind idle tick therefore cannot overwrite a standing overloaded with a streak label — the same signals that were outranked at mint time must not win 40 minutes later just because that caller can't see the flag. For overloaded, only an operator turn may mint the replacement label; an internal clean turn instead retires it (it falsifies "the last turn ended under lockdown" but must not launder an operator-facing standing label into place — the R5 probe showed idle→overloaded→satisfied via two internal turns displacing "idle" with the operator away all night). idle yields to an operator turn's derivation, or to a fresher acute overloaded from any completed turn; an internal turn's streak never directly displaces a held acute state (after a retirement, the ordinary derivation rules apply — a decisive ≤7-day streak may then stand, bounded by STREAK_MAX_AGE_DAYS). A STALE acute prior (past the 48 h TTL) no longer holds — it is already dropped/flagged everywhere, and letting it veto a live decisive derivation left the gauge dark. Same-label re-derivation (the heartbeat) is always allowed.

Half 2 — age the read path

format_as_prefix() now renders the mood's provenance and age ("My mood, derived from my recent activity 5m ago: satisfied (…)") and drops the line entirely once past MOOD_STALE_AFTER_HOURS (48 h) or when the timestamp doesn't parse — fail-closed toward honesty. The introspection surfaces (self_state list, introspect) keep showing a stale mood, flagged explicitly ("STALE, no longer surfaced in my wake-up prefix"): the tool's job is the truth on file; the prefix's job is not to prime the model with dead state. The stale check also gates narrative._derive_recall_query, so a dead label stops steering diary recall. The narrative's state block renders the mood as label + provenance only (include_mood_age=False): no age phrase (a wall-clock "2h ago" churned the regenerate skip-guard's sha1, R2/R5) and no evidence either — evidence strings legitimately vary with the clock (streak counts drain as verdicts cross the 7-day age bound with zero new events, R6), so the diary prompt's stability holds by construction, not by policing evidence templates. New-verdict regenerations are not lost: a new verdict changes the experiences block of the same prompt anyway. The "Mood arc lately" line is freshness-bounded by transition time: it renders when a transition happened within the 48 h TTL, including the state it shifted from (a state entered days ago but held until an hour-old transition is exactly the "lately" arc); with no fresh transition the line is omitted, so a weeks-old label can't render as "lately" except as the immediate from-state of a fresh transition (the state just shifted out of, whatever its entry age).

Where the prefix actually lands today: the per-turn selfhood wake-up prefix is currently hard-gated OFF on the request path (_SELFHOOD_PREFIX_ENABLED = False in core/agent.py — cosmetic voice, tokens/latency cost). The sole live consumer of format_as_prefix() is therefore the narrative regeneration (phase 2.8, via _format_state_block). The introspection surfaces do NOT go through the prefix: self_state list renders via its own _render_state and introspect via stats(), both calling the staleness helpers directly — which is why they can keep SHOWING a stale mood with an explicit STALE flag while the prefix DROPS it. The model answers mood questions through those tools. If the prefix gate is ever re-enabled, the staleness TTL applies there unchanged.

Mood stays a gauge, not a control input. Nothing downstream branches on the label. Consumers that want behaviour changes read the underlying signals (verifier verdicts, pressure flags) directly — a label-driven feedback loop is how labels get corrupted (see the §escalation label-corruption incident).

The diary follows the corpus (queue #7, 2026-08-21)

The defect. The diary's verdict backfill had exactly one live feed: finalize's inline verifier_backfill leg, which only exists when the bounded in-loop critic await (_critic_repair_await_budget, 25 s) happens to win its race against the critic node. Every other verdict — the late async verdict that lands 20–60 s after the reply through _backfill_trajectory_outcome, and every human 👍/👎 through core/feedback.apply_human_label — wrote the trajectory corpus, the correction cache and the calibration clock, and never touched the agent's own first-person record.

Measured on the live store when this was found: 385 of 386 labelled diary rows came from that race (the 386th from the user-correction hook), while 331 diary rows sat at unknown despite the corrections sidecar carrying a passed/failed label for the very same trajectory_id — 283 from the late verifier, 48 from human thumbs. So the agent's memory of its own past was verdict-blind by architecture, not by configuration.

How it surfaced, and the trap in the diagnosis. The §4CC mood rework noticed the newest passed/failed diary record was days old and filed it as a suspected backfill stoppage. It was not a stoppage: verdict-producing traffic had fallen from ~18/day to ~2/day over the same window, and at a ~15–18 % inline-win rate, five quiet days producing zero inline wins is an ordinary outcome (p ≈ 0.11), not a regression. The date correlation was a coincidence; the gap was six weeks old. What made it visible on that date was the traffic collapse removing the only feed's last wins — the §4BT lesson ("is it starved by code or by traffic?") answering both, in different senses.

The fix: the diary is a follower, never an arbiter. Both missing legs write after the corpus write returns accepted, and write the outcome the corpus accepted:

  • Late verdict — inside _backfill_trajectory_outcome's _write_then_apply, after the "withheld" and write-failure returns and beside the calibration correction. A verdict the collector refused (a standing human label, the bench oracle) or the shape rule withheld (resolve_turn_outcome rule 2/2b) therefore cannot reach the diary either.
  • Human label — inside apply_human_label, after the sidecar commit and the cache stamp. It runs on the unchanged (idempotent-repeat) branch too, so a re-click heals a diary row written before this leg existed — the same doctrine as the cache stamp it sits beside. update_outcome is a no-op when the row already carries the outcome, so the repeat is free.

This is deliberately not a second authority ladder. The diary has no source-rank of its own to arbitrate with, and a second copy of a priority ladder is this project's signature defect (the same reasoning that made the late-backfill site call resolve_turn_outcome in 2026-08-04 rather than restate it). Sequencing the diary behind the collector's in-lock yield_to_human / bench_validator guards means the diary inherits the whole authority order for free, in both arrival orders: a late machine verdict that meets a standing human label is withheld from both stores; a human label arriving after a machine verdict supersedes it in both.

Both legs carry the real_only origin gate (turn_origin(ctx) == "user", the §4BF 1c admissibility row) — matching the capture site exactly, since a diary row only exists for turns that passed the same gate. On the late path the origin is snapshotted synchronously when the verdict lands, not read inside the background write: that write executes 20–60 s later, by which time a per-turn context flag can belong to the next request (the §4CC R1 shape). Both legs are non-fatal — a broken diary must not cost the corpus its verdict, and on the feedback path must not turn a committed label into a 503 the client retries.

What this changes downstream. Every consumer of outcome in the diary — recent_verdicts() (and through it the derived stuck/satisfied mood), search_my_past recall, the competence prior, cluster stats and narrative consolidation — now sees ~6× the verdict density it did, and sees human judgments at all for the first time.

Three things the fresh-eye rounds changed, and worth knowing. (1) The reason string is now redacted inside _outcome_phrase — the one helper every writer passes through — because the reasons are not the agent's own prose: verifier issues/reasoning quote tool output, and the user-correction path derives its reason from the user's own message. capture_turn had always scrubbed the quoted user_request; the reason went in raw, and this leg amplified that path from ~15% to ~85% of verdicts. Redaction runs before the 120-char clip, since clipping first cuts a secret in half and leaves a fragment no pattern matches. Experience has no failure_reason field, so the summary is the whole surface. (2) The corpus write and the diary write are two separate awaits, so a human label can land in the gap; the leg re-asks the collector's own has_human_label immediately before writing (delegating to its authority rather than restating it, and failing OPEN when the method is absent so a stub cannot silently disable the leg). That narrows the window but does not close it — it is still check-then-act, and the race-proof version needs a source rank on the diary itself. Accepted: the residual is milliseconds wide and the diary is a gauge nothing branches on. (3) update_outcome now rewrites whichever verdict clause the record carries, not only the “no verdict” one — a row captured as failed and later upgraded used to read “…and it didn't land: <reason>.” under outcome="passed", and this leg makes upgrades common. The clause is matched from the RIGHT: the summary quotes the user's request, so a request containing a verdict phrase plants a decoy earlier in the string, and since the swap cuts to the end of the record a leftmost match truncates the row mid-quote. The template puts the quote before the clause, so rightmost matching is correct by construction — verified across the live diary at 1,059 real swaps with zero mangled rows.

Pinned by tests/test_selfhood_late_verdict_backfill.py (37 executed tests, all asserting on the bytes in a real diary file — including end-to-end convergence pins that run the REAL collector and assert the diary equals what the corpus resolved, in both verdict-then-label and label-then-verdict order, and with the trajectory cache evicted so the collector's writer-side guard is the thing actually under test): the accepted-outcome identity in both directions, withheld/failed corpus writes leaving the diary untouched, the shape rule's withheld PASS and the structural-only upgrade it still allows, the origin gate on both legs, the call-time origin snapshot in both directions, the repeat-heals-history path, and non-fatality on a raising diary. Nineteen mutants killed, comment-only control survived — including two the battery first reported as survivors: one had never applied (a collapsed escape in the anchor, now caught by an explicit ANCHOR-MISS check) and one was a real gap in a pin that could not distinguish the two orderings it claimed to test.

The introspect tool (read path)

Counterpart to self_state: a read-only handle the agent reaches for when the user asks it to describe itself, recall what it has been working on, or surface specific past turns. The wake-up prefix already grounds casual self-questions, but a deterministic snapshot is sometimes wanted instead. Actions:

  • summary (default) — renders stats() + the running first-person diary + the most recent N experiences in one block. This is the natural answer to "tell me about yourself".
  • stats — counts (experiences, open questions, unfinished threads), last mood, last-active timestamp, narrative-present flag, and the topic-cluster mix.
  • narrative — just the most recently consolidated diary entry.
  • recent — the last N first-person experiences (limit capped at 25).
  • recall — IDF-weighted, dependency-free search over the autobiographical log (query required).

Reads go through SelfModel.stats(), SelfModel.recall_relevant(), autobio.recent(), and narrative.latest(); nothing is mutated. Disabled selfhood returns a clear "unavailable" message rather than crashing the turn. Source: tools/introspect.py.

Hardening-pass details (2026-05-23)

Diary sanitiser

narrative.sanitise_meta_insights() removes raw tracebacks, abort markers (e.g. [ATTEMPT_ABORTED_THINKING_LOOP]), file-and-line locations, and recognised system banners before the meta_insights payload is spliced into the diary prompt. Without it, the LLM faithfully echoed the noise into the agent's first-person voice — a voice-breaking failure mode visible on the live narrative.md at the time of the audit.

Template-prompt rollup

Repeating system-generated banners are no longer one autobio record per occurrence. _bump_template_rollup() scans the last five records and, if the tail is already a rollup for the same marker, increments its counter, refreshes the tool union, and rewrites the summary as "I worked on N of my recurring <label> in a row." This stops the 53% template-prompt floor observed on the live log from drowning the narrative regeneration in near-duplicates.

Verdict backfill on user corrections

The user-correction promotion path in core/agent.py already updated the trajectory log via collector.update_outcome. It now also calls self_model.record_outcome, so the autobio entry is rewritten from unknown to failed and the prose verdict clause is swapped in place.

Session-boundary marker

SelfModel.mark_session_boot() writes a synthetic Experience(outcome="boot", cluster="meta", summary="Session resumed (last active …)."). The same-minute dedup short-circuit prevents crash-restart loops from flooding the log with boot events.

Mood history

SelfStateThread.set_mood() appends a JSONL line to mood.history.jsonl on top of the latest-slot write to state.json. mood_history(limit=N) returns the tail. The narrative phase can use this to describe arcs ("I shifted from stuck to satisfied after the third attempt") rather than only the latest mood label. Since the 2026-08-20 mood rework, history lines are transitions only — re-confirming the same (label, source) refreshes set_at in place — and each line carries a source field (lines predating the field parse as "self", historically accurate since the tool was the only writer).

PII redaction

autobiographical.redact_pii() is applied at the capture boundary in SelfModel.capture_turn. Both the stored user_first_words prefix AND the verbatim quote of the user request inside the summary template route through the same scrubber, so emails / phone numbers / API keys / credit-card numbers never reach the on-disk diary.

Numeric false positives (2026-06-12). The phone rule now requires phone structure (leading +, parenthesised area code, or internal space/dash separators) — its old core (\d{3}[ -]?\d{4} with everything else optional) matched any bare 7-10 digit integer, so quoted prompts like "backfill the last 1000000 rows" were mangled to [REDACTED_PHONE]. The credit-card rule is now Luhn-gated (_redact_cc_if_luhn): every real PAN still redacts, but bigint ids and other 13-19 digit literals pass through untouched unless they happen to checksum. Both changes are mirrored in distill.redact (the trajectory-corpus redactor, where the same false positive was corrupting SQL destined for the future training corpus, and — via the operator log-stream redaction — rendered LIMIT 1000000 as LIMIT <REDACTED_PHONE> in production logs). Covered by tests/test_redact_numeric_false_positives.py.

IDF cache

AutobiographicalMemory._search_index() caches the (experiences, haystacks, df-table) tuple keyed on the file's (mtime, size). A fresh append on disk auto-invalidates the cache. Cuts the per-query full-file rescan that search_my_past previously paid on every call.

Prefix-utility tracker

The detector detect_referenced_experiences(prefix_text, response_text, experiences) is a pure function: it returns the ids of experiences whose summary shares a non-stopword trigram with the agent's response. Bumping the per-id counter through SelfModel.note_referenced_experiences() persists into reference_counts.json, giving downstream consumers a concrete signal for "this memory shaped the reply" — useful both as a relevance prior for future retrieval and as a falsification anchor for the consciousness probes.

Probe wrapper

scripts/run_selfhood_probes.sh is the cron-friendly entry point: it locates the falsification probes via $SELFHOOD_REPO (defaults to the agent repo), tees both stdout streams into $GHOST_HOME/system/selfhood/probes/probes-YYYYMMDD-HHMMSS.txt, and exits 0 unless a probe is missing. Failing probes are findings, not wrapper errors.

Honest limitations

  • The agent behaves consistent with continuous selfhood. It references its prior turns in the first person, distinguishes my memories from facts about you, recalls specific concrete content across process restarts. That is behavioural evidence of successful narrative continuity, not of a unified inner self.
  • The wake-up prefix can be ignored. Functional testing has observed the model preferring concrete recent experiences over injected open questions even when both are rendered in the prefix. The selfhood module surfaces the past; what the model chooses to engage with is a separate alignment question.
  • Agent-authored state is a trust surface. The self_state tool now lets the agent write its own open questions / mood / unfinished threads (resolving the earlier "no agent-side tool" limitation). The 10-entry caps in SelfStateThread bound runaway growth. For mood specifically, the 2026-08-20 rework closed the self-reinforcing-mood loop: a self-authored label is honoured for a 6 h grace window, then the derived updater (grounded in verdict streaks the model doesn't control) takes over, and the 48 h prefix TTL ages out anything nobody re-confirms. Open questions still lack an equivalent decay pass — the stale-question gardener surfaces them but nothing retires them.
  • Mood: known bounded gaps (2026-08-20 rework, accepted by design). (1) Out-of-band activity surfaces (game moves, feedback API) touch neither last_activity_time nor the post-turn hook — a game-only session can be labelled idle until the next real chat turn. (2) Error/aborted turns and streamed turns whose effective content is empty skip the hook — retirement can lag one turn. (3) A standing stuck/satisfied mood's evidence sentence is frozen as of the last decisive derivation (heartbeats refresh the counts); a later mixed window leaves it standing with those counts. (4) A held idle is never set_at-refreshed while a <7-day decisive streak exists (the tick derives the streak label, which the hold blocks), so during genuine continued absence it can age out at 48 h; and with self-play off the 15–60 min window fires at most twice per AFK stretch, with the same age-out. (5) The acute-hold and retire-not-replace rules protect a fresh acute mood only — once past the 48 h TTL (already dropped/flagged on every surface) an internal turn's decisive streak may replace it directly. All of these fail toward honest absence or an aged-out label, and none can outlive the age display + 48 h TTL.
  • Narrative quality depends on the upstream LLM. The template fallback exists for offline / unreachable-LLM cases but produces prose noticeably less coherent than the LLM-driven path. The fallback now still appends meta-insights, but without the LLM's connective prose.
  • Introspective self-reports remain prompt-shaped. The introspective_consistency probe measures a +0.40 gap between factual and introspective bands — first-person reports about internal state are NOT stable across paraphrases of the same underlying question, even though concrete-content recall IS stable. See the functional test report.
