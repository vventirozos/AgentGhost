Trajectory logging and idle phases

Local-only trajectory logging and the idle-time phases that read it. Trajectory logging is ON by default (opt-out shape) when --no-memory is not set; it feeds the learning loop (failure replay and the regression suite) and introspect. The producer passes that used to sit here — reflection, post-mortems, the complexity router, the PRM, frontier self-play — were removed on 2026-10-11 (§4NM) together with their flags.

Helper scripts

Python entry points under scripts/. The optimizer, bench and arm-report scripts (run_gepa, optimize_*, verify_bench*, leaf_bench, if_bench, experiment_report, the router and foresight backtests) were deleted on 2026-10-11 (§4NM) with the subsystems they measured.

ScriptPurpose
scripts/eval_baseline.py freeze|compareRun the offline eval suite (--suite {default,post_learning}) via a stub runner or HTTP against a running agent. Freeze the result as a baseline or diff a subsequent run. Flags: --runner {stub,http}, --base-url, --api-key, --model, --timeout N (default 300s — template tasks on a local Qwen-scale model commonly run 80–250s).
scripts/ghost_kill_sessions.pyColor curses TUI over the agent's in-flight turns: lists every turn from GET /api/turns (full request id, RUNNING/QUEUED state, age, session, message preview — the log's 8-char tags are prefixes of these ids) with auto-refresh, and cancels the selected one via POST /api/turn/cancel — c cooperative (stops at the next boundary, keeps partial work), K hard-kill with confirm (cancels the asyncio task; the guaranteed release for a turn wedged in a long upstream call). Each turn's session id is joined against GET /api/sessions to show the session title and message count in the table (enrichment only — a sessions-disabled agent just shows raw ids), and a pane under the table shows the selected turn in full: untruncated request id, start time, session title · message count · last activity, whole preview. Colors: RUNNING green / QUEUED yellow / CANCELLING red; the AGE column escalates yellow at 2m and red at 10m (turns are globally serialized — an old running turn is blocking every client). Mono terminals degrade to bold/dim; $NO_COLOR disables color. --list prints once without the TUI (same columns; ANSI color only on a TTY). Auth: non-empty $GHOST_API_KEY, else --key-file (default ~/Data/AI/.ghost_api_key). Stdlib only. Tests: tests/test_ghost_kill_sessions.py.
scripts/build_sandbox_image.shBuild ghost-agent-base:latest from sandbox/Dockerfile — bakes apt deps, Python stack, and Playwright Chromium (with --with-deps) into the image. Runs a Chromium smoke test at the end. One-shot per Ghost version; the runtime sandbox wrapper picks up the freshly-built image on next ensure_running.
scripts/ghostlog.pyThe operator's lens on the agent log. $GHOST_HOME/system/ghost-agent.log is deliberately a COMPLETE archive — every mirror line including DEBUG, so a turn survives a restart and instruments can count events. Right for an archive, wrong for monitoring: measured on a 4000-line window, 1652 lines (41%) were one repeated string (critic compute — Routing verification…) while only 6 carried a verdict — 275 announcements per outcome. This reads INFO+ with consecutive repeats collapsed to ×N, so failures and outcomes stand out. --req <id> reconstructs one request in full, DEBUG included — the "how was this actually processed" view (mode switch, hydration, reasoning turns, monologue, prefill, tool calls, timings) without needing a TUI. Also -f follow, --since N minutes, --all (raw archive), --width (long hydration lines are truncated in the MIDDLE, so both the event and its outcome survive).
scripts/preflight_longrun.pyGate for any run long enough to waste real time or compute. Five preconditions, each traceable to a run that was actually wasted on this project: OBSERVABLE (progress readable while running), BOUNDED (item count PRINTED BY THE TOOL, never derived — a hand-computed denominator of 35 where the tool said 58 made every progress report wrong), RESUMABLE (a kill costs nothing), DISCRIMINATING (a smoke proved the config produces distinguishable output — the ~8h ablation whose two arms resolved to byte-identical flags passed every other check and still measured nothing), MEASURED (ETA from a timed slice, expressed as a RANGE). Any failure blocks. --force records an override with a stated reason, because an unexplained override is the same as no gate. Exit 1 = blocked.
scripts/runstatus.py PROGRESS.jsonReads a long run's own progress file — and does nothing else. No cache counting, no log parsing, no inferring position from side effects; every one of those was tried on a 90-minute bench and every one gave a wrong number. Reports four states, three of which are not a percentage: running (with a rate measured over a trailing window), finished, STALLED (the file stopped moving — do NOT read done as current), and missing (position UNKNOWN, not zero). Exit codes 0/2/3 let a script branch without parsing prose. Writers use eval.runprogress.RunProgress, which writes atomically and reports None for rate and percentage until there is evidence for them.
scripts/frames_fetch.pyThe external scoreboard — everything else here measures this agent against itself. Fetches Google's FRAMES (824 multi-hop Wikipedia questions) from the HF datasets-server anonymously and writes GAIA-shaped JSONL, so gaia_eval.py --tasks-file runs it unchanged. Why not GAIA: it is a gated dataset (measured: HTTP 401 vs FRAMES' 200) and the standing constraint is no keyed APIs and no accounts, ever — and the gate is a licence agreement, so an ungated mirror would breach terms rather than dodge a login. Why not AssistantBench (also open, closer to GAIA in spirit): its tasks need live browsing of arbitrary commercial sites, so under Tor-only egress the score measures Tor reachability, and its ground truth ages as real schedules change. FRAMES ships gold document links, which buys --oracle mode: naming the source articles removes the retrieval confound and measures the multi-hop reasoning actually under test (Wikipedia over Tor verified reachable, HTTP 200 in 3.2s, before this was relied on). --limit samples from the full set with a fixed seed — never a head slice, since the split is ordered. Writes a .provenance.json with a task digest so a run is reproducible. There is no code path that can send a credential, and that is enforced by a test.
scripts/frames_scorer.pyGrades FRAMES. The vendored GAIA scorer was the first choice and the readiness smoke caught it reporting accuracy 0.0 on two answers that were both correct ("5:31" vs "5 minutes and 31 seconds"; "A, B" vs "A and B") — not a bug in it, but it assumes GAIA's mandated answer format on both sides, and FRAMES ground truth is natural language. FRAMES' own paper grades with an LLM judge, so exact match was never the protocol. Two tiers: a deterministic strict_match pre-pass, then a judge on the residual only. Exactly one normalisation beyond GAIA's is kept — treating " and " as the list separator — because rules invented by staring at your own agent's failures produce a scorer tuned to raise your own score. The judge is the critic node (Gemma 4 E4B), a different model family from the answerer (Qwen3.8-27B; Qwen3.6-35B when this was built), so this is not self-grading; it is told to answer NO when uncertain, and unparseable or errored replies count as NO, so the number errs downward. Both no-think switches are load-bearing: without them the node returns empty content with finish_reason='length' and every answer grades NO — which does not fail loudly, it silently reads as the agent regressing. Validated 16/16 against hand labels (0 FP / 0 FN) with the switches, versus 0.69 agreement without. rescore_details() re-grades a finished run without re-running the agent, because the answers are the expensive artifact and the grading has already been wrong once.
scripts/verify_core_math.pyMechanized proof harness for the computational core: --bio-time-scale arithmetic, egress host classification, F8 episodic eviction ordering, the ablation delta metric, the anytime-valid confidence sequence, and a reconciliation pass against the live store. Every check is tagged with its rigour level — EXHAUSTIVE (the finite input space is enumerated, e.g. all 2390 (constant, scale) pairs), DIFFERENTIAL (a second independently-written implementation must agree, e.g. is_allowed_host over 8033 hosts), or PROPERTY (an algebraic invariant over randomized inputs). Exits non-zero on any failure; with no live store the last section SKIPs loudly and says so in the summary. Read-only — it writes only to temp dirs. Prints 26/26 against the live store, 21/21 offline.

The verdict instrument gets the heaviest treatment. asymp_cs_radius — the asymptotic anytime-valid confidence sequence of Waudby-Smith & Ramdas — decides every experiment verdict the agent reports, so a wrong formula there would silently invalidate every A/B conclusion while still printing plausible-looking intervals. It is checked nine ways: the variance estimator against an accumulator-free re-implementation; the radius against a different algebraic factoring of the same expression (which is what catches a transcription or precedence slip, where re-typing the formula would not); an enumerated 11-case degenerate-input table (n<2, NaN, ±inf, α outside (0,1), ρ≤0) that must all refuse rather than return a zero-width interval; monotonicity in α and contraction in n; a seeded Monte-Carlo coverage test under continuous monitoring (240 streams, n=30→80, measured 2.5% miscoverage against a nominal 5%, independently reproducing the figure the source docstring claims); a negative control proving that coverage test can fail (a quarter-width interval miscovers 89.2%); a wiring check that the n≥30 verdict gate actually gates; and the full 12-case verdict decision table, which may name a winner only when the interval excludes zero.

On trusting this harness. A verifier that only ever passes proves nothing, so it is itself mutation-tested: fifteen deliberate defects were injected into production code one at a time — seven in the core sections (IPv6 tunnel prefixes unblocked, the scale-guard floor zeroed, _bio_cooldown de-synced from _bio_scaled, F8 eviction reverted to pure age, the F8 credit writer disabled, the delta metric reverted to absolute counts, resolve_egress_proxy made fail-open) and eight in the confidence sequence (variance denominator, dropped prior, dropped inner square root, n²→n, inverted α, removed NaN guard, _MIN_VERDICT_N 30→2, strict zero-straddle) — and all fifteen must be caught. Two of the first seven were MISSED by earlier drafts and the harness was hardened until they weren't: one check derived its expected value from the constant under test (a tautology), and one proved an outcome that two different fields could each produce on their own. tests/test_core_math_verifier.py keeps the harness from being quietly gutted — it fails if the check count drops, if a rigour level vanishes, or if a covered symbol is renamed away.

Non-blocking verifier gate

The self-evaluation verifier normally runs after the answer is assembled and the turn blocks on its verdict. When --critic-nodes is set the verdict runs on that pool (a slower off-host model), so the gate goes non-blocking: the verdict is spawned as a background task and the response ships without waiting on it. A high-confidence REFUTED that lands late can no longer amend the (already-sent) response, but still scrubs any lesson that turn produced, so the next query can't retrieve a poisoned lesson.

Env varEffect
GHOST_CRITIC_GATE_TIMEOUTSeconds the gate waits inline for the verdict before releasing the response. 0 = pure async (never wait); a positive value gates inline up to that budget then falls through to async; unset defaults to 0 when --critic-nodes is configured and to "block forever" (legacy behaviour) when it is not.
GHOST_CRITIC_NO_THINKDefault 1; the live launcher sets 0. The verdict is a tiny JSON object, so the critic call disables the model's <think> prelude (the dominant latency on an off-host judge model — observed ~37s of pure thinking) via the /no_think soft-switch + enable_thinking=False hard-switch. Set 0 to restore a full reasoning verdict (slower, possibly more accurate on stylistic constraint checks).
GHOST_CRITIC_MAX_TOKENSDefault 512. Token cap for the critic verdict. Small because there is no <think> prelude to budget for; raise it only if you re-enable thinking.
GHOST_CRITIC_CALL_TIMEOUTDefault 120. Hard wall-clock cap (seconds) on a single critic-pool call; on timeout the verdict falls through to the worker/direct fallback instead of blocking the turn.
GHOST_CRITIC_ASYNCDefault 0 (off); the live launcher sets 1. When 1, the verifier never sits on the critical path: the in-loop repair-before-ship is skipped and the verdict runs purely after the response ships. A high-confidence REFUTED then scrubs the turn's lessons and queues a correction surfaced at the top of the next turn of the same conversation ("⚠️ Correction to my previous answer…"). Trades before-ship repair of the rare wrong answer for not paying the slow off-host verdict latency (~58s) on every turn. With this on, keep the accurate thinking verdict (GHOST_CRITIC_NO_THINK=0) — its latency no longer hurts. Conversation scoping (fix): the agent is a process-wide singleton, so a naive queue leaked one conversation's correction into the next turn of an unrelated conversation (or a different user). Each queued correction is now tagged with a conversation fingerprint (a hash of the conversation's first user message, stable across that conversation's turns) and a timestamp; a correction surfaces only when the incoming turn shares that fingerprint, is held for its own conversation otherwise, dropped after a TTL (_CORRECTION_TTL, 900 s) if that conversation never returns, and the queue is capped (_CORRECTION_MAX, 3, newest win) so a busy multi-conversation process can't accumulate a runaway banner chain. Covered by tests/test_critic_async.py.
GHOST_PIN_TOOL_SCHEMASDefault 0 (off); the live launcher sets 1. When 1, pins the byte-stable per-turn block (tool schemas + persona + playbook + hydrated memory + continuity) to the first user message — a fixed position — so the upstream KV-cache reuses it across the turns of one request instead of re-prefilling the ~23k-char block every turn (~15s). Only the volatile dynamic_state rides the moving last message. Native tool defs still travel in the payload tools field, so tool-calling is unaffected. Opt-in / reversible A/B for the per-turn prefill latency.
