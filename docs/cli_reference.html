Stage-1 self-improvement pipeline

Local-only trajectory logging, self-critique reflection, and complexity-routed dispatch. All three default to ON (opt-out shape) when --no-memory is not set; the pipeline is fully local — no external teacher, no hosted embedder. See self-improvement pipeline for the architecture.

--no-trajectoriesflagoffDisable the JSONL trajectory log at $GHOST_HOME/system/trajectories/. Also implicitly disables reflection (which reads from the log).
--no-reflectionflagoffDisable the reflection biological phase (2.5) even if trajectory logging is on. Trajectories still write to disk but the Reflector never fires.
--no-dreamflagoffDisable only the Deep REM Dream biological phase (2, 10–60 min idle: memory consolidation / heuristic harvest). Reflection and self-play still fire. This is the dream-off arm of the Track-B earn-your-keep idle-loop leave-one-out (ABLATION); pruned automatically if dreaming is measured not to earn its compute. See core / dream.
--no-self-playflagoffDisable only the Synthetic Self-Play biological phase (3, >60 min idle) — both fresh self-play and the counterfactual-replay slot. Dream and reflection still fire. This is the self-play-off arm of the Track-B idle-loop LOO. Distinct from --no-frontier-selfplay, which only changes how self-play picks a cluster, not whether it runs at all.
--router-modelpathunsetPath to a persisted ComplexityClassifier JSON. When unset, the dispatcher acts as a pass-through that always escalates to the full swarm pool list — never less capable, just never cheaper. Train a classifier via trajectories collected with --no-trajectories off.
--router-confidence-thresholdfloat0.3Minimum router confidence required to route a request to the cheap path. Below this, the dispatcher escalates to the full swarm (fail-safe).
--prm-modelpathunsetPath to a persisted PRM (Process Reward Model) JSON checkpoint. When set, the scorer loads on startup and plugs into the MCTS reasoner so plan candidates are scored in microseconds instead of paying a worker-LLM simulation per candidate — when that reasoner actually runs. The MCTS turn-start hint is module-gated off (_MCTS_TURNSTART_ENABLED) and also needs --deep-reason, so on a default box the checkpoint loads, logs success, and is consulted by nothing; boot logs a PRM Unread WARNING in that case (§4BN). Unset → no-op scorer returning 0.5 for every candidate (call sites stay branch-free). See PRM algorithms doc.
--prm-train-cooldownint (seconds)10800Cooldown for the idle-time PRM retrain pass (biological phase 2.7). Default 3 hours. Not gated on --prm-model (§4BN corrected this): the retrain phase skips unless a value-reading consumer is live — .score() (needs BOTH the _MCTS_TURNSTART_ENABLED module gate and --deep-reason) or .uncertainty() (--frontier-selfplay and trajectory logging). With neither live the phase is dormant and this cooldown is moot.
--prm-online-updateflagoffApply a guarded online PRM gradient step when a turn is promoted to FAILED by a user correction (closes the gap until the next idle retrain). The step is applied to a clone and committed only if it doesn't worsen BCE on a holdout of recent trajectories. Requires a trained PRM: it is a producer that refines only and never bootstraps a model (returns False when none is loaded). An idle-trained checkpoint is not a reliable way to get one, because the idle retrain itself skips unless a value-reading consumer is live — so on a box with neither, the flag is inert in THREE independent ways (no model; no reader; or trajectory logging off, which stops the update from ever being attempted) and boot logs a WARNING (§4BN). See PRM — online updates. A FOURTH limitation is architectural rather than config-dependent, so boot cannot detect it: the online step is dispatched only from an inline user correction, never from an /api/feedback label — the feedback path itself warns when that happens (§4BN R25/R26).
--calib-refit-cooldownint (seconds)3600Cooldown for the idle-time confidence-calibration refit (biological phase 2.7c). Re-fits τ + entropy/competence weights + uncertainty penalty λ on the logged (confidence, outcome) pairs, minimising Brier, and hot-swaps the result into the live CompositeConfidence. Only active under --enable-metacog. See core / calibration.
--frontier-selfplay / --no-frontier-selfplayflagoff (flipped 2026-07-09 — #27b: tied uniform seeding on self-play lesson yield in BOTH instrumented ablations, B3 2v2 / B4 equal in all 4 repeats; parsimony wins, machinery stays opt-in)Biological-watchdog phase-3 self-play picks the next cluster by (PRM uncertainty × trajectory rarity) instead of only the brittle-pool score. Surfaces clusters the agent has barely tried — which the outcomes-only signal misses, because "never tried" looks the same as "solved instantly". Degrades gracefully when the PRM is untrained or trajectory store is empty (strict isinstance gate; transparent fallback to pick_seed). See core / frontier_selection.
--frontier-uniform-sample-probfloat0.2Probability per self-play tick that frontier-aware selection is bypassed in favour of legacy pick_seed — sanity floor so a systematically-wrong PRM can't lock self-play onto one cluster forever (the PRM is itself learned from trajectories self-play produces).
--postmortemflagoffBiological-watchdog phase 2.5c. Where reflection (2.5) turns one failed turn into a behavioural lesson, the post-mortem engine reads the whole tool-call transcript of the worst recent FAILED runs and files a durable, classified defect report — behavioural (routed into SkillMemory like a reflection lesson), configuration (a proposed flag/threshold change), or code_defect (a broken tool / control loop). It's the autonomous form of the manual "evaluate the last N bad runs" triage. Selection is LLM-free and grounded in a structural signature (repeated-identical-error / two-tool oscillation / same-target read-loop counts), so no model call is spent on a healthy run and the operator sees concrete evidence. Read the queue with the postmortem tool. Nothing is ever auto-applied. Requires the trajectory log. See self-improvement pipeline.
--postmortem-cooldownint (seconds)10800Cooldown for the idle-time post-mortem pass (phase 2.5c). Default 3 hours — heavier than reflection (whole transcripts, optional patch calls). Only active under --postmortem.
--postmortem-min-severityfloat0.4Minimum structural severity (0..1) a failed run must score before it earns a post-mortem LLM call. Lower = more runs analysed (and more model calls). Only active under --postmortem.
--postmortem-propose-patchflagoffFor code_defect findings, also ask the coding model for a reproducing test + unified diff and attach them to the defect report as a proposal (stored for human review via the postmortem tool — never applied automatically). Adds one coding-model call per code-defect finding. Requires --postmortem.

Helper scripts

Python entry points under scripts/:

ScriptPurpose
scripts/eval_baseline.py freeze|compareRun the offline eval suite (--suite {default,post_learning}) via a stub runner or HTTP against a running agent. Freeze the result as a baseline or diff a subsequent run. Flags: --runner {stub,http}, --base-url, --api-key, --model, --timeout N (default 300s — template tasks on a local Qwen-scale model commonly run 80–250s).
scripts/run_gepa.py --signature <name>Run DSPy / GEPA prompt optimisation on one of the allow-listed signatures (planning.decompose, tool_selection.pick, reflection.critique). Reads trajectories from $GHOST_HOME/system/trajectories, uses Ghost's own upstream as the optimiser LM (no external teacher), writes the tuned instruction JSON to $GHOST_HOME/system/optim/ (staged + os.replace, with a .prev backup taken first and the promotion aborted if that backup fails). Ship rule: the margin over examples that reached a verdict in BOTH arms AND one-sided McNemar p <= ab_eval.SHIP_ALPHA; a call that timed out or raised is excluded rather than scored as a failure, and a run whose surviving pairs fall below what the pre-flight required cannot ship — --allow-insignificant-ship waives significance, never evidence, and is recorded in the artifact. §4CW seed arm: the candidate is also compared against the HAND-WRITTEN seed, and a candidate that beats the live artifact while losing to the seed is refused (the ratchet check); that arm gets the same exclusion, reporting and power treatment as the main one, so an outage can neither suppress nor manufacture the veto. --allow-seed-loss overrides it and is recorded. Flags: --ab-gate/--no-ab-gate, --ab-min-delta, --allow-insignificant-ship, --allow-seed-loss, --min-promotion-age-days, --private-pct, --max-examples, --max-iterations, --mined-bank. Exit codes (§4DA round 16, aligned with the sibling gate): 0 promoted, 1 the gate rejected the candidate, 2 could not measure — the five refusals that measure nothing (unusable margin, empty holdout, tier below the combined need, the re-draw guard, a zeroed mined bank) and the mid-run evidence-bar/seed-arm aborts, all of which used to return 1 — and 3 the optimizer returned the incumbent verbatim (no candidate; the A/B is skipped rather than measuring a guaranteed zero).
scripts/optimize_tool_descriptions.py --fixtures <pool>GEPA optimisation of tool descriptions (§4F Phase 2b), the second of three ship gates. Metric = tool-choice fidelity: replay each mined decision from a turn that passed, with candidate descriptions swapped into the tools array, and score 1.0 iff the model picks what production picked. Ships per-tool artifacts (tool_description.<name>.json) read by tools/registry.py, which replaces the hand-written description — deploy = agent restart. Ship rule (§4DA): the margin over usable pairs AND one-sided McNemar p <= ab_eval.SHIP_ALPHA; a pair whose replay failed to reach the model in either arm is excluded from both the statistic and the margin, and a run whose surviving pairs fall below what the pre-flight required to start cannot ship at all. --allow-insignificant-ship waives significance only (never the margin, the validators, or the power floor) and is recorded in the artifact. Two pre-flights, stated as one requirement: the private tier must resolve --min-delta and reach the significance floor. Pre-flight counts REPLAYABLE rows — a fixture whose recorded payload is gone replays in neither arm and can never be a discordant pair, so probing costs under a second on today's pool (measured 1.01s for 13 private fixtures; 19.8s if every one of 192 rows were probed) rather than a whole optimizer run that refuses at the end. Whatever the cause, a run whose surviving pairs fall below the number the pre-flight demanded cannot ship — but the refusal names the cause, because a transport outage is re-runnable and a corpus gap that opened mid-run means the recordings moved and needs restoring first. Supply and tier are REAL-only — bench fixtures may teach on the public side, never grade, and never be the reason a run starts. §4CW seed veto (§4DA round 16): this gate SEEDS FROM THE LIVE ARTIFACT when one is present and valid, so run N’s two arms are artifact-(N−1) and artifact-N and the hand-written description is in neither — each run only has to beat the previous winner. When any component was seeded that way, the candidate is also scored against the HAND-WRITTEN text on the same private tier, and a candidate that beats the incumbent while measurably losing to the baseline is refused. That arm gets the same exclusion and power treatment as the main one, so an outage can neither suppress nor manufacture the veto (an underpowered seed arm refuses the run). --allow-seed-loss overrides it and is recorded, along with the whole seed arm, under gate.seed_arm. It costs one extra private-tier evaluation, and only on a re-promotion whose main gate already passed. Re-draw guard (§4DA): a component promoted less than --min-promotion-age-days ago (default 7) refuses the run, so a second sweep cannot overwrite an artifact before the live check has any turns to judge it by; the guard is scoped to the components THIS run could touch, and --smoke (which promotes nothing) is exempt. Exit codes: 0 promoted, 1 the gate rejected the candidate, 2 refused to run / aborted, 3 the optimizer returned the seed verbatim (no candidate — a wasted run, not a verdict about the incumbent). Artifacts record the set the A/B judged them with (co_promoted, or co_candidates on a rejection record) and a gate_scope that says whether the numbers are that component’s own contribution (one component changed) or the set’s. Flags: --fixtures, --recordings, --upstream-url, --min-delta (default 0.02; must be ≥1e-6 and <1), --min-fixtures (REAL positives, not rows), --min-promotion-age-days, --allow-insignificant-ship, --allow-seed-loss, --force-supply (requires --smoke), --smoke, --components, --max-iterations, --confusion-out, --run-dir, --timeout (per-replay deadline, default 360s — the same as run_gepa.py and recheck_gepa_incumbent.py, so a replay one instrument calls a transport failure is not one the other scores normally). The live pool exists only when the miner's own gates pass; otherwise point --fixtures at the parked <pool>.notready.
scripts/mine_tool_fixtures.pyMine tool-choice fixtures out of the LLM recording day-files for the runner above. Writes the live pool only when its gates pass; otherwise parks the mine at <out>.notready and leaves the live artifact untouched (--force-write overrides). Its Labels: and Private REAL positives: lines are the operator's “is it time yet?” report and now state the runner's combined refusal — resolution and the significance floor from ab_eval.significance_floor(), one derivation shared by both runners and this miner. Its projection is real-over-real: bench-inflating the numerator over a real-only denominator over-stated the remaining work 3.4×.
scripts/gepa_live_check.py --signature <name>§4CZ — judge a live GEPA artifact by production turns, reading the optim_artifacts stamp optim/loader.py writes on every attributed trajectory. Refuses to conclude on un-randomized data: an artifact deployed to everything at once makes before/after confounded, so only turns the experiment registry split into control/treatment support a causal claim; anything else reports CONFOUNDED and does nothing. Fisher's exact (the live arms are different requests — unpaired — unlike the offline gate's matched replays). The comparison is scoped to the artifact that is LIVE: both arms carry the sha of the artifact they were served or withheld, so turns from an earlier promotion are excluded from BOTH rather than pooled into one (scoping only treatment made it a time window against a control arm of all history, which turned a KEEP into a REVERT). If the artifact exists but no sha can be derived from it, the script refuses rather than falling back to the pooled arm. --revert acts only on a REVERT verdict, renames the artifact to .retired-live-<UTC>, and prints the restart the rename needs to take effect. What retirement means depends on the read site and the message now says which: the planner signatures prepend (retiring removes a prefix), tool_description.* replaces (retiring restores the hand-written baseline). Exit codes (§4DA post-redesign; previously every state returned 0): 0 KEEP — the artifact still earns its place; 1 REVERT — reported, or retired when --revert was given; 2 could not measure — INSUFFICIENT, CONFOUNDED, a missing corpus, an unreadable artifact, or no artifact on disk at all (a pooled-history verdict about nothing live is not actionable in either direction); 3 a scoped REVERT whose artifact vanished between measurement and the rename (two runs racing).
scripts/recheck_gepa_incumbent.py --signature <name>Re-score a promoted artifact against its own baseline on today's corpus — the promoted-artifact invalidation rule ("re-score the incumbent when the metric or gate changes") made executable. Prints the original gate block: n, both pass rates, delta and bar, McNemar p over the discordant pairs, and a warning when that promotion used --allow-insignificant-ship. Both runners stamp that block under the same key names, and an ARTIFACT-ONLY signature (tool_description.*, which has no signature object and no trainset) now reports its gate record and says plainly that there is nothing to re-score against, instead of dying with “unknown signature” before the file is opened. In the artifact, delta and the two pass rates are the numbers the gate DECIDED on (over pairs that reached a verdict in both arms); raw_delta is the all-rows margin. The all-rows pass rates are recorded too — as raw_incumbent_pass_rate/raw_candidate_pass_rate in run_gepa.py’s block, and as the pre-existing top-level private_incumbent/private_candidate for tool_description.*, whose names already have external readers. They differ exactly when a replay failed to reach the model, which is when a promotion most needs re-examining. Exit codes: 0 the incumbent still earns its place, 1 it does not, 2 could not measure, 3 reported but not re-scorable (artifact-only families). A retirement needs the same evidence a promotion does (§4DA post-redesign): a measured loss must reach McNemar p <= SHIP_ALPHA, and the “no longer clears its own bar” verdict must come from a tier able to RESOLVE that bar (max(significance_floor, ceil(1/margin)) surviving pairs) — otherwise exit 2, because with a thin tier the sign of the delta is noise and used to decide which code a wrapper saw. --min-delta defaults to the artifact’s own recorded bar, and BOTH sources are validated against 1e-6 ≤ x < 1 (a recorded junk bar used to make a losing incumbent exit 0).
scripts/experiment_report.pyRead the live randomized-arm results off the trajectory corpus (core / experiments) — per-arm counts, stamp coverage, and anytime-valid intervals for failure rate / turn depth / latency, in an all-traffic block and a triggered-only block. The agent surfaces the same thing via introspect action='experiments'; this is the operator/headless entry point and the only one that can point at an arbitrary corpus. Flags: --trajectories, --day YYYY-MM-DD, --alpha, --json. Read-only.
scripts/tool_ontology_report.pyIs the toolbox carved right, or just badly labelled? (tool ontology) Mines recurring consecutive tool sequences from the trajectory corpus (macro-tool candidates, ranked by the loop steps a macro would actually remove) and — given a replay dump from optimize_tool_descriptions.py --confusion-out — classifies confusion pairs into one-way (a description fix) vs two-way (a boundary question, reported never adjudicated) vs no-tool stalls. Flags: --trajectories, --replays, --min-support, --min-pair, --all-kinds, --top, --json. Read-only; exits 2 on a missing corpus rather than rendering a conclusion.
scripts/router_confidence_backtest.py§4I Phase 2 — does the complexity router's turn-0 confidence actually predict failure? Buckets stamped turns by confidence and reports each bucket's real failure rate with an anytime-valid interval, requiring the best and worst buckets' intervals to be DISJOINT before calling it discriminating (a bare spread threshold gave ~88% false positives on flat ground truth). Exits 0 = discriminates, 1 = flat or thin, 2 = no corpus. A FLAT result stops §4I at Phase 2 by design. Flags: --trajectories, --min-per-bucket, --json. Read-only.
scripts/ghost_kill_sessions.pyColor curses TUI over the agent's in-flight turns: lists every turn from GET /api/turns (full request id, RUNNING/QUEUED state, age, session, message preview — the log's 8-char tags are prefixes of these ids) with auto-refresh, and cancels the selected one via POST /api/turn/cancel — c cooperative (stops at the next boundary, keeps partial work), K hard-kill with confirm (cancels the asyncio task; the guaranteed release for a turn wedged in a long upstream call). Each turn's session id is joined against GET /api/sessions to show the session title and message count in the table (enrichment only — a sessions-disabled agent just shows raw ids), and a pane under the table shows the selected turn in full: untruncated request id, start time, session title · message count · last activity, whole preview. Colors: RUNNING green / QUEUED yellow / CANCELLING red; the AGE column escalates yellow at 2m and red at 10m (turns are globally serialized — an old running turn is blocking every client). Mono terminals degrade to bold/dim; $NO_COLOR disables color. --list prints once without the TUI (same columns; ANSI color only on a TTY). Auth: non-empty $GHOST_API_KEY, else --key-file (default ~/Data/AI/.ghost_api_key). Stdlib only. Tests: tests/test_ghost_kill_sessions.py.

scripts/ghostlog.pyThe operator's lens on the agent log. $GHOST_HOME/system/ghost-agent.log is deliberately a COMPLETE archive — every mirror line including DEBUG, so a turn survives a restart and instruments can count events. Right for an archive, wrong for monitoring: measured on a 4000-line window, 1652 lines (41%) were one repeated string (critic compute — Routing verification…) while only 6 carried a verdict — 275 announcements per outcome. This reads INFO+ with consecutive repeats collapsed to ×N, so failures and outcomes stand out. --req <id> reconstructs one request in full, DEBUG included — the "how was this actually processed" view (mode switch, hydration, reasoning turns, monologue, prefill, tool calls, timings) without needing a TUI. Also -f follow, --since N minutes, --all (raw archive), --width (long hydration lines are truncated in the MIDDLE, so both the event and its outcome survive).
scripts/preflight_longrun.pyGate for any run long enough to waste real time or compute. Five preconditions, each traceable to a run that was actually wasted on this project: OBSERVABLE (progress readable while running), BOUNDED (item count PRINTED BY THE TOOL, never derived — a hand-computed denominator of 35 where the tool said 58 made every progress report wrong), RESUMABLE (a kill costs nothing), DISCRIMINATING (a smoke proved the config produces distinguishable output — the ~8h ablation whose two arms resolved to byte-identical flags passed every other check and still measured nothing), MEASURED (ETA from a timed slice, expressed as a RANGE). Any failure blocks. --force records an override with a stated reason, because an unexplained override is the same as no gate. Exit 1 = blocked.
scripts/runstatus.py PROGRESS.jsonReads a long run's own progress file — and does nothing else. No cache counting, no log parsing, no inferring position from side effects; every one of those was tried on a 90-minute bench and every one gave a wrong number. Reports four states, three of which are not a percentage: running (with a rate measured over a trailing window), finished, STALLED (the file stopped moving — do NOT read done as current), and missing (position UNKNOWN, not zero). Exit codes 0/2/3 let a script branch without parsing prose. Writers use eval.runprogress.RunProgress, which writes atomically and reports None for rate and percentage until there is evidence for them.
scripts/verify_bench_status.pyTier-0 staleness oracle for the verifier bench: is the recorded number still valid? Compares the current tree against the baseline's provenance — verifier code digest, bench code digest, prompt templates, case pool, fault library, discipline flags, judge identity, arm and route leg — and names each drifted component with the cheapest action that restores validity (replay vs full live re-bench). Costs nothing and calls no model. Reports three states: a field absent on either side is uncomparable, never drift — including the unrecorded sentinel, which bench_provenance writes into escalation.arm when no arm block was supplied. That sentinel is a string, so it used to slide past the is-None guard and score as a known, different value, yielding a false STALE — full live re-bench required (measured 2026-08-10, and acted on: the same baseline replayed clean at 1595 hits / 3 misses moments later). It bites from both directions, since every pre-2026-08-04 baseline carries it on disk. A genuinely different labelled arm is still drift — silencing the sentinel must not silence the field. Also prints the baseline's honest 95% interval and flags smallest_resolvable_delta as quantization rather than power. Pass the same pool/topology flags you would pass to verify_bench.py. Exit 0 = valid, 1 = stale, 2 = no baseline. See core / verifier.
scripts/verify_bench.py --cache-mode …Response cache for the verifier bench, content-addressed on everything the endpoint sees. off = fresh live run (the honest "number today"); write = live but record; read = replay hits and live-call misses (incremental — after a prompt edit only genuinely-changed prompts cost anything); strict = replay only, a miss is an error, which proves a delta is attributable to code rather than to the model having a different day. Measured: 4m27s live → 3.0s replayed, bit-identical. A replayed report is labelled code-vs-frozen-judge in provenance.cache.measures and must not be quoted as current quality. Strict misses exit 3 and dump the missing requests. --cache-dir is anchored to $GHOST_HOME/system/eval/verify_bench_cache, never to the CWD. It was previously the bare relative name, so running the bench from the repo root — the normal way — silently minted an empty cache there and missed on every lookup while the real 2,389-entry cache sat untouched; an empty cache reports 0 hits, which is indistinguishable from the 0 hits of a legitimately invalidated one (measured 2026-08-10: cost an hour and a published wrong conclusion that a full live re-bench was unavoidable, when the same run replayed in seconds once pointed correctly). read and strict now refuse to create a missing cache directory — a replay mode replays a cache, it does not mint one — while an existing-but-empty directory is still allowed, because missing (wrong path) and empty (nothing recorded yet) are different failures. The startup line prints the resolved absolute path and the entry count, and shouts when a replay mode finds zero entries; provenance.cache.entries records the count so a past run's 0 hits can be explained after the fact. --logit-expect on|off|inherit (§4BF flip i) pins GHOST_VERIFY_LOGIT_EXPECT for the run with the TWO_STAGE save/set/restore discipline and re-stamps provenance with the pinned value; probe payloads always miss the cache (new shape), so a probe-armed replay runs judge calls from cache and probes live.
scripts/verify_bench_compare.py OLD NEWPAIRED comparison of two verifier bench runs. The absolute balanced score carries a ±0.05 95% half-width at this bench's size, so comparing two runs as independent proportions can only resolve changes larger than ~0.1 — bigger than almost any real improvement. Both runs score the same cases under the same faults, so the trials pair and McNemar's exact test looks only at the trials that CHANGED; concordant trials carry no information about a difference and are correctly ignored. Exact two-sided binomial, not chi-square, which is unreliable at the small discordant counts this bench produces. It refuses to compare runs whose provenance says they measured different systems — the 2026-08-04 defect made mechanical — unless you name the intended difference with --expect-differs <component>. Withholds a "balanced" figure when a class is empty, and reports too-few-changes as a power limit rather than as "no effect". Exit 2 = refused.
scripts/frames_fetch.pyThe external scoreboard — everything else here measures this agent against itself. Fetches Google's FRAMES (824 multi-hop Wikipedia questions) from the HF datasets-server anonymously and writes GAIA-shaped JSONL, so gaia_eval.py --tasks-file runs it unchanged. Why not GAIA: it is a gated dataset (measured: HTTP 401 vs FRAMES' 200) and the standing constraint is no keyed APIs and no accounts, ever — and the gate is a licence agreement, so an ungated mirror would breach terms rather than dodge a login. Why not AssistantBench (also open, closer to GAIA in spirit): its tasks need live browsing of arbitrary commercial sites, so under Tor-only egress the score measures Tor reachability, and its ground truth ages as real schedules change. FRAMES ships gold document links, which buys --oracle mode: naming the source articles removes the retrieval confound and measures the multi-hop reasoning actually under test (Wikipedia over Tor verified reachable, HTTP 200 in 3.2s, before this was relied on). --limit samples from the full set with a fixed seed — never a head slice, since the split is ordered. Writes a .provenance.json with a task digest so a run is reproducible. There is no code path that can send a credential, and that is enforced by a test.
scripts/frames_scorer.pyGrades FRAMES. The vendored GAIA scorer was the first choice and the readiness smoke caught it reporting accuracy 0.0 on two answers that were both correct ("5:31" vs "5 minutes and 31 seconds"; "A, B" vs "A and B") — not a bug in it, but it assumes GAIA's mandated answer format on both sides, and FRAMES ground truth is natural language. FRAMES' own paper grades with an LLM judge, so exact match was never the protocol. Two tiers: a deterministic strict_match pre-pass, then a judge on the residual only. Exactly one normalisation beyond GAIA's is kept — treating " and " as the list separator — because rules invented by staring at your own agent's failures produce a scorer tuned to raise your own score. The judge is the critic node (Gemma 4 E4B), a different model family from the answerer (Qwen3.6-35B), so this is not self-grading; it is told to answer NO when uncertain, and unparseable or errored replies count as NO, so the number errs downward. Both no-think switches are load-bearing: without them the node returns empty content with finish_reason='length' and every answer grades NO — which does not fail loudly, it silently reads as the agent regressing. Validated 16/16 against hand labels (0 FP / 0 FN) with the switches, versus 0.69 agreement without. rescore_details() re-grades a finished run without re-running the agent, because the answers are the expensive artifact and the grading has already been wrong once.
scripts/verify_core_math.pyMechanized proof harness for the computational core: --bio-time-scale arithmetic, egress host classification, F8 episodic eviction ordering, the ablation delta metric, the anytime-valid confidence sequence, and a reconciliation pass against the live store. Every check is tagged with its rigour level — EXHAUSTIVE (the finite input space is enumerated, e.g. all 2390 (constant, scale) pairs), DIFFERENTIAL (a second independently-written implementation must agree, e.g. is_allowed_host over 8033 hosts), or PROPERTY (an algebraic invariant over randomized inputs). Exits non-zero on any failure; with no live store the last section SKIPs loudly and says so in the summary. Read-only — it writes only to temp dirs. Prints 26/26 against the live store, 21/21 offline.

The verdict instrument gets the heaviest treatment. asymp_cs_radius — the asymptotic anytime-valid confidence sequence of Waudby-Smith & Ramdas — decides every experiment verdict the agent reports, so a wrong formula there would silently invalidate every A/B conclusion while still printing plausible-looking intervals. It is checked nine ways: the variance estimator against an accumulator-free re-implementation; the radius against a different algebraic factoring of the same expression (which is what catches a transcription or precedence slip, where re-typing the formula would not); an enumerated 11-case degenerate-input table (n<2, NaN, ±inf, α outside (0,1), ρ≤0) that must all refuse rather than return a zero-width interval; monotonicity in α and contraction in n; a seeded Monte-Carlo coverage test under continuous monitoring (240 streams, n=30→80, measured 2.5% miscoverage against a nominal 5%, independently reproducing the figure the source docstring claims); a negative control proving that coverage test can fail (a quarter-width interval miscovers 89.2%); a wiring check that the n≥30 verdict gate actually gates; and the full 12-case verdict decision table, which may name a winner only when the interval excludes zero.

On trusting this harness. A verifier that only ever passes proves nothing, so it is itself mutation-tested: fifteen deliberate defects were injected into production code one at a time — seven in the core sections (IPv6 tunnel prefixes unblocked, the scale-guard floor zeroed, _bio_cooldown de-synced from _bio_scaled, F8 eviction reverted to pure age, the F8 credit writer disabled, the delta metric reverted to absolute counts, resolve_egress_proxy made fail-open) and eight in the confidence sequence (variance denominator, dropped prior, dropped inner square root, n²→n, inverted α, removed NaN guard, _MIN_VERDICT_N 30→2, strict zero-straddle) — and all fifteen must be caught. Two of the first seven were MISSED by earlier drafts and the harness was hardened until they weren't: one check derived its expected value from the constant under test (a tautology), and one proved an outcome that two different fields could each produce on their own. tests/test_core_math_verifier.py keeps the harness from being quietly gutted — it fails if the check count drops, if a rigour level vanishes, or if a covered symbol is renamed away.

Non-blocking verifier gate

The self-evaluation verifier normally runs after the answer is assembled and the turn blocks on its verdict. When --critic-nodes is set the verdict runs on that pool (a slower off-host model), so the gate goes non-blocking: the verdict is spawned as a background task and the response ships without waiting on it. A high-confidence REFUTED that lands late can no longer amend the (already-sent) response, but still scrubs any lesson that turn produced, so the next query can't retrieve a poisoned lesson.

Env varEffect
GHOST_CRITIC_GATE_TIMEOUTSeconds the gate waits inline for the verdict before releasing the response. 0 = pure async (never wait); a positive value gates inline up to that budget then falls through to async; unset defaults to 0 when --critic-nodes is configured and to "block forever" (legacy behaviour) when it is not.
GHOST_CRITIC_NO_THINKDefault 1. The verdict is a tiny JSON object, so the critic call disables the model's <think> prelude (the dominant latency on an off-host judge model — observed ~37s of pure thinking) via the /no_think soft-switch + enable_thinking=False hard-switch. Set 0 to restore a full reasoning verdict (slower, possibly more accurate on stylistic constraint checks).
GHOST_CRITIC_MAX_TOKENSDefault 512. Token cap for the critic verdict. Small because there is no <think> prelude to budget for; raise it only if you re-enable thinking.
GHOST_CRITIC_CALL_TIMEOUTDefault 120. Hard wall-clock cap (seconds) on a single critic-pool call; on timeout the verdict falls through to the worker/direct fallback instead of blocking the turn.
GHOST_CRITIC_ASYNCDefault 0 (off). When 1, the verifier never sits on the critical path: the in-loop repair-before-ship is skipped and the verdict runs purely after the response ships. A high-confidence REFUTED then scrubs the turn's lessons and queues a correction surfaced at the top of the next turn of the same conversation ("⚠️ Correction to my previous answer…"). Trades before-ship repair of the rare wrong answer for not paying the slow off-host verdict latency (~58s) on every turn. With this on, keep the accurate thinking verdict (GHOST_CRITIC_NO_THINK=0) — its latency no longer hurts. Conversation scoping (fix): the agent is a process-wide singleton, so a naive queue leaked one conversation's correction into the next turn of an unrelated conversation (or a different user). Each queued correction is now tagged with a conversation fingerprint (a hash of the conversation's first user message, stable across that conversation's turns) and a timestamp; a correction surfaces only when the incoming turn shares that fingerprint, is held for its own conversation otherwise, dropped after a TTL (_CORRECTION_TTL, 900 s) if that conversation never returns, and the queue is capped (_CORRECTION_MAX, 3, newest win) so a busy multi-conversation process can't accumulate a runaway banner chain. Covered by tests/test_critic_async.py.
GHOST_PIN_TOOL_SCHEMASDefault 0 (off). When 1, pins the byte-stable per-turn block (tool schemas + persona + playbook + hydrated memory + continuity) to the first user message — a fixed position — so the upstream KV-cache reuses it across the turns of one request instead of re-prefilling the ~23k-char block every turn (~15s). Only the volatile dynamic_state rides the moving last message. Native tool defs still travel in the payload tools field, so tool-calling is unaffected. Opt-in / reversible A/B for the per-turn prefill latency.
