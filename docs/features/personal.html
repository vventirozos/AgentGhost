Feature

Personal tools

Small, useful things for the owner: how the portfolio is doing, what the weather will be this week, and a game of chess. The portfolio is read-only by construction, and the games are played by the model itself, never by a hidden engine.

Runs on: Mac Studio (eva) + Mac mini (nova)

What it does

Portfolio

The portfolio tool reads your Interactive Brokers holdings from a separate small service. It can tell you the value, cash, gains against cost, today's change and dividends; look at one holding with its average cost and recent trades; check concentration and currency mix, and how today's mix would have behaved in the past (volatility, worst fall, comparison with a benchmark); show the range of past returns over one month, three months and a year; and give review prompts from fixed rules, each with its reason and the case against acting.

It cannot trade. The service has no order code, accepts only reads, and the IBKR Flex reports it uses only hand out statements. The agent never sees the Flex token or the account id.

Weather and location

Ask about the weather and the agent gets the current conditions and a 7-day forecast, with day names in the place's own calendar. Ask for hourly detail and it adds today and tomorrow in 3-hour steps. If you name no place, it uses the location saved in your profile. It uses keyless public sources over Tor (Open-Meteo first, wttr.in as a fallback).

Games

You can play chess and tic-tac-toe against the agent. "Against the agent" is literal: a client sends the position, and the model chooses the reply move. Code checks that every move is legal and detects the end of the game. If the model cannot give a legal move after three tries, the game says so instead of quietly letting an engine move for it. The model can add a short comment on the position, so a client can coach you as you play.

“Am I too concentrated in one stock?”The health view: concentration, currency mix, volatility and worst fall of today's mix.

How it works

  1. Portfolio: a service does the maths

    The IBKR service downloads a Flex statement, adds public prices, and computes every figure. The agent's tool passes that text through unchanged. Old or missing data is labelled inside the answer as STALE or Data gap, never guessed.

  2. Weather: geocode, then forecast

    The place name is turned into coordinates, then the forecast is asked for. Each call verifies TLS and retries over a fresh Tor circuit. An unknown place gets a clear "could not find a location named …" message.

  3. Games: the client owns the board

    Each move request carries the whole state (a chess FEN, or nine tic-tac-toe cells). The server applies your move, asks the model for its reply, checks legality, and returns the new state.

Where it runs

  • The portfolio service runs on the Mac mini (nova). By the owner's choice it uses the normal internet and a Flex token; the agent itself stays Tor-only and only reads text from it over the private network.
  • Weather and location run in the agent on the Mac Studio (eva), out over Tor.
  • Games are an HTTP endpoint on the agent (eva), answered by the main model. Apps running in a lab can reach this game endpoint and nothing else of the agent.

Limits and switches

  • The portfolio tool is hidden until its service address and key file are configured. Channel members never get it.
  • Portfolio figures are as fresh as the last Flex statement. When the token expires, the service keeps the last statement and says so.
  • Forecast ranges come from past returns. They are not predictions.
  • Weather depends on public services reached over Tor; a refusal from them is reported, not hidden. A member's weather request never reads the owner's saved location.
  • The games need a client that sends the position. Chess needs the python-chess library on the agent.
