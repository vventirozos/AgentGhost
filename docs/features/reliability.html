Reliability

A language model will happily say “done” when it is not. The agent surrounds the model with plain program checks, brakes and logs, so claims are tested and failures are visible instead of silent.

Runs on: eva Tor-only

What it does

Reliability here means five things:

  • Checking delivered work. When the agent says it made a page, a file or a picture, a program checks: does the page load, does the file exist, does the image show what the reply claims? A claim about a number or a fact is compared with the tool output it came from.
  • Guards and breakers. The agent notices when it repeats the same failing action, keeps editing the same file without progress, or works on with nothing to show. It stops or changes course instead of burning the hour. A circuit breaker stops calling a helper machine that keeps failing.
  • Failing closed. If Tor is not running, nothing leaves the sandbox. The safe state is “no network”, not “direct network”.
  • A health check. One command reports the machine, the stores, the services and the helper machines, with the problems listed.
  • Measuring. A failure census counts which detectors fire on your real turns, your thumbs up or down are recorded as ground truth, and every step is logged.

How it works

  1. Strikes during the turn

    A strike ledger keeps a signature of each failing action. The same failure twice is a loop; the same action with no progress is futile; repeated edits to one file without a passing run trip the edit-churn brake. Text files are treated more gently than code.

  2. Checks before the reply

    The verifier runs mechanical checks on what was delivered. Claim binding compares each figure in the draft with the evidence lines; a claim with no support is refuted first, and only confirmed when the evidence carries it.

  3. Breakers around the helpers

    Each helper node has a circuit breaker. After repeated faults it opens, and calls go to the main model until the node recovers.

  4. Egress that fails closed

    In the sandbox, firewall rules send every connection through Tor and reject everything else. The rules go in before Tor has started, so until Tor is up nothing leaves. The model, even as root in the container, cannot remove them.

  5. Record and count

    Each owner turn is stored with its tool results and verdicts. The failure census joins these with your thumbs and corrections to show which failure classes really happen now.

Where it runs

All of it runs inside the agent on the Mac Studio eva: the verifier, the strike ledger, the breakers, the health check and the logs. Some claim checks use the helper model on nova. The agent itself is supervised by launchd and restarts if it dies. See Infrastructure.

Limits and switches

  • Program checks prove what they test (a page loads, a file exists), not that the work is good. Fuzzy judgements by a model are advisory, not gates.
  • The health check repairs nothing and probes nothing. It reads the agent's own records; it does not contact the lab machine or start a stopped container.
  • The failure census changes no reply and calls no model. It covers owner turns only: not members, probes, jobs or scheduled turns.
  • Thumbs only add labels; removing a reaction does not undo one.
  • The agent log mixes days; the dated system log is the one to search by date.
