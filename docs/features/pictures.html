Pictures

Ghost can draw a picture from a sentence, edit a photo you give it, and put real people into a scene from their real photos. It also looks at pictures: it describes them, reads the text in them, and checks its own drawings before showing them to you.

Runs on: ghost (Jetson Orin) for drawing, nova (Mac mini) for looking Tor-only

What it does

There are two tools, one for each direction.

  • image_generation makes pictures. It sends your request to an image model (Qwen-Image-2.1-Turbo) on its own machine. It can start from nothing, or from up to three pictures you give it. The finished image is saved in the agent's sandbox and shown in the reply, with one or two sentences saying what it drew.
  • vision_analysis looks at pictures. It describes a photo, reads the text in a screenshot (OCR), pulls numbers out of a chart, reads the pages of a PDF, or answers one exact question about an image ("is the button green?").

The interesting part is likeness. An image model cannot draw a real person from a name: ask for "Markos on a beach" with no photo and you get a stranger. So when you name a real, well-known subject, the tool itself goes and fetches a photo of that subject and uses it as the reference. The model never has to guess a face.

How it works

  1. The model writes a prompt

    The main model turns your words into a detailed description, a size, and the list of reference files or subjects.

  2. References are prepared

    One file is sent as it is. Two or three files are scaled to the same height and joined left to right into one strip, because the image node takes exactly one reference. For named subjects, the tool looks each one up on Wikipedia over Tor, downloads the portrait into subject_photos/ and keeps a small record of where it came from.

  3. The image node draws

    The request goes to the image server on the Jetson, which runs the model through stable-diffusion.cpp and returns a PNG.

  4. Ghost looks at its own render

    Every finished picture is shown to the vision model before you see it. If a picture of several people came out as a two-panel collage, the tool tries once more with a new seed. What the agent says about the picture comes from what it saw, not from what it hoped to draw.

  5. The reply shows the image

    The picture is embedded in the reply as a download link. If the model forgets to show it, the system adds it.

Where it runs

The agent on eva (Mac Studio) decides what to draw and keeps the files in its sandbox. Drawing happens on ghost (Jetson Orin), which runs the image server. Looking happens on nova (Mac mini), where the helper model Gemma E4B reads images. Photo lookups for subjects go out over Tor like all of the agent's web traffic.

Limits and switches

  • At most three reference pictures per call, joined into one strip. Several references can tempt the model to copy the side-by-side layout; the collage check catches most of these, not all.
  • Subjects must be findable on Wikipedia. Private people (Elena, your neighbour) need a photo you upload. A wrong photo means a more specific name is needed.
  • Because subject names are sent out in a public search, your own address and private details are removed from them.
  • vision_analysis reads only the first 10 pages of a PDF and refuses files over 50 MB. For long documents use Documents instead.
  • If the Jetson is off, image requests fail with a clear error; nothing else in the agent is affected.
  • Switches: --image-gen-nodes points the agent at the image server; GHOST_RENDER_LOOK turns the look-at-every-render step on or off; GHOST_VISION_TIMEOUT bounds a vision call.
