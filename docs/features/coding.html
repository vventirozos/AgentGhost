Feature

Coding

Ghost writes code and runs it for real, inside a Docker sandbox that cannot touch the host and reaches the internet only through Tor. It can keep long jobs and small web services running, and it is checked against claiming it ran something it did not.

Runs on: eva (Mac Studio) Tor-only

What it does

  • execute runs Python or shell in the sandbox and reads back the output, errors, exit code and any files written. Python can run in a stateful Jupyter session.
  • file_system lists, reads, searches, writes and edits files in the workspace. Large files are written in parts.
  • Jobs: a run that is still working after about 90 seconds is not killed. It becomes a background job, and Ghost is woken when it finishes.
  • Services: a web app or API can be started as a named service that outlives the turn and even an agent restart. Ports 8100 to 8104 are reachable from outside the sandbox.
  • PostgreSQL 18 client: psql is installed in the sandbox.
  • probe_model: for experiments about language models, Ghost can send prompts to a model for real and keep the raw answers as a transcript the system writes.

“Run the tests and fix what fails.”Ghost runs pytest, edits, reruns, and reports what it actually saw pass.
“Ask the model the same question at three temperatures and compare.”probe_model runs the prompts in a fresh context and saves the transcript to a file.

How it works

  1. A persistent container

    One Docker container holds the workspace, bind-mounted from $GHOST_HOME/sandbox. The host's home folder is not reachable. Network access goes through Tor.

  2. Guarded runs

    Each command has a 600-second budget for going quiet. A run that is still making progress is detached as a supervised job, marked clearly as "still running", so nobody mistakes it for a success.

  3. Services

    A service is launched as its own process group with a log and a registry entry. Start checks that it is alive and that its port binds; if it crashed, you get the log tail with the cause.

  4. Claims are checked

    When Ghost says "the tests pass" or "I ran it", the system compares that with what its own tools actually returned. Claims without matching tool output are flagged.

  5. Experiments need proof

    In a project, an experiment task can be marked done only with a saved probe_model transcript (or an explicit waiver). This stops "simulated" model answers written by hand from passing as results.

Where it runs

Everything runs on eva: the agent, the main model that writes the code, and the Docker sandbox. probe_model uses the main model by default, or the helper model on nova as a second, different subject. Real database servers for bigger tests live on lab machines (see ghost-labs on the Pi), not in the sandbox.

Limits and switches

  • Only five service ports (8100–8104) are reachable from outside.
  • The sandbox has no clearnet access; downloads are slower over Tor and some sites block Tor.
  • probe_model takes at most 8 prompts per call and 600 seconds in total; inside your turn it shares the main model, so the conversation is re-read after it.
  • Files downloaded from .onion sites go to a quarantine that cannot be opened or run, only inspected.
  • Switches: GHOST_SANDBOX_MEM sets the container's memory limit.
