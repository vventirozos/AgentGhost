unified_forget — four-store sweep

forget(target) sweeps four stores in order: disk (sandbox files), vector memory (fuzzy filename match + semantic sweep), the profile, and the knowledge graph. The profile pass is the one users notice, because the profile is injected into the system prompt every turn — so anything it misses keeps being "remembered".

The profile pass now runs in two stages:

  1. Key sweep — exact key match, then word-boundary substring match on keys only (so forget('age') can't wipe a language key). Matched keys are deleted whole.
  2. Value sweep — for every key not already handled, match the values with _value_mentions_target (token/word-boundary aware). A matching scalar deletes the key; matching list items are pruned via ProfileMemory.prune_value, dropping the key/category when emptied.

Stage 2 fixes the long-standing case where a forgotten entity lived as a value (e.g. assets.pets = ["Hanzo the dog", "Mortimer the iguana"]): the key-only sweep never matched forget('mortimer'), so the model kept reporting the pet as owned — often annotated "(removed)" from an earlier soft-delete tombstone the merge semantics left behind. The token-boundary matcher avoids the destructive greedy-substring behaviour the key-only rule originally guarded against. Covered by tests/test_forget_profile_value_sweep.py.

Vector sweep — literal-mention override

The semantic sweep originally deleted a candidate only when its L2 distance fell under a type-dependent threshold (0.8 auto / 0.6 identity). That silently missed facts that name the entity outright — e.g. forgetting iguana left "user previously had an iguana that was removed" in place because the sentence-vs-word distance exceeded the bar. The sweep now also deletes any candidate whose text mentions the target as a word-boundary token, regardless of distance. n_results was raised 10 → 20 so more candidates are examined.

Entity-aware expansion (alias tombstones)

A deleted entity often survives under a synonym: forget('mortimer') can't reach a fact stored under iguana. Before severing graph edges, unified_forget calls GraphMemory.get_connected_entities(target) to pull the target's direct (1-hop) neighbours — mortimer → iguana via a mortimer IS_A iguana edge — filtering generic hubs (user, pronouns). It then runs a literal-mention-only secondary sweep (vector + graph + profile values) for each neighbour, so the alias tombstone goes too without semantic over-reach.

Stopping tombstone regeneration

The deepest cause was a feedback loop: each time the user asked "what pets do I own?", the model answered "you previously had an iguana that was removed", and the smart-memory consolidator (run_smart_memory_task) extracted that sentence back into a positive fact + graph triplet — so the tombstone regenerated itself faster than forget could remove it. Consolidation now drops removal/negation statements: is_removal_or_negation_text() bails before a removal fact is embedded, and is_removal_triplet() filters past-ownership predicates (PREVIOUSLY_OWNED, NO_LONGER_HAS, …) and (removed)-tagged entities before they reach the graph. A removal must delete knowledge, never insert a memory about the deletion. The post_mortem learning pass is also skipped on a forget turn (forget_was_called). Covered by tests/test_forget_hardening.py.

Intent guard on self_play / self_play_loop

Both tools refuse to run unless the current turn's user text explicitly asks for self-play, a practice round, or a training cycle. handle_chat stashes the turn's message on context.last_user_content right after parsing the request body; _user_asked_for_self_play(context) matches a conservative allow-list of phrases ("run self-play", "train until stopped", "practice cycle", "synthetic self-play", etc. — see _SELF_PLAY_INTENT_PHRASES). If the guard trips, the tool returns _SELF_PLAY_INTENT_REFUSAL without invoking the Dreamer. Rationale: the 2026-04-24 webOS incident showed the 30B-A3 model hallucinating "The user wants me to run self-play" 33 minutes into a webOS-building session where the user had never mentioned self-play. The tool description says "Use this EVERY TIME the user asks to practice, train, or do self-play" but that's LLM-side prose — the guard makes it enforceable.

The biological watchdog bypasses this check: phase 3 of _biological_tick calls Dreamer.synthetic_self_play directly, not through tool_self_play, so legitimate background self-play fires unaffected. Covered by tests/test_self_play_intent_guard.py.

Deterministic dispatch on an explicit terminal command (self_play / dream_mode)

Symptom. A bare self play ran the cycle the first time, but every repeat (self play again) printed an identical "Self-play complete…" summary without actually re-running — the trace showed tool=- in the metacog line and a ~126-char text reply, i.e. the model answered in prose and never emitted the tool call. dream_mode (go to sleep, consolidate memories) shares the identical failure mode.

Cause. Two reinforcing priming sources. (1) The direct-from-tool summary bypass (in agent.py, the block that stops terminal tools re-firing 2–3× per ask) persists the cycle result as a plain-text assistant turn with no tool_call. (2) The memory bus then re-hydrates that text as Context: Self-play complete…. So the model's only in-context example says the correct response to "self play" is to reprint that summary — which it dutifully imitates.

Fix. When the user's message is unambiguously a single-cycle terminal command, handle_chat dispatches the tool deterministically at the top of turn 0, before the LLM turn, so the model's indecision can no longer swallow the request. _explicit_terminal_command() is the single routing gate, returning "self_play", "dream_mode", or None:

  • _is_single_self_play_command() requires a command phrase (_SELF_PLAY_COMMAND_PHRASES — a tighter set than the intent guard's, single-cycle only), rejects continuous-loop markers (_SELF_PLAY_LOOP_MARKERS — "loop", "keep ", "until stopped", … which route to self_play_loop, the model's call), and caps length so a long task message that merely mentions self-play is left to the model.
  • _is_dream_command() matches _DREAM_COMMAND_PHRASES ("dream mode", "go to sleep", "consolidate memories", …) under the same length cap. Bare "sleep"/"rest"/"dream" are deliberately excluded — they substring-match prose ("interesting" contains "rest", "daydream" contains "dream"). dream_mode has no continuous-loop variant, so there are no loop markers to exclude.

The dispatch records a genuine tool_call + tool result in history (so any future model-driven turn imitates the tool, not the summary), distills the user-facing summary via _distill_terminal_tool_summary (with the right prefix — "Self-play complete." / "Dream cycle complete."), and breaks the turn loop straight into the post-loop metacog/calibration finalisation (the reading still records domain=memory tool=<name>). A thinking_budget_override == "selfplay" guard prevents any recursion from a self-play solver sub-agent. As part of the dream extension, _distill_terminal_tool_summary also gained an explicit strip for dream's two-clause SYSTEM: SESSION FINISHED. STAND BY. footer (the single-keyword pattern couldn't span the period — the model-driven dream bypass leaked it too). Covered by tests/test_self_play_deterministic_dispatch.py.

Self-play loop internals

  • Cool-off between cycles is adaptive (5–180 s clamped) via FrontierTracker.adaptive_cooldown. Falls back to a 30 s baseline if no tracker is available.
  • The loop task + stop event are stashed on context.selfplay_loop_task and context.selfplay_loop_stop. handle_chat checks these on every user message and sets the stop event — the loop checks it at each cycle boundary and during the cool-off asyncio.wait_for.
  • Between cycles the loop explicitly drains the short-term journal via context.agent.process_journal_queue() so hippocampus doesn't fall behind during long runs. Cheap no-op when the journal is empty.
  • Inside the isolated sub-agent's context, selfplay_loop_* attributes are stripped to prevent the inner solver's handle_chat from tripping the user-message interrupt on the outer loop.

Memory bus pattern

When a MemoryBus is attached, insert_fact calls publish_fact("insert_fact", ...) rather than writing the vector store directly. The bus fans the write out to vector + graph (and other tiers) in parallel, and the dedup-LRU gate prevents re-publishes within a 256-unique-event window.

Audit fixes (2026-07-26)

Findability: transcribe is an alias, and that is the point 2026-08-12

The tool is named for what it STORES, but a model that needs this capability is holding a VERB. It thinks "I need to transcribe", scans the tool list for a transcriber, finds none, and plans a Whisper pipeline — observed live twice: once installing openai-whisper, once producing a four-task project plan whose middle two tasks ("Whisper Transcription", "Knowledge Base Integration") were a single existing tool call.

Presence was never the problem. §4AW measured it: knowledge_base was advertised on all 16 tool-carrying payloads, sat 3rd of 44, and its description already contained "Do NOT write or install transcription code" — at 82% through a 537-character run-on. A guard built on that measurement was reviewed and reverted (it saw only execute(command=…), scanned post-base64, and blocked grep of the repo's own docs). Adding a second prohibition would have repeated a failed experiment.

So the fix is discoverability, on three surfaces the model actually reads:

  • action='transcribe' is a first-class alias of ingest_document (with transcribe_document, transcription, ingest, ingest_file). The action enum is short and always read — it is where a model with a verb in mind looks — so transcribe leads it. An unknown action is still rejected; the aliasing is a fixed map, not a catch-all.
  • The description leads with the capability and carries a worked call. "transcrib" moved from 20% of the text to 1%, and the prohibition is now attached to the positive claim ("this tool IS both of those steps") rather than trailing at 82%. It names what not to build — Whisper, ffmpeg, speech-to-text, transcribe.py — because those are the words that appear in the wrong plan.
  • A planning rule (PLANNING_SYSTEM_PROMPT §8), because the observed failure was a PLAN, not a tool call: a plan may never contain a transcription task or a separate "save it to the knowledge base" task. It deliberately does NOT forbid the download — fetching the media is real work, and yt-dlp genuinely is not in the image.

Tests: tests/test_transcribe_discoverability.py (16 pins, including one that fails if the capability drifts back down the description).

forget is type-scoped: both sweeps (semantic + entity-expansion) queried the nearest-20 with NO type filter, and the literal-mention override deletes regardless of distance — with 96.6% of live rows being ingested document chunks, forgetting a word appearing in a manual silently gutted the document (library index still listed it; content-hash dedup then refused re-ingest), and episode/skill twins were fair game too. Both sweeps now scope {"type": {"$nin": _FORGET_PROTECTED_TYPES}} (document / episode / skill / acquired_skill) with a per-row belt check. Ingest dedup re-check after auto-resolution: the library pre-check ran on the RAW argument, so ingest_document('postgresql-manual') sailed past it, resolved to …pdf, and re-extracted + re-embedded the whole 3k-page manual (hours of CPU, zero effect). Bus reports honored: remember / update_profile / learn_skill no longer discard the publish report — subsystem failures return PARTIAL:. Bare excepts on the recall path no longer swallow asyncio.CancelledError. Tests: tests/test_memory_audit_fixes_2026_07_26.py::TestForgetSweepScoping, ::TestBusPartialReporting.

Splitter corruption (utils/helpers.py, the audit's #1 finding): recursive_split_text dropped whitespace separators on rejoin (found_sep.strip() falsy for \\n/\\n\\n/space), fusing the last word of each line to the first word of the next in EVERY chunk it produced — live: all 7,131 postgresql-manual chunks ("DocumentationThe PostgreSQL…"), degrading embeddings, BM25 token matching, and the passage text the model reads. Separators are now re-attached to every fragment, and chunk_overlap finally applies on the separator path (it only ever worked on the no-separator hard split) — capped at chunk_size//4, because callers can arrive with the overlap clamped to chunk_size-1 (semantic_split_text shrinks the effective chunk size below the overlap for long headers) and an uncapped carry advances one fragment per chunk: quadratic output blowup that spun the test suite for 36 CPU-minutes before the cap. Already-ingested documents remain corrupt until re-ingested — delete + re-ingest to repair. Tests: ::TestSplitterSeparatorPreservation.
