tools / probe_model.py

Runs prompts on a language model for real and keeps the raw answers — the instrument for any experiment whose data are model outputs. 2026-10-18 §4QA

Why it exists

Project 448d5afa86f0 set out to test whether "3-layer recursive thinking culminates in self-awareness" by running introspection loops on an LLM. The agent had no way to call a model as a subject, so every "Layer N response" was prose it wrote itself (with invented 2024 timestamps). The "cross-model validation" script held hard-coded simulate_model_response texts labelled temperature 0.3 and 0.9. The final report said the hypothesis was "robustly confirmed". The model even said it: "Since I can't spin up separate LLM instances, I'll simulate…".

Tool: probe_model

ArgumentMeaning
prompts1–8 prompts (each cut at 4,000 chars), sent in order.
chaintrue: each prompt is sent with the earlier prompts and answers (a recursive cascade). Default false: every prompt gets a fresh context.
temperature0–1.5, default 0.7.
max_tokensPer answer, 64–3,000, default 1,500 (§4QA-e; it was 600). Thinking is off.
nodemain (the model the agent runs on) or worker (a different model on the worker node — a second subject). A worker call asks for no fallback to main (off_main_only). If the answer still came from main anyway (served_leg(data)["served_by"], e.g. no worker pool is configured), the probe stops there: "the worker did not answer … no second subject is available".
systemOptional system prompt for the subject. The transcript quotes it like a prompt, so it cannot pose as a recorded row.
save_toA NEW project-relative .md path. The system writes the transcript there. It records the model that answered (the response's model, not the main model's configured name), the node, temperature, chain and time. Each prompt is quoted and each response is verbatim inside a fence longer than any backtick run in it, so a response cannot pose as a section.
  • The path is resolved like file_system's (/workspace/projects/<id>/results/r.md is results/r.md). It must stay inside this project's workspace, and a released project's workspace is refused (_released_write_block).
  • An existing file is refused before any call, so nothing runs.
  • The write itself is exclusive: a temp file is hard-linked to the name, and link() fails if the name exists. Two probes that finish together never overwrite each other; the loser returns its transcript as partial.
  • Both the temp file and the link are made through one handle on the target folder. That handle is reached from the workspace one folder at a time with O_NOFOLLOW, creating missing folders in place. The workspace folder itself is identified (device and inode) before any model call, and the opened root must still be that folder at save time. A folder or the workspace swapped for a symlink during the minutes of model calls cannot redirect the write (r10–r12), and no folder is ever created outside the workspace.

Results come back as ToolOutcomes: ok (with the transcript, cut at 12,000 chars; at 1,500 tokens an answer is about 6 KB, so without save_to the third answer on is cut, and the result says those characters were neither shown nor saved and to call again with save_to), rejected for bad input before any call, failed when a model call fails (nothing saved), partial in three cases:

  • the probe ran but saving did not (world_changed=False);
  • the call's total limit (600 s) stopped it before the last prompt;
  • a model call failed after earlier prompts had answered. The answers so far are kept and saved, and the result says where it stopped. A failure on the first prompt is failed.
Each model call, including slot waits and retries, is bounded by utils.aio.wait_for with what is left of the 600 s (total_budget too), and each is also capped at 180 s. An answer that stopped at max_tokens is marked "cut off" in the transcript.

Cut answers (§4QA-e)

The old default of 600 tokens cut every answer of all 11 runs in project 448d5afa86f0. The model's own answers run about 530–810 tokens, at about 87 tokens a second. In a chain, each later prompt was answered on top of a cut answer, and nothing said so. Now, when any answer is cut:

  • the transcript header carries a ⚠ line: how many answers were cut, which ones, and, in a chain, which prompts were answered after a cut answer;
  • the tool result carries WARNING: right after its first sentence (SUCCESS: … or Stopped after …), the same text, and the advice to run again with a higher max_tokens (up to 3,000) and a new save_to. The save-failure results carry it too.

Eight prompts at 3,000 tokens take about 275 s, inside the call's 600 s limit.

Kept transcripts and the quote check (§4QA-e)

A saved transcript is also kept byte for byte outside the sandbox, at <memory_dir>/probe_transcripts/<project>/<sha256>.md, with an index of the path it was saved as. At task close, a deliverable that cites a transcript must quote it word for word. See core.probe_transcripts.

Main-slot cost

Calls are foreground inside the owner's turn (is_background=_idle_invocation(context); an unattended caller parks behind the owner): there, a background call parks behind its own request (the §4QA self-stall in autoadvance's self-analysis). A probe on main sends fresh messages, which displaces the slot's cached conversation, so the turn's next step re-reads it (one re-prefill, about 30 s on a long chat; a state past llama's 2 GB --cache-ram is re-read whole). §4SC-b (2026-10-29): inside a live turn the main probe is a side call (side_main=(not _bg and node == "main"), task_label="probe-model"): the conversation in the slot is saved to disk first (📼 "saved to disk before this request's probe-model call") and the turn's next head call restores it, ~1–2 s each, instead of the re-prefill; a background probe parks behind its request as before. node="worker" leaves the main slot alone. §4SC-c: the restore line after it names the call (📀 "restored the head before this request after its own probe-model call"; it said "picture look" for every side call). See head_saves.

Who can call it

  • Owner only: members are on an allowlist (_MEMBER_ALLOWED_TOOLS) that does not name it.
  • A work tool: refused on a status question while work is live (_WORK_TOOLS), under the deadline preflight (_BATCH_WALL_TOOLS). Its result is outside content (UNTRUSTED_SOURCE_TOOLS).
  • Never inside a replay (REPLAY_FORBIDDEN_TOOLS) or as a composed-skill macro step (MACRO_FORBIDDEN_STEP_TOOLS). Sub-agents and coding leaves have allowlists without it.

How projects use it

In a GENERAL project whose goal names a model (LLM, language model, chatbot, ChatGPT, GPT, Qwen, Llama, Claude…; "the model" alone does not count), autoadvance stops before a task that runs, tests, probes, measures, replicates or repeats something, or that names a control condition, falsification test, cross-model study or ablation. A task that runs a code file (Run recursive_harness.py …) is code, not an experiment. The goal does not have to say a model is run on. That rule was inverted after phrase lists missed "Evaluate Qwen on GSM8K"; a false positive only waits for the turn.

The batch ends with stop_reason="model_experiment" and the turn decides:

  • If the task's data are a model's answers, run its prompts with probe_model (save_to a new results file), write the deliverable from that transcript, quote it word for word, and never write a model response yourself.
  • If they are not ("Measure market share of LLM vendors"), do it the normal way (web_search, read, write the file), and never ask a model for facts it should look up.

Then the turn closes the task with task_update and calls autoadvance again. An unattended run holds the task NEEDS_USER for the owner instead. See projects §4QA.
