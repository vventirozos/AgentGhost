tools / workspace.py

Read-only ACTIVITY LEDGER of the user's workspace — file watchlist changes, scheduled-task outcomes, research artifacts, command outcomes, running narrative. A record of what already happened; it does no work.

Description sharpened (§4FJ, 2026-09-07). On the 587-fixture tool-choice replay the full head picked workspace 98 times while it was the recorded truth once — 60 of those were file_system requests about building or fixing things ("the ball spawns inside the wall…", "add the option to pin a competition event…"), drawn in by "files" and "show me what you've been doing in my project" in the old text. The advertised description now says what it is (a ledger of what ALREADY HAPPENED), what it cannot do (read, write, edit, build, fix, run, continue), and names the tools those requests belong to. Measured against the old text with scripts/tool_head_diet_bench.py --pair full-legacy-workspace,full on all 587 fixtures (journal §4FJ/§4FK): wrong workspace picks fell from 98 to 67 and 26 of the 98 now land on the recorded tool (0 before), but there is NO net accuracy gain — at the fixture-row level 0.337 → 0.363 (p = 0.16) and at the correct unit, the distinct request (264 of them; one request is recorded 40×), 0.489 → 0.466 (p = 0.43), with no-tool replies rising from 83 to 101 rows. The text is kept because it is true and it removes the targeted error; it is not evidence of a routing improvement. The diet (which hides the tool) converted more of those rows.

Why this tool exists

The workspace continuity module's wake-up prefix is already spliced into every system prompt, so casual workspace questions ("what's been going on?") are grounded by default. This tool is the explicit handle for deterministic snapshots and ad-hoc queries the wake-up prefix doesn't cover.

It is the world-model counterpart to introspect (which reads the agent's selfhood). The writable counterpart is workspace_track.

Parameters

FieldTypeNotes
actionenumOne of summary, stats, files, changes, tasks, research, commands, narrative, recent, search. Defaults to summary. (recall is accepted as an unadvertised alias for search — kept out of the schema enum to stay lean.)
limitintFor tasks / research / commands / recent / search: how many entries to return. Defaults to 10; capped at 50. A value of 0 or less, or one that is not a number, falls back to 10.
querystringRequired for search: keywords to find in past workspace events. The near-miss arg names q / text / keywords are accepted too — the point of the action is to absorb guessed calls, not strike on them.

Failure semantics

  • Workspace disabled (--no-workspace-model / --no-memory): returns a single human-readable "unavailable" sentence.
  • Unknown action: returns "SYSTEM ERROR: 'action' must be one of …".
  • Internal exception: caught at the tool boundary and returned as a short failure string. Introspection never breaks a user turn.

Tests

tests/test_workspace_tool.py covers every action including the empty / no-tracked-files / disabled / None / invalid-action paths, plus registry wiring. tests/test_workspace_search.py covers the search/recall action: IDF ranking, payload/URL matching, the missing-query error, the no-match redirect, and a consistency guard that every schema-advertised action is accepted by the dispatcher (the enum and _VALID_ACTIONS are two sources of truth).

What the workspace record says is true 2026-10-05 §4LP

  • Probe turns write nothing (research artifacts, navigations, command outcomes). One project's continuity text had become probe noise.
  • Research records only the sources that loaded (642 of 1,124 live entries were failed sources booked "pulled"). A failed or blocked browser interact is not "pulled" either.
  • "Last touched" moves on every boot. The first-touch test read a persisted field, so it was frozen at 2026-07-07.

Fresh-eye review: the ledger and its writers 2026-10-15 §4PE

One reader (5 MAJOR, 8 MINOR, plus dead paths). The ledger is lightly used (one owner call in two weeks) but it feeds the wake-up prefix and the narrative.

  • Every result is declared. The ledger splices command lines and task errors verbatim; an undeclared result let a recorded grep "EXIT CODE: 1" read as this tool's own failure banner (the unanchored exit-code rule) and strike. tool_workspace and workspace_track declare OK/rejected; the narrative is headed so stored LLM text cannot be read as a failure.
  • Probe turns leave no trace. note, track, mark_seen, the changes/summary scan mirror and record_task_outcome were ungated — a probe's mark_seen hid the owner's later real pull. The tool refuses under a probe; the model's writers skip.
  • Tracked paths are workspace paths. track watched host paths verbatim: the model's /workspace/… names never resolved, a relative one watched the server's CWD, and ~/.ssh was trackable (an existence/mtime oracle; a changed .py there was read and parsed). WorkspaceModel.workspace_host_path maps container and relative paths under the sandbox root (set by main.py) and refuses anything outside or non-file; a relative path lives in the current project's workspace; track, untrack and files all use the /workspace/… spelling.
  • Services face: the one Error: string that follows a real TERM+KILL ("survived TERM+KILL") is booked FAILED with world_changed=True, not a refusal; "sandbox not running" is a declared infrastructure failure; a missing name says required, not invalid; the port-lease note says the dead run's port is yours now.
  • Noted, not changed (operator): events carry no origin (idle work is presented as the user's — exposure low while autopilot is off); a promoted command's outcome is never updated; "changed" means mtime-or-size; write_changelog is write-only.
  • Pins: tests/test_4pe_files_projects_review.py (55 tests — the confirm-flow pins drive handle_chat itself); battery scripts/mutate_4pe.py — 51/51 mutants killed, controls behaved (run 2: 46 killed, 5 survivors were helper-level pins — passage splice, released-guard parts fold, local save fault, http-named download, briefing events — re-pinned at the hook and killed on rerun; M14 after a truncated anchor was fixed; the FIFO mutants re-run with a pin that cannot wedge the worker). Suite 24,398 passed. Deployed 2026-10-15, pid 39017; probes: download receipt with size/type, deleted-id note, services name-required, probe refused by the ledger.

Every row says who did it; a promoted command's real outcome lands 2026-10-15 §4PF

Closed before autopilot goes to production.

  • Origin. WorkspaceEvent.origin is stamped on every writer from request_origin_label() (owner | autopilot | scheduled | sub-agent | self-play | job | probe | test | system). An unattended advance tick pins autopilot; the owner's own autoadvance pins owner. The wake-up prefix and the workspace listings tag non-owner rows ([autopilot] ran `make build` exit=2).
  • Promoted commands. When the job reaper lands a promoted job — done, lost, TTL-expired or cancelled — record_job_finished books the real outcome on the job's project with the job's origin (recorded at promotion; a probe's job leaves no row), never on whoever observed the landing; the commands listing hides the "still running — promoted" row once its outcome row exists.
  • Listings are scoped to the active project (the task-local pin inside an autopilot tick) and say "(project …)"; the activity reader filters by project while scanning, so a busy other project cannot push this one's rows out of the window; research pulls dedupe per project record (the fetch dedupe stays global); a missing file is not "newly tracked" news; the navigation nudge is returned to the caller, never persisted.
  • Services: a port-less service (port=0) whose liveness probe failed says "started — liveness NOT confirmed", not RUNNING.
  • Pins: tests/test_4pf_open_items.py (27 tests); battery scripts/mutate_4pf.py — 40/40 mutants killed, controls behaved (run 2: 39 killed; M11 survived as an expiry-only reaper pin → a sentinel-DONE pin through the real reaper, killed; M27 survived because the second in-thread check masked the first → the swap pin also requires that no temp file is ever created in the swapped directory, killed). Suite 24,441 passed. Deployed 2026-10-15, pid 26156; probes: a probe's project events carry origin: probe.
