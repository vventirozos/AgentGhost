verify_ui: the question channel (2026-07-31)

The incident. Debugging its own pinball game (req 66d64313), the agent verified five successive geometry fixes with bare describe_picture calls. Each ~30 s round-trip returned a generic caption; the agent had to infer "is the ball out of the launcher channel?" from prose, misjudged one frame, and the late verifier REFUTED the turn because the coordinates its claim leaned on were not found in the vision output — a caption structurally cannot carry them.

verify_ui makes the question explicit: the agent's prompt (mandatory — the call fails fast with an instructive error without it, before any file I/O) is embedded in a fixed verdict schema and judged by a meticulous UI auditor system prompt that answers only from the pixels, with an explicit UNCERTAIN-don't-guess escape hatch for blank/loading/menu frames. The result banner is UI VERIFICATION RESULT (judged from pixels only): so the downstream verifier can tell a pixel verdict from a caption.

Thinking suppression. Same failure mode (and same GHOST_VISUAL_NO_THINK knob) as the verifier's visual gate: on a thinking vision model the <think> prelude can consume the whole token budget and the JSON never appears. verify_ui ships the /no_think soft-switch + chat_template_kwargs {enable_thinking: false} hard-switch; a verdict is a tiny object and needs no reasoning prelude.

When NOT to use it. For numeric state in a page the agent controls (positions, scores, element geometry), the browser interact evaluate action reads the app's own variables — exact and instant. Vision is for how things look; evaluate is for what the state is. Both steers live in the tool descriptions and the system prompt. Covered by tests/test_vision_verify_ui.py.

PDF handling

PyMuPDF rasterises the first 10 pages at 2× zoom to JPEG; otherwise the host's vision LLM would balloon context. A single image file is base64-encoded directly. 2026-07-14: the 10-page cap is no longer silent — when the PDF has more pages, the result carries an explicit only the first 10 were analyzed note pointing at read_chunked/knowledge-base ingestion for the rest. The fitz branch is also gated on the file actually being a PDF: previously action='extract_text_pdf' forced it for ANY target, so calling it on an image replaced the already-extracted image data with a doomed PDF parse — for a non-PDF target that action is now just a prompt choice (OCR over the image).

Local-file typing (2026-07-14)

Local files are typed from CONTENT first — magic-byte sniffing (_sniff_image_mime: PNG/JPEG/GIF/BMP/TIFF/WEBP) — with the original target name's extension as fallback. A file that matches neither is refused with a pointer to file_system(operation='read'). Previously an unknown type was silently guessed image/jpeg, so a .txt/.bin was shipped to the vision model to hallucinate over. Sniffing also fixes extensionless screenshots. The prompt parameter heals the aliases the model reaches for (question/query/text/instruction).

Node format normalization (2026-07-29)

The vision nodes decode images with stb_image (llama.cpp), which has no webp/tiff support — a webp shipped as-is made the node answer an HTTP error and the whole path surfaced as vision node offline. Before base64-encoding, _normalize_for_node now re-encodes anything outside the node-safe set (png/jpeg/gif/bmp, see _NODE_SAFE_MIMES) to PNG via Pillow (first frame only for animations; exotic modes like CMYK are flattened to RGB since PNG can't hold them; output is bounded by the same pixel budget as PDF rasterisation — a 10 MB webp can decode to a 100+ MB PNG otherwise). Node-safe formats pass through untouched without a thread hop; an actual transcode runs in asyncio.to_thread. If Pillow is missing or can't decode the bytes (e.g. SVG), the original data ships unchanged with a Vision Transcode warning — pre-guard behavior, but self-identifying. Companion fix in core/llm.py: node-failure logs now render _node_error_detail(e) (HTTP status + bounded body snippet) instead of the bare exception class, so a 400 unsupported image format no longer reads identically to a dead node. Covered by tests/test_vision_webp_transcode.py.

Execution

Calls llm_client.chat_completion({"messages": [...]}, use_vision=True). Returns "VISION ANALYSIS RESULT:\n{response}" ("UI VERIFICATION RESULT (judged from pixels only):\n{response}" for verify_ui). Two result-shape rules added after the 2026-07-31 live retry (req 2c5ec4b5): (1) an EMPTY model answer ships as a named Vision API Error, never under the success banner — a contended node returned "" and the agent lost 57 s noticing the emptiness itself; (2) a bare describe_picture (no prompt) result carries a TIP steering specific questions to verify_ui — the moment-of-use counterpart to the prompt-level guidance, which live probes showed loses to habit and to auto-learned lessons embedding the old caption workflow (same pattern as the browser tool's PRE_INTERACTION line).

Safety

  • 50 MB cap on both local files and URL downloads (streamed with a byte cap, so a lying Content-Length can't OOM the host).
  • Path-traversal guard via _get_safe_path, with the read-only sandbox-root fallback for project-scoped sessions.
  • SSRF-on-redirect closed (2026-07-14). URL fetches used follow_redirects=True while validating only the ORIGINAL url — a public page 302-redirecting to 127.0.0.1/169.254.169.254/a LAN host bypassed the guard (the exact hole closed in tool_download_file on 2026-07-07; vision never got that fix). Auto-redirect is now OFF; every hop's Location is re-validated via the shared _download_redirect_target, bounded at 5 hops. Covered by tests/test_vision_hardening.py.

2026-07-27 audit fixes

  • PDF rasterisation was unbounded by page DIMENSIONS (HIGH, closed). The 50 MB file-size cap — whose comment claimed it prevented OOM — cannot bound get_pixmap. A KB-sized vector PDF declaring large pages (poster/blueprint/CAD, or a crafted one fetched via the URL branch) allocated page_w×2 · page_h×2 · 3 bytes per page: a 788-byte PDF with a 10000×10000 pt page produced a 1.2 GB pixmap, ×10 pages on a host that runs the LLM pinned in RAM. Zoom is now derived per page from a pixel budget (_MAX_PDF_PAGE_PIXELS), so A4 keeps full 2× quality while an oversized page scales down.
  • The URL branch trusted Content-Type (MED, closed). It defaulted to image/jpeg when the header was absent and never magic-sniffed the bytes — resurrecting for remote files the exact hallucination bug that magic-byte sniffing was added to kill for local ones: an HTML error page was base64-shipped to the vision model, which duly "analysed" it and returned a VISION ANALYSIS RESULT:. Content is now sniffed first; a header claiming a sniffable raster type whose bytes carry no matching signature is refused.
  • PDFs are also detected by the %PDF- magic prefix (not only the extension/header), and _process_pdf closes the fitz document in a finally so a mid-loop failure can't leak it.
