tools / introspect.py

Read-only handle the agent reaches for when asked to describe itself, recall what it has been working on, or surface specific past turns.

Why this tool exists

The selfhood wake-up prefix is already spliced into every system prompt (see Selfhood), so a casual "tell me about yourself" is already grounded in the running diary. introspect is the explicit handle for cases where the agent wants a deterministic snapshot rather than relying on whatever the prefix happened to surface — answering specific recall questions, producing a structured self-report, or letting evaluation scripts pull a known shape.

Counterpart to self_state: introspect reads, self_state writes. The two are deliberately split so a single tool description does not conflate "introspect myself" with "author my forward-looking continuity slot".

Failure semantics

  • Selfhood disabled (--no-self-model / --no-memory): the tool returns a single human-readable "unavailable" sentence. It does not raise.
  • Unknown action: returns "SYSTEM ERROR: 'action' must be one of …".
  • Missing query on recall: returns "SYSTEM ERROR: 'query' is required for recall.".
  • Internal exception in the SelfModel read path: caught at the tool boundary, logged at WARNING, returned as a short failure string. Introspection must never break a user turn.
  • activity exceptions: the branch returns before the SelfModel try-block, so it carries its own guard (added 2026-07-27 — it previously escaped the never-raises contract). A failed ledger read returns an explicit read-error message, never the calm "No background activity recorded" a genuinely quiet window produces.
  • learning exceptions: caught in-branch; degrades to "Learning health unavailable: …".

Wiring

Declared in tools/registry.py:

  • TOOL_DEFINITIONS entry adjacent to self_state, with the read-only intent emphasised in the description so the model picks the right tool when asked introspective questions.
  • get_available_tools(context) dispatch lambda binds context.self_model into tool_introspect — the same pattern self_state uses.

Tests

tests/test_selfhood_introspect_tool.py covers:

  • Default action renders the summary block (stats, recent experiences, first-person framing).
  • Explicit action="summary" matches the default exactly.
  • stats reports correct counts, current mood, and at least one topic cluster.
  • narrative reports "No narrative" when empty; returns persisted diary text when present.
  • recent returns the last-N experiences, gracefully handles the empty-log case, and clamps absurd limits.
  • recall requires a query, surfaces relevant past turns, and rejects unrelated ones via IDF scoring; the no-match case is explained quietly.
  • Disabled / None SelfModel returns the "unavailable" message rather than crashing.
  • Invalid action returns the system-error string.
  • An exception in the underlying recall path is swallowed — the tool never re-raises.
  • Registry wiring: introspect appears in TOOL_DEFINITIONS with the expected enum, and the dispatch lambda binds context.self_model.

Learning-health action (2026-07-26 improvement #1)

introspect action='learning' renders the LEARNING-HEALTH report — the instrument for the "watch/keep-or-kill in ~2 weeks" criteria the 2026-07 loop-closing work left pending. Read-only aggregation of the on-disk learning stores (via core/learning_health.py, also runnable headless as scripts/learning_health.py): lesson outcome-arm distribution (pass-only / fail-only / both) + hit-rate + stale/prune candidates; per-domain competence with the prompt-inject verdict (gated on total observations across domains, mirroring agent.py — see the 2026-07-27 review fixes below); episode field coverage; calibration Brier + observed-entropy coverage; graduated auto-skills; and a COGNITIVE WIRING section (which producers run, which consumers are gated OFF — the observability for the wire-or-retire question, improvement #5). Branches before the self_model gate so it works with selfhood disabled. (Two early "live signals" this report surfaced — a seemingly inert FAILURE arm and "degenerate" entropy — both turned out to be metric artifacts and were re-instrumented 2026-07-27; the current report words both honestly.) Tests: tests/test_learning_health.py.

2026-07-27 audit fixes

  • introspect action='activity' had been dark for two weeks (HIGH, closed). The renderer called log.read_since(0), which inherits limit=200 — so it read the 200 oldest lines of a ledger that never rotates. Reproduced against the live ledger (1518 records, newest 2026-07-27): the call returned records ending 2026-07-13, and the report printed "No background activity recorded in the last 24 hours" — even at the 336-hour maximum window. The tool went blind at exactly the point the 2026-07-17 chat-noise decision made it the only home of routine-maintenance records. Existing tests passed because their fixtures build sub-200-line ledgers.
  • The report now reads the ledger tail (_read_activity_tail): it seeks to size - _ACTIVITY_TAIL_BYTES and drains forward, keeping a bounded record window. This also bounds the scan cost, which a from-byte-0 replay grew linearly forever.

2026-07-27 — learning-health telemetry corrections

  • Calibration entropy is reported as COVERAGE, not degeneracy. The report said "entropy distinct values: 2 (DEGENERATE — w_entropy cannot be fit)", which read like a mysterious numerical failure. It is a plain coverage fact: the upstream refuses logprobs on tools + stream payloads, so most turns observe none. The section now reports how many samples actually OBSERVED entropy and counts distinct values over those only — conflating "no logprobs came back" with "the model was 50/50" is what made the metric unreadable. See calibration.
  • Graduation eligibility is broken out. "0 graduated" alone cannot distinguish a stuck pipeline from a playbook with nothing tool-shaped in it. The report now shows eligible (reusable ∩ mechanizable), so the operator can see which gate is binding. See dream.
  • PRM wiring is reported in full. The line named only .score() (MCTS turn-start, module-gated off) and omitted .uncertainty() → frontier self-play seed selection (--frontier-selfplay, default off and absent from the live launcher). With BOTH off the idle retrain wrote a checkpoint nothing read — 41 such retrains in one recent ledger window — while logging "value model refit", which reads like learning progress. The idle phase now SKIPS with an explicit reason when no consumer is live. This is a runtime check, not a deletion: enabling either consumer resumes training on the next idle pass with no code change.
  • Background-activity counts carry a comparability warning. Reflection appeared to run ~10x less than dream, which looks like a starved loop but is a recording artifact — reflection logs only outcome-producing runs and deliberately skips ticks whose trajectory corpus is unchanged since an all-duplicate pass, while dream logs every cycle. The counts are per-phase event records, not a workload budget.

2026-07-27 — introspect-subsystem review (5 bugs + 8 improvements)

A dedicated review of the introspect subsystem (tool + learning_health + the selfhood read path) against the mechanisms it reports on.

Bugs fixed

  • Competence inject-gate mis-mirrored the mechanism. The report gated per-domain (n ≥ 20 for each domain) and could print "NONE (block not injecting yet)" while agent.py — which gates on the total observation count across all domain rollups, then renders every domain — was injecting the block on every turn (e.g. 4 domains at n=5..15, total 35). The report now mirrors the real rule (total_observations vs the gate) and reads the gate constant from GhostAgent._COMPETENCE_MIN_OBS itself.
  • entropy_learnable used a different formula than the fit. Report: distinct ≥ 3 and observed ≥ 30. Fit (calibration.py): observed ≥ _MIN_ENTROPY_SAMPLES and both outcome classes represented among the observed samples. Forty one-class observed samples read as "LEARNABLE" while the fit pinned w_entropy to 0. Now mirrors the fit gate exactly and reports entropy_observed_pos/neg.
  • action='learning' was undiscoverable. It was in the enum but absent from the tool description (tool selection is description-driven), and the description's closing claim "All reads route through your SelfModel" was false for activity/learning. Both fixed in registry.py.
  • The activity report silently truncated its window. The tail scan is byte/record-capped (512KB / 1000 records) but the header claims "last N h" up to 336h; a busy ledger dropped older records with no annotation. The report now appends a note when the oldest scanned record is newer than the window start. A failed read (previously a bare except: pass) now logs and renders as an explicit read error instead of "No background activity recorded" — a broken instrument must not read as a quiet fortnight.
  • The activity branch escaped the never-raises contract (returned before the try-block); it now carries its own guard.

Improvements

  • Operating principles rendered in stats (count) and summary (full list) — the behaviour-shaping values layer was invisible to introspection.
  • recent/recall lines carry a compact age ("3.2h ago"), matching the activity report's time language.
  • AutobiographicalMemory.count() / cluster_counts() are served from the (mtime, size)-cached search index — stats() previously cost two whole-log scans per call on the summary path.
  • Gate constants the report mirrors are now imported live from their owning modules (agent, calibration, memory/skills — the stale gates got named constants there) with last-known fallbacks; hand-copied mirrors are what drifted into the two gate bugs above.
  • _load_jsonl bounds memory with a deque(maxlen=limit) and honours the limit on a mid-read failure.
  • Pass-only / fail-only / mixed lesson counting is a single O(n) pass (was O(n²) dict-equality membership, which also misclassified duplicate lessons).
  • Every action emits one pretty_log line (previously only summary and activity announced themselves on the operator stream).
  • Test coverage added for action='learning' end-to-end, the truncation note, the read-error path, the never-raises guard, principles/ages rendering, and index-cache invalidation.

2026-07-27 (later) — feature-liveness verdicts made honest

The learning report's per-feature table (_feature_health) blended entropy's neutral 0.5 stand-ins (unobserved samples) with real observations — ~1300 stand-ins drowned the handful of post-n_probs-fix real values and branded the feature DEAD with separation ~0 by construction (the same "no signal" vs "neutral measurement" conflation fixed earlier for entropy_distinct_values). Entropy is now judged over OBSERVED samples only, every feature row carries n, and the verdict is three-way: live / dead / insufficient (fewer than 10 eligible rows or a single outcome class — no honest verdict yet, and critically NOT "live" either: 5 one-class observations must not read as a working feature). Same session: uncertainty_pressure's constant 0.0 was root-caused as an ordering bug in the turn loop, not a dead concept — see uncertainty.
