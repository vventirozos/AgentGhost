Ghost Agent

A self-hosted AI agent. It runs on your own hardware, remembers what you tell it, does the work in a sandbox, and runs program checks on what it delivered — a page that loads, files that exist.

Python 3.10+ Runs locally Docker sandbox Tor-only egress No accounts, no API keys

Most AI assistants are a website you send text to. Ghost is a program you run. Nothing leaves your machine unless you asked for something that needs the internet — and when it does, it goes out through Tor.

What actually happens when you send a message

This is the whole product in five steps. Everything else in these docs is a detail of one of them.

  1. You send a message

    From the web page, Slack, your voice, or a plain HTTP request. It all arrives at the same place.

  2. Ghost looks up what it already knows

    It puts your profile, the facts it holds about you and the rules you approved in front of the model — before the model starts thinking. Older documents, notes and past conversations stay on disk and are searched when you ask it to recall something.

  3. The model decides what to do

    Answer directly, or reach for a tool: run some code, read a file, search the web, look at an image. Tools that touch your machine run inside a Docker container, not on your actual system.

  4. It repeats until the job is done

    Tool result goes back to the model, which decides the next step. Most questions take one pass. Real tasks take several.

  5. Mechanical checks look at what it delivered

    Mostly program checks, not a second opinion on the answer: does the page it built load without errors, are the files it claims on disk, is the reply an answer rather than narration, does an image show what the reply says. The reply waits up to 15 seconds for them; a page that throws or a missing file gets one repair round before sending. A failure found later is recorded. The second-model judge that used to read every answer is off since 2026-10-14 (§4OW).

The turn loop. Steps 3 and 4 repeat; step 5 runs once.

One message, end to end walks through the same five steps with the parts named, for when you need to debug one of them.

Is this for you?

A good fit if

  • You want an assistant that keeps working when your internet or a vendor's API doesn't.
  • You care that your conversations stay on your own disk.
  • You're comfortable running a couple of background services and reading a log.
  • You want it to remember your projects across weeks, not just the current chat.

A poor fit if

  • You don't have a machine that can run a large language model locally, or a spare box to run one on.
  • You want zero setup. This needs Docker, Tor, and an LLM server running before it will start.
  • You need frontier-model reasoning quality. Ghost is built around a local model and trades some raw capability for privacy and control.

What you need before you start

An LLM server
Anything that speaks the OpenAI chat API — llama.cpp, vLLM, or Ollama. Ghost runs on Qwen3.8-27B (since 2026-10-24; it was developed on Qwen 3.6 35B-A3 before that), and the prompts assume a model of roughly that capability. See the note on model choice below.
Docker
The daemon must be running. Every piece of code Ghost executes goes into a container, so without Docker the tools that matter won't work.
Tor
A local Tor daemon on port 9050. Ghost refuses to start without it — see Safety and privacy for why that's deliberate.
Python 3.10+
Plus the packages in requirements.txt. A virtual environment is strongly recommended.
A note on model choice. Ghost is developed and tested against uncensored models — for the main model and for the helper models on the other nodes. It works with a standard aligned model, but expect refusals on operations that are routine for an agent running on your own machine and unusual for a chat assistant: clearing out its own sandbox, deleting files you asked it to delete, searching Tor hidden services, or handling security material.

A refusal doesn't look like an error. The tool never runs, the model explains why it won't, and the turn completes normally — so it reads as "the feature is broken" when the model simply declined. If something won't work, check the log for the model refusing rather than the tool failing. If you turn the LLM judge back on (GHOST_VERIFIER_JUDGE=1, off by default since §4OW), the same applies to it: an aligned judge can reject a perfectly good answer on subject matter alone.

How it compares

Self-hosted agents are a crowded category, and most of what Ghost does has an equivalent somewhere. The table below is about where the line is drawn — what's built in versus bolted on, enforced versus configured, measured versus assumed.

No product names, on purpose. These projects move quickly and a name-by-name matrix goes stale within months — and it would ask you to trust a claim about someone else's code that we haven't audited. The middle column describes the common design across self-hosted agents and the tools built for them, not any one project. Where something is genuinely widespread, it says so.
CapabilityThe usual approachIn Ghost
Runs on your own hardware The whole point of the category. Widely available. Same. No advantage claimed.
Sandboxed execution Common, especially in coding agents — usually a container per session. Same idea. One shared directory, its own process and network namespaces, memory and process caps.
Memory across sessions A mature field now, with several dedicated frameworks. Usually one store — vectors, sometimes plus a graph — retrieved by top-k similarity. Several stores. Every prompt gets your profile, the facts it holds about you and the rules you approved; the fact and document store, past episodes and past conversations are searched when you ask (recall). The prompt sources are merged by rank rather than score, with a fixed weight table — the learned weights were removed on 2026-10-11 (§4NN).
Anonymous egress Direct connections. Tor is available as an optional add-on for specific tools, so the agent's other traffic still goes out normally. Tor is the transport for the whole process. A boot probe plus a process-wide socket guard blocks any direct connection to a public address. Unreachable Tor means Ghost doesn't start.
Hidden-service (.onion) search Available — several capable bolt-on skills exist, some with identity rotation. Built in, on the same enforced transport. Each retry takes a fresh circuit, and engines sharing one search index are tagged so corroboration counts independent sources.
Checking its own answers A known pattern — a critic or reviewer agent, usually wired per workflow by the developer. Mechanical checks on what the turn produced: does a built page load, are claimed files on disk, is the reply an answer, does an image show what the reply says. A page that throws or a missing file gets one repair round within a 15-second window before sending; a failure found later is recorded and is not shown to you. The second-model judge is off since 2026-10-14 (§4OW): measured on real turns it was wrong on 9 of 17 refusals. It does not check whether facts in an answer are true.
Learning from its own runs Uncommon. Memory frameworks store what happened; they don't generally change behaviour because of it. Your 👎 or correction starts an idle-time replay of the question that ends in one proposed rule and a proposed regression test — adopted only when you say so. The self-teaching passes (automatic skills, self-written lessons, reflection, post-mortems) were measured on real turns, did not help (§4NC/§4ND), and were removed on 2026-10-11 (§4NM).
Tuning its own prompts Real and in production use — reflective optimizers like GEPA are an established technique, typically run offline against a strong teacher model. Not any more. Ghost ran that family of optimizer against its own local model from mid-2026; no tuned prompt ever beat the hand-written one on real turns, and the optimizer and its autonomy loop were removed on 2026-10-11 (§4NM). Every prompt it uses today is hand-written; the small loader that renders tool descriptions from their signatures is all that remains.
Models it trains itself Rare in self-hosted agents. None now. It used to train two small logistic-regression models on its own turns — a process reward model and a complexity router — but nothing that changed an answer ever consumed either, and both were removed on 2026-10-11 (§4NM).
Acting without being asked Agents generally act when invoked. Scheduling is usually external. A background loop (the idle scheduler) runs memory upkeep, replays your failures and re-runs your regression tests during idle time, and never interrupts a turn. Scheduled and condition-triggered tasks are first-class.
Measuring whether a change helped Rare outside published benchmarks. The regression suite: every rule you adopt comes with a test that is re-asked after each deploy and daily, so a fix that stops working is reported. Live randomised A/B arms were tried and dropped: at this traffic none could reach a verdict (§4ND), and the whole experiments registry was removed on 2026-10-11 (§4NN).
Third-party accounts Usually at least one key — a search API is the common case. None. Search runs against scrapers over Tor, which costs result quality and is a deliberate trade.

What that costs

The same table read the other way. A local model caps reasoning quality below what a frontier API gives you. Search over Tor against scrapers is slower and less accurate than a keyed search API. The answer checks are mechanical, so they catch a broken page or a missing file but not an invented fact — on hand-graded owner turns (2026-10-14 to 10-20) about 43% were right and 14% wrong, and invented knowledge is the main open failure. Failure replay and the regression tests only run if the machine stays on and idle. And more moving parts means more that can quietly stop working — several subsystems here have been silently inert for weeks at a time before instrumentation caught them, which is why so much of the tooling is about detecting that specific failure.

The unusual parts, in detail

The mechanism behind each of the rows above.

It remembers across sessions, in several shapes

Closing the chat wipes nothing. Facts and documents, relationships between things, a profile of you, the rules you approved, a running journal, and past episodes and conversations are stored separately — because "what do I know about Postgres?", "who is Anna to me?" and "what went wrong last time?" want different shapes of answer. Only your profile, your facts and your rules go into every prompt; the rest is searched when you ask. How memory works →

It checks what it delivered

After each reply, mechanical checks look at what the turn actually produced. Does the page it built load without errors? Are the files it says it wrote on disk? Is the reply an answer, not just narration of its work? Does an image show what the reply describes? A failure is recorded and can start a replay in the learning loop. Since 2026-10-14 (§4OW) the second-model judge that also read the answer against the evidence is off by default. Measured on a week of real use, it was wrong on 9 of 17 refusals, and none of them was shown to you. GHOST_VERIFIER_JUDGE=1 turns it back on. How the self-check works →

It learns from you, and asks before it changes

A 👎, or a next message that says the answer missed, starts a loop: while you're away Ghost asks itself the same question again, works out what went wrong and one rule that would fix it, tests the rule on the same question and on your regression tests, and then asks you. Nothing changes until you say "learn rule N". The same complaint becomes a test that is re-asked after every update, so a fix that breaks later is reported. It does not grade or teach itself — measured, that didn't work. The learning loop, with a worked example →

It can search Tor hidden services

Normal search engines don't index .onion sites, so there's a separate path through the dedicated onion engines. Each retry is forced onto a fresh Tor circuit, because whether an engine answers depends on which exit you drew — and engines that share a search index are counted once, so corroboration means independent sources. How onion search works →

It fails closed on the network

Outbound traffic goes through Tor, and this is enforced rather than intended: a boot-time probe plus a process-wide block on direct connections to public addresses. If Tor is unreachable, Ghost won't start. A silently-cleartext agent is worse than a stopped one. How that's enforced →

It works while you're away

Given a quiet stretch, Ghost files away facts from your recent turns, tidies its memory stores, replays your recent failures to find a rule worth proposing to you, and re-runs the regression tests you kept. None of it interrupts you, and none of it runs while you're active. Ask it what it did — the answer reads from a real ledger, not the model's recollection. The full idle schedule →

Every advanced feature, in one table

The six sections above are the ones worth prose. This is the rest of them — the whole advanced surface in one place, each row linking to the page that explains it properly.

The right-hand column is the honest part. on means it runs on a stock install with no flag. A flag or environment variable means it doesn't, and that's what turns it on. opt-in marks the ones that are off by default because they're experimental or expensive — they are listed here rather than quietly omitted, because a feature you believe is running and isn't is worse than one you know is off.

Rank-fusion memory The prompt's memory sources merged by rank with a fixed weight table, because similarity scores from different stores aren't comparable to each other. Since October 2026 only your lessons and rules and facts about you are added to every prompt; the vector, graph, episode and past-session stores answer when you ask (recall). The prompt tiers for those stores were removed on 2026-10-11 (§4NM). on
Episodic memory Whole past episodes — the sequence of actions and how it turned out — recalled when you ask. Since 2026-10-10 they are no longer added to every prompt (15% relevant, 19% harmful). on request
Experience How past turns like this one went — only turns a human graded (the census, your 👍/👎): the steps and the pages that answered them, and what went wrong in a graded-wrong one. Fact ledger When each fact about you was stated, replaced or removed, and in your own words — always written; shown on questions about yourself once a replay proves it (the October 2026 replay did not: seeded rows carry store dates, not the dates you said things). written shown: off (replay failed)

Live: the reply after a look went from 179 s to 14 s. Old files are cleaned up automatically. on via the launcher: GHOST_HEAD_SAVES=1, GHOST_CONV_KEEP=1

Doing the work
Docker sandbox Code runs in a persistent container with its own process and network namespaces — not on your actual system. needs Docker
Background jobs A command that outgrows its time budget is detached and supervised instead of killed halfway. on
Sandbox services Long-running servers it starts for itself, with pidfiles, logs, liveness probes and leased ports. on
Browser automation Headless Chromium with DNS forced through Tor and a cookie profile that survives between sessions. needs Docker

Privacy, safety and operations
Mandatory Tor egress A process-wide socket guard: any direct connection to a public address raises, and unreachable Tor means Ghost won't start. on
Stylometric scrubbing Outbound search text is normalised toward neutral phrasing, so your writing style isn't itself a fingerprint. on
Circuit breaker Three consecutive failures takes a node out of rotation; it half-opens to probe after a cooldown. on
Log redaction Secrets, onion addresses, home paths and personal details masked in both console and file logs. on
Activity ledger and liveness probes What it did while you were away, read from a real ledger — plus a probe per subsystem answering whether that subsystem actually fired. on
Durable sessions A conversation started in Slack carries on in the web UI; the history lives on the server, not the client. on
Self-model An autobiographical log, open questions and a running diary, readable through introspect. The wake-up prefix that put this in every prompt, and the idle job that derived a mood from it, were removed on 2026-10-11 (§4NM). on
Off by default — opt-in and experimental
Test-time scaling On a borderline verdict, generates several candidate answers and picks the winner by comparing them against each other. opt-in GHOST_TTS_ADAPTIVE_BON=1
Push notifications Webhook, ntfy or iOS Web Push when something happens while you're away — public targets go out over Tor like everything else. opt-in --notify-ntfy
