interface / externals / cli

Terminal client: streaming Markdown chat, durable sessions, real turn cancellation, files/workspace, projects, and ops — one PEP-723 script.

Location & launch

One extensionless executable script, interface/externals/cli/ghost (moved into the repo 2026-07-17; previously it lived only at ~/Data/AI/bin/ghost, which is now a symlink to the repo copy — that directory is on the operator's PATH, so the command stays ghost and edits land in exactly one place). Dependencies are declared PEP-723 inline (requests, prompt_toolkit, rich) so uv run ghost works anywhere; on the operator's machine the system python has them installed.

Connection

Talks DIRECTLY to the agent (GHOST_URL, default http://eva:8000) — not through the web-interface proxy. The key rides X-Ghost-Key, resolved env-first then ~/Data/AI/.ghost_api_key (blank env never shadows the file — the Slack-bot " " incident class). Each turn sends an X-Request-ID keying the agent's turn registry, so Ctrl-C cancels the turn server-side (releasing the global turn lock) instead of just closing the socket.

Rating — human outcome labels (2026-08-27)

The Slack bot (👍/👎 reaction) and the web UI (thumb buttons) can resolve a turn's outcome=unknown by writing an explicit human label through POST /api/feedback. The CLI now can too — it is the surface where typing a reason is natural, and on a negative that reason becomes the trajectory's failure_reason, which is worth considerably more to the verifier/distiller than a bare thumb.

FormEffect
/good [note] · /+1👍 the last reply → signal: positive, outcome passed
/bad [why…] · /-1👎 the last reply → signal: negative, outcome failed; the free text is the note (agent caps it at 500 chars and redacts it before logging). A bare /bad on a tty prompts why? (enter to skip) once; off a tty it records the bare label rather than blocking. Enter skips the reason, Ctrl-D skips it, Ctrl-C cancels the rating entirely — it used to fall in with Ctrl-D and record a bare 👎 anyway.
/good ^2 · /bad ^3 reason…rate N replies back (^1 = newest). The ^N token can't collide with a reason.

Labels ride source: "cli", so operator-CLI labels stay distinguishable from web and slack:U… in the corpus. Switching thumbs re-labels (last-write-wins server-side); a repeat of the same thumb returns unchanged and is reported as already labeled — it is still POSTed, because the agent's repeat path re-heals the cache stamp and the diary row.

Why the CLI is not a copy of the web client

Three differences, each load-bearing:

  • Parsed before shlex. Every other slash command goes through shlex.split; a reason is free text, and /bad it didn't find the file dies there with "No closing quotation". Dispatch catches that and posts nothing — the label would be lost to a quoting rule the operator never opted into. /good//bad are therefore matched off the raw line before the split.
  • Synchronous retry, honest report. The agent records the trajectory after the stream closes (post-semaphore), so a thumb typed the instant a reply lands 404s. The web client must fire-and-forget with one blind retry; the CLI operator is sitting at the prompt, so it retries in-line (RATE_RETRY_DELAYS = 0.5s / 2s / 4s) under a spinner and then reports what actually happened. A surviving 404 says label NOT recorded — no trajectory matched, which is the "trajectory logging is off" diagnosis, not a bare HTTP code. Nothing is ever reported as recorded without HTTP 200 and ok: true.
    ⚠ The first version retried 404/429/5xx only, and justified the 5xx leg as "the agent restarting — the window a deploy creates." A restarting agent refuses the connection: that is requests.ConnectionError, not HTTP 503. So the loop covered the less likely manifestation of its own motivating scenario and dropped the label on the more likely one — measured, 1 attempt against 4. Transport failures are now retried on the same schedule and surface as status 0. The label also carries its own RATE_TIMEOUT of (5, 10): the retry multiplies the timeout, and on _json's (10, 60) default four attempts could freeze the prompt for ~287s against a hung agent.
  • Cancelled and errored turns are not rateable. A Ctrl-C'd turn is truncated by the human: labeling it failed teaches the verifier that an operator's abort was a model failure, and labeling it passed teaches it that stopping early is fine. Both are label noise in a corpus where labels are scarce enough to be load-bearing, so stream_reply stamps _turn_interrupted (cancelled/error) and both thumbs refuse, naming which case it was. The web client has no equivalent guard.

Refs are also dropped by /clear, /new, /resume and /load: after those, a /good would label a turn from a conversation the operator has left (a stored or restored history carries no request ids at all). The request id itself is the X-Request-ID the CLI already mints per turn — the agent stamps it as the trajectory's req_id, which is what /api/feedback resolves against, so this needed no server-side change.

Tests: tests/test_ghost_cli.py::TestRating — 14 single-guard mutants (shlex routing, the interrupted guard and its per-turn reset, each ref-drop site, the retry loop, the ok check, the 404 diagnosis, source, the note cap, the ^N parse, the isatty branch) all killed by the full file.

Full-client review — 2026-08-27

A multi-lens review of the whole script (state, protocol, terminal, security, crash-resilience, performance), every finding reproduced by execution rather than by reading. Eleven fixes; 25 further single-fix mutants all killed by the suite.

Local files are never destroyed by a failed transfer

cmd_download and cmd_save "cleaned up" a failure with dest.unlink(missing_ok=True) — but the writer only opens dest on HTTP 200, so on a 404 the unlink deleted whatever local file happened to share the name. Verified: a real report.pdf plus /download report.pdf against a 404 removed the operator's own file. The mirror case was equally wrong: a transfer that died mid-stream left a truncated file over the original. Both writers now stream through a sibling temp file and one os.replace, cleaning up on BaseException (Ctrl-C included), and the callers unlink nothing.

Control characters cannot reach the terminal

rich strips only [7, 8, 11, 12, 13]. ESC is not in that set, so every CSI and ST-terminated OSC in agent- or server-supplied text was written to the terminal raw — confirmed for \x1b[2J, \x1b[?1049h and \x1b]52;c;…\x1b\\, which writes the operator's clipboard. The agent summarizes Tor-fetched pages, and this is the only client that renders into a terminal instead of into HTML (the web UI and Slack escape by construction). _safe() now strips ESC, the C0 controls rich lets through, DEL and the C1 range (U+009B is a one-byte CSI) at every point untrusted text becomes output: _StreamPrinter.feed (which also cleans the copy kept as history and written by /save), notice, _trim, _table, the piped one-shot branch, and the health/notification/briefing fields. Sequences are defanged, not swallowed — the inert remainder stays visible so an attempt is legible in the transcript.

One bad payload no longer ends the session

dispatch caught only requests.RequestException and chat() guarded only the prompt, so a single unexpected response shape killed the REPL and took the local history and the rateable turn refs with it (verified: a session row missing id → KeyError; rss_limit_mb as a string → ValueError). dispatch now catches Exception, reports, and continues; /health additionally coerces the limit rather than relying on that catch.

Ctrl-C means one thing per context

It meant three, and two of them ended the session. Now: during a reply it aborts and cancels the turn server-side; at an idle prompt it clears the line (it used to share a break with EOF, so the key /help advertises as the abort key also quit the CLI); Ctrl-D exits. A second Ctrl-C landing while _abort_turn posts the cancel is caught and reported instead of unwinding the REPL, and a Ctrl-C during post-reply image fetching no longer costs the reply — the history append and the turn ref now happen before rendering, so a reply the agent already finished stays in context and stays rateable.

The same gap existed in one_shot, which never cancelled at all: turns are globally serialized, so a Ctrl-C'd script left the agent working and holding the lock for every other client. It now cancels the request id it actually sent and exits 130.

Streaming cost no longer depends on reply shape

feed() built Markdown(pending) once per chunk and that constructor runs a full markdown_it parse. _flush_point only advances on a blank line, so for a reply that has none — a table, a long bullet list, which this agent emits routinely — the pending region is the whole reply and was re-parsed on every token. Measured: a 400-row table cost 12.24s against 0.07s for the same volume of prose, with Markdown.__init__ → markdown_it.parse accounting for 14.6s of a 16.9s profile across 1410 calls. _LazyMarkdown holds the markup and parses inside __rich_console__, so the parse runs on Live's refresh clock instead of the token rate: the same table now costs 0.14s, the list 0.12s. Pinned as the mechanism (parse count), not as wall-clock.

Smaller

  • GHOST_URL=eva:8000 parsed as scheme='eva', netloc='' and fell through to a bare MissingSchema on every call; a missing scheme now defaults to http:// (https is never downgraded).
  • A rating confirmation names the turn it labeled, not just its id — with ^N in play, "which one did that hit?" is a real question.
  • Undocumented /+ and /- aliases removed and /bye added to both the completer and /help. A drift test now asserts that dispatch, COMPLETER and HELP name the same command set — when they diverge, Tab and /help lie.

One candidate was retracted on inspection: the CLI replaying its full local history every turn alongside the server's stored history looks like double-counting, but core/sessions.py::merge_history_detail is built for exactly this fat-client replay — stored is always a prefix, only the unmatched tail is appended, and client-side assistant messages are stripped from that tail, so an aborted turn's partial reply cannot poison the store either.

The look — 2026-08-27

Three structural problems, all visible in the first screenful:

  • The banner wrapped. Its rule was a hardcoded 52 columns and it assembled the full URL, the session id and up 3h 20m unconditionally — so it under-ran a wide window and spilled onto a second line in a narrow one. _fit_line() now drops optional segments from the tail (endpoint, then session id) and truncates as a last resort; identity and liveness are never what gets cut. The rule spans the terminal. Pinned as exactly three lines at every width from 16 to 140, including a 50-character hostname — measured by counting LINES, since a wrapped banner shows up as extra short lines rather than as an over-long one.
  • Replies were the one thing out of alignment. Markdown printed flush at column 0 while every notice, table and hint was indented two. Everything now shares one GUTTER; _reply_block() is the single place reply text is rendered, so the settled blocks, the live tail and the end-of-stream flush cannot drift apart.
  • rich's stock colours leaked into every reply. Markdown tables rendered with cyan borders and headers, code spans as bold cyan on a BLACK background, headings in magenta — none of it from the palette, and the loudest thing on screen in any reply containing a table. The theme now owns every markdown.* style rich ships with a colour, and a test asserts that set is fully covered so a future rich release cannot quietly add one back.

The palette moved to deliberate truecolor values named by role (you, ghost, notice, err, ok, mute, faint), so a re-theme is one dict. Note that faint is used for the session id and for link text, not only for rules — with terminal hyperlink support rich styles the anchor TEXT with markdown.link_url, so a true border-grey there makes every link in a reply nearly invisible.

The prompt, and the gap under it

The prompt is › (in PROMPT_GLYPH; a test pins that chat() actually uses it — a constant nothing reads is decoration). ❯ is the shell-prompt cliché, and the first replacement, ▌, was worse for a reason that had nothing to do with taste:

prompt_toolkit reserves eight rows for the completion menu by default (reserve_space_for_menu=8), for the whole session, menu showing or not. That is a permanent blank gap under the prompt — and because those rows are a scrolling redraw region, every frame leaves a copy of the prompt glyph behind in scrollback. With a solid block that reads as one continuous vertical bar running down the left of the transcript, which is what the operator saw. The session now reserves nothing and completes like a shell (CompleteStyle.READLINE_LIKE, complete_while_typing=False): Tab lists, which is what the banner has always promised. Pinned, along with a check that the glyph is not a block- or heavy-line drawing character.

Replies get a plain indent rather than a coloured left rail. The rail was built and rendered — it is the one thing that makes a reply read as the agent's on an ordinary prose turn, since markdown.text carries no colour and a reply with no table, code span or heading looks exactly as it did before the palette existed — but it also prefixes every line the operator copies out of the terminal. Copy-clean won; the rail was removed rather than left in the file unused.

Two of the fifteen visual mutants initially survived, and one is worth recording: the gutter-alignment test built its expected indent out of cli.GUTTER, so setting GUTTER = 0 made it pass trivially. It now measures the rendered indent of the reply, the notice and the table, asserts all three agree, and asserts the agreed value is at least 2 — a literal, not the constant under test.

Mutation runs never touch the deployed client

~/Data/AI/bin/ghost is on PATH and symlinks to interface/externals/cli/ghost. The mutation harnesses used to write each broken variant into that file and restore it a couple of seconds later — so every mutant was briefly the operator's live client. Launching ghost inside one of those windows loaded the broken build: on 2026-08-27 a mutant that disables the rating branch (signal = None) made /good and /+1 answer "unknown or incomplete command" in a real session, and the operator reasonably reported it as a bug in the feature.

An EXIT/INT/TERM trap does not fix this — a trap restores afterwards, and the window is the problem. The suite now honours GHOST_CLI_PATH, pointing itself at a copy; harnesses write mutants there and the deployed file is never opened for writing. A run is verified by checksumming the deployed file before and after. Two guards back it up: the deploy-contract tests assert against the repo path rather than the override, and TestLocation::test_the_deployed_client_dispatches_its_rating_commands loads the file the symlink actually resolves to, so a leaked mutant fails the suite instead of surfacing in the operator's next session.

Streaming render — tail-cropped live view (2026-07-26)

Replies stream into a rich Live region re-rendered as Markdown ~12×/s. The original implementation used vertical_overflow="visible", which breaks structurally once the rendered reply is taller than the terminal: rich repositions by emitting content-height cursor-up ops, but a terminal can't move the cursor above the top row, so each refresh erased only the top screenful, reprinted the whole reply from the clamp point, and pushed a stale partial frame into scrollback — the operator-reported "erratic, half-screen" transcripts (worst in small panes/tmux; mid-stream markdown aggravates it, e.g. an unclosed ``` fence transiently renders everything after it as one tall code block, and a resize mid-stream reflows narrower → taller).

Fix: while streaming, the live view renders only the reply's tail (_TailCrop: last height−2 rendered lines — rich's own crop/ellipsis overflow modes keep the TOP lines, the wrong end for chat), and the Live is transient; when the stream settles the full reply is printed once, at the current terminal width. The region stays repaintable at any reply length, so the glitch is structurally impossible, and an abort/error mid-stream still leaves the partial reply on screen (the settled print rides _settle() / _finish(), reached from every exit path). Applies to both the interactive loop (stream_reply) and one-shot mode (one_shot).

Inline images (2026-07-17)

After a reply settles, ![…](name.png) references are fetched from the agent sandbox (GET /api/download/{name}, in-memory, 25 MB cap, ≤4 per reply, de-duplicated; http/data schemes skipped — the CLI only fetches from the agent) and drawn in the terminal below the reply. Protocol auto-detection: iTerm2/WezTerm (OSC 1337 inline escape; LC_TERMINAL honoured over ssh) → kitty (graphics protocol, f=100 PNG-only so non-PNG transcodes via Pillow or falls through) → half-block (universal truecolor fallback: two vertical pixels per cell via ▀, needs Pillow) → none. Escape-protocol failures fall through to half-block. Images can't be drawn INSIDE the rich Live region (the escapes are raw byte streams a repaint would shred), hence after-the-reply placement. /download of an image also renders it. Override with GHOST_CLI_IMAGES=off|iterm|kitty|halfblock. Pillow rides the PEP-723 deps but is optional at runtime (protocol paths ship raw bytes without it).

Ref normalization + tmux (2026-07-17, first live use). Replies embed whatever path shape the model chose — the first live image arrived as the FULL API path (![…](/api/download/gen_x.png)), which double-prefixed the fetch → 404. _normalize_image_ref strips /api/download/, /workspace/ and sandbox: prefixes (anchored, not mid-path); a pathed ref that still 404s is retried as its flat basename (generated images land at the sandbox root). And under tmux, auto-detection picks half-block instead of an escape protocol — tmux swallows OSC-1337/kitty sequences unless allow-passthrough is on (off by default since tmux 3.3), and a swallowed escape looks like no image at all. Forcing GHOST_CLI_IMAGES=iterm under tmux wraps sequences in DCS passthrough framing (ESC-doubled, the imgcat trick) — full-resolution images inside tmux panes, provided set -g allow-passthrough on is in .tmux.conf.

Sixel — redraw-persistent images in tmux (2026-07-17, second live report). Passthrough images are OVERLAYS: tmux repaints panes from its character grid, so any redraw — a resize, a pane switch — erases them (operator: "disappears if I slightly resize"). Sixel fixes this structurally: a sixel-built tmux (Homebrew builds it in since 3.4; the operator runs 3.7b) consumes the sequence itself, stores the image in its own model, and repaints it across resizes. New pure-python encoder (_render_sixel: Pillow 256-color quantize → 6-row bands, RLE, ~0.4s for 640×480) — emitted RAW even under tmux, never passthrough-wrapped (tmux must SEE it to own it). Auto-detection under tmux now prefers sixel when the stack supports it (tmux ≥3.4 + iTerm2/WezTerm outer + Pillow), falling back to half-block; GHOST_CLI_IMAGES=sixel forces it.
