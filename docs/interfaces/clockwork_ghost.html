UI layout

One full-width column over a full-window face since 2026-08-02 — not the left/right split it used to be. The face (the web UI's matrix_graph.js in a QWebEngineView; the three QPainter faces are gone) is the background of the whole window at explicit geometry, and every panel is glass floating on a translucent overlay above it.

  • Top row: rate the last reply (▲ GOOD / ▼ BAD) on the left; on the right ◇ LOAD and ◆ SAVE (two chips — the single one flipped from load to save and could not load once anything had been said), ◈ FORM, ◐ FACE. Every chip carries a word since 2026-10-01.
  • Middle: left_widget → the transcript, as real QLabel bubbles (operator right, agent left). This is the only item in the column with a stretch factor.
  • Bottom row: text input (with up/down history) sharing one row with ■ STOP (shown only while a turn runs), camera snap, push-to-talk, TTS toggle and the status readout.

Fullscreen face (◐ / F11)

Hides self.overlay — the entire glass sheet, leaving nothing but the face. Verified on-device against the real MainWindow: 9 of 9 controls visible normally, 0 of 9 while hidden, face still rendering.

Getting back. This is a frameless, always-on-top kiosk, so with the overlay hidden there is no visible control to restore it — losing the way back would be worse than the bug. Two independent paths, deliberately redundant:

  • F11 — an ApplicationShortcut, not the default WindowShortcut: with the overlay gone the QWebEngineView is all that is left to hold focus, and a window-scoped shortcut could be swallowed by it. The face is also NoFocus for the same reason.
  • Any other key — keyPressEvent restores the UI before its normal type-to-focus handling.

Escape / Alt+Escape / Ctrl+Escape never reach keyPressEvent (they are QShortcuts and fire first), so push-to-talk, TTS and SNAP keep working while the UI is hidden — face-only voice mode rather than a dead end.

Two wrong targets, both shipped before the right one (2026-08-03). "Hide the UI" looks like it should hide a panel; it has to hide the sheet.

Live turn status — what replaced "cogitating" (2026-08-03)

The waiting bubble used to read cogitating ··· for the whole 30–90 s a turn takes. It now carries the same caption the web UI shows under its waiting bubble — elapsed clock, a plain-English description of the current step, and that step's icon: 

0:34   reading a file · notes.md   📖
1:02   delegating to the worker node · verify → Worker Node (worker-1)   🔧
1:19   thinking…   💭

The chat stream cannot supply this. /api/chat carries content tokens only — nothing about tools, memory or thinking — so the description comes from a SECOND channel, exactly as it does in the browser: the interface server tails the agent's pretty log and rebroadcasts every line over wss://eva.taila2b1d.ts.net:8080/ws?key=…, and the client turns those lines into captions. Same host, port and certificate (Let's Encrypt via tailscale cert, §4KR) as the voice endpoints, so GHOST_VOICE_VERIFY_TLS applies here too; GHOST_LOG_WS overrides the whole URL. The key rides in the query string because the endpoint is gated the way the web UI is and WebSockets take no custom headers.

  • turnstatus.py (new file — remember it in deploy.sh) holds the caption logic and the socket reader. It is deliberately Qt-free, so unlike the rest of the client it is unit-tested for real: tests/test_clockwork_turnstatus.py.
  • Corridor filtering. Dreams, self-play and other clients stream over the same socket. The ticker adopts the id of the first request started corridor to open after the operator sends and ignores every line that does not carry it — otherwise the handheld narrates the agent's dreams while the operator waits on their own question. A corridor already open at send time can never be adopted.
  • Degradation is the design. The reader reconnects forever with exponential backoff and never raises; if the interface is down (or websockets is missing from ~/gui_env) the caption falls back to the old cogitating and chat — which talks to the agent directly on :8000 — is unaffected.
  • One line, always. The description is elided at 46 characters (caption_html). The web UI one-lines with white-space: nowrap + text-overflow: ellipsis; a QLabel has no equivalent, and a caption that wraps also changes the bubble's height every few seconds, which reads as the transcript twitching. The description is raw log text and is escaped — the bubble is in RichText mode, so an unescaped < from a tool's output swallows the rest of the line.
  • Repaints are gated on change. Every mutator returns whether the caption actually moved; each repaint re-measures and re-fits a QLabel, and the socket carries every line the agent logs. The clock ticks at 1 s (second granularity — 500 ms bought nothing but fits).
  • Hand-synced tables. ICON_CLASS / TICKER_VERBS / TICKER_NOISE are ports of the tables in interface/static/app.js. The device never sees app.js, so nothing at runtime can catch drift — the test parses both files and fails when they diverge. Change the JS and the Python together.

Camera

CameraPreviewDialog via OpenCV VideoCapture on /dev/video0 at 1280×720 MJPG (GHOST_CAM_W/_H/_FPS), previewed about 15 times a second. It was forced to 1920×1080 at 60 fps with a 16 ms timer — a 6 MB frame converted on the UI thread of a CM4 up to 60 times a second. With no camera attached the dialog says so (it used to be a black rectangle and a dead CAPTURE button), and every way out of it — including the Escape key, which used to skip the cleanup — releases the camera. Ctrl+Esc snaps a frame; the user can optionally upload + add a prompt.

Input shortcuts

  • Esc — tap to toggle recording, or hold to talk and let go to send.
  • Alt+Esc — toggle TTS.
  • Ctrl+Esc — snap camera.
  • Shift+Esc — stop the running turn (again to force).
  • PgUp / PgDn, or Shift+↑ / Shift+↓ — scroll the transcript.
  • Ctrl+↑ / Ctrl+↓ — rate the last reply good / bad.
  • F11 — face only (any key returns).
  • Slash commands — /help lists them: /new (/clear), /stop, /sessions, /open N, /good, /bad [why], /bright, /vol, /tts, /face, and /shutdown, /reboot, /exit, which must be typed twice. The rules for what counts as a command are in §4KU.

Stats

Timer every 5 s: ● ▂▄▆ ⚡ 100% 10:30 AM. The dot is the agent (green when it answered the last poll, red when it did not, dim before the first), the bars are wifi quality from /proc/net/wireless, the bolt appears only while charging (it used to be printed always), and the percentage turns red under 15% on battery. Concurrency

qasync.QEventLoop wraps the QApplication so asyncio and Qt cooperate. Async tasks for audio_fetch_task(), audio_worker_task(), send_chat_request(). Signal/slot pattern for cross-thread UI updates.

The face — the web UI's own, hosted in QWebEngineView (2026-08-02)

The three QPainter faces below were removed. The handheld now runs the same matrix_graph.js the browser does (webface.py + webface/), so it gets the thermal two-pole palette, every form the browser has (cube · tesseract · vortex · descent · empty since 2026-09-22; eight different ones when this shipped), the immersion dive, pulses and error flinches — and future work on the web face lands here for free instead of the two drifting into forks. The ◈ chip now cycles forms rather than swapping renderers.

The face opens on the last form you chose (2026-08-03)

A ◈ press is remembered and applied at the next start. Precedence: GHOST_FACE_FORM (explicit, this run only) > the remembered form > facestate.FALLBACK_FORM = descent on a device that has never been cycled.

Why localStorage could not do this. matrix_graph.js already persists the choice and restores it at load, and on the handheld that mechanism can never work — for two independent reasons, either one fatal:
  • The client's QWebEngineView uses the default, off-the-record profile (there is no ~/.local/share/**/QtWebEngine directory on the device), so web storage dies with the process.
  • localStorage is keyed by origin, and the face is served from http://127.0.0.1:<free port> — a different port, so a different origin, every boot. Even a persistent profile would look the value up under a key it never wrote.
So the memory is one line of text in ~/.ghost_face_form, written by cycle_form and read by startup_form — facestate.py (new file; add it to deploy.sh), Qt-free and unit-tested in tests/test_clockwork_facestate.py. A corrupt, over-long or no-longer-existing form name is ignored rather than handed to setForm, which no-ops silently on an unknown name.

The startup choice is printed ([face] opening on 'lattice' (remembered='lattice') in /tmp/ghost_ui.log), because otherwise which form the face opened on is observable only by looking at the panel — no help over ssh, and none at all when the screen is asleep.

  • Why a browser and not a port: reimplementing ~2,700 lines of particle engine and GLSL in QPainter would have been a fork with a maintenance tail. QtWebEngine and WebGL 1.0 are both already available on the device, so hosting the original costs nothing to build and nothing to keep in sync.
  • Performance is purely fill-rate bound (measured on the CM4): 16 fps at 1280×720, 35.7 at 854×480, 50.9 at 640×360. Busy state + dive cost nothing extra. GHOST_FACE_ZOOM (default 2.0) shrinks the CSS viewport so the drawing buffer shrinks with it and the browser upscales — and at 640×329 the face also trips its own IS_MOBILE query (max-height: 600px), halving node count 250→120 and bloom scale. That mobile profile exists for exactly this class of GPU.
  • ES modules need HTTP — file:// silently refuses to execute the module (no console error at all), so webface.py serves the bundle from a loopback-bound thread. This is not optional.
  • QtWebEngineWidgets must be imported before QApplication exists, otherwise Qt refuses to construct the view ("must be imported … before a QCoreApplication instance is created") and the face degrades to a blank panel. Hence the module-level import in webface.py plus AA_ShareOpenGLContexts in client.py.
  • three.js r160 is vendored under webface/vendor/ (module + EffectComposer/RenderPass/UnrealBloomPass and their deps) so the device needs no CDN at runtime and the face works offline.
  • Measured CPU after the swap: the client process fell from 61% of a core to below the 3% reporting threshold; QtWebEngine holds ~41% for the rendering. Memory: client ~284 MB, webengine ~233 MB. This contradicts the claim in the legacy notes below that hidden QPainter faces cost zero CPU — on the deployed build they did not, and pausing their timers explicitly changed nothing (60.8% vs 61.0%). Only removing them recovered the core.

Glass UI restyle (2026-08-02)

The face moved from the right half to the background of the whole window, and every panel became tinted glass over it. Placement is unchanged — transcript and input left, chips top-right, status strip bottom-right — but nothing is opaque, so the thermal palette reads through the entire interface.

  • Widget-over-webview compositing works on this device, which is what makes the design possible at all — but only with the face as an explicitly-positioned child plus raise_() on a transparent overlay sheet (WA_TranslucentBackground). The window is a fixed-size frameless kiosk, so no resize handling is needed.
  • The cyan accent was dropped. The face's ring runs blue → violet → crimson with essentially no green channel, so #7be0ff sat outside that range and made chrome and face look like two different applications. The accent is now violet (#c9a6ff) lifted from the face's own mid-palette, with warm sand (#ffc08a) for user text against its crimson core.
  • Qt cannot do backdrop-blur, so readability comes from tint alone: the transcript carries a heavier fill (0.46) than chips and inputs (0.30), rather than the uniform low alpha the web UI can afford with real blur behind it.
  • The left/right split is gone (second pass, same day). Once the panels were transparent the split had no purpose — a nearly-invisible container was still reserving half the screen and still reading as two columns. The transcript container is now fully invisible (no fill, no border) and spans the full width; each message is its own glass bubble that places itself, operator right, agent left, exactly as the web UI does, capped at 54% width so the face stays visible down the middle (the web UI caps at 35% for the same reason — to clear the sphere). Input keeps its bottom-left position and the action chips keep bottom-right; they simply share one row now instead of living in separate columns.
  • Rounded bubbles + typography (third pass, same day). The QTextBrowser was replaced by chatlog.py — a QScrollArea of per-message QLabels — which gets true per-corner radii (notched on the speaker's corner, 16/4/16/16 like the web UI) and content hugging, so a one-word reply is a small pill instead of a half-width slab.
    The non-obvious part: a word-wrapped QLabel reports a SMALL sizeHint().width() regardless of maximumWidth, so any size policy that defers to the hint (Maximum, Preferred) leaves every bubble a narrow ribbon — and raising the cap changes nothing, because the cap was never the binding constraint. _Bubble.fit() measures the text unwrapped, then pins minimum == maximum width to min(natural, cap) so the layout has no choice.
    Typography: markdown arrives as bare <h2>/<p>/<ol> and Qt applies its own defaults — <h1> at ~2x base, <h2> at ~1.5x — so a briefing's headings came out enormous. QLabel offers no document-stylesheet hook, so style_markup() injects sizing inline per tag, with headings only slightly above body size (in a bubble a heading is a label, not a page title). Prose is now SANS (DejaVu/Liberation) at 20px; monospace is reserved for the operator's own messages, inline code and code blocks — mirroring the web UI, where only .message.user overrides to mono. Reading a briefing in 21px monospace was the bulk of "text doesn't look great".
  • Superseded: bubbles as TABLES (square). Qt's rich-text engine lays tables out reliably with per-cell width and background where aligned/floated divs stack unpredictably — but QTextDocument does not support border-radius at all. That is a hard engine limitation, not a styling oversight, so the bubbles use a 2px accent rail on the speaker's side instead of the web UI's notched corners. Rounded bubbles would require replacing the QTextBrowser with a QScrollArea of per-message QLabels.
  • Cost of the glass: translucent widgets must be re-blended as the webview repaints underneath, so the client process went from below the 3% reporting threshold to ~49%, with QtWebEngine at ~32% (load ~2.5 of 4 cores). That is the price of the look; turn GHOST_FACE_ZOOM up to claw it back if it ever feels sluggish.

Legacy: face/ — avatar package (REMOVED 2026-08-02, kept for context)

Three interchangeable faces share one public API (set_mood · pulse · feed_audio · startle · wake · set_state) and one mood system (moods.py: idle/listen/think/speak/error/sleep, palettes lerped over 0.45 s transitions). The default is NetworkFaceWidget; the ◈ toolbar chip cycles to FluidFaceWidget (smoke oracle) and NeuralFaceWidget (iris eye).

  • NetworkFaceWidget (2026-07-12 "tamed" rework) — sparse MoE diagram: 42 nodes / 72 edges (was 111/276), 4 experts, one expert per pulse. A wavefront takes ~1.8 s to cross; activations decay fast enough that a thought visibly passes instead of lighting the whole net. Expert hues are the dark-jewel family: deep violet, crimson, dark blue, dark green. No bloom pass, no offscreen buffer, no wavefront bands, no status readout.
  • Mood palettes follow the same family as the web UI dark theme: idle/listen indigo-blue, think deep purple, speak dark green, error crimson.

Performance model (CM4, software raster — the lessons)

  • All three faces exist in a QStackedWidget, but animation timers are gated by showEvent/hideEvent — a hidden face costs zero CPU. (Previously all three simulated at 30 fps forever: the client pinned a core at ~113%.)
  • Full-screen software ops are the budget: nebula composite, wireframe skeleton, and vignette+scanlines are all cached pixmaps, re-rendered only when their inputs actually change (nebula scroll ~3 s, wireframe 200 ms, vignette per-resize). Grain is the only per-frame overlay blit.
  • Per-node QRadialGradient halos were replaced by flat translucent discs; active edges get one Bézier stroke, not glow+core, and are skipped below the skeleton's own brightness.
  • Adaptive frame rate: 20 fps active moods, 15 fps idle, 10 fps sleep.
  • Measured on-device: client steady-state ~20% of one core idle (was 113%), think ~60% during generation.

External dependencies

  • PyQt6 + qasync + PyOpenGL.
  • httpx, OpenCV (cv2), markdown, subprocess (arecord/aplay).

Voice — repointed 2026-08-02

STT/TTS used to target http://192.168.0.24:8000, a Raspberry-Pi voice server (faster-whisper + Kokoro) that no longer exists — so voice on this device had been failing silently against a dead LAN host, which is why it looked "unused". Both now use the interface's local endpoints (see Voice loop): STT = ffmpeg + the Gemma 4 audio node, TTS = the macOS synthesiser in Ava (Premium) since 2026-08-03. The device inherits the voice change for free — it only ever posts text to /api/tts and plays the WAV it gets back, so nothing on the uConsole needed touching.

Two differences from the old Pi server, both load-bearing:

  • The endpoints live on the interface (port 8080, TLS), not the agent (port 8000, plain HTTP) that chat uses — hence https and a different port. GHOST_VOICE_BASE / GHOST_HOST override the default https://eva:8080.
  • They require X-Ghost-Key, like /api/chat already did. The interface serves a real certificate for its tailnet name (tailscale cert, renewed by §4KR), so TLS verification is on by default (GHOST_VOICE_VERIFY_TLS=0 turns it off). The host is GHOST_HOST, default eva.taila2b1d.ts.net — the name the certificate is for. (Before 2026-09 this page said self-signed, verification off.)

Verified on-device 2026-08-02 (host clockworkpi, aarch64): eva resolves via MagicDNS to the tailnet IP; a real-speech clip posted from the device transcribed correctly; TTS returned audio/wav and aplay -q - played it (exit 0); the default arecord capture device (a USB Logitech BRIO on card 3) records real audio, so no -D flag is needed. STT errors now surface the server's own message instead of a bare status code — "HTTP 503" alone sent one diagnosis down entirely the wrong path.

Two traps found while deploying on 2026-08-03, both of which looked like broken builds:
  • A hand-started client survives every deploy. deploy.sh used to pkill -f 'bin/client.py', which does not match python3 client.py (launched from ~/bin by hand). One such instance ran alongside five successive deploys. Two clients is not cosmetic: they compete for the CM4's single GPU, the newer face never gets a WebGL context, and grim screencopy starts failing. The pattern is now 'client\.py' and the deploy reports the client COUNT.
  • A powered-off panel stalls the face. swayidle -w timeout 600 wlopm --off '*' blanks the screen after 10 minutes idle; while the output is off, grim fails with "failed to copy output DSI-1" and the webview never finishes WebGL init, so no [face] line appears and the remembered form is never applied. wlopm reports the truth (DSI-1 off) where wlr-randr still says Enabled: yes; wlopm --on '*' wakes it and the face comes up immediately.
Deploy note: the LIVE client on the device is ~/bin/client.py (launched by ~/bin/launch_ghost.sh, which sources the ~/gui_env venv and sets QT_QPA_PLATFORM=xcb) — not ~/clockwork_ghost/. Deploy with deploy.sh, never by hand: it stages the build in ~/bin/.stage, compiles and probes it there (device_probe.py), and installs only if that passes (§4KU). ⚠ Since 2026-10-01 the launcher restarts a crashed client: to stop the client by hand, kill launch_ghost.sh first, then the client — a hand relaunch on top of a live launcher is two clients fighting over one GPU. Always diff the device copy against the repo copy first — device-deployed externals can drift. The API key lives at ~/.ghost_api_key (mode 600).

A reply flagged reasoning_unparsed 2026-09-29 §4KP

Same contract as the CLI: on {"ghost": {"reasoning_unparsed": true}} the client holds the reply — neither shown nor spoken — until the stream's own [DONE], then emits and speaks strip_orphan_think_close(reply) (a copy of the agent's rule, pinned by the parity table). Speech cannot be taken back, which is why the hold exists. An error frame is now shown (the client used to ignore it); reading continues, because the agent may still send its fallback sentence after an abort frame, but a held reply is never released after one. The stream is read one SSE line at a time (aiter_lines). Unflagged replies stream and speak as before.

The UI/UX pass 2026-10-01 §4KU

A review of the client on the device (code, a screenshot, CPU samples) found five visible defects and a dozen daily-use gaps; fixing them found two worse ones that had been there all along. What changed, and where each piece lives:

Where the logic went

client.py and chatlog.py import PyQt6, which exists only on the handheld, so nothing in them can be executed by the test suite. The decisions were therefore moved out into five modules that import no Qt and are unit-tested (tests/test_clockwork_ux.py):

ModuleWhat it decides
markup.pyWhat a bubble draws: markdown → HTML, chat-sized typography per tag, wrapping for code and long unbroken runs, escaping.
speech.pyWhat is said aloud (SpeechChunker), and the chime.
devstatus.pyBattery, wifi, the status readout, backlight, volume, the panel, and the face's frame rate.
agentapi.pySessions, stop, ratings, notifications, frame parsing, error wording.
commands.pyWhat counts as a slash command, and which must be typed twice.

What only a real Qt can show is checked by device_probe.py (below).

Two crashes that were already there

  • A turn that failed before its first token killed the client. ChatLog.end_agent removed the empty waiting bubble by looking up bubble.parentWidget().layout() — which is not the bubble's row but the transcript's whole column — and unparenting it. The next message added to the log segfaulted. That path runs whenever the agent is unreachable, answers an HTTP error, or refuses the key: exactly when the client most needs to stay up. Reproduced on the device against the build then live. The bubble now removes its own row.
  • Every turn left the stream half-closed. The loop did break at [DONE], which leaves httpx's chain of async generators suspended; qasync installs no async-generator finalizer, so they were torn down by the garbage collector mid-await ("async generator ignored GeneratorExit", anyio's "exit cancel scope in a different task"). It went unseen because the client's stderr went nowhere. The loop now reads to the end of the stream, which the agent closes straight after [DONE].

Also fixed in the stream loop: a frame whose choices is an empty list (the usage frame) raised IndexError out of the stream. Frame parsing is agentapi.frame_content now and accepts any shape.

The transcript

  • Bubbles shrink again. QLabel.sizeHint() is expanded to the widget's minimumSize(), so once fit() had pinned a width the "natural" width could never come back smaller. Every reply opens as a waiting caption (~540 px), so every short answer stayed 540 px wide ("Hello!": 540 px after a caption, 120 px fresh). fit() releases the pin before measuring.
  • Nothing is clipped. A word-wrapped QLabel wraps at word boundaries only and a <pre> not at all: a 1,078 px code line in a 670 px column ran off the edge with no way to scroll to it. Code is white-space: pre-wrap (indentation kept), and a run of more than 40 non-space characters gets a zero-width break every 20. ⚠ Those breaks are real characters: text copied out of a bubble carries them.
  • The view follows new content only while you are at the bottom. It used to jump to the end on every streamed token. Scrolling up stops the following; returning to the bottom (or sending) resumes it. PgUp/PgDn and Shift+↑/↓ scroll from the input, which never loses focus.
  • The agent's bubbles may take 70% of the width (was 56% — a briefing left nearly half the panel empty); the operator's stay at 56%. GHOST_BUBBLE_AGENT / GHOST_BUBBLE_USER.
  • The operator's own text is escaped (a typed < used to be swallowed as markup), as are error messages, notification text and session titles.

One turn at a time, and a way to stop it

There was no guard: Enter during a reply started a second stream into the same bubble. Every message now goes through _submit, which refuses while a turn runs — at the moment of commitment, because the camera dialog is modal and a turn can start underneath it. The text stays in the input.

■ STOP / Shift+Esc / /stop cancels the turn on the agent (/api/turn/cancel), by the request id this client minted for it and nothing else. The first press asks the agent to stop at its next boundary; a second forces it. ⚠ An earlier draft fell back, on a 404, to "the turn in my session" and "the turn whose text starts like mine" and a reviewer cancelled a browser's turn with it; a 404 now only ever leads to one retry of the same id (the turn may not have registered yet).

Sessions

The conversation used to live only in the process: a restart, a crash or a reboot lost it. Every turn now carries a session_id (kept in ~/.ghost_session_id), the agent stores the conversation under it, and the client restores it at startup. /new (or /clear) starts a new id — reusing the old one would bring every earlier message back into the next turn. /sessions lists recent conversations from any client and /open N continues one, which is how a chat started in the browser is picked up on the handheld.

Commands

The old test was text.startswith('/clear'): /clearly that is wrong wiped the conversation and /shutdown powered the device off on Enter. The rule now turns on what follows the word (commands.parse):

  • a command alone, or with the argument it takes → the command;
  • a no-argument command followed by one stray word (/stop it) → nothing runs, the text stays in the input;
  • a command word followed by a sentence (/new idea: use a queue, /help me fix the parser) → a message, and it is sent;
  • an unknown word alone, or a near miss with one argument (/hlep, /brigth 5) → answered locally with a suggestion, text kept;
  • anything with a second slash (/etc/hosts) → a message.

/shutdown, /reboot and /exit must be typed twice within 10 s, with nothing else in between.

Voice

  • What is spoken. The old splitter read everything: code symbol by symbol, table rows, URLs. SpeechChunker skips fenced code and tables, reads a link as its label and a bare URL as "a link" — and gives the same utterances however the token stream is cut (the tests fuzz that).
  • Barge-in. Starting a recording stops playback and drops what was queued, and nothing is queued while recording (the agent used to talk into the open microphone).
  • A moment to correct. A transcript sits in the input for 2.5 s (GHOST_STT_REVIEW_S) before it sends itself; any key but Enter stops the countdown. In face-only mode it sends at once.
  • Tap or hold. A tap of Esc toggles the recording (tap again to send); Esc held for 0.4 s or more (GHOST_PTT_HOLD_S) is push-to-talk — letting go sends. ⚠ Holding Esc used to be a storm: a QShortcut auto-repeats while its key is held and this one is a toggle, so the recording started and stopped some twenty-five times a second, each stop uploading the file the next start was already rewriting ("STT Error: Too much data for declared Content-Length", eleven in a row on the device). No shortcut auto-repeats now, every recording has a file of its own, and the clip is read into memory and its file removed before the upload begins. A recording shorter than 0.3 s is a slip of the key and is not uploaded.
  • The PTT chip shows elapsed time, and a recording ends itself at 120 s (GHOST_PTT_MAX_S) — a tapped recording can be left on by accident.
  • A voice failure is shown once in the transcript; it used to be a print() per sentence into a log that did not exist.

The face: slower when nobody is looking

Measured with nothing happening, before: client 47% of a core, web renderer 32.5%, compositor and XWayland about 8% — the face redrawing at full rate behind glass that re-blends on every frame. devstatus.face_rate now picks a rate from activity:

StateRateKnob
turn in flight, speech, recording, or input in the last 45 sfull GHOST_FACE_IDLE_S
idle10 fps (5 on battery) GHOST_FACE_IDLE_FPS / GHOST_FACE_BATTERY_FPS
idle past 600 s (the panel has blanked)paused GHOST_FACE_SLEEP_S

Measured at the 10 fps cap on the device: client 18–19%, renderer 12%, compositor and XWayland about 3% — roughly 33% of a core in place of 88%. The cap is webface/throttle.js, a wrapper around requestAnimationFrame loaded before the face module (which stays a byte-for-byte copy of the browser's). Two things about it: it is a ceiling (10 draws about 9), and below 20 fps the face runs in slow motion, not just choppily, because matrix_graph.js clamps a time step at three frames. Any key lifts the cap at once.

The face also now gets the browser's signal layer — a gait per step class, a kick per tool call, a comet per recall, a verdict-shaped release, a second breath while a background turn holds the lock — from the log lines the client already received (turnstatus.face_signals_for_ticker, a port of app.js's; the test runs the original under node and compares).

Small things the kiosk could not do

  • /bright 1-9 | + | - (never 0: at zero the panel is black and the command to undo it is typed blind) and /vol 0-100 | + | - | ±N.
  • A reply that lands on a dark panel wakes it (wlopm --on), and chimes if the turn took 20 s or more or the panel was off (GHOST_CHIME_AFTER_S, 0 = off; never when replies are spoken).
  • ▲ GOOD / ▼ BAD (Ctrl+↑/↓, /good, /bad why) rate the last reply through /api/feedback. Off while a new reply is arriving, and for a reply the agent filed no trajectory for.
  • What the agent did while nobody was asking (/api/notifications/pending, consumer clockwork) appears in the transcript, and is spoken when TTS is on. The ack rules are the Slack bot's.

Launcher and deploy

  • launch_ghost.sh owns the log and restarts a crash. The autostart entry ran it with its output going nowhere, so after an ordinary boot /tmp/ghost_ui.log did not exist. It now writes the log itself (the previous run is kept as .1) and restarts the client when it crashes: exit 0 (/exit), 130 and 143 (a deliberate signal) stop; anything else restarts, with a doubling wait, and five crashes in a row give up.
  • deploy.sh stages, probes, then installs. The build is copied to ~/bin/.stage, compiled, and device_probe.py is run there; only if it passes is anything installed. The launcher is replaced by rename (it is a running script), the three newest backups are kept, and the restart is confirmed by the same pid six seconds apart and no CRASHED line — "a client is alive" passed on a crash loop, because the launcher had restarted it.
  • device_probe.py builds the real MainWindow offscreen on the device, with the WebGL face replaced by a recorder and the agent by a fake served from a thread, and drives real turns through it: 98 checks. It replaces the three things the client does to the device (killing playback, running helpers, power commands) with recorders, so it is safe beside the live client. Broken on purpose 29 ways, it failed 29 times.
