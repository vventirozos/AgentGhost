interface / server.py

Browser-facing FastAPI proxy on port 8080. Handles auth, streaming, file I/O, log tailing, voice forwarding.

Streaming model

  • Per-task state dict keyed by UUID in global active_chat_tasks.
  • Background worker spawned on POST /api/chat with stream=true, sharing a pooled httpx.AsyncClient.
  • The worker reads upstream chunks and appends bytes to task["buffer"]; an asyncio.Event signals new data.
  • The stream generator yields by chunk index (not byte index) and clears the event before draining to avoid races.
  • Truncation is detected via task["truncated"] and surfaces as an SSE error marker.
  • Resume endpoint accepts an offset for reconnection.
  • A janitor task evicts done tasks past 10-min TTL or hard cap of 200.

Request timeouts

Chat proxying to the agent backend uses a split httpx.Timeout built by _chat_timeout(), applied to the shared pooled client, the streaming client.stream() call, and the non-streaming client.post() call.

  • Read / write / pool: CHAT_TIMEOUT_S (env GHOST_CHAT_TIMEOUT, default 1800s / 30 min). This is the ceiling that matters for long turns. httpx's read timeout is the max gap between received bytes, not total wall-clock — a long agent turn (deep browser automation, many sequential tool calls) can run for minutes without flushing any SSE bytes. The old flat timeout=600.0 fired the read timeout at 600s, aborted the stream, and the UI rendered a bare "No response" because no assistant tokens had arrived yet. Raising this prevents that premature cut.
  • Connect: CHAT_CONNECT_TIMEOUT_S (env GHOST_CHAT_CONNECT_TIMEOUT, default 10s). Kept short and separate so a genuinely down backend still fails fast instead of hanging for the full read window.
  • The browser front-end (app.js) imposes no timeout of its own — it streams via fetch until the reader reports done, and only aborts on explicit user action (stop button). The server-side ceiling above is therefore the effective limit.

Buffer & payload limits

  • Per-task stream buffer cap 50 MB (GHOST_INTERFACE_STREAM_CAP).
  • Global stream buffer ceiling 200 MB across all chat tasks (GHOST_INTERFACE_TOTAL_STREAM_CAP) — the per-task cap alone still allowed hard-cap × 50 MB ≈ 10 GB worst-case. On overflow the worker first reclaims the oldest done tasks' resume buffers (_reclaim_buffered_bytes) — otherwise a few large completed turns would brown-out every new stream for up to the 10-min TTL — and only truncates (same BufferCapExceeded marker, message says which cap fired) if live streams alone exceed the ceiling. A resume of a reclaimed stream 404s.
  • Request body: max 500 chat messages.
  • Body sizes are enforced at the ASGI layer by BodySizeLimitMiddleware BEFORE parsing: upload routes (upload, workspace/load, stt) get MAX_UPLOAD_BYTES (100 MB, plus 1 MB multipart-envelope slack), every other POST body is JSON and gets MAX_JSON_BYTES (env GHOST_INTERFACE_MAX_JSON_BYTES, default 10 MB). Oversized declared Content-Length → immediate 413; chunked bodies with no declared length are counted as they arrive and aborted on overflow. This matters because FastAPI parses the entire multipart body (spooling to disk) before a handler runs, and request.json() slurps the whole body into RAM — a handler-level check alone fires only after the bytes were already received.
  • Upload body backstop: 100 MB per-file cap via _read_capped_upload(); 64 KB chunks; rejects non-bytes.

Document caching

The root GET / reads index.html from disk on every request (so front-end edits need no server restart) and serves it with Cache-Control: no-cache, must-revalidate, private. Static assets are cache-busted via a ?v= query (e.g. style.css?v=2.7); without no-cache on the document, a browser holding a cached copy of the HTML would keep referencing the old ?v= and never fetch updated CSS/JS until a manual hard refresh. private stops shared proxies caching the document, which carries the injected GHOST_API_KEY. Guarded by tests/test_interface_index_no_cache.py. Note: bumping the ?v= on changed assets in index.html is still required for those assets themselves.

Log streaming

A log_streamer() task spawns tail -f on the agent log and broadcasts to connected websockets. Detects ERROR/Exception and tags is_error for client reactivity. Lines decode with errors="replace" (binary garbage in the log must never kill the loop), and the tail subprocess is reaped with timeout-then-kill in a finally — i.e. on every exit path, not just cancellation. Broadcast is concurrent with a per-send timeout (GHOST_WS_SEND_TIMEOUT, default 2 s): a stalled client is evicted and closed instead of back-pressuring the whole broadcast (and, transitively, the tail pipe) for everyone else.

Auth

  • GHOST_API_KEY mandatory; the module fails to import without it.
  • All state-mutating endpoints depend on verify_interface_key() which compares X-Ghost-Key.
  • The page itself is gated by a query parameter check (browsers send keys in URL on first load only).
  • CORS: allow_origins=*, allow_credentials=False.
  • Key provenance (2026-07-13 rotation): the prod key comes from the canonical mode-600 secret file ~/Data/AI/.ghost_api_key, exported by bin/start-ghost-client.sh — this deliberately OVERRIDES the stale GHOST_API_KEY=ghost-secret-123 still present in /Library/LaunchDaemons/com.local.ghost-client.plist (plist edit needs sudo; the old public key no longer works anywhere). The same value is the AGENT's key (agent auth enabled the same day), which is why the baked upstream X-Ghost-Key keeps working. Bookmarks using ?key=ghost-secret-123 must be re-saved with the new key.

Concurrency

  • asyncio throughout; one shared httpx.AsyncClient pool.
  • FastAPI Depends(verify_interface_key) for auth.
  • StreamingResponse with custom generator for back-pressure.
  • Background tasks for upstream polling + log streaming.

Live log stream — path + resilience (2026-07-12)

The tail target defaults to ~/Data/AI/Logs/ghost-agent.log, overridable via the GHOST_AGENT_LOG env var — the --agent-log flag can never arrive in the prod deployment because uvicorn server:app owns sys.argv. The previous default was missing the Data/ segment, so the live-log stream (face pulses, planner monologue) tailed a nonexistent file and was silently dead in production (tail -F retries forever without erroring). The streamer is also now a restart loop: if the tail subprocess ever exits, it respawns after 5 s instead of ending the stream until the next server restart. Hardening in the same pass: the stream-buffer cap now closes the upstream connection when hit (it previously kept draining a discarded stream for up to 30 min), and a text form field named file on /api/stt is a clean 400 instead of an AttributeError 502. Regression-guarded by tests/test_interface_log_and_mobile.py.

Mobile / touch

The UI is touch-ready: 100dvh layout (no Safari address-bar jump), ≥16 px inputs (no iOS zoom-on-focus), 44–52 px touch targets, hold-to-talk with the full touchstart/touchend/touchcancel lifecycle + touch-action:none on the mic (the long-press belongs to the recording gesture, not text-selection or the iOS callout), wss: auto-selected under TLS, and an iOS getUserMedia permission timeout. The service worker does not register over a self-signed cert (browser policy) — which is why the mobile entry point is the tailscale-served front door below, not :8080 directly. The face-form menu clamps to the viewport on BOTH axes and scrolls internally (max-height) — a right-anchored menu near the left edge of the centered phone header used to hang half off-screen (2026-08-01; tests/test_interface_log_and_mobile.py + Playwright verification).

Empty-state splash (redesigned 2026-08-16)

The first screen of an empty chat is a hairline GHOST wordmark (200-weight, wide tracking, letters fading up in a short cascade), a hairline rule that draws itself outward, and one line of orientation (Ask anything · ⌘K for commands; the shortcut half is dropped on coarse pointers). There are no suggestion chips.

The previous version carried a 2.2 rem/700-weight wordmark with 10 px tracking, two stacked text-shadows, an infinitely sweeping gradient, and three starter prompts ("What are you capable of?" …). It sits on top of the live animated face, so that was two competing animations plus a button row over the most striking element on the screen — the operator's verdict was "ugly". An empty state is a threshold, not a billboard. Motion is disabled under prefers-reduced-motion, and the last letter's trailing tracking is pulled back (margin-right: -0.42em) so the word is optically centred. Pinned by tests/test_webui_splash_and_ios_keyboard.py.

iOS keyboard: the composer-at-the-top bug (fixed 2026-08-16)

On iOS, after a long reply, the composer could jump to the top of the screen and overlap the status bar while the keyboard was open. Cause: two keyboard-avoidance mechanisms both applying.

  • syncBodyHeight pins document.body to visualViewport.height whenever a keyboard is genuinely open — which by itself already lifts the footer to sit just above the keyboard;
  • the --keyboard-height custom property additionally translates #ui-layer up by the same distance.

Together that is the same correction twice, and the composer leaves the top of the screen. The transform is still required for the window the body pin does not cover (_vvKeyboardOpen() also needs this orientation's max height to be learned and the drop to exceed 80 px, so a just-focused input still relies on it), so the fix is mutual exclusion, not deletion: updateKeyboardOffset zeroes the offset exactly when the body pin is active. Whichever is doing the work, exactly one of them is.

Mobile app model — PWA, resume, web push (2026-08-01)

The client now behaves like the Claude/Gemini mobile apps: send a request, lock the phone or kill the tab, the agent keeps working, the reply is there when you return, and a push tells you it's ready. Four cooperating pieces:

  • Trusted front door. tailscale serve --bg --https=8443 https+insecure://127.0.0.1:8080 fronts the self-signed uvicorn with a real LE cert at https://<your-host>.ts.net:8443/?key=… (tailnet-only). Service workers and APNs web push both require trusted HTTPS, so the phone must use this URL. Disable with tailscale serve --https=8443 off.
  • PWA install. GET /manifest.webmanifest (key-gated like /; the link is INJECTED by server.py so its URL — and the manifest's start_url — carry the access key without ever placing it in the unauthenticated /static mount). apple-touch-icon + icons under static/icons/. iOS delivers web push ONLY to Home-Screen-installed PWAs, so the SW registration gate is (!isIOS || isStandalonePWA) — the old blanket !isIOS skip kept even installed PWAs pushless.
  • In-flight turn survival (app.js `ghost_inflight_turn` + GET /api/chat/task/{id}/state). The proxy already buffered every stream (task lives while running + 10 min after; TTL counts from COMPLETION) and the agent persists finished replies into the session store — what died with the page was only the in-memory task id. The handle is now persisted; on boot / visibility-return / bfcache-restore the client probes task state and either reattaches the live stream (fresh thinking bubble + /api/chat/resume), polls a still-running agent turn (/api/turns), or ADOPTS the session's server-side history wholesale — never appends, which would recreate the merge_history doubling case. Suspend/resume is SILENT (2026-08-16, operator request): the old "Safari suspended the UI…" and "Reconnected directly to Ghost Server." system bubbles are gone — the reply stream continuing is the only signal; only genuine errors and user cancels still surface as system messages. Pinned by tests/test_interface_silent_resume.py (the silence, the latched and 3-attempt-capped network resume, structured error rendering) and tests/test_webui_console_review.py (the ADOPT-not-append property itself — previously attributed to the silent-resume suite, which never asserted it).
  • Web push (interface/webpush_notify.py; VAPID keys ~/Data/AI/.ghost_vapid.json, subscriptions ~/Data/AI/.ghost_push_subs.json, both 0600). Two producers: (a) reply-ready — the stream worker schedules a probe at completion; if live page JS didn't confirm delivery via POST /api/chat/ack/{id} within the grace window (GHOST_PUSH_ACK_GRACE, 12 s — server-side "stream drained" is NOT proof: a locked phone's dead socket swallows the tail into TCP buffers), every subscribed device gets a push with a preview of the request; (b) the agent's notify-severity ledger via a 30 s poller under its own watermark consumer web-push (≤5 pushes/cycle; overflow is acked unpushed and stays in the bell). sw.js shows a notification per push (iOS revokes subscriptions on silent pushes) and opens the KEYED url on click. Endpoints: GET /api/push/vapid, POST /api/push/subscribe (upsert by endpoint), POST /api/push/unsubscribe; dead subscriptions (404/410) are pruned on send. Hardening from the same-day review: pywebpush gets a py_vapid.Vapid INSTANCE built from the PEM (passing PEM text dies inside Vapid.from_string — push was silently dead until the real-crypto test existed); a user-cancelled turn sets cancelled and never pushes; the client compares its subscription's applicationServerKey against /api/push/vapid and re-binds on VAPID rotation; the notify poller keeps a last-acked watermark (no 30 s notify_consumers.json mtime churn); resume has a synchronous re-entry latch + tab-ownership heartbeat (two concurrent resumes replayed one stream into one bubble twice), /clear drops the in-flight handle, and session-mismatched handles are discarded rather than resurrecting a cleared conversation. Tests: tests/test_interface_push_and_resume.py (incl. REAL py_vapid/pywebpush signing+encryption with only the HTTP POST faked — the test that catches key-format regressions).

iPhone setup (one-time): open the 8443 URL in Safari → Share → Add to Home Screen → open the installed app → tap anywhere once to grant notifications. Uninstalling the PWA or clearing Safari data kills the push subscription; re-opening the app re-subscribes automatically.

A MutationObserver in app.js watches #chat-log for tool-emitted artefact links. Two cases:

Instruments. The suites now EXECUTE the client's branchy helpers under node (tests/helpers.eval_js, extract_js_function, extract_js_listener) because if (true) / if (false) walks straight through any token assertion — that is how void 0 && addMessage(…) and authFailed = false && … survived. tests/test_interface_cachebust.py fails when a static module changes without its ?v= moving, and when a leaf is bumped without its ancestors (which ships nothing). Three tests were found fully vacuous and rewritten: one asserted that set.discard does not raise (testing CPython), one compared 200 against a mock returning 200, and one hand-rolled an app that never catches — so the BaseException escape hatch _BodyTooLarge exists for was never exercised.

2026-09-04 UI/UX audit fixes

Found by auditing the live server headlessly (Playwright at six viewports, 1512×945 down to 375×667 plus an 844×390 landscape phone) and measuring contrast ratios, touch-target sizes and layout geometry in-page, rather than by reading the source. Every fix is mutation-pinned; the suites are tests/test_interface_markdown_render.py, tests/test_interface_rail_dismiss.py, tests/test_interface_contrast.py and tests/test_interface_a11y.py.

  • Agent markdown had nowhere to land (HIGH, closed). style.css styled pre, code, ul/ol, blockquote, a and img inside .message — and nothing else. table, th, td, h1–h6 and hr took the UA defaults inside a bubble designed for none of it. Measured on a live reply: th padding was the UA's 1px with border-collapse: separate, so a four-column comparison rendered as ragged text whose columns could not be told apart — the table was worse than the list it replaced; hr came out as the UA's rgb(128,128,128) groove, the brightest element in the bubble, reading as a heading underline rather than a section break; h2 landed at 2em UA bold beside 0.95rem/300 body text. Tables now collapse their borders with 7×10px cells and a mono eyebrow header row; headings differentiate by weight and the mono/sans axis rather than by scale (h3 and below become mono eyebrows — at these sizes a half-step of scale is invisible but a family switch is not); hr is a fading hairline matching .empty-hero-rule. A table wider than the bubble now SCROLLS instead of being crushed: decorateTables() in app.js wraps each one in a focusable .table-scroll region and the table takes width: max-content. Idempotence comes from the DOM (is my parent already a wrapper?) rather than a data- marker — streaming re-runs the decorators on every chunk, and mutation testing showed the marker the first version carried was fully redundant with the derived check, as well as being able to go stale in a way the derived check cannot.
  • The sessions drawer never closed after you picked a session (HIGH, closed). workspace.js had passed isDocked and setRailOpen into the sessions context since the rail was built, and sessions.js destructured neither — a capability plumbed all the way in and never consumed, which nothing failed on because nothing looked. On a phone you tapped a conversation and the rail stayed over it: the one action the drawer exists for gave no sign it worked. switchTo and newChat now dismiss the drawer on success (and on re-tapping the session already open, which is still a navigation gesture), while deliberately NOT dismissing on the mid-turn refusal or a failed load — closing the rail under an error toast reads as success for something that did not happen. Docked rails never close: there the rail is the navigation, not an overlay. The dismissal passes persist=false, which is load-bearing — setRailOpen's default writes ghost_rail_open, which initRail and the docked-media-query handler both read, so persisting would mean that picking a session on a portrait tablet and then rotating to landscape (crossing the 900×500 docked threshold) brought the docked rail back CLOSED.
  • Three text styles failed WCAG AA (MED, closed). Measured in-page: .session-meta ("1h ago · 48 msgs", the line you navigate the rail by) at ~3.1:1 and 9.9px, .msg-time at ~3.2:1, both rgba(158,170,192,0.55) → 0.75. #planner-monologue was #c22745, which is --error-color verbatim: ordinary planner narration was painted in the colour reserved for failure, and measured 3.6:1 besides — now the #b894ff accent already used by .notif-phase. The pin RECOMPUTES the ratio from the shipped value; a text assertion cannot tell 0.55 from 0.75, only that somebody wrote an rgba. Note the model composites over the DECLARED surfaces, which is the optimistic bound — these sit on translucent panels with a backdrop-filter over the animated face, so the real backdrop varies frame to frame and a brighter face lowers the true ratio further.
  • Sixteen controls had no accessible name, including the send button (MED, closed). #send-btn — the most-used control in the app — carried no title, no aria-label and only an inline SVG, so assistive tech announced it as "button"; fifteen other icon-only controls had a title and nothing else, and title is not surfaced by touch at all. Names that CHANGE with state are set in JS rather than markup: #send-btn flips Send / Stop the current turn / Working, and #workspace-btn flips Load / Save with its title. A static name on a control whose meaning changes is worse than none, because it is confidently wrong.
  • The focus ring was a hand-kept list, and the primary actions were not on it (MED, closed). :focus-visible enumerated ten selectors; #send-btn, #mic-btn, #palette-input, .face-form-item and #delete-all-sessions-btn were missing, so a keyboard user tabbing to the primary action saw nothing. Replaced with a rule over the interactive element types, wrapped in :where() to keep specificity at 0-1-0 so components can still override it. The first version of this fix had the same bug it fixed: at 0-1-0 it was outranked by four outline: none declarations on IDs (#chat-input, #session-search, #palette-input, #memory-match/#memory-replacement), and a real browser computed outline-style: none on all four while every selector-coverage test passed — asking "does a rule match?" is a proxy for "is a ring visible". Three of those suppressions are gone; #chat-input keeps its as the one DECLARED exemption, because #input-area:focus-within restyles the whole composer pill (border, fill, glow and a 2px lift), which is a stronger indicator than a ring around a borderless textarea inside it. That exemption is asserted, not just commented: the test fails if the focus-within rule is ever removed while the suppression stays.

Not fixed, recorded here as known.
