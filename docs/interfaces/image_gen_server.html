interface / externals / image_generation / img_gen_server.py

SD1.5 image-generation node on the Jetson Orin Nano (8GB, CUDA). Current checkpoint: DreamShaper 8.

Endpoints

Method · PathBehaviour
POST /generate · POST /v1/images/generationsBody: {"prompt", "negative_prompt", "steps", "width", "height", "size", "seed", "clip_skip"}. Requires X-Ghost-Key. Size clamped to a VRAM-safe pixel budget. Returns {"data": [{"b64_json": ...}]}.
GET /health · GET /readyUnauthenticated. /health reports {ok, ready, load_error}; /ready is 200 when the model is loaded, 503 while warming, 500 on load failure.

Model & scheduler

  • StableDiffusionPipeline.from_single_file on models/dreamshaper_8.safetensors, torch.float16. DreamShaper 8 replaced CyberRealistic v9 (2026-07-26): same SD1.5 size/VRAM/speed, but versatile — photoreal, fantasy, surreal, cartoon/illustration — with style chosen by the prompt.
  • DPMSolverMultistepScheduler pinned to DPM++ 2M Karras (use_karras_sigmas=True, algorithm_type="dpmsolver++").
  • clip_skip defaults to 2 (DreamShaper's recommendation); callers can override per request.
  • VAE: the checkpoint's baked VAE by default; IMGGEN_VAE=clear switches to ClearVAE fp16 (only if colors wash out).
  • Default negative prompt bans quality defects only — it deliberately does not ban cartoon/anime/3d-render, since those are now legitimate styles.

Tunables

  • Sizes: default 512×768, per-side cap 768, area budget 512×768 px (768² OOM-asserts on the 8GB Jetson).
  • Steps: default 30, floor 15 (below that a non-LCM SD1.5 model looks bad), cap 50. Guidance 6.0.
  • Queued requests wait up to 180s for the GPU, then 503.

Boot & resilience

The port binds in ~1–2s; torch/diffusers imports and the model load run in a background thread (requests get a clean 503 while warming). A post-restart CUDA-teardown OOM (Tegra NvMap still releasing) retries up to 5× with 20s backoff instead of parking until a manual bounce. One dedicated GPU thread serialises all CUDA work.

Prompt quality layer

A1111-style attention weights ((x:1.4), [x]) are parsed for real, and arbitrary-length prompts are encoded via 77-token chunking (the "lpw" approach) — nothing is silently truncated. clip_skip selects the penultimate CLIP layer A1111-style.

Auth (2026-07-15). The node binds 0.0.0.0 on the LAN and a generation monopolises the GPU for ~30–60s, so /generate requires the fleet X-Ghost-Key (resolved from GHOST_API_KEY env, else ~/Data/AI/.ghost_api_key, else the server refuses to start — an explicit GHOST_API_KEY='' knowingly disables it on a trusted network). Auth is checked before the readiness gates, so an unauthenticated caller can never probe warmup/GPU state. Monitoring endpoints (/health, /ready) stay open. The agent stamps the key only on its image_gen httpx pool (llama.cpp pools don't check keys). Covered by tests/test_imggen_node_auth.py.

Dependencies

  • diffusers (StableDiffusionPipeline, AutoencoderKL, DPMSolverMultistepScheduler)
  • torch (float16, CUDA)
  • PIL, fastapi/uvicorn
