interface / voice.py

The local voice loop: speech-to-text on the Gemma 4 audio node, text-to-speech on the macOS synthesiser in Ava (Premium). No extra hardware, no API key, no egress.

There is no voice server any more. This page keeps its filename for stable links, but nothing here is a separate service: STT is an HTTP call to a worker node the agent already runs, and TTS is a subprocess on the interface host. The only moving parts are interface/voice.py and the two proxy routes in interface/server.py.

What changed (2026-08-02)

The push-to-talk UI has shipped since 2026-07 (mic button, MediaRecorder, full touch lifecycle in app.js), but /api/stt and /api/tts proxied to a separate voice server on a Raspberry Pi / Jetson running faster-whisper + Kokoro. That host no longer exists. The default raspberrypi.local does not resolve, and the launcher's override http://disorder:8000 resolves on the tailnet but listens on nothing — so the mic button was a no-op against a dead node, the classic silent-inoperative-subsystem shape.

Both halves now run on infrastructure that is already live and already supervised. The wire contract is unchanged — /api/stt still returns {"text": …} and /api/tts still returns audio bytes — so the existing browser UI needed no modification.

What changed (2026-08-03)

  • Voice switched to Ava (Premium), a neural voice, from Samantha (which had itself replaced the Daniel en_GB male voice the day before). Verified end-to-end rather than by inspection: audio returned from the live /api/tts endpoint is byte-identical (SHA-256) to a local say -v "Ava (Premium)" render of the same text, which is what rules out the silent-fallback failure below — a wrong voice name still returns 200 and plausible audio.
  • The last PI_VOICE_URL setter is gone. The variable had been dead in code since 2026-08-02 but was still exported by bin/start-ghost-client.sh and still documented as a live knob on two pages — a reader configuring voice from the docs would have set a variable nothing consumes. Launcher line removed, docs corrected, and a test now guards the settings tables.

The deleted external (interface/externals/tts_stt/)

Removed 2026-08-03, along with its soundfile pin. voice_server.py was a FastAPI "Orin Nano Optimized Voice Node" running faster-whisper + Kokoro on the companion GPU box. It had been unreferenced since 2026-08-02 and unrunnable on this host (neither kokoro nor faster_whisper is installed), and it was the only importer of soundfile>=0.12.0 — so a dependency was being carried, and documented as required, for a service that could not start.

The live voice loop needs no Python audio library at all: ffmpeg for transcode and the system say binary for synthesis. Design record for anyone rebuilding a GPU voice node, since the file is gone and this project has no version control:

Grep trap, now one hit shorter. Searching the tree for TTS used to surface that file's voice='af_heart' first — the wrong answer to "what voice does this agent use". One decoy remains: src/ghost_agent/core/tts.py is test-time scaling, not text-to-speech. The only real answer is interface/voice.py.

⚠ The launchd PATH trap (cost every STT request a 503)

launchd hands a service a minimal PATH — /usr/bin:/bin:/usr/sbin:/sbin — which does not include Homebrew. say lives in /usr/bin so TTS worked, but ffmpeg and ffprobe live in /opt/homebrew/bin, so a bare shutil.which("ffmpeg") returned None and every STT request 503'd under the daemon while working perfectly from a shell — which is precisely why it survived testing. It presented as a Safari-only failure; it was not browser-related at all.

Both call sites now use resolve_binary(): explicit GHOST_<NAME>_BIN override → PATH → known install prefixes (/opt/homebrew/bin, /usr/local/bin, /usr/bin, /bin). The error text names launchd and the override rather than the misleading "not installed". memory/audio_ingest.py had the identical latent bug — the agent is also a LaunchDaemon — and was fixed with it. Standing checklist item: anything a daemon shells out to must not trust the inherited PATH.

Two traps, both measured

  1. The empty-response trap. Gemma 4 emits thinking blocks that its chat template strips. With max_tokens too low the entire budget goes to thinking and the API returns empty content with finish_reason="length" — no error, just nothing. Measured: 256 tokens → ''; 1024 → correct. transcribe() detects that exact shape and raises, because a silent "" would be auto-sent to the agent as an empty prompt.
  2. The dialect trap. Audio must ride an input_audio part. The audio_url data-URI shape tools/vision.py uses for images is rejected with 400 unsupported content[].type — so this is deliberately not a copy of the vision payload builder.

Measured characteristics (live, 2026-08-02)

  • 25.0 audio tokens per second — constant across 3.2 s, 38.9 s and 377 s clips.
  • ~11× faster than real-time — a 6.3-minute clip processed in 33.6 s.
  • No encoder window limit — codewords at the start, middle and very end of a 6.3-minute clip were all recovered. Chunking is a context-budget concern only.
  • Push-to-talk round trip (3.6 s clip, browser-shaped WebM/Opus): ~6 s.

Design notes

  • Verbatim transcription, not intent extraction. The transcript goes straight to the 35B agent, which is the thing that should interpret intent — summarising on the small model would discard information before the smart model sees it. Verbatim also preserves the spoken language (no forced translation).
  • Text reaches say through a file (-f), never argv or a shell string: agent replies routinely contain quotes, backticks and newlines.
  • Errors carry their own HTTP status. VoiceError distinguishes an unusable upload (4xx) from a backend failure (5xx), so a client mistake is never reported as a 502.
  • Privacy. Audio never leaves the tailnet. Keyless local processing is the only speech path compatible with the no-identity-egress rule — this capability cannot be bought, only built.

Tests

tests/test_interface_voice.py (28) — dialect guard, thinking-trap detection, silence vs failure, duration cap, argv-injection resistance, dead-host regression guard. The TTS content-type test in tests/test_interface_review_fixes.py was replaced: the Pi passthrough it guarded is gone by design.

Four guards added 2026-08-03, all aimed at the same failure mode — speech that keeps working while quietly using the wrong voice, which no ordinary assertion catches because the endpoint still returns 200 and valid audio:

  • test_configured_voice_is_passed_to_say_as_one_argv_element — the name contains a space and parentheses. Split across argv, say would see Ava and (Premium) as separate arguments, exit non-zero, and drop onto the fallback.
  • test_unavailable_voice_falls_back_without_the_v_flag — the retry must carry no -v at all, or it re-fails on the same missing name. Asserts exactly two invocations.
  • test_premium_voice_suffix_is_not_dropped — pins the exact string. Bare Ava is a different compact voice installed alongside the premium one, so a stripped suffix downgrades quality without erroring.
  • test_docs_do_not_advertise_the_dead_voice_knob — checks only the name column of settings tables, so prose explaining a retirement stays legal while a re-added row fails. Verified non-vacuous: it fires on the removed PI_VOICE_URL row and passes on the replacement row and on prose.
