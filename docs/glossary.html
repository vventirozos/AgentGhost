Reference

Glossary

This project's logs and source use a lot of shorthand. Here's what it all means, in ordinary words.

Reading the deep reference? Keep this page open beside it. The module pages assume every term below.

The core loop

Turn
One complete exchange: your message in, Ghost's answer out. A turn can contain many model calls and many tool calls internally. Capped at 40 passes.
Hydration
Searching memory and pasting the relevant results above your message before the model sees it. "The hydration was empty" means the memory search found nothing useful, not that memory is broken.
RRF · Reciprocal Rank Fusion
How several memory stores get merged into one ranked list. Each result is scored by its position in each list rather than its raw similarity score, because the stores don't share a scale. Something ranked highly by several stores beats something ranked highly by one.
Tool call
The model's request to do something — run code, read a file, search. Ghost accepts two formats and will attempt one repair on a malformed one.
Trajectory
The recorded log of one turn: what was asked, what tools ran, what came back, how it ended. This is the raw material every background learning pass reads.
Streaming vs non-streaming
Whether the answer arrives word by word or in one piece. It matters more than it sounds: streamed answers are self-checked after they reach you, so a correction shows up on the next turn.

Memory

Vector memory
The searchable pile of facts and document passages. "Vector" because text is stored as a list of numbers representing its meaning, which is what makes searching by meaning possible.
Embedding / embedder
The model that turns text into those numbers. Changing it invalidates everything already stored — the old numbers stay valid-looking but stop meaning anything, which is why Ghost refuses to start on a mismatch.
Graph memory
Entities and the relationships between them. Answers "how is X connected to Y?" where the searchable pile can't.
Episode
A stored sequence of actions and their outcome — I tried X, it failed because Y, so I did Z. Unlike a fact, it has causality and order.
Journal
The short-term queue. Things noticed during a conversation land here first, and a background pass files them into long-term memory a couple of minutes later.
Scratchpad
Notes for the current conversation only. Expires after a day. Used to park a long tool result without carrying it in the context.
Profile
Durable facts about you. Special because it's always present in the prompt rather than searched — which is why a wrong entry here is so persistent.
Lesson
A recorded mistake-and-fix pair. Retrieved alongside facts when a similar task comes up. Sometimes called a playbook entry.
Skill
Confusingly, two things. An acquired skill is a reusable tool Ghost wrote for itself. A lesson is stored in something called SkillMemory. When someone says "show me your skills" they usually mean the first; "what have you learned" means the second.

Checking itself

Verifier
The second model that reads a final answer against the evidence and decides whether it holds up.
Verdict · confirmed / refuted
The verifier's decision. "Refuted" means it thinks the answer doesn't hold — either it doesn't answer the question, or the evidence doesn't support it.
Escalation
When a cheap judge refuses an answer, the main model re-examines it and its verdict wins. This exists because the cheap judge refuses more often than it should.
Auto-repair
Ghost getting a bounded second attempt at an answer the verifier refused, with the critique in hand — rather than shipping something that just failed.
Calibration
Making Ghost's stated confidence match how often it's actually right. An agent that says "90% sure" and is right 60% of the time is badly calibrated, and its confidence numbers are worse than useless.
Loop breaker
A guard that stops Ghost repeating the same successful-but-useless action forever — clicking the same button, taking the same screenshot, concluding nothing. Fires on the third identical repeat.
Pre-flight guard
Blocks a tool call that already failed the same way recently, handing the model the previous error instead of re-running a known failure.

Background work

Biological watchdog
The background loop that runs the idle-time passes. The name is a metaphor — sleep, dreaming, memory consolidation. If it dies, Ghost keeps answering but stops learning.
Dream cycle · REM
Memory consolidation. Reviews recent memories, merges duplicates, generalises repeated patterns. Runs after about ten minutes of quiet.
Self-play
Ghost inventing a challenge for itself, attempting it, and scoring the result. Practice. Runs after about an hour of quiet.
Reflection
Re-reading recent failed turns and writing down what went wrong, which becomes lessons.
Post-mortem
Deeper than reflection: reads the whole transcript of a bad run and files a classified defect report — bad choice, bad setting, or broken tool. Off by default.
Frontier
The edge of what Ghost is uncertain about. Self-play aims here rather than practising things it already handles.
Distillation
Compressing many recorded turns into something smaller and reusable — a lesson, a skill, a trained scorer.
GEPA
The optimizer used to rewrite Ghost's own internal prompts from its successful turns. Run offline by you, not during the idle loop. A tuned prompt only replaces the hand-written one if it wins an A/B comparison.
Signature
An internal prompt that's treated as tunable rather than fixed, described by its inputs, outputs and a baseline instruction. There are three: task decomposition, tool choice, and self-critique.
Proxy gaming
An optimizer learning to score well on the measurement instead of doing the task. It gets worse the longer optimization runs, which is why the round cap here is low and deliberate.
Tool ontology
The question of whether the toolbox is divided up correctly in the first place — as opposed to being divided correctly but described badly. Repeated confusion between the same two tools is evidence for the former, and better wording won't fix it.

Models and machines

Upstream
The LLM server Ghost talks to. Ghost is not a model; it's a program that uses one.
Node pool
A group of extra LLM machines assigned to one kind of work. Ghost has six: worker, critic, coding, vision, image-gen, swarm.
Worker node
A machine for background and small jobs, so they don't compete with your conversation for the main model.
Critic node
A machine dedicated to the self-check. Usually the most valuable one to add.
Swarm
Fanning one task out across several models in parallel.
Circuit breaker
After a node fails repeatedly, Ghost stops sending it work for a while instead of retrying into a dead machine. "Open" means it's been taken out of rotation. Nothing to do with Tor circuits.
PRM · Process Reward Model
A small local model that scores whether a partial plan looks like it's heading somewhere useful — judging the working, not just the answer. Ghost trains it on its own recorded turns.
Router
A small local classifier that predicts how hard a request is, so easy ones can go to a cheap machine. Off unless you point at a trained one.
MCTS · Monte Carlo Tree Search
Exploring several possible next actions and looking a step ahead before committing, rather than taking the first plausible one. Only on hard problems, and only with --deep-reason.

Network and sandbox

Tor circuit
The chain of relays your traffic takes. The last one — the exit node — is what the destination site sees.
NEWNYM
Tor's "give me a fresh circuit" signal. Ghost sends it after a 503, on the theory that a rate-limited exit will clear on a different route. Not sent for 401 or 403, which a new exit wouldn't fix.
SOCKS5h
A proxy mode where the proxy resolves hostnames, not your machine. The "h" is the whole point: without it your own DNS server sees every site you visit, even though the traffic itself is anonymous.
Egress guard
The process-wide block on direct connections to public addresses. Makes "everything goes through Tor" enforced rather than merely intended.
Fail closed
When something's wrong, stop rather than degrade. Ghost refuses to boot without Tor instead of quietly using a normal connection.
Sandbox
The Docker container where all code runs. It shares exactly one directory with your machine and has its own network and process namespaces.
SSRF guard
Refuses fetches aimed at private or loopback addresses, so a tool call can't be turned into a scanner of your own network.
Hidden service · .onion
A site reachable only through Tor, with no ordinary domain name. Normal search engines don't index them, which is why searching for one needs a separate set of engines.
Circuit isolation
Deliberately sending each request over a different Tor route. Used for search because whether an engine answers depends on which exit node you happen to have — the same query can fail then succeed with nothing changed but the circuit.
Independent corroboration
Counting a result as confirmed only when genuinely separate sources report it. Several onion engines share one underlying search index, so they're tagged and counted once rather than mistaken for agreement.

Sense of self

Selfhood
The group of features that give Ghost continuity across sessions: a first-person diary, a running narrative, and state it carries forward.
Self-state
What Ghost writes for its future self — open questions, unfinished threads, its current mood, and operating principles it has chosen. Shown back to it at the start of the next session.
Narrative consolidation
Periodically rewriting many individual experiences into one running summary, so "what have you been doing?" has an answer that isn't a list of a thousand events.
Workspace model
The counterpart to selfhood, pointed outward: what changed in your files, what scheduled tasks did, which URLs it has already read.
Wake-up prefix
The block Ghost is shown at the start of a session summarising where things left off and what changed while it was away.

Measurement

Ablation
Turning a feature off to measure whether it was helping. Most of the --no-* flags exist for this.
Arm
One side of a comparison. "Control arm" is the current behaviour; "treatment arm" is the change being tested.
Bench
A fixed set of test cases used to score a component in isolation, so two versions can be compared fairly.
Metacognition uplift
The optional stack that has Ghost monitor its own state — confidence, uncertainty, host health, competence at different task types. Off unless you pass --enable-metacog.
