Reference

Glossary

This project's logs and source use a lot of shorthand. Here's what it all means, in ordinary words.

Reading the deep reference? Keep this page open beside it. The module pages assume every term below.

The core loop

Turn
One complete exchange: your message in, Ghost's answer out. A turn can contain many model calls and many tool calls internally. Capped at 40 passes.
Hydration
Searching memory and pasting the relevant results above your message before the model sees it. "The hydration was empty" means the memory search found nothing useful, not that memory is broken.
RRF · Reciprocal Rank Fusion
How several memory stores get merged into one ranked list. Each result is scored by its position in each list rather than its raw similarity score, because the stores don't share a scale. Something ranked highly by several stores beats something ranked highly by one. Each source's weight comes from one hand-tuned table per question type (factual, procedural, contextual) in core/bus.py; the learned weights that used to override it were removed on 2026-10-11 (§4NN).
Tool call
The model's request to do something — run code, read a file, search. Ghost accepts two formats and will attempt one repair on a malformed one.
Trajectory
The recorded log of one turn: what was asked, what tools ran, what came back, how it ended. This is what the learning loop, the regression suite and introspect read.
Streaming vs non-streaming
Whether the answer arrives word by word or in one piece. It matters more than it sounds: streamed answers are checked after they reach you, so a failed check is recorded after the fact (and, since §4NF, not shown to you) rather than repaired before sending.

Memory

Vector memory
The searchable pile of facts and document passages. "Vector" because text is stored as a list of numbers representing its meaning, which is what makes searching by meaning possible.
Embedding / embedder
The model that turns text into those numbers. Changing it invalidates everything already stored — the old numbers stay valid-looking but stop meaning anything, which is why Ghost refuses to start on a mismatch.
Graph memory
Entities and the relationships between them. Answers "how is X connected to Y?" where the searchable pile can't. Since §4OM only copies of your profile facts and your projects are written to it.
Episode
A stored sequence of actions and their outcome — I tried X, it failed because Y, so I did Z. Unlike a fact, it has causality and order. Searched only when you ask; not added to prompts since 2026-10-10.
Journal
The short-term queue. Things noticed during a conversation land here first, and a background pass files them into long-term memory a couple of minutes later.
Scratchpad
Notes for the current conversation only. Expires after a day. Used to park a long tool result without carrying it in the context.
Profile
Durable facts about you. Special because it's always present in the prompt rather than searched — which is why a wrong entry here is so persistent.
Lesson
A recorded mistake-and-fix pair in the playbook. Since October 2026 the only new ones are rules you approved, which go into every one of your prompts, and lessons you dictate, which are found when they look relevant. See the learning loop.
Rule
One sentence you adopted ("learn rule N", or "learn this rule: …" quoting the proposed rule's text) that is put in the prompt of every one of your turns, under ### OWNER RULES. Proposed by the learning loop after it replayed one of your failures and tested the rule.
Regression test
A question you said was answered wrong, plus checks a program can run on the reply ("mentions 18.6", "opens postgresql.org"). Proposed from your 👎; kept only when you say "keep test N"; re-asked after every update and daily.
Skill
Confusingly, two things. An acquired skill is a reusable tool Ghost wrote for itself. A lesson is stored in something called SkillMemory. When someone says "show me your skills" they usually mean the first; "what have you learned" means the second.

Checking itself

Verifier
The checks run on a finished turn. Since 2026-10-14 (§4OW) only the mechanical ones run: does a built page load, are claimed files on disk, is the reply an answer, does an image show what the reply says. The second-model judge that read the answer against the evidence is off (GHOST_VERIFIER_JUDGE=1 turns it back on).
Verdict · confirmed / refuted
The verifier's decision. "Refuted" means a check failed — today a mechanical one, such as a page that throws or a file that isn't there.
Escalation
Part of the LLM judge, so off with it: when the cheap judge refused an answer, the main model re-examined it and its verdict won, because the cheap judge refused more often than it should.
Auto-repair
Ghost getting a bounded second attempt at an answer a check refused, with the failure in hand — rather than shipping something that just failed. With the judge off (§4OX) the reply waits up to 15 seconds for the mechanical checks, and a page that throws or a missing file gets one repair round before sending (GHOST_MECHANICAL_REPAIR_BUDGET). A failure found later is recorded, not shown to you (§4NF).
Loop breaker
A guard that stops Ghost repeating the same successful-but-useless action forever — clicking the same button, taking the same screenshot, concluding nothing. Fires on the third identical repeat.
Pre-flight guard
Blocks a tool call that already failed the same way recently, handing the model the previous error instead of re-running a known failure.

Background work

Idle scheduler (formerly "biological watchdog" · "Biological Daemon")
The background loop that runs the idle-time jobs: memory-journal consolidation, maintenance, store hygiene, workspace tidy, project autoadvance (autopilot projects only), the self and workspace narratives, stale open questions, and failure replay plus the regression suite. At boot it prints Idle Scheduler — started; jobs: … naming exactly the jobs this boot will run. If it dies, Ghost keeps answering but stops its background upkeep; the status chip then says idle scheduler DEAD. Renamed on 2026-10-11 (§4NN); the code still calls it biological_watchdog, and the /api/health key is still biological_watchdog_alive.
Memory journal (formerly "Hippocampus")
The queue of memories buffered during your turns and consolidated into the stores once you have been quiet for a while. Its log lines are tagged Memory Journal; if you come back mid-drain it stops with owner returned — paused with N item(s) left and finishes later. Renamed on 2026-10-11 (§4NN).
Maintenance cycle (formerly "dream cycle" · REM)
Store upkeep: project digests, manifest backfill, the daily verified snapshot, the trajectory archive, forget-archive purges, graph prune and merge. Becomes eligible after about ten minutes of quiet; on a quiet day it runs about every six hours. The lesson-writing consolidation that gave it the "dream" name was removed on 2026-10-11 (§4NM), and the phase itself was renamed maintenance the same day: the idle log line, the activity ledger and the liveness table say maintenance, and one line after each pass says what it did (N project activity digests written; N project file descriptions written; store backup taken (<file>) / no store backup this pass (one a day) / FAILED; memory graph cleaned: N stale links removed, N duplicate entities merged (or memory graph cleanup not due (every 6 h) / FAILED), then the memory reconcile's repairs when it made any, led by nothing needed — when the pass changed nothing (§4PQ; it read maintenance: project digests N, manifests N, snapshot yes/no, graph pruned N, graph merged N until 2026-10-16)). Older ledger rows tagged dream are read as maintenance. The code module is still core/dream.py (class Dreamer), and the CLI switch is still --no-dream.
Failure replay (the idle slot formerly called "self-play")
The idle slot after about an hour of quiet. The Idle Cycle console line names it failure-replay (replays one of your past failures or runs your regression tests): … followed by what it did, e.g. nothing to do (no owner failure to replay, no test due) (§4PQ). It replays one of your recent failures, diagnoses it, tests a rule and proposes it to you, and runs your regression tests. The invented challenges that gave the slot its name (synthetic self-play) were removed on 2026-10-11 (§4NM): Ghost passed 8 of 9 at the first try, so they taught nothing.
Reaction judge
The short idle check in which the main model reads your next message after an answer and decides whether it showed the answer missed. One of the two signals (with 👎) that can start a replay.
Signature
An internal prompt described by its inputs, outputs and a baseline instruction. The loader in optim/ renders tool descriptions from them. (They were once the targets of a prompt optimizer; see GEPA under Removed.)
Distillation
In this codebase, distill/ is the trajectory collector: it records turns, redacts them and promotes your corrections. The failure-cluster distillation that wrote lessons from it was removed on 2026-10-11 (§4NM).

Removed in October 2026 (§4NM)

These terms still appear in old logs, the project journal and the audit page. None of the mechanisms exists any more; each was measured on real turns, found not to help, and deleted on 2026-10-11.

Reflection
Re-read recent failed turns and wrote lessons. Its lessons reached the turn they were for 18% of the time.
Post-mortem
Read the whole transcript of a bad run and filed a classified defect report. 129 of 130 runs found nothing.
Self-play (synthetic) · challenge templates · adversarial generator · frontier
Invented practice problems, aimed at the clusters Ghost was most uncertain about. Passed 8 of 9 at the first try; replaced by failure replay on your real failures.
Dream REM consolidation · counterfactual replay
Generalised memories into lessons, and re-ran recorded episodes with one thing changed to grade a lesson's effect. The control leg of the replay engine never reproduced recorded outcomes reliably enough to label anything.
Automatic skills · skill pruning
Turned repeated tool sequences into "skills" and retired lessons by a utility score. The skills were trivial; the pruning deleted 13 good lessons on noisy labels.
GEPA · prompt tuning · tool ontology
An optimizer that rewrote three internal prompts and the tool descriptions from successful turns, its autonomy loop, and the analysis of whether the toolbox was carved right. No tuned prompt was ever shown to help on live traffic.
PRM · Process Reward Model · MCTS
A small local model that scored partial plans, and the lookahead that would have consumed it. Nothing on the request path ever read either.
Router (complexity router) · System-2 planner
A classifier that predicted request difficulty, and the planning path it gated. Nothing used the label; the planner never ran in production. The planner itself (--use-planning, its prompt, the per-turn plan and its GHOST_PLANNER_* knobs) was deleted in the second pass of the same day. The project task tree (core/planning.py) is a different thing and stays.
Foresight · imagination · risk governor · PPI
Per-tool-call outcome predictions, the gate that would have let them steer, a nudge on struggling turns, and the arm report's estimator. Its depth estimates were 10–26 points wrong; the rest had no consumer.
Evolve (scaffold mutation) · negative controls · bench banks
Self-proposed changes to the agent's own scaffolding behind a fence, the known-bad candidates that tested the fence, and the externally graded task banks that scored them. The banks were saturated (≥90%) and the mutator never shipped a change.
Wake-up prefix · derived-mood idle job
A block of self-state in every prompt and an idle job that derived a mood while nobody was talking. The self-state is still written and is read on demand through introspect; a mood is still derived after each of your turns and shown by self_state.
Owner-facing verifier corrections
The switch (GHOST_VERIFIER_SHOW_OWNER) that showed you the late verifier's corrections, notices and source caveats. 2 of the last 3 shown corrections were false. Verdicts are still recorded; a channel member's correction still reaches the member.
Vector, episode and session hydration tiers · vector match floor
The fetchers that put fact-store hits, past episodes and past replies into every prompt, the topical graph fetch, their four GHOST_BUS_*_TIER switches and GHOST_VECTOR_MATCH_FLOOR. A prompt now gets your facts (when you ask about yourself) and the lessons; recall still searches every store.
Competence in prompts and in the confidence score
The per-domain success table in the prompt and as a term of the confidence blend (GHOST_COMPETENCE_PROMPT, GHOST_CONF_COMPETENCE). It counted error-free calls, not successful turns. The profile itself was removed later, with the confidence score (see below).
Equal-mass bench cap · bench enrollment
The calibration cap on bench rows and experiment enrollment for bench solves. Old bench rows on disk are still read: the source rank bench_validator and the bench direction gate stay. (The offline judge bench library eval/verify_bench.py is kept — the verifier's tests drive it.)
Scripts for removed subsystems
objection_replay.py, label_noise_audit.py, measure_undecidable_turns.py, ablation_trackb4.py, lesson_generalize_legacy_4kw.py.

Removed in October 2026, second batch (§4NN)

Deleted on 2026-10-11 after the first batch. Each had no consumer on the request path, or was switched off in production. Their old data files stay on disk; nothing reads them.

Belief versioning · contradiction log (ContradictionLog)
A ledger of every stored belief Ghost revised and why. Nothing had read it into a prompt since §4KZ. The project advancer still detects a contradiction between sibling tasks and records it as a contradiction_detected project event; only the separate ledger write went. contradiction_log.json is left on disk.
Uncertainty tracker · flag_uncertainty · λ (uncertainty penalty)
A tool the model called to register unknowns and assumptions, a per-turn scan for hedging phrases, the Recurring uncertainties prompt block, the clarifying-question gate ("Before I proceed, I need to clarify…") and the Assumptions I made reply footer. The confidence score's penalty × (1 − λ·pressure) went with it. uncertainty_log.jsonl is left on disk.
--deep-reason · HypothesisTester · System-3 hypothesis grounding
After repeated failures, generated root-cause hypotheses and ran a minimal sandbox test for each. The crisis pivot itself still runs (and still looks up past recoveries); it no longer generates or tests hypotheses. --deep-reason is still accepted so an old launcher boots, but it does nothing — remove it from the launcher. GHOST_HYPOTHESIS_GROUNDING is no longer read.
Experiments registry · live randomised arms · PPI · introspect action='experiments'
The A/B arm machinery (core/experiments.py, its estimator core/ppi.py, request enrolment, the experiments trajectory stamp, the GHOST_EXPERIMENTS switch). Every spec was already disabled, so every consumer now takes its no-arm path: the evidence-gate steer is gone, adaptive best-of-N follows GHOST_TTS_ADAPTIVE_BON only, and the batched paths read in file_system is no longer offered. introspect lost its experiments action and its overview section. system/experiments.json is left on disk.
Learned RRF weights
Per-intent source weights fitted from logged turns (core/rrf_weights.py, system/rrf/weights.json). The hand-tuned table in core/bus.py is now the only one, and it lists just the two live prompt sources (your facts in the graph, and lessons).
Biological · Hippocampus · REM · Dream Mode (log names)
Renamed, not removed: the loop is the idle scheduler, its log tag Idle Maintenance (was Biological Hook), the memory queue the memory journal, and the maintenance pass logs Maintenance Digests, Maintenance Manifest and Trajectory Archive (were Dream Projects, Dream Manifest, Dream Mode).

Removed later in October 2026

Cut because it did not do its job when measured. Its data files stay on disk; nothing reads them.

Confidence score · calibration · competence profile · arbiter
A per-answer confidence number blended from a per-task-type success table (the competence profile) and how uncertain the model's word choices were, re-fitted every hour against how turns actually ended (calibration). Its job was to pick the least confident answers for a deeper check and, once a day, to ask you to 👍/👎 one of the shakier answers. Measured against real outcomes it ranked answers no better than a coin flip, and the deeper check it fed sat behind a verifier judge that is switched off. The second-solver arbiter, already switched off, went with it. The metacog conf log line and the confidence figure on the turn outcome line appear only in old logs.

Models and machines

Upstream
The LLM server Ghost talks to. Ghost is not a model; it's a program that uses one.
Node pool
A group of extra LLM machines assigned to one kind of work. Ghost has six: worker, critic, coding, vision, image-gen, swarm.
Worker node
A machine for background and small jobs, so they don't compete with your conversation for the main model.
Critic node
The machine that ran the LLM judge. With the judge off (§4OW) it serves the image look checks (GHOST_VISUAL_CHECK_POOL=critic); in production it is the same helper box as the worker node.
Swarm
Fanning one task out across several models in parallel.
Circuit breaker
After a node fails repeatedly, Ghost stops sending it work for a while instead of retrying into a dead machine. "Open" means it's been taken out of rotation. Nothing to do with Tor circuits.

Network and sandbox

Tor circuit
The chain of relays your traffic takes. The last one — the exit node — is what the destination site sees.
NEWNYM
Tor's "give me a fresh circuit" signal. Ghost sends it after a 503, on the theory that a rate-limited exit will clear on a different route. Not sent for 401 or 403, which a new exit wouldn't fix.
SOCKS5h
A proxy mode where the proxy resolves hostnames, not your machine. The "h" is the whole point: without it your own DNS server sees every site you visit, even though the traffic itself is anonymous.
Egress guard
The process-wide block on direct connections to public addresses. Makes "everything goes through Tor" enforced rather than merely intended.
Fail closed
When something's wrong, stop rather than degrade. Ghost refuses to boot without Tor instead of quietly using a normal connection.
Sandbox
The Docker container where all code runs. It shares exactly one directory with your machine and has its own network and process namespaces.
SSRF guard
Refuses fetches aimed at private or loopback addresses, so a tool call can't be turned into a scanner of your own network.
Hidden service · .onion
A site reachable only through Tor, with no ordinary domain name. Normal search engines don't index them, which is why searching for one needs a separate set of engines.
Circuit isolation
Deliberately sending each request over a different Tor route. Used for search because whether an engine answers depends on which exit node you happen to have — the same query can fail then succeed with nothing changed but the circuit.
Independent corroboration
Counting a result as confirmed only when genuinely separate sources report it. Several onion engines share one underlying search index, so they're tagged and counted once rather than mistaken for agreement.

Sense of self

Selfhood
The group of features that give Ghost continuity across sessions: a first-person diary, a running narrative, and state it carries forward.
Self-state
What Ghost writes for its future self — open questions, unfinished threads, and operating principles it has chosen. Read back on demand through introspect (the prefix that put it in every prompt was removed on 2026-10-11, §4NM).
Narrative consolidation
Periodically rewriting many individual experiences into one running summary, so "what have you been doing?" has an answer that isn't a list of a thousand events.
Workspace model
The counterpart to selfhood, pointed outward: what changed in your files, what scheduled tasks did, which URLs it has already read.

Measurement

Ablation
Turning a feature off to measure whether it was helping. Most of the --no-* flags exist for this.
Arm
One side of a comparison. "Control arm" is the current behaviour; "treatment arm" is the change being tested. No arm runs today: none could reach a verdict at this traffic (§4ND), and the experiments registry was removed on 2026-10-11 (§4NN) — see Removed.
Bench
A fixed set of test cases used to score a component in isolation, so two versions can be compared fairly.
Metacognition uplift
An optional add-on that, with --enable-metacog, logs each time the shell or SQL checks block a command and counts the blocks for a summary at shutdown. The checks themselves always run. (It used to also watch host health and raise re-plan alarms; that was removed in §4PT, 2026-10-17.)
