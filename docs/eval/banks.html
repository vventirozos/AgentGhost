eval / banks.py — bench banks (§4BF Track 1b)

Externally-imported graded tasks (MBPP code-with-tests, GSM8K exact-match math, gsm8k_text reply-graded math) run through the self-play machinery during deep idle — the resolved-outcome flywheel. Tests: tests/test_bench_banks.py, tests/test_track2_flip_ii.py.

Why

The learning stack's binding constraint is RESOLVED-outcome supply (§4AQ/§4BC: ~3.5 real turns/day, most unknown). Bench banks turn idle cycles into mechanically-graded outcomes: unit tests and gold answers give free ground truth at whatever volume the idle battery can burn. This also answers B4's failure mode — B4 ceilinged twice because SYNTHESIZING hard tasks is hard; importing hard tasks isn't.

The flow

  1. Import (operator/build-time, never agent runtime — the agent's egress is Tor-only-keyless): scripts/import_bench_banks.py --mbpp … --gsm8k … normalizes raw dataset rows into the self-play (prompt, setup, validator) triple and writes $GHOST_HOME/system/bench/banks/*.jsonl. Every MBPP item's validator is SELF-TESTED against the dataset's reference solution at import — a broken oracle turns every future FAIL into label noise (2 of 974 rows failed and were dropped on the 2026-08-13 import).
  2. Idle phase 3b (_biological_tick, deep idle >3600s, cooldown _BENCH_COOLDOWN=2700s, skips ticks that already ran self-play, kill switch --no-bench — deliberately independent of --no-self-play per §4Q): banks.pick_next_item() (deterministic round-robin, persisted cursor, wraps on exhaustion) → Dreamer.synthetic_self_play(injected_challenge=…, bench_meta=…) — the SAME isolated solve loop as self-play (full tool loop, throwaway Docker sandbox, 3 attempts, read-only memory) → outcome appended to bench/results.jsonl and an autonomous_activity "bench" record. Phase is INERT until banks exist on disk — armed-but-unloaded is the rollout.

Contamination doctrine (1c DECIDED 2026-08-13 — see core/admissibility)

  • Bench trajectories go to a separate root (bench/trajectories/) with task_kind="bench" (context-attr override in _record_turn_trajectory) and origin=bench on the request log line (explicit turn_origin_label override — the read-only heuristic would have folded bench into "sim"). No reader of the production corpus ever sees them by accident; admitted consumers read them through admissibility.iter_bench_trajectories(consumer), which fails closed for any consumer without a matrix row.
  • Trainsets take bench with origin as a feature: GEPA trainsets (TrainExample.origin), the tool-fixture miner (ToolChoiceFixture.origin, joined by extra.req_id), the PRM and the router (an appended origin_bench feature column). Validation stays REAL: the router's §4AA held-out gate and every viability floor are computed on the real population alone.
  • Calibration takes bench: samples carry origin="bench", the bank oracle re-labels each attempt at the bench_validator source rank, and the fit blends populations under an equal-mass cap.
  • Lessons mint TAGGED (source="bench") through the same extracted gate as self-play; the neutral pinned frontier shape + the novelty=None pin mean struggled-then-won (always verified) is the only bench pass-mint path. Frontier recording and the scratchpad report stay real-only.
  • Live experiment arms never enroll bench turns; bench-scoped specs (ExperimentSpec.scope="bench") enroll bench turns exclusively, and a bench verdict announces as a gate for a live watch-window — never an auto-apply.

Oracles

  • MBPP: validator execs the solver's solution.py and runs the dataset's asserts; challenge_test_list rows are HELD-OUT (in the validator, not the prompt; failures report an index, never the body).
  • GSM8K: the solver's solution.py must print the final number; the validator (house style — it subprocess-runs the solution like the template validators) compares the last number on stdout against the gold with relative tolerance.
  • Anti-cheat: golds and hidden tests are base64-embedded (a deterrent — the sandbox is shared, same trust model as template validators) and the prompt forbids reading dot-files; failure feedback never prints the gold or hidden-test bodies (retries would otherwise cheat).
  • Injected challenges count as pre-verified for the self-play validator self-test gate (external ground truth; the echo-style instrumentation can't apply and would false-WARN per run).

graded_on — what the oracle grades (§4BF Track 2 flip ii)

Every item optionally carries graded_on: "artifact" (default — the validator inspects files the solver wrote) or "final_response" (the validator reads answer.txt, which dream's solve loop writes with the turn's final reply text — post adaptive-BoN substitution — right before running the validator; the solver never writes it). The field is deliberately not in ITEM_FIELDS: adding it to the required set would make load_bank's all-fields-present check silently drop every pre-§4BF row on disk. Readers use item_graded_on(item), which defaults absent/unknown values to artifact.

gsm8k_text (normalize_gsm8k_text, imported via scripts/import_bench_banks.py --gsm8k-text <raw>): the same 1,319 GSM8K items, but the challenge asks for the answer in the reply (final numeric answer on the last line) and the validator grades answer.txt. This is the bank flavor whose oracle can measure mechanisms that rewrite final TEXT — built for the bench-scoped tts_bon arm (see experiments). Validator exit codes are load-bearing: 0 correct · 1 wrong number (feedback never leaks the gold) · 4 no number in the reply (a real solver failure — the format was pinned in the prompt; an EMPTY reply also grades 4) · 5 answer.txt missing, reserved for "the harness seam did not run" — dream triages 5 as INFRA_ABORT, never an agent failure (the §4AO label-noise class). Import self-tests each validator in BOTH directions (gold passes, gold+1 fails) — a check the R1 review then extended to the artifact --gsm8k branch too, which previously had none. Tolerance cap (R1): the first import exposed that a purely relative tolerance makes golds ≥1.45M accept ±1 (two such items sat un-dropped in the artifact bank on disk); both gsm8k validators now use min(rel·max(1,|gold|), 0.5) (_TOL_EXPR — one shared string so the flavors can't drift), which keeps float-formatting slack while failing every integer near-miss at any magnitude. Re-imported 2026-08-13: 1,319/1,319 in both banks, all self-tests green. Grading subject (R1 CRIT, two independent reviewers): the harness strips finalize-appended system notes (reply_smoothing.strip_system_notes) before writing answer.txt — the verifier's own "**Verifier note:**" tail otherwise displaced the final number in BOTH directions (a note ending in a digit flunked correct answers; a refute quoting the correct value passed wrong ones). Accepted residuals (documented, not defended): the last-number heuristic mis-grades exotic reply tails (unicode minus, LaTeX fractions, e-notation, trailing "in 2 steps") — the challenge's pinned last-line format is the mitigation.

A uniform-draw mode that was built and removed (§4BO, 2026-08-15)

Recorded because the reasoning is the reusable part. The premise was: the cursor walk starts at index 0, MBPP/GSM8K are ordered roughly easiest-first, so 18 passes in 18 runs may just be where the walk started. Checked against the actual bank files, that is false:

  • MBPP index 0 is a 2-D dynamic-programming min-cost-path problem; index 967 is "find the minimum of two numbers". The tail is easier than the head — the order is task_id, which is MBPP's train/test/prompt split order.
  • GSM8K: corr(index, question_chars) = +0.04, corr(index, numeric_tokens) = +0.01, quartile means flat. No trend.

So the banks are unordered, the sequential prefix is already a fair sample, and a uniform draw would have the same expected pass rate — a fix aimed at a bias that does not exist. It also carried real costs: with-replacement duplicates (P(≥1 duplicate in a 200-item drain) ≈ 99.6% over the 3,610 on-disk rows) feeding a lesson the isolate reads back on the repeat, and a two-stage bank-then-item draw over a population where gsm8k and gsm8k_text are byte-identical questions under two grading modes.

What 18/18 does bound honestly: a 95% one-sided lower bound of p ≥ 0.847. What it does not tell you is the variance or where the hard items are — and the answer to that is more items, which is what the drain provides.

Operator-armed drain (§4BO)

The idle economy yields ~14 items/day (measured: 18 rows over 29.9 h, median gap 72 min) because an item needs a deep-idle window, a self-play dice miss, and a 45-minute cooldown. A drain lifts all three:

curl -s -X POST http://127.0.0.1:8000/api/bench/drain \
  -H "X-Ghost-Key: $(cat ~/Data/AI/.ghost_api_key)" \
  -H 'Content-Type: application/json' \
  -d '{"count": 30}'                  # optional: "banks": ["mbpp"]

The endpoint arms a budget; it never runs an item. The biological watchdog spends it, which keeps the watchdog the single caller of pick_next_item — that function's cursor is an unsynchronized read-modify-write, and "bench from a second process" is the race its docstring names. {"count": 0} cancels the queue (but not the item already solving). The remaining budget is readable from GET /api/health (bench_drain_remaining); it is in-memory by design, so a restart clears it.

What a drain still obeys: --no-bench (absolute, and refused at the door with 409), a live turn (foreground_requests > 0), and a 60-second quiet floor — re-read at the moment the phase runs, not sampled at the top of the tick, because the phases above it can burn minutes and a stale sample let a solve start one second after the operator's reply.

Per-item timeout. The solve loop has no internal timeout and the watchdog is the process's only long-lived background task, so one item parked on the shared inference slot stops every idle phase — journal, dream, reflection, skills, PRM/router retrain, calibration, autoadvance, self-play — until a restart, while /api/health still reports biological_watchdog_alive: true (the task is alive, parked inside one await). At the organic cadence that was a ~0.3% duty cycle; a drain runs at a measured 24–75% (mean 41%). Hence GhostAgent._BENCH_ITEM_TIMEOUT (15 min ≈ 5× the 179 s worst honest run measured here), after which the item is cancelled and recorded INFRA_ABORT — excluded from the pass-rate denominator, because a wedged box is not the agent getting the answer wrong. The bound is a floor, not a ceiling: asyncio.wait_for cancels the task and then awaits it, including a finally that removes a Docker container and deletes a workspace, so the real worst case is roughly the timeout plus docker-py's ~60 s client timeout. A cancellation landing inside asyncio.to_thread(ensure_running) cannot stop that thread either, so a container may be created after its workspace is gone and leak — narrow, but per-item under a drain rather than per-incident.

⚠ A bank-scoped drain evicts that bank from the organic rotation

pick_next_item serves the bank with the lowest cursor, and the drain shares that cursor. So {"count": 200, "banks": ["mbpp"]} advances mbpp to 206 while the others sit at 6 — and the organic walk will not return to mbpp until roughly 402 items have run on the other banks, about 28 days at the measured cadence (the figure scales with the number of banks — 2 banks ≈ 14 days, 4 ≈ 43). Meanwhile stats(source="idle")["mbpp"] — the very series the split exists to keep comparable — is frozen. The endpoint says so in its reply when a filter is given. Drain all banks unless you want that trade.

Cost. 200 items is roughly 5–13 h of the box's only inference slot (llama-server runs -np 1); the arm response returns an estimated_hours range. A bench generation already in flight owns that slot, so an operator turn arriving mid-item waits for it — drain when you are away, not while you are working.

Provenance. Every ledger row carries source: idle (organic) or drain. These are genuinely different machine conditions, so stats(source=…) keeps them separable and the learning-health report breaks them out — pooled, 200 drained rows swamp the ~14/day organic ones and silently redefine what "pass rate" means on that line. Rows written before 2026-08-15 have no field and read as idle. The tag rides the trajectory too (bench_meta["source"]), because every admitted learning consumer reads the corpus rather than this ledger.

⚠ A drain floods any live bench-scoped experiment arm

Bench-scoped arms (ExperimentSpec.scope="bench", e.g. tts_bon) accrue from exactly the population a drain multiplies. A 200-item drain delivers roughly fifty nights of accrual in one, under a different machine regime — and while every row now carries bench_source, no analysis path filters on it yet. The arm endpoint names any live bench-scoped arms in its reply (bench_scoped_arms) so the decision is made before the drain, not discovered after it. Record the drain window against the arm, or pause the arm first. Stated plainly: that advisory string is the only mitigation. If a drain is ever armed while a bench-scoped arm accrues, the earned fix is a bench_source != "drain" filter where the bench verdict pass reads the corpus — one keyword argument — but it is premature before a drain has actually run.

Sandbox hygiene under a drain

The FD leak (fixed 2026-08-15, found by running the first real drain). Each solve builds a fresh DockerSandbox, whose __init__ opens a docker client — and nothing closed the connection pool, so every item leaked ~11 unix sockets. A 20-item drain reached [Errno 24] Too many open files at item 16: the remaining items failed to solve and failed to write their ledger rows, and the whole daemon degraded (critic nodes unreachable, journal consolidation skipping, the HTTP API accepting TCP but answering nothing). The per-solve teardown now goes through close(remove=True), which closes the client and removes a container even when the failure path never bound it. Measured after the fix: six solves, FDs 353 → 354, unix sockets flat.

Boot sweep. A finally cannot run through SIGKILL, so a daemon killed mid-solve leaves its container behind. Boot now reaps them — but note the criterion, because the obvious one is wrong: a killed process also cannot run TemporaryDirectory.cleanup(), so the workspace survives and "mount no longer exists" spares exactly the containers it targets. The test is the KIND of workspace — tmp* under the system temp root is a per-solve sandbox and is removed; $GHOST_HOME/sandbox (the agent's own) and ghostjobs-* (a detached job, deliberately kept alive across restarts) are never touched. Also guarded by a 30-minute age floor, a 25-container cap, and GHOST_SANDBOX_SWEEP=0.

Still worth a periodic docker ps -a: a cancellation landing inside asyncio.to_thread(ensure_running) cannot stop that thread, so a container can still be created after its workspace is gone. The boot sweep will collect it next restart.

Watching a drain

GET /api/health carries bench_drain_remaining, bench_drain_banks, bench_item_started_at and bench_last_item_at. The start stamp is non-null iff an item is in flight (cleared when one ends), so: non-null and not advancing = wedged; null with budget remaining = deferring on the quiet floor or a live turn. Reading a stale stamp as a wedge leads to a restart, which discards the in-memory budget.

Reading the flywheel

python3 - <<'EOF'
from ghost_agent.eval import banks
print(banks.stats())                    # pooled: what the flywheel ran
print(banks.stats(source="idle"))       # the organic cadence alone
print(banks.stats(source="drain"))      # operator-armed drains alone
print(banks.list_banks())               # items on disk
EOF

Ledger rows: {ts, bank, item_id, cluster, passed, status, attempts, source}. A run that never concluded records NO_RESULT with passed=false — silent drops would inflate the pass rate. INFRA_ABORT/NO_RESULT are the UNRESOLVED bucket (excluded from the pass-rate denominator); ABORTED_BY_SOLVER counts as a FAILURE (1c: bench items are oracle-self-tested at import, so an abort is the agent capitulating — the lesson gate still writes nothing from abort transcripts, a deliberate asymmetry: no-fault for LEARNING, at-fault for the SCOREBOARD). Accepted residual: the cursor advances at pick time, so a hard process kill mid-solve consumes one item with no ledger row (the in-process finally covers exceptions, not SIGKILL); recovered on wrap.
