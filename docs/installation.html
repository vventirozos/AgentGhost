Installation & Runtime Setup

What to install, which environment variables to set, and how to start every process.

Hard prerequisites

  • Python 3.10+ (tokenizer + dataclasses + asyncio.to_thread).
  • A running Docker daemon. The sandbox uses the Docker SDK; on macOS it auto-detects OrbStack / Docker Desktop sockets (sandbox/docker.py:13-54).
  • An OpenAI-compatible LLM endpoint reachable from the agent (llama.cpp, vLLM, Ollama). Default expectation: http://127.0.0.1:8088.
  • Required: a Tor SOCKS proxy for outbound traffic (TOR_PROXY=socks5h://127.0.0.1:9050). Ghost Agent fails closed if it is unreachable — see Safety and privacy.
  • Optional: a Postgres database for the postgres_admin tool; GPU servers for image generation / vision.

Boot sequence

From main() in main.py and the lifespan async context in the same file:

  1. Parse CLI flags + env vars.
  2. Make sure GHOST_HOME/sandbox and GHOST_HOME/system/memory exist.
  3. setup_logging() wires colourised structured logs (utils/logging.py).
  4. load_tokenizer() grabs / downloads the Qwen3 tokenizer for token budgeting.
  5. Build GhostContext with Scratchpad, MemoryJournal, SkillMemory, FrontierTracker.
  6. Construct the FastAPI app and attach the lifespan coroutine.
  7. Lifespan startup:
    • LLMClient with foreground + swarm/worker/visual/coding/image_gen pools.
    • DockerSandbox.ensure_running() in a worker thread.
    • ProjectStore always (for user-driven multi-session projects).
    • Memory stores (vector, graph, profile, episodes, adaptive threshold) — skipped under --no-memory.
    • APScheduler for user-defined cron tasks.
    • MemoryBus, Verifier. (The UncertaintyTracker was removed on 2026-10-11, §4NN.)
    • --deep-reason is accepted and ignored: the HypothesisTester it used to start was removed on 2026-10-11 (§4NN; the MCTS reasoner it paired with went in §4NM). Remove it from the launcher.
    • GhostAgent + the idle-scheduler task (biological_watchdog in code), which logs Idle Scheduler — started; jobs: ….
  8. Lifespan shutdown: cancel the idle scheduler, stop scheduler, close LLM client, stop sandbox container (kept around with remove=False for fast resume).
  9. uvicorn.run(app, host, port, log_config=None).

Process commands

# core agent
python -m src.ghost_agent.main \
    --upstream-url "http://127.0.0.1:8088" \
    --host 0.0.0.0 --port 8000 --verbose

# web UI proxy (separate port)
python interface/server.py --agent-log /var/log/ghost-agent.log

# Slack bot (Socket Mode)
SLACK_BOT_TOKEN=xoxb-... SLACK_APP_TOKEN=xapp-... \
  python interface/externals/slack_bot/main.py \
    --log-file /var/log/ghost-slack-bot.err

# (No voice server. STT/TTS run inside the web UI proxy above — see
#  docs/interfaces/voice_server.html. The tts_stt external was deleted
#  2026-08-03; there is nothing to start.)

# Image gen server (GPU box)
python interface/externals/image_generation/img_gen_server.py
Heads-up: the agent's lifespan stops the sandbox container with remove=False so subsequent restarts resume in seconds. There is no flag for a clean start: remove the ghost-agent-sandbox-… container yourself (docker rm -f) and the next start creates a fresh one. While background jobs or sandbox services are live, shutdown leaves the container running so they survive the restart.

Pre-provisioned sandbox image (optional, recommended)

The runtime sandbox wrapper can provision Chromium + apt deps + the full pip stack on first boot, but this takes 2–3 minutes the first time and can silently rot if committed before --with-deps was added. The repeatable path is to build a proper image:

scripts/build_sandbox_image.sh
# → builds ghost-agent-base:latest (~2 GB first run; ~5 min on warm cache)
# → runs a Chromium launch smoke test at the end

The image bakes apt system packages, the deep-learning pip stack, and playwright install --with-deps chromium at build time — self-play + browser tasks start instantly. The runtime gate checks both the /root/.supercharged.v2 marker AND that the Chromium binary is actually on disk; if the marker is present but the binary is missing (the exact silent-failure mode the v2 bump exists to catch), a full reinstall fires on next ensure_running.

If you skip this step, the fallback inline provisioning still produces a correct image; it just takes longer on the first turn.

Test runner

python scripts/run_suite.py             # full suite (-n 8) + the lint gate after it
python scripts/run_suite.py --no-lint   # tests only — ~5.5 min
pytest -n 8 --dist loadfile              # the same tests without the runner's timing report
pytest tests/test_agent_planning.py      # single file
pytest -k "memory and not slack"         # filter
black src interface tests
pylint src/ghost_agent

The suite is 16,200+ tests. Serially that is ~24 minutes, which is too slow to run after every change — and the whole discipline here depends on running it after every change. pytest-xdist brings it to just over four minutes on a 14-core machine.

Memory and time (2026-10-26). A full run took 10 minutes and swapped hard: every worker imported transformers (and with it torch, scipy, sklearn, pandas — 425 MB and 3.4 s per process) through utils/token_counter.py, and the pylint gate's 8 jobs ran beside the 12 test workers, taking 436 s of the run (71 s alone). The tokenizer import now happens in load_tokenizer only (an agent import is 70 MB, 0.3 s), and the gate runs once after the tests (test_lint_gate's three gate tests run only with GHOST_LINT_GATE=1). Result: tests 5 min 34 s, peak 2.9 GB (was 4.4). Tests that look slow in the report (40–85 s) were mostly starved, not slow: alone they take 0.04–5 s. On the main Mac llama wires 28 GB of 36, so the suite still pushes the machine into swap at -n 12, so the runner defaults to -n 8 since 2026-10-26 (operator); times above were measured at 12.

--dist loadfile is not optional. It keeps every test in a file on one worker, so module-level state a file sets up in one test and reads in another still works. Plain --dist load scatters tests within a file across workers and produces failures that are artifacts of the scheduler.

Parallelism finds latent order-dependence; it does not create it. Enabling it surfaced seven contaminations that serial alphabetical ordering had been hiding, every one of them a real defect — a test-body monkeypatch.undo() that un-isolated GHOST_HOME and repointed it at the operator’s live data directory mid-test, and a _PrettyLogHandler that outlived the test attaching it and piped every later test’s agent warnings into that test’s captured stdout. A test that fails under -n 8 and passes alone is reporting a bug in the suite, not in xdist. See PROJECT_JOURNAL.md §4CX.
