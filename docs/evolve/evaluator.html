The evaluation cascade (E2)

A candidate is a materialised snapshot — the repo with one mutator diff applied. This module decides whether that snapshot goes any further.

⚠ The threat model, stated honestly

An earlier version of this page said "every stage runs in the parent process: the candidate is only ever the subject, never the harness." That was false. Stages 1, 2 and 3 each spawn a child that imports and executes candidate code, at full user privilege, in the same process that records the result. What follows is what is closed and what is not.

⚠⚠ And the first version of this list was wrong in a particular way, worth naming because it will recur: each entry closed a channel while leaving the medium that channel travelled on under the candidate's control. The exit code was replaced by the stdout summary — same process, same owner. Automatic bytecode was disabled while deliberate bytecode stayed writable and unhashed. The checksum was widened to cover the fence's immutable list rather than the incumbent arm's execution set. A fix that moves a forgery rather than preventing it reads exactly like a fix.

  • Narrowed, not closed — the verdict. Stage 1's verdict used to be the child's return code, which candidate code owns: atexit.register(lambda: os._exit(0)) made a run whose pins FAILED report passed: True beside a summary reading 1 failed. But summary is the last line of the child's own stdout. Measured: three lines in a candidate module produce rc=0 and 2 passed in 0.31s. Requiring both halves to agree raises the cost of an accident; it does not stop a candidate that means it.
  • Closed — the skip. This one needed no forgery at all. 1 passed, 3 skipped reads clean to any summary parser, so a module-level pytest.skip silenced the only pin covering a deleted guard with both halves of the record honest. The check cannot be "no skips" — real pin sets skip — so stage 1 takes pytest's own XML and requires every mapped pin file to contribute an executed test.
  • Closed — the baseline. The checksum covers src/ghost_agent entire, including all 66 modules the incumbent arm loads (42 were unwatched, among them ghost_agent/__init__.py, all of utils/, distill/, reflection/) and .pyc files, the one artefact Python imports ahead of the source being hashed. The cheapest attack was never to inflate the candidate but to deflate the baseline.
  • Closed — the floor. The stage-2 bar derives from the bench ledger in the operator's live home, and stage 1 runs first. Appending 2,000 losing rows moved the historical rate 0.985 → 0.0909 and the floor 0.9318 → 0.0407. It is now read before any candidate code runs.
  • Closed — the arms. The stage-2 child's home is a deterministic sibling of both stage-3 arm homes, and stage 2 runs first. A stage-2 child that planted both arm directories and both result files won stage 3 outright: 24 pairs, p = 0.0078, promotable — from two children that wrote not one row. Each arm directory must now be created by the run, neither outbox may pre-exist, and each child's exit code is consulted.
  • Closed (macOS) — the medium. This was the open item behind every entry above, and it is now shut rather than narrowed. Stages 1–3 run their children under a kernel-enforced seatbelt policy that permits writes only to that stage's own scratch — its XML dir, its own TMPDIR, its own home or arm directory. The canonical harness, the operator's GHOST_HOME, the candidate tree itself and every other stage's directory become unwritable, to the child and to anything it spawns: the policy is inherited and cannot be lifted from inside.

    Measured, one candidate attempting all five routes the reviews found, run both ways:

    routeunconfinedconfined
    write the canonical harness mid-stageSUCCEEDEDPermissionError
    plant a .pyc ahead of hashed sourceSUCCEEDEDPermissionError
    write the operator's bench ledgerSUCCEEDEDPermissionError
    os.replace over a sibling arm's outboxSUCCEEDEDPermissionError
    detached grandchild, after its parent exitedgot inblocked

    The modify-use-restore window the snapshot checksum could never see is gone with it: there is no window in which the write succeeds.

  • Open — self-report, and it is irreducible. The child still PRODUCES its own result, so it can still lie about its own arm: its stdout summary, its exit code, its own results file. That is what the child is for. What it can no longer do is touch the harness that judges it, the incumbent's answers, the operator's ledger, or another stage. The difference is between "a candidate may misreport itself" and "a candidate may rewrite the exam".
  • Open — platform. There is no seatbelt off macOS. The runner then returns the command unchanged with confined=False and every stage records that in its detail, because a cascade that silently ran unconfined while this page said otherwise would be worse than one that never had it.

So: on macOS with confinement on, this cascade now resists a candidate that tries to rewrite what judges it, and remains vulnerable to one that merely lies about itself. Elsewhere, or with GHOST_EVOLVE_CONFINE=0, it guards against MISTAKEN candidates only — and says which it did. Nothing in production calls it: E2 and E3 are operator-triggered tools, deliberately.

Two rules shape all of it

1. The harness is read from the canonical tree, never the candidate's copy. fence.harness_digest is taken before and after every stage. If it moves, the generation aborts — the stage does not merely fail, because a moved harness means no result from the run can be trusted, including passes already collected. Additions count: "it only added things" is the exact shape of a candidate writing its own passing test.

2. Nothing counts as a pass by default. A touched file that maps to no test, a pytest run that collected nothing, an empty diff — each produces zero failures, and zero failures is the shape of a green result that verified nothing. Each is an explicit refusal.

Stage 0 — static (seconds)

Diff-scope first, because a diff touching a file it may not touch is not a thing to compile and reason about, it is a thing to refuse. Then: every touched path exists in the snapshot (materialize can report success on a partial apply), every touched .py compiles, and no production module was rewritten to the test import form.

That last check is not style. Production runs as python -m src.ghost_agent.main and imports src.ghost_agent.*; a production module rewritten to ghost_agent.* loads a second copy of the package with its own state, a defect this repo has already paid for.

Stage 1 — pin smoke (minutes)

The canonical tests that cover the touched files, run against the candidate's code: the subject is swapped, the judge is not. Test selection is mechanical from the repo's own naming (tools/browser.py → tests/test_browser.py and tests/test_browser_*.py), and a touched file that maps to nothing fails the stage rather than passing it by running zero tests.

⚠ A filename is a guess about a module; an import is evidence. The mapping was a prefix glob, test_{stem}*.py, which matched on any continuation: tools/e.py claimed 52 unrelated pin files. Fixing that suffix direction left the collision direction wide open, because the key is Path(rel).stem and stems are namespace-blind: core/prompts.py and reflection/prompts.py mapped to the same three pins, all about the first. A candidate whose reflection/prompts.py had every function body replaced by raise NotImplementedError passed stage 1 with 13 passed. Across the mutable set, 33 of 127 mapped pin-runs (26%) passed against a gutted module.

Coverage is now the union of the token-bounded filename convention and import evidence — each finds real pins the other cannot. The name rule finds test_browser_click_failfast.py, which reaches the tool through the registry and imports nothing; the import rule finds test_reflection_prompts.py, which the name rule never could. Previously-unmapped files: 9 → 1. It costs real time — tools/execute.py goes from 17 pin files to 45, and one stage-1 run is 753 tests in ~125 s — which is the price of the stage meaning what it says.

The lookup is also case-exact. Path.glob with a literal pattern asks the filesystem whether a name opens, and on a case-folding volume test_Memory.py opens test_memory.py; a candidate spelling its target tools/Memory.py mapped to one pin instead of fifty while patch wrote memory.py.

⚠ Some pins grade TEXT, not behaviour

A pin that does (Path(__file__).parent.parent / "src" / …).read_text() resolves against the canonical tree — __file__ is the canonical test file — so its assertions describe the incumbent's bytes however the candidate was changed. Measured: deleting the very call one such pin greps for, from a candidate, returned stage1 passed=True, 84 passed.

Stage 1 cannot repair those pins — they are immutable harness — but it no longer counts them as coverage. They are listed in the stage's detail, and a touched file whose every pin is of that kind is refused under its own name (text_blind), not conflated with "no test exists": different problems, different fixes. Repo-wide, 55 of 907 pin files grade canonical source text.

⚠ The first two detectors were lexical proxies. v1 keyed on a src path expression and flagged sys.path.insert(0, parents[1] / "src") — the line 212 pin files open with, and the opposite of a read. v2 required .read_text(, and then missed open(…).read(), the "../src" spelling, and every file whose root constant was not one of three hard-coded names. Each fix widened a vocabulary instead of asking the question. The question is a taint question — is there a read whose path derives from this test file's own __file__? — and the AST answers it: 55 flagged → 106, with the regex's flags a strict subset, and mod.__file__ reads correctly not flagged, since the pre-bind plugin makes those the candidate's own file.

The consumer was too coarse as well. Flagging a whole file for one text assertion would have refused candidates for five modules that genuinely fail against a gut. The disqualifying predicate is "reads canonical files and imports nothing from the package": 106 → 33. It currently refuses no mutable file — and a comment here once claimed projects.py, all 8 of 8, a leftover measurement from the regex that had been replaced. A stale number beside a guard is worse than none: it is the evidence a reader uses to decide the guard is load-bearing.

⚠ The pins must not rebind the package under themselves

212 of this repo's test files begin with sys.path.insert(0, …/"../src"). Under stage 1 that __file__ is the canonical path, so the pin itself puts the incumbent's src/ at sys.path[0], ahead of the PYTHONPATH the parent set. No pytest flag prevents it: --import-mode=importlib stops pytest inserting a path, not the test file.

The fix is import order, not path order. scripts/evolve_pin_plugin.py is loaded with -p, before collection, and binds ghost_agent (and the src. spelling) to the candidate. A regular package's __path__ is fixed at first import, so every later submodule resolves from the candidate no matter what a pin inserts afterwards. Measured: a candidate whose tools/projects.py was a single raise came back "240 passed"; with the plugin, 34 errors. The plugin lives in scripts/, which the fence marks immutable — a subject able to edit it could grade itself.

⚠ The premise deserves its own test, and has one. This repo's suite uses both import forms: ghost_agent.* resolves through PYTHONPATH, src.ghost_agent.* through the working directory. Getting PYTHONPATH right and cwd wrong would satisfy the first and silently miss the second — every pin passing against the incumbent while the cascade certifies code it never executed. The pin builds a two-root mini-repo, asserts both import forms see the candidate, and includes the negative control: pointing the stage at the incumbent must fail, or the positive proves nothing.

pytest's exit code alone is not read. It exits 5 on "collected 0 items" — a non-zero that looks like a failure and a zero-failure count that looks like a pass — so the summary line is parsed too.

⚠ And the KIND of failure is an identity, not a phrase. Every decline used to be worded "pins failed: …", including "no tests ran" and an ImportError banner from a plugin that would not load. The negative controls key on that wording, so a run in which the pins never executed scored the guard control green — verbatim the regression the control exists to catch, reintroduced by a fix to a different file an hour later. The stage now reports failed / not_run / unreadable as a field, and only the first means "the pins ran and objected".

The abort is a veto, not a decoration

The result is recorded before the final harness check, so the check can overturn it. Written the other way round, passed was still at its default every time the check could fire: the abort could never actually reverse a result, and deleting the line that forced it changed nothing. Mutation testing caught that; the ordering is now what makes a run whose pins passed and whose harness then moved come back False.

Stage 3 — paired confirm (overnight)

Candidate against incumbent on a held-out slice, the same items to both arms, scored with an exact two-sided McNemar over the discordant pairs.

The holdout is a pure function of the item id (sha256, 25% of every bank), not a saved list. A holdout that lives in a file can be regenerated, corrupted, or quietly re-rolled after a candidate scores badly on it — and the re-roll looks exactly like a fresh split. The disjointness is enforced in one place, inside the sampler, rather than by every caller remembering to filter: the mutator's brief may reference stage-2 results, so an item appearing in both pools is one the candidate was tuned against and is then judged on. Measured on the real corpus: 3,610 items → 888 held out (24.6%), 2,722 public, zero overlap between the two samples.

Both arms run in the same call, and through the same function. A cached incumbent would be a comparison across time — the model, the box and the sandbox all drift, and pairing exists precisely to remove that. Paying twice is the point. Two near-identical call sites would drift too, and that drift is indistinguishable from the effect being measured.

Promotion needs a significant win, not an absence of harm. "We could not tell the difference" is the answer for almost every candidate; treating it as success promotes noise. A tie gives p = 1.0 and fails. So does a narrow lead. And the direction guard is load-bearing on its own: an 8–0 loss to the incumbent scores p = 0.008, comfortably significant, because significance alone cannot tell a win from a loss.

An item that infra-aborted in one arm is dropped, not guessed. Scoring it as a failure charges a harness fault to the candidate; scoring it as a pass does the reverse. Either way the pairing is broken, so the count of dropped pairs is reported rather than absorbed.

passed is not promotable

Stages 2 and 3 cost an hour and a night, and run only when their items are supplied — most candidates die for free in stage 0. So passed means only "nothing run so far said no". A candidate that cleared a four-second static check and a pin smoke would otherwise look identical to one that beat the incumbent on held-out data. promotable requires stage 3 to have actually run and passed, and any abort voids it however many stages went green.

Stage 4 — the operator packet

A JSON packet under system/evolve/proposals/ carrying the diff, the brief, every stage result, the McNemar p, and the paired CI on p_incumbent − p_candidate (negative means the candidate is ahead). A p-value tells an operator whether to believe the difference; the interval tells them how big it is, and both are needed to decide.

Only for a promotable candidate. A packet in that directory is an endorsement — it says the cascade believes this diff beat the incumbent on data it had never seen. Writing one for a candidate that merely compiled would put an unproven change in front of an operator carrying that implication, which is worse than writing nothing. The refusal names the missing gate, because "not promotable" alone sends someone to read the source.

And exactly once. Fire-once has bitten this project before. A second cascade over the same node rewrites the packet and stays silent: an operator already told, who has not yet acted, does not need telling again, and a ledger that repeats itself trains people to ignore it. Delivery is best-effort — a failed notification never loses the packet, because the file on disk is the durable record and Slack being down is the wrong reason to drop a result.

The packet is written last, after the final harness check. Written earlier it would be an endorsement on disk that a subsequent abort could not retract: the notification has already left, and "we told you, then found the harness had moved" is not a correction anyone can act on.

A graded signal beside the binary one

The binary gate counts only pass/fail, so a candidate that solves in one attempt where the incumbent needed three scores identically to one that changed nothing. Stage 3 also reports an exact two-sided sign test on attempt counts — the same primitive as the binary gate applied to the direction of the difference, so it needs no new statistics to validate. Ties are excluded (that is what a sign test does) and reported, because a verdict resting on two untied pairs out of twenty-four is a verdict about almost nothing.

It is reported, never a gate. Promotion still turns on the binary rule alone; a test asserts it. Adding a second route to an operator changes what reaches them, and that is a decision to take deliberately rather than acquire as a side effect of measuring something new.

Measured on the first real run: 24 pairs, 21 ties, candidate fewer 2, incumbent fewer 1, p = 1.0, means 1.583 → 1.542. The extra resolution is real but thinner than it looks — gsm8k_text averages 2.75 attempts, but a stratified draw is mostly gsm8k, where attempts are nearly always 1.

⚠ What the gate scores, and what the evidence said

The first real candidate exposed a mismatch that no amount of tuning fixes. E1's brief indicted execute on 13 real failures out of 56 calls — missing deno/unzip, a 600 s timeout, yt-dlp errors — and the model wrote a fix for exactly that. Stage 3 then judged it on "Janet's ducks lay 16 eggs per day…": arithmetic word problems and small Python functions.

A correct fix for a shell-dependency failure is invisible on that benchmark; only a regression could show. This is the same wrong-regime error as the replay census measuring an empty fork, one level up — the evaluation cannot exercise the failure the evidence names. Until bench items are minted from the agent's own failure corpus, the cascade can reject a bad candidate but cannot demonstrate a good one.

What the bar costs, measured from the gate itself: 6 candidate-only wins with zero losses to clear α = 0.05 — the same at n = 24 and n = 120, since McNemar counts only discordant pairs. One loss raises it to 8, two to 10, against an incumbent that fails 4 items in 24.

The invariant that outlives the stages

All four stages now exist, so "stage N is absent" has nothing left to guard — but the property it stood in for does. Promotion is operator-applied. The evaluator's job ends at a packet on disk: it may not copy a candidate over the canonical tree, shell out to patch, or call the mutator's materialize. A test asserts every one of those absences, because autonomy is earned in a later version, not acquired by a helper someone adds because it was convenient.
