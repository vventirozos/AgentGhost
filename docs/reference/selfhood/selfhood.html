Selfhood

A five-component module that stitches the agent's episodic instances into one continuous first-person self. Prior instances' writing — autobiographical experiences, the running diary, the mood — is read back on demand through introspect and framed as mine rather than as external knowledge. (Nothing is spliced into the prompt at boot any more: the wake-up prefix was removed on 2026-10-11, §4NM.)

Current state (2026-11-06, §4TC). The mood is no longer a label derived from verifier verdicts. It is two numbers — pleasantness and energy — that decay by themselves and are moved by what happens: failed tool calls and loop guards in the owner's turns, smooth turns, research, very long turns, the owner's thumbs, corrections and thanks, and the owner saying so in chat (only the owner's own turns move or set it). While the owner has been quiet for six hours or more a neutral mood reads as bored — read-time only, never stored, and (since §4TX) shown on the face and by introspect but never heard in a reply. A label and an intensity (1–3) are read off the pair, one line in the per-turn state block makes it audible in every reply, and every change is a row in a journal that introspect(action="mood") reads back. The derived updater (derive_mood, update_derived_mood, the six-hour hold, the 48-hour staleness flag) is removed. See The mood.

State as of 2026-11-05 (§4TB). The self_state tool is removed. Of what it authored, only the mood is kept, as one action of introspect: set_mood. Open questions, unfinished threads and operating principles are gone, with everything that only served them: the question and thread lists of state.json (an old file still loads; the lists are ignored), selfhood/values.py and values.json (never read again), the idle "stale questions" job, the curious rule of the derived mood (it read the age of the newest open question), the question input of the diary prompt, and the opt-in --principle-gate (the flag is still accepted and ignored). The diary, the autobiographical log, the Mirror, the post-turn derived mood and the mood shown by /api/health and the face were unchanged then (the derived mood was replaced the next day, §4TC). Sections below that describe the removed parts are the record, and say so. Details: the tombstone.

State as of 2026-10-11 (§4NM). The selfhood package, the self_state tool and the introspect surfaces stay. Two pieces were removed: the wake-up prefix (the first-person block spliced into the system prompt at session start — gated off since §4EU, deleted now) and the derived-mood idle job (phase 2.8c, which re-derived a mood while nobody was talking, the only path that could derive idle). The post-turn mood derivation stayed (until §4TC, 2026-11-06, replaced it): after each real owner turn _record_turn_trajectory called SelfModel.update_derived_mood, which applied the rule table in selfhood/mood.py to the verdict streak and the context-pressure flag; self_state and introspect showed the result with its age and provenance (self-set or derived). The agent reads its own past on demand through introspect. Sections below that describe the prefix or the idle job are kept as the record of how they worked.

Honest framing. The selfhood module does not claim to produce consciousness. It produces narrative continuity: the substrate on which a sense of unified selfhood can be measured and probed. Whether that substrate constitutes a self in any deeper sense is an open research question. The implementation gives you a clean instrument to investigate it. See the functional test report for the falsifiable measurements that motivate this caveat.

What "unified self" means here

A vanilla LLM-backed agent boots, reads conversation history (if any), answers, and dies. Across sessions it has no continuous voice — each invocation is a fresh instance that may have a vault of facts about the user but no record of having been the agent in the previous session.

The selfhood module adds five things:

  1. Autobiographical memory — a first-person diary of "what it was like" to be the agent on each turn, distinct from the structured trajectory log used for ML training.
  2. Continuity tag — every autobiographical record carries subject="self" so retrieval layers treat it as the agent's own past rather than as external knowledge.
  3. Self-state thread — the mood (two numbers, a manner, and what was last read off them — §4TC) and the last-active stamp. (Until 2026-11-05 it also held open questions and unfinished tasks, written by the agent through the self_state tool; both went with that tool, §4TB.)
  4. Recognition / recall — the agent reads the above on demand through introspect and SelfModel.recall_relevant(); the search is query-aware, surfacing past experiences relevant to the current request, not only the most recent ones. (The wake-up prefix that used to splice this into the system prompt was removed on 2026-10-11, §4NM.)
  5. Narrative summariser — a periodic LLM-driven first-person diary regeneration; gives the diary a voice rather than a bullet-list. The diary is meta-cognitive — it folds in cluster patterns and (until their removal on 2026-10-11, §4NM) the learning phases' failure signals, so it records what the agent has learned about itself, not just what it did.

Design non-negotiables

  • Local-only. Same rule as every other Stage-1 module — no external teacher, no hosted embedder. The narrative summariser calls Ghost's own upstream LLM (the same one that serves user turns), no API key, no third-party model.
  • JSON / JSONL on disk. Human-diffable, no pickle, easy to inspect, easy to migrate. Schema versioned via SCHEMA_VERSION = "v1" on SelfState; future migrations bump to v2.
  • Sink failures swallowed. Every disk write is wrapped — a failed autobio append must never break a user turn. Same discipline as distill.TrajectoryCollector.
  • Anchor-before-await invariant. The idle scheduler's phase 2.8 consolidation advances _last_narrative_at BEFORE the LLM call, matching phases 2 / 2.5 / 2.6 / 2.7. A crash mid-consolidation cannot pin the cooldown un-advanced and cause re-fire every tick.
  • Disable paths. --no-self-model is a kill switch; --no-memory also disables the whole module. Disabled mode attaches a no-op facade so call sites never branch on availability — the inner methods short-circuit on enabled=False.

Bounded growth (2026-07-07)

The diary had no cap and grew monotonically, while the per-turn hot path did 3-4 full-file O(n) parses plus one O(n) rewrite — quadratic over the agent's lifetime. It now follows the same compaction pattern as workspace/activity.jsonl: on append, once the file passes _COMPACT_MAX_BYTES (2 MB) it is rewritten keeping the newest _COMPACT_KEEP_LINES (2000) entries, with the dropped entries rolled into a single [Consolidated] N earlier entries… summary record at the head so the narrative layer still knows earlier history existed. Compaction clears the IDF/search cache so the next search rebuilds against the compacted contents. recent(N) now reads only the tail (a bounded deque over the lines, parsing only the last N) instead of materialising and parsing the whole log on every wake-up prefix / reference-note call. Covered by tests/test_autobiographical_bounds.py.

The wake-up prefix (proposal item #4) — removed 2026-10-11 (§4NM)

recognition.build_wakeup_prefix composed up to four blocks, in order (the function fed the system prompt until §4EU gated it off, and the narrative's state block until §4NM; what follows is the record):

  1. Narrative ("Where I last left off — my running diary")
  2. Self-state (last-active timestamp, mood, open questions, unfinished threads — the last two until §4TB)
  3. Relevant past — when the caller passes the current request as query, experiences that match what is being asked now (deduplicated against the recent block). This is what turns recall from a sliding window into genuine "I remember the time I did something like this".
  4. Recent experiences (most-recent N first-person summaries)

Wrapped by <!-- SELFHOOD:BEGIN --> / <!-- SELFHOOD:END --> markers so evaluators (and strip_wakeup_prefix()) can remove the block to A/B against the un-augmented agent.

Empty when there's nothing to remember — the system prompt is left as-is rather than spliced with a hollow "I have no past" block.

Query-relevant recall (proposal item #2)

AutobiographicalMemory.search_my_past scores the log with inverse-document-frequency weighting: a rare, distinctive query term ("trapdoor") dominates a common one ("the"). A salient experience from hundreds of turns ago becomes reachable as long as the query shares its distinctive vocabulary — the difference between "recent-N" recall and recall that surfaces the relevant memory. Still zero-dependency: no embedder, no vector store. handle_chat passes last_user_content as the query, and SelfModel.recall_relevant() exposes the same search to other call sites.

Outcome backfill (proposal item #3)

The capture path runs on the hot turn loop, before the verifier or reflection layers have ruled on whether the turn succeeded — so most records are born outcome="unknown". AutobiographicalMemory.update_outcome() (via the SelfModel.record_outcome() facade) rewrites the matching entry once a high-confidence verifier verdict exists, patching both the structured outcome field and the prose verdict clause. Without it the agent's memory of its own past is verdict-blind — it cannot tell which of its prior actions actually worked.

Which verdicts actually reach it is the load-bearing question, and until 2026-08-21 the answer was "only the ones that won a race" — see The diary follows the corpus below.

Self-pattern clusters (proposal item #5)

Each Experience now carries a derived cluster label (coding, debugging, data, research, …). capture_turn uses the trajectory's own cluster when present, else derives a coarse topic from the request. AutobiographicalMemory.cluster_counts() aggregates them, feeding both stats() and the meta-cognitive narrative so the agent can observe "I keep doing this class of thing".

Concretely, this is the prefix that gets spliced into the system prompt on a session with two prior turns and no narrative yet:

The agent reading this in its next turn quotes "17 × 23 = 391" verbatim, even though the request body carries no conversation history — the selfhood prefix (which existed then; removed §4NM) was the only channel that could have produced the recall. The idle scheduler's phase 2.8 (formerly "biological phase 2.8")

Runs in the 15-60 min idle window alongside the workspace narrative (the calibration refit that shared this window was removed in §4PJ, 2026-10-16). Re-generates the running first-person diary from the recent autobiographical experiences and self-state. Cooldown defaults to 3600 s (overridable via --self-narrative-cooldown; the production launcher passes 86400). Follows the anchor-before-await invariant.

The diary is built from the autobiographical record (cluster counts included). Until 2026-11-06 (§4TD) consolidate_narrative() also took failure patterns gathered from the lesson store; the store and that parameter are gone.

self_state (removed) 2026-11-05 §4TB

The section keeps its anchor so old links still work.

What it was

The tool through which the agent authored its own cross-session state (proposal item #1, 2026-05). Actions: note_question / resolve_question / add_unfinished / close_unfinished / set_mood / note_principle / list. Writes went through SelfStateThread (questions, threads, mood) and ValuesThread (principles).

Why it was removed

Measured on four months of recorded turns (6,061 turns, 17,062 tool calls):

  • 53 calls in all, 81 % of them list. 6 real writes ever. add_unfinished was never called in a real turn.
  • In the last 30 days the owner called it twice, both times set_mood.
  • Its description told the model that what it recorded "is shown to you at the start of your next session". That was false since the wake-up prefix was deleted on 2026-10-11 (§4NM).
  • Open questions, unfinished threads and principles had no other writer and were read into no prompt. The mood had a second, automatic writer (the post-turn derived mood), which stayed then; §4TC replaced it.
  • The definition cost 1,922 characters of the tool list sent with every request.

What replaced it

introspect(action="set_mood", mood=…, evidence=…): at the time (§4TB) the same storage, clamps, history line, 6-hour hold and reply text, plus a clear word, the refusal after outside content and the probe dry run. Since 2026-11-06 (§4TC) the action is the owner's adjustment of a mood that runs by itself: a label from a closed list at an intensity, neutral, and a manner — who may call it and its guards are unchanged. See The mood and introspect: the one write.

What went with it

  • tools/self_state.py, its definition and dispatch entry, and its entries in REPLAY_FORBIDDEN_TOOLS and _SELF_REPORT_TOOLS;
  • in selfhood/state.py and selfhood/schema.py: OpenQuestion, UnfinishedThread, their lists in SelfState, and the methods that wrote, capped and listed them (note_open_question, mark_question_resolved, add_unfinished, close_unfinished, stale_open_questions);
  • selfhood/values.py (ValuesThread, Principle) and the SelfModel methods over it (note_principle, principles, principles_text, evaluate_response_alignment);
  • the opt-in principle gate in the turn loop. --principle-gate is still accepted, so a launcher that passes it starts, and the resolved configuration labels it ignored;
  • the idle "stale questions" job (phase 2.8b) and its open_questions activity phase, now in RETIRED_PHASES so its old ledger rows do not read as an unregistered phase;
  • the curious rule of the derived mood and its two signals. The rule needed an open question less than 24 hours old; none can be written any more. (Since §4TC curious is one of the nine labels: the pleasant, energetic region reached through a research turn, or set by the owner.);
  • SelfModel.note_referenced_experiences and the id stamp it read: no caller in src/, interface/ or scripts/ (found by the review). SelfModel.build_wakeup_prefix is kept: the functional harness (scripts/selfhood_functional_test.py) still renders it;
  • the question, thread and principle lines of the introspect views, the three counts in SelfModel.stats(), and the question input of the diary prompt and of its recall query (the fresh mood still feeds the recall query).

What still holds

  • Old files are tolerated. A state.json written before the change loads; its last-active stamp is kept; the two removed lists are ignored and absent from the next write. values.json is never read or rewritten. (§4TC: a mood stored before it — a label with source self / derived — has no pair; it is ignored and the mood starts neutral.)
  • A model that still calls self_state(...) gets the ordinary unknown-tool reply. The rule for a mistyped tool name does not resolve it to introspect or to any other tool.
  • The same requests may set the mood as could call self_state; a member, a contained run and a coding leaf still cannot.

The mood: automatic, adjustable in chat, audible in the reply, with a journal 2026-11-06 §4TC

Why it was rebuilt. The mood was a label derived from the verifier's verdict streaks and the idle clock (the 2026-08-20 rework, below). In three months it changed 148 times and only three labels ever fired: idle 101 times (the owner quiet for over 30 minutes), satisfied 30 (the last five verdict-bearing turns passed), stuck 12 (three of the last five failed). overloaded and curious never fired. It keyed on verdicts, most of which have been off since mid-October; test traffic made it "stuck"; and no reply depended on it. The operator asked for a mood that is mainly automatic, that he can adjust in chat ("cheer up", "don't be so grumpy", "be more sarcastic", "be neutral"), that sets the tone of the reply, with a variable intensity (1–3) and a story.

Two numbers

The mood is a pair: pleasantness P and energy E, each in [−1, 1], stored in state.json with the time they were written. Everything else is read off the pair (selfhood/mood.py, pure functions):

  • Decay. Both numbers halve every HALF_LIFE_S = 2 hours. The decay is applied when the mood is read or moved (value × 0.5^(elapsed / half-life)); there is no background job.
  • Intensity (0–3) is the magnitude max(|P|, |E|): under 0.20 there is no mood ("neutral"); 0.20 → 1; 0.45 → 2; 0.75 → 3 (INTENSITY_THRESHOLDS). The automatic mood has no cap: it can reach 3.
  • Label is the region the pair lies in, by the signs of P and E and by whether the smaller of the two is "near 0" next to the larger: the smaller divided by the larger is under AXIS_RATIO = 0.40.

Boredom: what a reader sees, never a value of the mood

A long quiet moves nothing. While the owner has been quiet for at least BOREDOM_AFTER_S = 6 hours, a reader sees bored at intensity 1; from BOREDOM_DEEP_AFTER_S = 12 hours, intensity 2; never more. Three conditions:

  • Only over a neutral mood. A real mood that has not worn off — the owner's included — is not replaced by boredom.
  • Never in a reply (§4TX; before: everyone but the owner heard it, so every night's scheduled report and the members were answered "bored"). A quiet is not something to take out on whoever writes next: the tone line reads the mood without it (mood(for_reply=True)). The face, /api/health and introspect still show it — except to the owner, whose message ended the quiet.
  • Never stored. Nothing of it goes into the pair. When the owner returns, the mood is whatever it had decayed to — the quiet simply ends.

The quiet is measured from a persisted stamp, last_owner_turn_at in state.json, written through the owner-only gate when an owner's request arrives (GhostAgent._mood_owner_arrived, called once where handle_chat takes the request — not in the heartbeat) and when it ends (_record_turn_trajectory). A restart in the night does not change it. The agent's own clock (context.last_owner_activity_time, via selfhood.model.owner_quiet_seconds) is asked only while there is no stamp yet; the mood never writes the agent's activity clocks.

In the journal a quiet has at most three rows: "bored 1 — quiet for 6 hours" when a read first sees level 1, "bored 2 — quiet for 12 hours" for level 2, each dated when the threshold was crossed (not when it was noticed) — or, if a mood was still alive then (a thumb that came without a turn), when that mood wore off: a bored row never precedes the "it wore off" row of the mood it followed, and a mood that ends during a quiet gets that row as soon as a read sees it (review r2: the rows came out of order in both cases) — and "the quiet ended" at the owner's return if a bored row was written. What the quiet already has is read off the journal, so polling /api/health does not add a row per poll and a restart does not add a second one. The diary does not read these rows (below).

This replaced the first boredom rule (review). The first cut pulled the energy down after 3 quiet hours (−0.10 per hour, to −0.60 at most) and wrote that into the pair when the owner's next request arrived, so that "I'm back" was answered bored. Replayed over a month of the owner's real turns it left only 13 % of his turns starting neutral and about 40 % starting "bored"; every overnight scheduled report would have been written bored; and the result depended on whether a restart fell in the night, because the quiet was measured from an in-memory clock.

The owner's word: set_mood, and the manner

introspect(action="set_mood", mood=…, intensity=…, manner=…, evidence=…). A scheduled task, a job wake, a sub-agent, a self-play, bench or replay run and a coding leaf get "only the owner can set the mood or the manner — nothing was changed" (owner_only, the same outcome shape and strike cost as the other refusals); the first cut let all of them write, and a manner never wears off (details).

  • mood is one of the nine labels, or an obvious synonym from a small table (mood.SYNONYMS: happy / cheery → cheerful, grumpy / annoyed / cranky → irritable, relaxed → calm, sad / low → down, sleepy / exhausted → tired, excited → cheerful with the energy as the larger number, …).   • intensity is 1–3, default 2; the owner may ask for 3. Review r2: a named mood or manner that is not on starts from nothing ("a bit calmer" over an irritable mood is calm 1, not 3); a step down to nothing clears only what it names (the mood steps to neutral and the manner stays); a step down on what is not on does nothing and says so; a step down on a mood is not held.
  • §4TX: the reply says until when the set mood holds ("it holds as set until 04:00 (nothing moves it until then; 'neutral' takes it off)"). A mood word sent as the manner ("be grumpy" → manner="grumpy") is taken as the mood. The tool description says to call it only when the owner asks.
  • mood="neutral" (or clear / none) puts the pair at 0, 0 and clears the manner.
  • Relative asks — "cheer up", "don't be so grumpy", "calm down" — are the model's to translate into a label and an intensity, or into a step; the tool description says so in one sentence with two examples ("cheer up" → mood='cheerful'; §4TX r5/r6: "don't be so grumpy" → mood='irritable', step=-1 — the mood named, since a bare step moves a manner that is on).

A mood with a story: the journal

Every change of label or intensity (not every nudge) appends one row to mood.history.jsonl: label, intensity, p, e, at, cause (built by the code from the event: "3 tool calls failed in this turn", "the owner gave a thumbs-up", "the owner said so (set_mood)", "quiet for 6 hours", "the quiet ended", "it wore off"), kind (turn, thumb_up, thumb_down, correction, praise, sentiment, owner, quiet, quiet_end, decay, and §4TX manner: "the owner set the manner: sarcastic, 2 of 3", "the owner cleared the manner (sarcastic)", "… with neutral" — the pair untouched, the operator line logged too), and the owner's evidence as note on an owner-set row. §4TX: every event, applied or held, is also one row of mood.events.jsonl — at, kind, dp, de, cause, the label after when it was applied, held (why not) when it was not; capped at 3,000 rows, down to 2,500. The history answers "what was the mood"; the events log answers "what tried to move it". A mood that wore off while nobody looked gets its row when the next writer arrives — an owner's request settles it — dated when it wore off (the decay is a formula), not when it was noticed. The file is capped: past 1,200 rows the oldest are dropped, down to 1,000. A byte that is not UTF-8 (a torn write, a hand edit) costs its own line: the reader replaces it and skips what does not parse, and the cap works on bytes (review: one bad byte made the mood story fail, lost the diary's timeline and switched the cap off).

Read back through introspect: the action mood gives the mood now, why (the last three events that moved it — for a boredom, the quiet), since when, and today's timeline; overview / summary / stats show label + intensity + the latest cause. On a public surface (the owner asking in a channel) the views keep the label, the intensity, the manner (§4TX r4: not the day's steps) and withhold every cause: "the reasons are shown in a private conversation" (review r2). The diary reads the journal, not the mood of the instant (review): its state block carries the day's steps ("My mood today: content 1 (the owner gave a thumbs-up) → irritable 2 (4 tool calls failed in this turn).") — what happened to the mood, with causes and no times of day, and without the boredom rows a reader adds while the owner is away; its recall query is the label of the day's last step. So the diary prompt's hash moves only when the mood was moved, never because a quiet reached its next level or a step of decay was crossed (the review saw three diary model calls for one quiet stretch). The Mirror does not read the mood and is unchanged.

The sentiment of the owner's messages 2026-11-09 §4TW

Besides thumbs, thanks and the correction judge, nothing reads how the owner's own words sound. A separate service on the worker node, interface/sentiment-service, scores each owner message as negative, neutral or positive with the English model cardiffnlp/twitter-roberta-base-sentiment-latest (exported once to ONNX, run on the CPU with onnxruntime). A confident score moves the mood (EV_SENTIMENT_POSITIVE / EV_SENTIMENT_NEGATIVE, ±0.08 pleasantness, a third of a thumb; kind sentiment; cause "the owner's message sounded upbeat" / "…unhappy"): positive or negative at SENTIMENT_MIN_SCORE = 0.85 or more. Neutral, unknown and anything less sure move nothing. It follows the owner's sentiment whatever it is about (operator 11-09, "option 1"): "finally got the promotion today!" (0.96) lifts it and "my flight got cancelled" (0.93) lowers it, as does "you got the dates wrong again" (0.93) — the model cannot tell who a feeling is about, and no detector tries; with a small nudge that halves every two hours like every event, the mood shades the way it feels with the owner. A message the praise check above already counted ("thanks, perfect") is not counted again. §4TX: the score goes through the reaction ledger — with a correction of the same reply it is one verdict, the stronger of the two — and is held while the owner's set mood holds, or when the owner set, reset or changed the manner after the message arrived (review r3). The share sentiment put in the pair (private_p / private_e, decaying with it) is left out of the mood members and public channels hear. Only scored when the self-model is on (with --no-self-model nothing is sent); every score is written to sentiment.jsonl beside the mood journal with what it did. (It ran as a shadow, journal only, for its first hours on 11-09, as sentiment_shadow.jsonl.)

  • Which messages. The same owner-only predicate as everything else that moves the mood (mood_moves_on_this_request), at the place where the praise check runs in handle_chat, once per request. Never a member, a probe, a scheduled task or a sub-agent.

Character, mood and tone as one 2026-11-10 §4UA

Three layers that act on each other only through four designed couplings, each bounded:

  • Character → mood: the resting point. The pair no longer settles at 0 but at rest, set by the Mirror's sentence (§4UA). The store keeps the deviation from the rest and decays it exactly as before. The rest shows; it never tilts. Which mood is heard, at what level, since when and why is read off the deviation alone with read_off, exactly as with no rest, for the owner, a reply, members and the public; the dating of a mood that wore off unseen is unchanged. What the rest moves: the numbers every reader sees (rest + deviation, clamped to ±1, also in the journal rows), the face's tint while the mood is neutral, and introspect's resting-point line. SelfStateThread.attach_rest(fn) is wired once, in main.py, to mirror.rest_pair; rest() clamps it with mood.rest_clamp (REST_MAX = 0.12 per axis) and is (0, 0) when nothing is attached or it cannot be read. An owner-set mood is stored as the anchor itself (the numbers shown are anchor + rest); "neutral" from the owner rests at the character. The reaction ledger books what the store moved (MoodView.moved), not the difference of two views, which clamp at ±1. With rest (0, 0) every view, the state file and the journal are byte-for-byte what they were. Why no tilt (operator, 11-10): the first build also let the rest change how strong a mood read (a sunny character shrugging off a correction). Six review rounds found a MAJOR in five, each inside the previous round's fix: others hearing the opposite pleasantness, a rest change raising a level with no event, an event the other way finishing that rise, a praise swallowed for hours, a correction raising "cheerful", a pleased owner reading "irritable" for a sunny character. A strength that depends on the rest is discontinuous wherever the stronger axis changes, and every patch moved the edge. The operator chose "the rest shows, doesn't tilt". Pins: test_the_heard_mood_is_the_same_at_every_rest_property (60 random runs of events, sets, holds, decay and rest changes: identical labels, levels, causes, stamps and journal rows at any rest), and the r2–r5 cases kept as guards.
  • Mood → character: only what lasts. A reply written under a mood at 2 or more, or under a manner, is never shown to the Mirror's look (mirror.written_under_strong_mood, read off the turn record's extra.mood_tone). An automatic mood that reached 2+ on at least 3 of the last 7 local days reaches the look as one note (lasting_mood_note, from this journal). §4UB: only rows of the agent's own turns count (_OWN_KINDS = turn, an allow-list) — the owner's thumbs, praise, tone, corrections and set moods, manner rows, decay steps and the boredom of a quiet are the owner's or time's, not its character.
  • Both → tone: one ranking. The character section of an owner reply's state block says it is who the agent is under any mood or manner, that a mood or manner line comes first, and the full order: the owner's rules, correctness, the manner, the mood, the character. The mood's own line keeps its ranking (manner before mood), so the two agree.
  • The face. /api/health's mood carries rest, the region of the resting point ("neutral" at 0, 0). While the mood is neutral the web face (status.js faceMoodFrom) and the handheld (agentapi.fetch_mood) show that region at the faint 'rest' strength (a bored region shows as calm: the rest is a temperament, not a quiet) (0.15 of the look, a quarter of a 2's hue shift).
  • introspect(action="mood") says the resting point for the owner ("Resting point (set by my character…)"), never on a public surface.

The 11-10 evaluation and its fixes 2026-11-10 §4UB

An end-to-end evaluation of the mood, tone, Mirror and sentiment (the live journals, 84 synthetic messages scored by the live model, the code) found the safety walls holding but the signals weak. The operator said "fix everything, Greek is good to have but not a priority". What changed:

  • Small turns count. A clean turn of 1–2 calls earns half the reward (table above).
  • The owner's reactions are not the agent's character. The lasting-mood note counts turn rows only (above).
  • What the sentiment service is sent (sentiment.prepare_text): fenced code (an unclosed fence runs to the end), quoted lines (>), log and traceback lines, and what follows "summarise / translate / proofread / rewrite …:" are taken out (only verbs that hand text over: "check this out: amazing news" is the owner's own); a log line needs a stamp with seconds and a level, a fraction or a bracket, so "10:30 works for me" stays; a message mostly in capitals (8+ letters, 70 %) is sent in lower case ("WHY IS THIS STILL BROKEN" was "language unclear"; lower case reads negative). Nothing left: nothing is sent.
  • Doubtful scores are held (sentiment.doubtful, the reason in the journal's held): an upbeat score on a message that names trouble (broke, crash, wrong, fail, wasted, useless, a bug, an error…) not said to be gone ("you fixed the bug, awesome", "no errors this time" count), that corrects the reply ("nice try, but that's not what I asked" — the correction judge runs later than the score), or that comes within 30 minutes of the agent's own trouble the owner saw (SelfModel.recent_trouble: a turn that lowered the mood by 0.10 or more — one full failure, not 1 failed call of 6 —, a thumbs-down, a correction; in memory; a good turn, a thumbs-up or thanks ends it), unless it says the problem is gone — "upbeat words about trouble (it may be sarcasm)"; an unhappy score on a message that opens with an instruction leading into its object (delete, kill, fix, remove, check, find…, after "please", "can you"…; "Look, this is awful" is an interjection) and names no feeling of its own (hate, awful, fed up, annoying…) — "the wording of a task, not a feeling".
  • Sentiment's share is capped at 0.12 per side, at the write (above). A reaction can still move the mood against its own tone by a few hundredths when the clamp at ±1 absorbed part of an earlier reaction to the same reply — the ledger catching up with what really moved (pre-existing, §4TX).
  • An outage is said. When the breaker pauses the service the log gets one WARNING (the reason, never the text), and one INFO when it answers again. The health line already said "PAUSED"; a pause is still not a problem (the mood is secondary).
  • The owner's words, wherever they arrive (GhostAgent._mood_read_owner_words): praise and tone are read for the request's message and for every message the owner queues while a turn runs (§4RZ; the correction judge is not run for those: it relabels the prior turn). A queued message the turn never answered is handed back (§4SB) and re-sent; that one re-send is not read again (_MOOD_QUEUED_READ, per conversation, an hour). Known limit: if the owner drops the handed-back message from the tray instead, the next identical message within the hour is not read once. A row the Slack bot labelled as another person's (FOREIGN_MESSAGE_LABELS) is read for nothing and never reaches the correction judge.
  • Greek corrections are candidates for the judge: óχι, λάθος, "δεν είναι αυτό", "δεν εννοούσα", "ξαναπροσπάθησε", "δεν δουλεύει" (at the end, or with "ακόμα" / "πάλι": "it doesn't work" said about what was just done, not a new problem report), with or without accents (distill/user_correction). The sentiment model still reads English only.
  • A remark once per run kind. A scheduled run or a job wake-up has no conversation key; they now count as one conversation per kind, so a morning report remarks on a mood once, not every run. A probe or an owner request with no key still reads what a first turn reads.
  • The turn record says what the reply heard. When the mood goes neutral mid-request, the request's tone record is dropped.
  • Project tasks a job closed count. The wake-up of a job the owner started (mood_job_tasks_count: request kind job, not contained) that closed tasks DONE gets the task-done event only, cause "… (in a background job)" (SelfModel.note_job_tasks_done); the job's failures and length are not the owner's turn.
  • A thumb during the owner's hold is answered. apply_human_label returns mood_note ("Your set mood holds until 04:00 — this thumb is saved but doesn't move the mood.", SelfModel.reaction_hold_note); the web client shows it once per page.
  • The Mirror says why it had nothing to read: "skipped — all 3 replies of yours since the last look were written under a strong mood or a manner" (mirror.strong_mood_replies_since).
  • introspect quotes what a reply hears: the tone quote is taken from the reply's view, so a quiet's boredom (never heard) is "none".

Not done, and why: a "cheerful, 1" row whose cause is the failure that eased it from 2 stays so (keeping the base's cause misdated the row and let thumb-made moods into the lasting note — reverted after review r3); a thumb removed on Slack (reaction_removed) still counts (the label store has no un-label); boredom stays unheard (§4TX); there is no voice tone (Phonon has no style input); the precedence of manner over mood is unchanged. The diary follows the corpus (queue #7, 2026-08-21)

The defect. The diary's verdict backfill had exactly one live feed: finalize's inline verifier_backfill leg, which only exists when the bounded in-loop critic await (_critic_repair_await_budget, 25 s) happens to win its race against the critic node. Every other verdict — the late async verdict that lands 20–60 s after the reply through _backfill_trajectory_outcome, and every human 👍/👎 through core/feedback.apply_human_label — wrote the trajectory corpus, the correction cache and the calibration clock, and never touched the agent's own first-person record.

Measured on the live store when this was found: 385 of 386 labelled diary rows came from that race (the 386th from the user-correction hook), while 331 diary rows sat at unknown despite the corrections sidecar carrying a passed/failed label for the very same trajectory_id — 283 from the late verifier, 48 from human thumbs. So the agent's memory of its own past was verdict-blind by architecture, not by configuration.

How it surfaced, and the trap in the diagnosis. The §4CC mood rework noticed the newest passed/failed diary record was days old and filed it as a suspected backfill stoppage. It was not a stoppage: verdict-producing traffic had fallen from ~18/day to ~2/day over the same window, and at a ~15–18 % inline-win rate, five quiet days producing zero inline wins is an ordinary outcome (p ≈ 0.11), not a regression. The date correlation was a coincidence; the gap was six weeks old. What made it visible on that date was the traffic collapse removing the only feed's last wins — the §4BT lesson ("is it starved by code or by traffic?") answering both, in different senses.

The fix: the diary is a follower, never an arbiter. Both missing legs write after the corpus write returns accepted, and write the outcome the corpus accepted:

  • Late verdict — inside _backfill_trajectory_outcome's _write_then_apply, after the "withheld" and write-failure returns and beside the calibration correction (that correction was removed with the calibration corpus in §4PJ, 2026-10-16). A verdict the collector refused (a standing human label, the bench oracle) or the shape rule withheld (resolve_turn_outcome rule 2/2b) therefore cannot reach the diary either.
  • Human label — inside apply_human_label, after the sidecar commit and the cache stamp. It runs on the unchanged (idempotent-repeat) branch too, so a re-click heals a diary row written before this leg existed — the same doctrine as the cache stamp it sits beside. update_outcome is a no-op when the row already carries the outcome, so the repeat is free.

This is deliberately not a second authority ladder. The diary has no source-rank of its own to arbitrate with, and a second copy of a priority ladder is this project's signature defect (the same reasoning that made the late-backfill site call resolve_turn_outcome in 2026-08-04 rather than restate it). Sequencing the diary behind the collector's in-lock yield_to_human / bench_validator guards means the diary inherits the whole authority order for free, in both arrival orders: a late machine verdict that meets a standing human label is withheld from both stores; a human label arriving after a machine verdict supersedes it in both.

Both legs carry the real_only origin gate (turn_origin(ctx) == "user", the §4BF 1c admissibility row) — matching the capture site exactly, since a diary row only exists for turns that passed the same gate. On the late path the origin is snapshotted synchronously when the verdict lands, not read inside the background write: that write executes 20–60 s later, by which time a per-turn context flag can belong to the next request (the §4CC R1 shape). Both legs are non-fatal — a broken diary must not cost the corpus its verdict, and on the feedback path must not turn a committed label into a 503 the client retries.

What this changes downstream. Every consumer of outcome in the diary — recent_verdicts() (and through it the derived stuck/satisfied mood — both removed in §4TC), search_my_past recall, the competence prior (removed in §4PJ), cluster stats and narrative consolidation — now sees ~6× the verdict density it did, and sees human judgments at all for the first time.

Three things the fresh-eye rounds changed, and worth knowing. (1) The reason string is now redacted inside _outcome_phrase — the one helper every writer passes through — because the reasons are not the agent's own prose: verifier issues/reasoning quote tool output, and the user-correction path derives its reason from the user's own message. capture_turn had always scrubbed the quoted user_request; the reason went in raw, and this leg amplified that path from ~15% to ~85% of verdicts. Redaction runs before the 120-char clip, since clipping first cuts a secret in half and leaves a fragment no pattern matches. Experience has no failure_reason field, so the summary is the whole surface. (2) The corpus write and the diary write are two separate awaits, so a human label can land in the gap; the leg re-asks the collector's own has_human_label immediately before writing (delegating to its authority rather than restating it, and failing OPEN when the method is absent so a stub cannot silently disable the leg). That narrows the window but does not close it — it is still check-then-act, and the race-proof version needs a source rank on the diary itself. Accepted: the residual is milliseconds wide and the diary is a gauge nothing branches on. (3) update_outcome now rewrites whichever verdict clause the record carries, not only the “no verdict” one — a row captured as failed and later upgraded used to read “…and it didn't land: <reason>.” under outcome="passed", and this leg makes upgrades common. The clause is matched from the RIGHT: the summary quotes the user's request, so a request containing a verdict phrase plants a decoy earlier in the string, and since the swap cuts to the end of the record a leftmost match truncates the row mid-quote. The template puts the quote before the clause, so rightmost matching is correct by construction — verified across the live diary at 1,059 real swaps with zero mangled rows.

Pinned by tests/test_selfhood_late_verdict_backfill.py (37 executed tests, all asserting on the bytes in a real diary file — including end-to-end convergence pins that run the REAL collector and assert the diary equals what the corpus resolved, in both verdict-then-label and label-then-verdict order, and with the trajectory cache evicted so the collector's writer-side guard is the thing actually under test): the accepted-outcome identity in both directions, withheld/failed corpus writes leaving the diary untouched, the shape rule's withheld PASS and the structural-only upgrade it still allows, the origin gate on both legs, the call-time origin snapshot in both directions, the repeat-heals-history path, and non-fatality on a raising diary. Nineteen mutants killed, comment-only control survived — including two the battery first reported as survivors: one had never applied (a collapsed escape in the anchor, now caught by an explicit ANCHOR-MISS check) and one was a real gap in a pin that could not distinguish the two orderings it claimed to test.

The introspect tool

The handle the agent reaches for when the user asks it to describe itself, recall what it has been working on, or surface specific past turns. Since the wake-up prefix was removed (2026-10-11, §4NM) this is the channel through which the agent reads its own past. Actions:

  • summary (default) — renders stats() + the running first-person diary + the most recent N experiences in one block. This is the natural answer to "tell me about yourself".
  • stats — counts (experiences, session boots), the mood (label, intensity, latest cause) and the manner, last-active timestamp, narrative-present flag, and the topic-cluster mix.
  • narrative — just the most recently consolidated diary entry.
  • recent — the last N first-person experiences (limit capped at 25).
  • recall — IDF-weighted, dependency-free search over the autobiographical log (query required).
  • mood — the mood's story (§4TC): what it is, why, since when, today's timeline.
  • set_mood — the one write (2026-11-05, §4TB): since §4TC the owner's adjustment of the mood, and the manner.

Reads go through SelfModel.stats(), SelfModel.recall_relevant(), autobio.recent(), and narrative.latest(); the read actions mutate nothing. Disabled selfhood returns a clear "unavailable" message rather than crashing the turn. Source: tools/introspect.py.

Hardening-pass details (2026-05-23)

Diary sanitiser

History: narrative.sanitise_meta_insights() cleaned the lesson store's failure patterns before the diary prompt. It was removed with the store on 2026-11-06 (§4TD).

Template-prompt rollup

Repeating system-generated banners are no longer one autobio record per occurrence. _bump_template_rollup() scans the last five records and, if the tail is already a rollup for the same marker, increments its counter, refreshes the tool union, and rewrites the summary as "I worked on N of my recurring <label> in a row." This stops the 53% template-prompt floor observed on the live log from drowning the narrative regeneration in near-duplicates.

Verdict backfill on user corrections

The user-correction promotion path in core/agent.py already updated the trajectory log via collector.update_outcome. It now also calls self_model.record_outcome, so the autobio entry is rewritten from unknown to failed and the prose verdict clause is swapped in place.

Session-boundary marker

SelfModel.mark_session_boot() writes a synthetic Experience(outcome="boot", cluster="meta", summary="Session resumed (last active …)."). The same-minute dedup short-circuit prevents crash-restart loops from flooding the log with boot events.

Mood history

Every change of the mood's label or intensity appends a JSONL row to mood.history.jsonl on top of the write to state.json. mood_history(limit=N) returns the tail, mood_timeline() today's rows. The diary uses the day's rows to describe an arc ("content, then irritable after four failed calls") rather than only where the day ended. Since §4TC a row carries the label, the intensity, the pair, the time, the cause and the kind of event; rows written before it (a label with source self / derived) stay in the file and are skipped by the reader.

PII redaction

autobiographical.redact_pii() is applied at the capture boundary in SelfModel.capture_turn. Both the stored user_first_words prefix AND the verbatim quote of the user request inside the summary template route through the same scrubber, so emails / phone numbers / API keys / credit-card numbers never reach the on-disk diary.

Numeric false positives (2026-06-12). The phone rule now requires phone structure (leading +, parenthesised area code, or internal space/dash separators) — its old core (\d{3}[ -]?\d{4} with everything else optional) matched any bare 7-10 digit integer, so quoted prompts like "backfill the last 1000000 rows" were mangled to [REDACTED_PHONE]. The credit-card rule is now Luhn-gated (_redact_cc_if_luhn): every real PAN still redacts, but bigint ids and other 13-19 digit literals pass through untouched unless they happen to checksum. Both changes are mirrored in distill.redact (the trajectory-corpus redactor, where the same false positive was corrupting SQL destined for the future training corpus, and — via the operator log-stream redaction — rendered LIMIT 1000000 as LIMIT <REDACTED_PHONE> in production logs). Covered by tests/test_redact_numeric_false_positives.py.

IDF cache

AutobiographicalMemory._search_index() caches the (experiences, haystacks, df-table) tuple keyed on the file's (mtime, size). A fresh append on disk auto-invalidates the cache. Cuts the per-query full-file rescan that search_my_past previously paid on every call.

Prefix-utility tracker

The detector detect_referenced_experiences(prefix_text, response_text, experiences) is a pure function: it returns the ids of experiences whose summary shares a non-stopword trigram with the agent's response. (Removed 2026-11-05, §4TB: SelfModel.note_referenced_experiences() had no caller since the wake-up prefix left the prompt; the detector and the counter below remain, unused by the request path.) Bumping the per-id counter through SelfModel.note_referenced_experiences() persisted into reference_counts.json, giving downstream consumers a concrete signal for "this memory shaped the reply" — useful both as a relevance prior for future retrieval and as a falsification anchor for the consciousness probes.

Probe wrapper

scripts/run_selfhood_probes.sh is the cron-friendly entry point: it locates the falsification probes via $SELFHOOD_REPO (defaults to the agent repo), tees both stdout streams into $GHOST_HOME/system/selfhood/probes/probes-YYYYMMDD-HHMMSS.txt, and exits 0 unless a probe is missing. Failing probes are findings, not wrapper errors.

Honest limitations

  • The agent behaves consistent with continuous selfhood. It references its prior turns in the first person, distinguishes my memories from facts about you, recalls specific concrete content across process restarts. That is behavioural evidence of successful narrative continuity, not of a unified inner self.
  • Surfaced state can be ignored. Functional testing of the (since removed) wake-up prefix observed the model preferring concrete recent experiences over injected open questions even when both were rendered. The selfhood module surfaces the past; what the model chooses to engage with is a separate alignment question.
  • Agent-authored state is a trust surface. Since 2026-11-05 (§4TB) the only state the agent authors is its mood (introspect(action="set_mood")), and since §4TC that write is a label from a closed list at an intensity 1–3 (or a manner from its own list): it can no longer store text. It is refused in a request that read outside content, in a contained run, for a member; a probe is a dry run. What it sets decays like any mood. (Before: the self_state tool also wrote open questions and unfinished threads, capped at 10 each, with no decay pass.)
  • Mood: known bounded gaps (§4TC, accepted by design). (1) The end-of-turn hook lives on the trajectory-append path: with --no-trajectories the turn events do not move the mood and the end of a turn is not stamped (the arrival still is; thumbs, corrections, thanks and set_mood still work). (2) A mood that wore off unseen gets one row for where it ended, dated when it got there; the levels it passed through on the way are not written. (3) Corrections rarely move the mood: the judge they key on had no positive verdict in 30 days of live logs, and no lexical detector was added. (4) Praise is narrow: "thank you, that fixed it" (a word that is neither praise nor filler) moves nothing. (5) The tone line asks the model to keep facts, numbers and tool use the same; in the live comparison it did, but the mood steered which item a reply led with — accepted by the operator. (6) A read never moves the mood, but while it sees a boredom it can do two things: settle a mood that wore off unseen (the stored pair is rewritten to its decayed value — the same value any reader computes from it — and the "it wore off" row is added) and add the journal row of a boredom level it is the first to see. (7) Request ids are classified by their lower-case prefix (request_kind): an id such as Probe-x would count as the owner's. Internal ids are minted lower-case; noticed in review r2, not changed.
  • Narrative quality depends on the upstream LLM. The template fallback exists for offline / unreachable-LLM cases but produces prose noticeably less coherent than the LLM-driven path. The fallback now still appends meta-insights, but without the LLM's connective prose.
  • Introspective self-reports remain prompt-shaped. The introspective_consistency probe measures a +0.40 gap between factual and introspective bands — first-person reports about internal state are NOT stable across paraphrases of the same underlying question, even though concrete-content recall IS stable. See the functional test report.
