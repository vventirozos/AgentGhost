core / coding_executor.py

§4UY C18 (2026-11-18): the spec executor was REMOVED. What is left is a small module of shared pieces and the production executor MARKER.

Why it was removed

The spec executor built one project leaf from ONE model call that returned whole files as JSON, then wrote them and ran one verify, up to a few attempts (3,272 lines: think/no-think policy, grammar retries, generated files streamed round by round, non-regression and append guards, owner yields). Since §4UL (2026-11-12) every project task runs as one full agent turn (project_turns) with every tool and the close gates of manage_projects task_update; the spec path was only the fallback for a turn that could not be built (task turns switched off, no model or project store, a prompt that raised). Its last run in the live log was 2026-11-07, and its tests pinned a path production no longer took. A fallback to a weaker builder is the class §4AT-C already refused for a crash, so the fallback is gone rather than kept as a silent second route.

What happens instead

advance_once: a CODING task wired with the production executor runs as a task turn, or — when that turn cannot run — its claim is released (the task goes back to PENDING, or to the owner's hold it was claimed from) and the tick returns blocked with TASK_TURN_UNAVAILABLE_PREFIX and worked=False. An owner batch stops there (stop_reason = "step_crashed"), it does not re-pick the task. A research task keeps its research path. A caller-supplied (unmarked) executor — the advancer's own tests — is still called and its CodingResult consumed as before.

What the module still holds

  • build_coding_task — the marker the callers pass (manage_projects autoadvance, POST /api/projects/{pid}/advance, the idle loop's _aa_build), marked by project_turns.mark_real_executor. The advancer never calls it; called directly it builds nothing and returns CodingResult(ok=False, SPEC_EXECUTOR_REMOVED).
  • leaf_deadline_context / caller_waits_context and _request_left_s — the turn clocks project_turns, coding_loop.run_leaf_turn and the lab tool read.
  • CodingResult — the result shape the advancer consumes from a caller-supplied executor.
  • _TASK_NAMED_FILE_RE — the task-named-file pattern of the advancer's workspace gather.

Removed with it: coding_loop.build_coding_task_agentic and its selection (executor_kind, the shape rule, GHOST_CODING_EXECUTOR, metadata.executor), and the settings only the spec path read (GHOST_CODING_THINK_SKIP_AFTER, GHOST_CODING_THINK_PROBE_AFTER, GHOST_LEAF_BUILD_MAX_S, the spec grammar switches). The history of the removed design is in PROJECT_JOURNAL.md (§4AT, §4EI, §4FG–§4FL, §4QA, §4SD, §4UL).

Pins: tests/test_4uy_code_spec.py (no builder runs with the marker — turns off, idle or not, and a turn that cannot be built; the claim is released; an owner batch stops; an unmarked executor is still called; the marker builds nothing), tests/test_4ul_autopilot_turns.py::test_switched_off_or_unbuildable_nothing_builds_and_the_task_is_reopened.
