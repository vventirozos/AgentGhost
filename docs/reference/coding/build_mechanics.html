Build mechanics (§4UU) — make the model's coding loop do the checking

Five mechanical changes to how a coding turn runs (2026-11-17): a headless page load after every web write, a checklist ticked only by checks, a strict definition of "ran it", hints for labs / the tailnet / privilege refusals, and a web-app starter project.

Why it exists

A study of 38 owner coding turns (10-25 → 11-17) found the model fixes bugs it can see well (median one fix cycle, no same-error loops). The cost was elsewhere: monolithic web builds (the web OS 11 times from scratch, 10.2 h, 41 % of owner coding time), browser-driven UI testing (120 calls, 27 failed), "done / tested" claims after only a syntax check or a read (37 of 38 replies claimed done; about 5 turns ran the program after the last write), lab misuse (32 failures: no member 6×, invented templates) and environment limits retried (tailnet through the Tor browser 9×, su after EPERM). Each item below closes one of those, without a model call.

1 · Page check after a web write (core/page_check.py)

A successful file_system write / edit of .html .htm .js .mjs .css — the LAST web write of its tool batch, not a file still open for parts, not a syntax-refused write, never in a member's turn — loads its page headless through GhostAgent._execute_web_artifact (the WEB-EXEC probe: the page itself, or the index.html next to an edited script; served through a running sandbox service when it calls the network). The result is appended to that write's tool result:

  • [PAGE CHECK] ✓ loaded '…' headless: no uncaught JS exception. Ran: app.js, index.html.
  • [PAGE CHECK] not run — … for a page that calls the network with no running service covering it. When the page fetches its OWN data file by a relative URL (fetch('sales.json'), .json/.csv/.tsv/.txt/.md/.xml/.geojson), a [PAGE CHECK] note: follows: opened by double-click (file://) the browser blocks that fetch and an http check does not test it — embed the data (inline JSON or a <script src="data.js">) and check over file://, or say it needs a server (2026-11-18 live run: a "double-click" chart was tested only over http and errored from disk). page_check.local_fetch_note.
  • [PAGE CHECK] ✗ '…' FAILS on load (an uncaught exception, or its own files did not load) — … Ran: …. followed by the exceptions, or the console lines of a LOCAL file that never loaded (net::ERR_FILE_NOT_FOUND, an ES module a file:// page cannot load — with the classic-script hint). Network / CDN errors do not fail it (they depend on Tor);
  • for an HTML page the probe could not load: "not run — … load it yourself before you say it works"; nothing for a script with no page.

The probe navigates with SYSTEM_PROBE_NAV set (tools/browser_support.py): its visits go to a throwaway .last_url.sysprobe sidecar, so the model's own url-less browser calls keep re-opening the page the model last visited. A later write in the batch takes the probe over only when it SUCCEEDED in writing a web file of the SAME page (a script in js/ css/ scripts/ styles/ assets/ static/ belongs to the index.html one level up — the probe looks there too).

The write keeps its status (information, not a block). The Ran: list is the page plus its <script src> files that EXIST and their relative ES imports (four levels, from script files and inline module scripts; data-src is not a load); the claim arm reads the line back from the row (page_check.checks_in), so a clean load counts as a RUN of each file and a throw as a FAILED run — the same live and in the failure census. Only the FIRST whole line that starts with the marker counts (what follows a ✗ line is the page's own exception text). Switch: GHOST_PAGE_CHECK=0.

2 · The checklist (tools/checklist.py)

A tool the model keeps its build plan in — one item per feature, each {title, check}. There is no "mark done": only check changes an item's state, by RUNNING the check.

CheckPassed when
a shell commandit exits 0 through the sandbox execute. A command that runs nothing (a syntax check, ls, cat, grep, test -f, echo, true, bash -c true) is refused at set/add by the §4UU-3 rule. A request to a service running here counts when a bad answer fails it: curl -f localhost:5000/api, curl -s 127.0.0.1:8080/ | grep ok. A check whose failure is swallowed at the end (|| true, ; exit 0, || echo no, set +e) can never fail and is refused.
page:<file.html>the page loads headless with no uncaught exception (the item-1 probe).
file:<path>the file exists and is not empty (a folder: it holds something).

A drop of ids the list does not hold is refused; a check call that runs out of its time budget says which items it did not run; a damaged list file loses only the damaged rows. Actions: set (replace the list; an item with the same title and check keeps its state), add, check (ids, or all), drop, view, clear; at most 20 items. The list lives in the HOST data dir, $GHOST_HOME/system/checklists/<scope>.json — never in the sandbox, so code running there cannot tick an item. Scope: the turn's project (kept until cleared), else the conversation (idles out after 24 h), else the request.

  • Stale passes. A file_system write, or an execute that writes code (a heredoc, a redirect, filename=, sed -i / perl -pi, cp/mv onto a code file, git checkout/restore, a formatter with its write flag, inline Python/Node open(…,'w') / writeFileSync) — whatever the call's status, unless it was refused — turns every ✓ item into ↻ "passed before the last code change — check again": which feature a file serves is unknown, so all are re-checked. Docs, tables and images (.md .txt .csv .png …) do not count. Exempt: the items a checklist call of the same batch RAN after that write — every checklist call for a file_system write (writes run in the batch's first phase), only LATER ones for an execute (they wait for it) — read from that call's own result rows.
  • Honest rows. A check is one line that does not contain "— check:"; a title's "—" becomes "-", so a title can never plant a check the claim arm would read. A list of only file: checks, and weak checks (exit 0, :, sleep, --version), are refused.
  • Order and limits. One checklist operation at a time; in a batch, a checklist call waits for the earlier execute / lab / run calls (and they for it). One check starts no new check after 600 s. A check that runs a privilege program the request already saw refused is not run (the §4UU-4 memo applies, and a check's own refusal is recorded).
  • Status line. While items are open, the last tool result of a batch that writes / runs code or uses the checklist ends with [CHECKLIST 2/5 passed · next: #3 rotate ✗; #4 score].
  • Done claim. A reply that says the work is done / working / live while items the request worked on have not passed gets one repair round (the same re-entry as the code-claim arm, checklist_directive) — not when the reply itself says what is unfinished ("not yet", "except", "still fails", "remaining").
  • Claim arm. A checklist check row counts as a run of the files its checks ran (by the execute rule; page: as a page load) — only items chosen by that call, never a view.
  • Turn-loop machinery treats it like execute: a failing check is the program's own failure (no strike); a check resets the edit-churn reminder (so does a write the page check loaded); a status-only question does not start checks; operation=check is a mutation like action=check; checks run through the egress-guarded execute. Members never see it; a contained / replay surface forbids it, and any surface that forbids execute or browser forbids it too.

3 · A run is a run (core/code_claims.py)

Each shell command is split into segments (per line, && || ; |), and each segment is a run, a check (node --check, python -m py_compile, bash -n, tsc --noEmit, linters) or a read (cat grep head ls curl wget test echo …). Only run segments credit a written file (an interpreter's syntax flag counts only BEFORE the script: node server.js -c conf is a run; cat app.py | python3 runs app.py; git bisect run … runs its command; --version / --help / -h anywhere run nothing, a compile or build is a check and a run masked by || credits nothing (§4UY); files are keyed by path, not basename, and a project runner (cargo run, node ., npm start, python -m pkg, ./app, a written run.sh) or a suite credits its folder — see code claims; every $(…), <(…) and backtick is a command of its own, quoted or not; a heredoc body written to a file is data and one fed to an interpreter is the program (§4UY); a multi-line python3 -c "…" / node -e '…' is one command, and inline code runs what it imports or executes (import x, exec(open(x)), require, a subprocess interpreter) — not a file it only opens; bash -c '…' is classed by its own commands; a CLEAN browser load (or a Playwright page.goto in an execute) also runs the scripts the page's own <script src> loads (§4UY C20: from the page text this request wrote); a deleted file (file_system delete, rm) is not "never run"; a formatter's check-only flags (black --check, isort --check-only, prettier -c) are no rewrite, and mv is a rename; a command string counts as run only when passed to a runner (subprocess.run('python3 app.py'), execSync), not when printed or logged; a page that threw or whose own script did not load credits nothing; a tests/check_page.py run marks pages tested only when its exit code is the command's (last, or followed only by &&); shell keywords and grouping — if then do ! { ( — lead into the real command, and [[ ]], read, fi done run nothing); a check marks it "only syntax/lint-checked, never run". The note and the repair directive say so: "a syntax check or a read is not a run".

4 · Labs, the tailnet, privilege refusals

  • Lab templates are an enum in the tool schema (LAB_TEMPLATES, pinned to interface/ghost-labs/templates/*.yaml).
  • Lab member default for read actions (http, screenshot, logs) in an owner's call: the kept app's member when it exists, else the lab's only member; never a guess among several, never for exec/put/get. A note naming the member chosen is appended to the result.
  • Tailnet URLs (*.ts.net, 100.64.0.0/10) are refused by the browser at once with the way that works: file:// / a sandbox service, or — when the model has the lab tool — lab http / lab screenshot (tools/browser_tailnet.py).
  • Privilege refusals (core/env_limits.py): an execute that exits non-zero with "Operation not permitted" / "must be root" / "not in the sudoers"… records the privilege program the refusal NAMES (su: Authentication failure), or the command's only privilege program when it names none (su sudo setpriv runuser chroot nsenter umount iptables …; not mount, sysctl, unshare, which work unprivileged in some forms) for the request. Quoted text and heredoc bodies written to a file are data; a heredoc fed to a shell (bash <<EOF, cat <<EOF | sh) is commands; and command -v sudo / which su run nothing; a later command that runs one again is not run, and the model is told why and what works (current user, a purpose-built tool, a lab machine — labs give root). Plain programs are never recorded, and nothing is recorded when the refusal names another program of the command (chown: … Operation not permitted); capsh --print reads capabilities and is never blocked.

5 · The web-app starter (tools/scaffold.py)

file_system(operation='write', path='<new folder>', template='web-app') writes index.html, css/style.css, js/app.js (the App namespace; one js/<feature>.js per feature), js/main.js (starts the app, sets window.__appReady) and tests/check_page.py: a Playwright check over file:// with the network blocked, which fails on any uncaught exception or console error and runs per-feature step lists (click fill press wait visible hidden text count eval); python3 tests/check_page.py <word …> runs only the checks whose name contains every word — what a checklist item runs. A check that freezes the page fails after 30 s (a watchdog) instead of hanging; a missing file is named; a malformed step says what it needs; text / count retry while content renders. A path= that names a file (app/index.html) is refused. Classic <script src>, not modules: Chromium blocks ES modules from file://. The folder may be relative, host-absolute or /workspace/…; the confirmation names it relative to the workspace, a .git folder is refused, and the files count as this request's own (a later whole rewrite needs no read first). A folder that already holds files is refused (nothing is ever overwritten); the confirmation is one SUCCESS: Wrote … line per file, so every write ledger, the project change log and the page check read it as ordinary writes.

6 · Hosts no tool reached, controls no user can click 2026-11-23 §4VG

Req 9d5bbe77: a web app iframed https://doom.30th.com/, a parked domain that every attempt in the request had failed to reach (TLS "unrecognized name"), and a "LOADING…" overlay (z-index:3) sat over its only button. The page check passed (the page loaded), the verifier passed (the files exist), and the model's browser check ran only evaluate calls, so nothing hit-tested the button.

  • Reach ledger (tools/host_reach.py): per request, every clearnet host a file_system download or a browser navigation tried, and whether ANY attempt got an answer (an HTTP status of any kind counts: the server exists); a web_search page read that returned text books a reach too. A download books the host it actually DIALLED (a redirect hop's own), never a refusal by the Tor proxy itself. A browser failure counts as a miss only when it carries a network error code (net::ERR_…, except ERR_ABORTED) and is not a crash on our side (a closed page, a killed runner); "Download is starting" and an empty error status (ERR_HTTP_RESPONSE_CODE_FAILURE) are the server answering (a reach), our Tor proxy refusing (ERR_PROXY_CONNECTION_FAILED), ERR_ABORTED and "interrupted by another navigation" (the page's own script may have navigated) book nothing, and a timeout books nothing (review r5: the page may have committed). An interact goto that redirected books both the host it asked for and the one it landed on. Loopback, private and onion hosts are not booked; :443/:80 are the same host. A scheduled run starts its entry over (its id, sched-<job>, is the same on every run: main._handle_chat_foreground calls forget_request), and an entry idle for 3 h is dropped.
  • [REACH CHECK]: a successful file_system write of a code file (.html .js .mjs .cjs .ts .tsx .jsx .vue .svelte .py .css) whose text names an http(s) URL (or a protocol-relative "//host/…") on a host this request tried and never reached gets a note on its result, once per file and host: the attempts, the last cause, and "use an address a tool did reach, or tell the user plainly that this one is unverified (the sandbox reaches the web only over Tor, so it may still work for them)". Information, never a block. Switch: GHOST_REACH_NOTE=0.
  • No site by that name: a TLS alert "unrecognized name" (curl TLSV1_ALERT_UNRECOGNIZED_NAME, LibreSSL tlsv1 unrecognized name, Chromium net::ERR_SSL_UNRECOGNIZED_NAME_ALERT) is the server saying it has no HTTPS site for that host name. A download stops after that first answer (no second circuit) and says it is not a Tor or network fault; the browser's failure hint says the same. It used to read "one later retry may work".
  • Covered controls (tools/browser_runner.py _covered_controls): at the end of every interact whose final page is the model's own (file:, 127.0.0.1, localhost, [::1]) and that did not abort, the visible controls (button, [role=button], a[href], input, select, textarea, [onclick]) whose centre is hit-tested to another element are listed (up to 5) as ⚠ COVERED CONTROLS above the per-action results. Frames of the page (srcdoc, the same own address) are scanned too, their rows prefixed iframe >, unless the parent hides the frame; an iframe under a cover is itself reported (an overlay left over an app's frame). Controls are tested newest first (reverse document order: the window just opened is last) within a 1.5 s in-page budget, so a huge page returns the rows it reached. A second pass catches the live app's state the hit test cannot see (review r5): an opaque layer with pointer-events:none drawn over a control — clicks pass through, so every hit test (Playwright's actionability check too) says the control is fine, yet the user sees only the loading screen. The reached controls are hit-tested again with a constructed stylesheet (* { pointer-events: auto !important }) adopted and removed inside the same synchronous call (no frame is painted with it; the page's own adopted sheets are restored from a copy); a layer that is shown, at least 90% opaque (a background colour, or a full-size gradient layer with every stop opaque; never an image) and covers the control's whole box comes back with hidden: true, worded "drawn over by …". A control is also reported when an ANCESTOR answers the hit test at a point inside the control's own box (a ::after loading layer, a control painted behind its parent). Not reported: a control under 3 px, or not shown (it or an ancestor hidden, display:none or opacity:0; screen-reader-only clipping), has pointer-events:none, is disabled, or is scrolled out of a scrolling / clipping ancestor on its containing-block chain (a fixed control escapes every clip, an absolute one the static ancestors below its containing block); a cover that holds a control the user can use (shown, at least 3 px, not disabled, not pointer-events:none) or a frame with content (a blank or empty iframe left over the button does not count; a frame from another site does), shadow roots included (another window, a dialog with buttons, a native showModal() dialog with a button, a menu), or one too big to walk (over 5000 nodes: unknown, so not reported); a bar or toast — every element from the hit point up to its fixed / sticky container under a quarter of the viewport tall (click-through pointer-events:none layers aside), and a fixed one within 96 px of a viewport edge (a small fixed box in the middle is a spinner, reported). There is no whole-page modal exemption: a modal with no control (an accessible aria-modal loading screen) is reported like any other cover. A cover with no shown control (a loading screen, an invisible layer, a backdrop) is reported. Page-made ids and classes are reduced to word characters and every row is one line.

Pins: tests/test_4vg_reach_and_cover.py (the covered-controls cases in real Chromium, the note through the dispatch batch). Battery: scripts/mutate_4vg.py. Journal: §4VG.

Residuals

  • A heredoc body written to a file is read as commands: cat > run.sh <<EOF … python3 app.py … EOF credits app.py (pre-§4UU behaviour; a body-aware version was tried in review and dropped — it lost real runs such as timeout 30 python3 - <<EOF).
  • A literal in single quotes that looks like a substitution (echo 'try `python3 app.py`') credits a run.
  • Stale marking and the claim arm see the write forms listed above; a generator script that writes code, or code changed by a long-running service, goes unseen.
  • os.setuid from Python is not recorded by the privilege memo (only shell privilege programs are; fail-open: a retry, never a false block).
  • §4VG: hosts reached by deep_research, an execute curl or a lab are not booked in the reach ledger (neither as reached nor as missed), so a URL reached only that way never gets a note; a URL built at run time ("https://" + host) is not seen.
  • §4VG: the covered-controls scan does not look inside cross-origin frames or into shadow roots for the CONTROLS (only for a cover's own controls), it sees the page only at the end of the sequence, an open modal whose backdrop holds no control (a custom backdrop beside its dialog) is reported as a cover of the page under it, a cover that holds a link or an onclick counts as one the user can act on (so a loading screen with a "help" link is not reported), a cover shorter than a quarter of the viewport inside a fixed / sticky container is read as a bar, a control outside the viewport of a page that cannot scroll is not seen, a URL inside a code comment still triggers the reach note; and (review r4, accepted as advisory by the operator) controls inside shadow roots are not scanned, rows scrolled out of a transform / contain scroller and rows under a sticky header taller than a quarter of the viewport are reported, menus and tooltips built from plain divs count as covers with no control, and an overlay that shares a parent with nav buttons is excused by them. The click-through pass (review r5/r6) does not see a layer whose pointer-events:none is !important or inside a cascade @layer (it outranks the probe sheet), one in a shadow root, one mid-allow-discrete transition, or an ancestor's ::after; a small solid custom cursor over a tiny button reads as a wall. A layer counts as solid only by an opaque background colour or one full-size gradient layer whose every colour stop is at least 90% opaque, so fades, vignettes and scanlines are quiet; an image (url()) never counts (a grain texture, a watermark, a spinner gif cannot be judged), so a splash IMAGE, an <img> or a drawn <canvas> with no CSS background, an inset box-shadow fill, an overlay under 90% opaque and a masked spotlight are residuals, as are (review r8, false reports) an opaque click-through layer the user sees through by other means — background-clip:text, a blend mode, a mask, filter:opacity(), a gradient moved off by background-position — and (misses) a gradient sized contain / auto 100% or after a quoted URL with an unbalanced parenthesis; a click-through wall a quarter of the viewport tall or more is never read as a bar.
  • A bare MagicDNS name (http://nova:8097) is not refused by the browser: a single-label host is also how a sandbox service is named.

Review: six rounds by fresh readers, then a second verification round (11-17: guard interplay, runtime of the checklist and the runner, a corpus replay of 1,017 real commands, the model-facing text, live functional probes) (r1 2×, then one reader per round on the previous round's fixes); MAJORs in r1–r5, mostly inside the shell-parsing fixes themselves.
