core / task_kind.py

§4SU Phase 2 (2026-11-02): a task may declare its kind when it is planned; the advancer routes it by that kind, not by its wording. The wording keeps its safety role (gate words, the experiment hold).

Why it exists

The 11-02 audit counted about nine wording classifiers deciding what a project task is (build, research, a model experiment, the owner's job). Each took 5–11 review rounds and still flip-flopped. A CODING project skipped the experiment hold entirely. The model already knows what each task is when it writes the plan, so the plan now says so.

The kinds

kindwhat the advancer doesroute label
buildthe coding executor writes or changes files (code, a site, a script)coding
writethe coding executor writes a document (a report, notes, a brief)coding
researcha web search and a research brief (self-analysis when it is about Ghost itself)research
model_runnever built: held for the owner's turn, where probe_model runs it; the §4ST close gate needs a kept transcriptmodel_run
ownerwaits for the owner (NEEDS_USER, wait owner/review; see task_wait)needs_user

normalize_kind(value) maps aliases (code/coding → build, doc/report → write, experiment/probe/model → model_run, user/human/manual → owner) and returns "" for empty, none or auto. An unknown word raises ValueError: a typo must not quietly become "undeclared". ROUTE_LABEL is the advancer's route for each kind.

The deliverable

The deliverable stays the description's trailing → path, the one place every gate already reads (task_deliverable.declared_deliverable). with_deliverable(description, deliverable) appends a declared one, unless the description already declares a file.

Rules

  • Undeclared tasks are routed exactly as before. Kind "" runs the classifiers, settle_gate, the router and the self-analysis override, unchanged.
  • The gate words stay a safety floor. A declared task whose description has a whole gate word (needs_user_gate: "publish", "approve", "send", "delete production"…) waits for the owner whatever its kind (logged). A gate word in another form (gate_form: "approval", "has approved", "sending"…) holds a declared task unattended only, as a hold (wait_on="owner_turn", code gate_form, §4SU Phase 3; event hold: gate_form) that the owner's own run takes back and runs. An undeclared task needs a classifier to agree on those forms; a declared one has none (review r1: "Wait for the owner's approval, then release v2" declared build was built unattended). Review r2: as a park the loose form jammed ordinary work ("Build the approval form", "Implement the email sending queue") for good, even on the owner's run. Review r3: this hold has no introspective exemption (a hold does not jam; "Post my self-reflection essay once the owner has approved it" was built unattended). An introspective task (about Ghost itself) with a whole gate word is not parked (the §2026-07-12 jam on "choose"): unattended it gets the same hold (review r4: the old exemption sent "Publish my own self-analysis to the public blog" to a brief that closed DONE, nothing published; r1: before that it was built); in the owner's run it takes the undeclared route (a research brief, or the file it promises), never the executor for a build/write it declared; a declared model_run stays one, a declared owner task still waits. Open item: an UNDECLARED introspective task with a whole gate word still goes to a brief unattended and closes DONE (behaviour since 2026-07-12, left for the operator).
  • A kind may add the experiment hold, never remove it. A declared model_run holds in every project kind (the audit's CODING skip) and its close needs a kept transcript whatever its words. Any other declared kind is still judged by its words, in the advancer and in the §4ST close gate (r1: otherwise task_update task_kind="build" after a refusal closed an experiment with no transcript and no recorded waiver). A false trigger keeps the waiver, override={"model_run": "<why>"}, which is recorded.
  • Declared research that promises a file goes through the router, which decides by the declared file: a path the brief writer cannot write is built.

Where it is read and written

  • memory.projects: the kind column (default "", migrated on an old database), add_task(kind=), update_task(kind=).
  • planning: TaskNode.kind; decompose(kinds=); the plan shows <kind> before the description.
  • tools.projects: subtasks items may be objects {description, kind, deliverable}; task_kind on task_add / task_update.
  • project_advancer: the declared route.
  • experiment_gate and task_close: the model-run gate reads the kind.
  • api.projects_routes: kind on task create and PATCH.
  • core/prompts.py: the OPEN TASKS line shows <kind> when declared.
