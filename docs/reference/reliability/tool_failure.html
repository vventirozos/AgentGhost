tools / tool_failure.py

Failure classification taxonomy. Decides what a failed tool call tells the model: try once more, stop repeating the call, or read the error and fix it.

Classify the error, not the advice 2026-09-15

Tools append a --- HINT --- block to a failure for the model's benefit, and those hints enumerate failure modes by name — the browser's begins "If this is a navigation timeout, try wait_until='domcontentloaded'…". Patterns are scanned in order with first match winning, so the hint decided the class of the error it was attached to. Live: a deterministic 

ValueError: selector '.frag_copy' did not match any element

was booked RETRYABLE on the word "timeout" three paragraphs below it, and charged to the transient strike budget (Transient strike 1/4 (timeout)) — a budget no retry can satisfy, because the selector will never match. Measured across the recorded trajectory corpus, 31 of 53 hinted tool errors (58.5%) changed class once the advice was excluded, every one of them retryable → diagnostic/unknown.

strip_advisory_sections now removes advisory blocks before classification — a dashed rule, a short label ending in HINT, a dashed rule — matched generically so execute's --- 💡 DIAGNOSTIC HINT --- (different label, different rule length) is covered by the same implementation. It cuts to the block's closing rule rather than to end-of-text, so anything appended after a hint survives; text with no hint is returned unchanged; and a result that is nothing but advice classifies UNKNOWN rather than inventing a failure. tests/test_tool_failure_hint_stripping.py carries an ast.parse enumeration that walks every string constant in src/ and fails if a producer ever invents a banner shape the stripper cannot see.

The exit code of an execute-shaped result — exec_exit_code() (2026-09-20, R4-1)

Five readers — distill/outcome_heuristics._looks_like_tool_error, core/project_advancer._looks_like_failure and classify_verify_result, tools/registry._acquired_skill_result_class, tools/composed_skills._step_result_ok (removed with the macro engine, §4TA) — plus the turn loop's fallback-hint scan and acquired_skills' TDD gate each ran an unanchored EXIT CODE:\s*(\d+) over the whole body, while the turn loop's “Process finished successfully.” rule already demanded a line-anchored banner. Measured on the September 2026 corpus (2,331 calls replayed through every reader): a manage_projects status payload that quotes a past build — one JSON line holding … --- EXECUTION RESULT --- EXIT CODE: 1 STDOUT/STDERR: … — was booked as a failed manage_projects call by the corpus readers (3 of 2,005 clean rows), a false failure fed to failure-distillation and the foresight index (both removed on 2026-10-11, §4NM).

exec_exit_code(text) is now the one implementation: it returns the integer code for the sandbox-job form [sandbox job … EXIT CODE: N] or an EXIT CODE: N banner at the start of a line, and None for anything else (a quoted banner mid-line, a sentence that mentions one). 711/711 genuine execute results in the same corpus are line-anchored, so no real exit code is lost; an execution-framing requirement was tried and dropped (a pasted log carries framing too, and eight existing pins say "boom\nEXIT CODE: 127" is a failure). After the change the replay reads 326/326 recorded failures caught, 0/2,005 false failures. tests/test_exec_exit_code_anchored_r41.py pins each reader on one input (R5) and walks the package for any unanchored search outside the helper; the only sites allowed to search wide are guarded by an == "execute" name check, i.e. their input is execute's own output.

Same call, same result 2026-10-04 §4LN

_SAME_CALL_SAME_RESULT_PATTERNS run before the retryable ones and class these as DIAGNOSTIC. Each said "timeout" or "connection refused", so the model was told "will retry", and the same-failure stop never ran.

  • A selector that never appears (waiting for locator, Page.click … Timeout, "did not match any element").
  • The host memo's "will fail the same way" refusal.
  • ERR_CONNECTION_REFUSED on the agent's own loopback.

Vision hints: a URL 404 gets URL advice.

The transient notice no longer promises a retry 2026-10-12 §4NW

A RETRYABLE failure was reported as "TRANSIENT ERROR (will retry)", but nothing retries it: the loop only counts a transient strike. It now reads "a temporary failure; the same call may work if you issue it once more (nothing retries it for you)".

Program-output classes, third pass 2026-10-15 §4PH

The job banner counts only at the start. exec_exit_code read a [sandbox job … EXIT CODE: 0] fragment ANYWHERE in a result before the line-anchored banner, so a failing result that merely quoted one read as 0 (the user-facing "Process finished successfully" head, the fallback-hint gate). The sandbox-job form is now LINE-anchored and the framing that comes first wins: a quoting execute result has its own EXIT CODE: line above the quote, while jobs(action='collect') puts the banner under a "Collected N finished job(s)" header and must still yield the job's code (the r3 reader found a start anchor blinded _hint_code, the fallback head and the new claim ledger to every collected job).

The budget kill is a strike; the infra error is the transient. "timed out / killed after 600s" was RETRYABLE — counted only as a transient, never a structural strike, and formatted as "may work if you issue it once more" under a hint that said the opposite. It is diagnostic now. The two sandbox-layer results that ARE transient ([SANDBOX INFRA ERROR — not your code] docker daemon wedged, [SANDBOX INFRA ERROR] the sandbox container stopped or restarted) matched none of the words in _SANDBOX_RETRYABLE_PATTERNS (busy / unavailable / starting / not running) and were charged as execution strikes; the pattern now names the producers' own prefix.
