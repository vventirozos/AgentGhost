core / failure_dimension.py

Harness-dimension failure attribution (MemoHarness adaptation, 2026-07-19). The companion failure_distill.py — the dream-side failure-cluster distillation pass — was removed on 2026-10-11 (§4NM).

Why

Three multi-day debugging episodes in this project's history were rooted in the same mistake — a harness failure read as a model failure: the verifier "not in evidence" refutes (evidence-packer truncation, not the judge), the code-correction failures (fail-open SEARCH/REPLACE parser, not the LLM), and the introspect breakage (native-tools arg corruption). Every failure record now carries a dimension naming the harness layer it was attributed to, so the debugging prior is audit the harness before blaming the model — and so recurring failures can be grouped and distilled into preventive lessons.

Taxonomy (adapted from MemoHarness D1–D6, arXiv:2607.14159)

DimensionCoversExample signals

orchestrationverifier route, loop-breaker, strikes, dispatch, planning"verifier REFUTED" · "loop-breaker" · "replan"

output_processingparsers, SEARCH/REPLACE blocks, scrub, schema validation"SEARCH/REPLACE" · JSONDecodeError · "malformed output"
modelbase-model reasoning error despite correct context/tooling"hallucinated" · "miscalculated" · "refused"
unknownno signal matched — offline-adjudication candidates—

Precedence: first-match-wins over the tables in the order output_processing → memory → context_assembly → orchestration → tool_interaction → generation_control → model. Harness dimensions are deliberately checked before model, and specific beats generic — a network timeout (ETIMEDOUT) lands on tool_interaction while an LLM timeout (ReadTimeout) lands on generation_control.

The tag is a prior, not a verdict. Regex over failure text sees where a failure surfaced, not necessarily where it originated. Individual tags can be wrong; the aggregate distribution (a month of tags showing one dimension spiking) is the reliable signal. The matched signal is debug-logged at each write for spot audits.

Where attribution happens

  • Lessons — removed with the lesson store (§4TD, 2026-11-06). Until then attribution ran inside its one write path.
  • Work logs — the finalize chain captures failure heads next to classify_tool_failure (context._turn_failure_texts, capped at 6/turn) and classifies them (plus the verifier reason on a verifier:failed outcome) into the work_log payload's failure_dimension. Only failed turns pay for classification.

failure_distill.py — removed (2026-10-11, §4NM)

Until October 2026 a dream-side pass gathered the last 14 days of failure records, grouped them by (dimension, cluster) and asked the worker model to distill one cross-case pattern lesson per group of ≥3 cases (source="distilled"), with a per-cluster evidence fingerprint in $GHOST_HOME/system/failure_distill_state.json and a _last_run stamp so a barren cycle was distinguishable from one that never ran. The §4NC producer review found its lessons were re-bumped rules that never changed a real reply; the pass, its state file, its env switches (GHOST_FAILURE_DISTILL, GHOST_FAILURE_DISTILL_MAX, GHOST_FAILURE_ADJUDICATE) and its routing labels (CLASSIFY_FAILURE, DISTILL_PATTERN) were removed with the other lesson producers. The dimension tags it grouped on are still written at record time and still read by learning_health.
