core / evidence_gate.py — the evidence-sufficiency check

One pure function reads the turn's tool results and answers "did any call this turn return substantive evidence?". When every evidence-bearing call came back empty, weak or errored, the turn is marked as having no evidence. Shipped 2026-09-07 (journal §4FD) as an EVIDENCE CHECK steer under the experiment arm evidence_gate; that arm was concluded to control (§4LF), and on 2026-10-11 (§4NN) the steer itself (GhostAgent._evidence_gate_block) was removed with the experiments registry. What remains is the pure function assess_turn_evidence, which the claim binder (core.claim_binding) and the turn-state check (core/turn_state_check.py) use as the single definition of an "empty" result.

Why it exists

The largest real failure class in six weeks of live turns (~30 of 124 labelled failures, and most of the human 👎) was a confident answer produced after every retrieval came back empty or unrelated: recall returned rows about pg_stat when asked for a project codename and the agent invented a name; browser extract_text returned LENGTH: 1 and the agent answered "around 4 hours"; web search returned nothing usable 54 times and the agent defined a Greek dessert anyway. arXiv 2606.21409 measures the mechanism — unreliable retrieval is worse than none (44.8 → 4.7 F1 on shuffled context) — and this model abstains readily when it is told the evidence is empty. Nothing told it.

What it does

assess_turn_evidence(tools_run)Walks the turn's recorded tool results (synthetic loop-minted rejections excluded). Hand-built rows may still carry arguments/args and error keys.
EvidenceAssessment.firesTrue only when the turn consulted evidence and got none of it. A chat turn with no retrieval never fires; one good result among empties never fires.
render_evidence_steer(assessment)The steer text: names up to four reasons, forbids stating facts that were not retrieved, and allows exactly two moves — one more targeted attempt, or say plainly what was not found, and stop.

The empty shapes

Each shape is the tool's own wording, and this module is the single place they are recognised — a tool that rewords its empty result reddens the shape pin in tests/test_evidence_gate.py rather than silently disarming the gate.

Loop wiring and the arm (removed §4NN)

History. Nothing below runs any more: no steer is injected, no arm is consulted, and GHOST_EVIDENCE_GATE is not read.

GhostAgent._evidence_gate_block(tools_run_this_turn, req_id) is called at the volatile-state assembly site, right after the explicit-constraints block, and its text rides the volatile block (never a tool result — the corpus stays what the tool returned, the §4K lesson). It is arm-gated: experiments.arm_for(ctx, "evidence_gate", req_id); the trigger is marked on both arms (evidence_gate_fired: True on treatment, False on control) so the report can condition on turns where it would have fired; the text ships on treatment only. The key is registered in TRIGGER_KEYS and CONTEXT_MUTATING_KEYS. Kill switch: GHOST_EVIDENCE_GATE=0; an unregistered arm is inert.

The gate read keys no row ever carried 2026-09-13

The first version read t["arguments"] and t["error"]. No production row has either: the dispatch loop's row is the API message, and an extra dict key would be sent upstream. With no operation visible every file_system write fell into the read branch, its "SUCCESS: Wrote …" counted as substantive, and one scratch-file write silenced the gate for the whole turn — the confabulation class it was built for was unguarded from the day it shipped, and the shape pins could not see it because they hand-build rows with the keys. Two changes: ToolOutcome gained a call_args slot that the loop fills from the parsed call (invisible to the payload — the outcome is a str), and the gate reads row_call_facts: arguments from the outcome, error from the outcome's status (a REJECTED or FAILED result is empty even when its text has no ERROR: head; PARTIAL and UNRESOLVED are judged by their text — a fact_check partial carries the research results, a promoted execute job its output), and mutations skipped. The R3 review of this fix found two defects inside it: the canonical rewrap helper with_text (which the context cutter runs on tool rows in place every iteration) rebuilt the outcome without call_args, and is_failure ("not OK") had made partial results errors — both fixed and mutated. tests/test_evidence_gate_real_rows.py drives the real _dispatch_and_process_tool_batch and asserts the row shape, the recorded arguments and the gate's verdict on the same input; 8 gate/row mutants killed (PROJECT_JOURNAL §4GG).

Tests: tests/test_evidence_gate_real_rows.py (real rows, through the loop), tests/test_evidence_gate.py — every real shape both ways, the fires-only-when-all-empty rule, synthetic exclusion, bounded reasons, and (until §4NN) the arm gating, the kill switch, an AST pin on the loop call and the registry keys — those pins left with the steer. Mutation battery §4FD: all gate mutants killed.

Browser rows read by their header 2026-10-04 §4LN

A browser row is judged by its own STATUS: header, and the generic Error-head scan is skipped for it. A page whose text opens "Error handling in …" is evidence. A navigate with no page text stays evidence, because canvas pages and the agent's own apps have none.
