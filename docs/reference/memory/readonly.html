memory / readonly.py — read-only store façades

Isolate an agent that may READ the operator's memory but must never WRITE it — today the coding-loop leaves (and the knowledge-base path in tools/memory.py). It was written for the delegated sub-agent, removed 2026-10-30 (§4SI).

Model (hardened 2026-07-14 bug hunt)

Default-allow-reads / explicit-deny-writes. A base _ReadOnlyProxy proxies every attribute through to the real store EXCEPT: names in the subclass _MUTATORS set (return a no-op) and names in _BLOCKED_ATTRS (return None). Being wrapped says nothing about being simulated: since §4TD the simulation guards read one flag, context.simulated (core/isolation.py), and is_read_only is gone. The real store is held as _real, so proxy.real hits __getattr__ and is blocked.

Why the rewrite

The previous version no-op'd guessed method names (add_memory, delete_memory, add_triplet, insert_fact) that do not exist on the real stores, while the REAL mutators fell straight through __getattr__ and executed against the operator's live memory:

  • Vector: add, ingest_document, process_batch, smart_update, bump_retrievals, bump_helpful, forget_episode, delete_document_by_name, correct_fragment, delete_fragment, delete_by_query — all unblocked.
  • Graph: add_triplets (plural), delete_by_target, wipe_all, prune_stale_edges, bump — all unblocked.
  • Skill (façade removed with the lesson store, §4TD): remove_by_trigger, record_retrieval, record_helpful_retrieval, record_retrievals_bulk, mark_verified, retract_lessons_from_trajectory — all unblocked.
  • And the raw writable handles .real / chromadb .collection / .client / graph .nx_graph were reachable, so a caller could write around the façade entirely.

Combined with the sub-agent tool-surface escape (see delegation), a delegate could permanently rewrite the operator's vector DB and knowledge graph — the exact outcome the read-only wrap exists to prevent.

Guard against drift

The _MUTATORS sets are pinned to the real method names and covered by tests/test_readonly_memory.py, which introspects each real store and fails if a store grows a new writer that isn't blocked. search and search_advanced are special-cased on the vector proxy to force record_retrievals=False — a read that reinforces retrieval stats is still a write to operator memory. search_advanced was an explicit leak (2026-07-22): it unconditionally called _bump_retrieval_stats, so a delegated sub-agent — which IS granted recall — mutated operator memory metadata on every single recall; the proxy is now an explicit method forcing the bump off, not a pass-through.

_update_library_index is now a blocked mutator (2026-07-22). It writes the operator's real library_index.json. ingest_document was already blocked (returns None), but tools/memory.py's tool_gain_knowledge only checks for a tuple result, so it fell through and called _update_library_index DIRECTLY — a self-play ingest permanently registered a synthetic filename with ZERO stored chunks, after which the real store's dedup refused every future genuine ingest of that name ("Skipped: already ingested") while queries returned nothing. Silent, permanent, hand-fixable only.

NOTE: the strict façades built for self-play and then used by the failure replay (removed 2026-11-05, §4SZ) live in core/isolation.py (ReadOnlyVectorMemory, ReadOnlyGraphMemory; ReadOnlySkillMemory went with the lesson store, §4TD); the earlier inline copies in core.dream were moved there (they predate this module and carry self-play-specific behaviour). Keep the semantics in sync if you change them there.

Audit fixes (2026-07-26)

(History, §4TD removed this façade.) ReadOnlySkillMemory closed two leaks (found independently by two auditors): quarantine_lesson — a real playbook writer added 2026-07-17, AFTER the façade hardening — was missing from _MUTATORS, so a delegated sub-agent could quarantine a REAL operator lesson; and get_playbook_context passed through with its default retrieval-stat bump AND stamped the operator's last_playbook_triggers attribution record. A façade override now forces record_retrievals=False, stamp_triggers=False (mirror of ReadOnlyVectorMemory.search). The drift-guard test's _WRITE_HINTS gained the "quarantine" prefix — the guard can only catch writers it can name. Tests: ::TestReadOnlySkillFacade.

Every writer is blocked, listed or not 2026-10-04 §4LI

The named _MUTATORS lists are a deny-list, and every writer added after them leaked through (unquarantine_lesson, reconcile_vector_orphans, heal_missing_twins, _update_lesson_fields). A method whose name starts with a mutating verb (add, set, save, write, update, upsert, delete, remove, retract, prune, mark, credit, record, bump, (un)quarantine, reconcile, heal, learn, forget, wipe, ingest, reset, archive, rotate, store, put, insert, merge, apply, purge, clear, drop, rename, restore, relabel, backfill, graduate, promote, demote, evict, compact, rebuild, reindex, migrate, repair, refresh) is a no-op through every façade, public or private (_MUTATING_NAME). Every such name on the real stores is a writer; no reader matches.
