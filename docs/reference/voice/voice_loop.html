interface / voice.py

The local voice loop: speech-to-text on nova's whisper-server (Whisper large-v3, since §4SL; the Gemma 4 audio node when GHOST_STT_URL is unset), text-to-speech on nova's tts-service (Phonon, voice Lottie, since §4TK) for English and the macOS synthesiser for Greek or when the service fails. No extra hardware, no API key, no egress.

The old Pi voice server is gone. This page keeps its filename for stable links. STT is an HTTP call to whisper-server on the worker node. English TTS is an HTTP call to tts-service on the same node (interface/tts-service), and all other TTS is a say subprocess on the interface host. On this side the moving parts are interface/voice.py and the two proxy routes in interface/server.py.

What changed (2026-08-02)

The push-to-talk UI has shipped since 2026-07 (mic button, MediaRecorder, full touch lifecycle in app.js), but /api/stt and /api/tts proxied to a separate voice server on a Raspberry Pi / Jetson running faster-whisper + Kokoro. That host no longer exists. The default raspberrypi.local does not resolve, and the launcher's override http://disorder:8000 resolves on the tailnet but listens on nothing — so the mic button was a no-op against a dead node, the classic silent-inoperative-subsystem shape.

Both halves now run on infrastructure that is already live and already supervised. The wire contract is unchanged — /api/stt still returns {"text": …} and /api/tts still returns audio bytes — so the existing browser UI needed no modification.

What changed (2026-08-03)

  • Voice switched to Ava (Premium), a neural voice, from Samantha (which had itself replaced the Daniel en_GB male voice the day before). Verified end-to-end rather than by inspection: audio returned from the live /api/tts endpoint is byte-identical (SHA-256) to a local say -v "Ava (Premium)" render of the same text, which is what rules out the silent-fallback failure below — a wrong voice name still returns 200 and plausible audio.
  • The last PI_VOICE_URL setter is gone. The variable had been dead in code since 2026-08-02 but was still exported by ~/Data/AI/bin/start-ghost-client.sh and still documented as a live knob on two pages — a reader configuring voice from the docs would have set a variable nothing consumes. Launcher line removed, docs corrected, and a test now guards the settings tables.

The deleted external (interface/externals/tts_stt/)

Removed 2026-08-03, along with its soundfile pin. voice_server.py was a FastAPI "Orin Nano Optimized Voice Node" running faster-whisper + Kokoro on the companion GPU box. It had been unreferenced since 2026-08-02 and unrunnable on this host (neither kokoro nor faster_whisper is installed), and it was the only importer of soundfile>=0.12.0 — so a dependency was being carried, and documented as required, for a service that could not start.

The live voice loop needs no Python audio library at all: ffmpeg for transcode and the system say binary for synthesis. Design record for anyone rebuilding a GPU voice node, since the file is gone and this project has no version control:

§4SL — Whisper replaces Gemma (2026-10-31)

Measured on nova with this module's exact Gemma request (same prompt, 16-bit WAV) against whisper.cpp 1.9.5, on FLEURS read speech: 100 Greek and 50 English clips (5–15 s), plus ten ~30 s Greek clips. WER = word error rate after lower-casing and stripping punctuation.

ModelGreek WERGreek CEREnglish WERMedian per clip
Gemma 4 E4B (old path)60.8 %40.9 %6.6 %9.1 s (Greek), 5.2 s (English)
Whisper large-v3-turbo q8_013.5 %5.1 %5.0 %2.0 s
Whisper large-v3 q5_0, no VAD11.9 %4.4 %4.8 %3.3 s
Whisper large-v3 q5_0 + default VAD12.5 %4.6 %7.8 %3.5 s
Whisper large-v3 q5_0 + tuned VAD (production)12.2 %4.6 %5.2 %3.4 s (Greek), 2.7 s (English)

Gemma wrote 30 of the 100 Greek clips in Latin letters ("Oflios eche ipachos…"); 55 of 100 had more than half their words wrong. The agent only ever sees the transcript, so that is what it received. Large-v3 beat turbo on 34 Greek clips and lost on 18 (same clips), for ~1.3 s more per clip; switching is one line in nova's bin/start-whisper-server.sh.

VAD is required. Without it, Whisper answers silence or background noise with a subtitle credit it learned in training ("Υπότιτλοι AUTHORWAVE"), and a clip with 4 s of room noise around real speech came back as only that phrase — the speech was lost. With Silero VAD (--vad) silence returns "" in 0.05 s and the padded clip is transcribed in full. VAD's defaults (30 ms of padding around speech) cut the first words of sentences — English rose from 4.8 % to 7.8 % ("In fact, it is not easy…" became "not easy…"); the production flags -vp 300 -vsd 500 -vt 0.35 (300 ms padding, split only on 0.5 s silences, threshold 0.35) brought it back to 5.2 % and still return "" on silence and noise. The server runs as the LaunchDaemon com.local.whisper-server on nova, beside the Gemma llama-server (about 1.1 GB of weights).

A reply with no word outside Whisper's own tags ([BLANK_AUDIO], (music), ♪, a lone .) is silence; any word keeps the whole reply — push-to-talk and ingest use the same rule; segment line breaks are joined with spaces so the agent receives one message. A 200 carrying {"error": …} is a failure, never silence. Tests: tests/test_4sl_whisper_stt.py.

§4TK — Phonon speaks English (2026-11-07)

The operator chose Phonon 31M's voice Lottie by ear over Ava, Qwen3-TTS 0.6B and Audio8 Realistic Air. Later the same day the operator moved to the voice Maeve.

TextSpoken by
Englishtts-service: Maeve, 24 kHz, about 0.03 s of work per second of audio on nova's CPU
Greek (the rule in tts_voice_for)say with GHOST_TTS_VOICE_EL: Phonon is English only
A sentence the service can't speak (HTTP 400, 413 or 422, such as ✅ alone)say with GHOST_TTS_VOICE; the next sentence goes back to the service

Because /api/tts makes this choice, the web client and the handheld behave the same. A reply mixing the two languages changes voice between sentences. Measured with a Gemma job running on nova: Gemma 53.4 to 52.4 tok/s, a sentence 0.26 to 0.31 s.

Setup and the voice list are in interface/tts-service/README.md.

Talking over a reply (2026-11-07)

The web client only. interface/static/bargein.js holds the decisions and has no browser code; app.js supplies the microphone and acts on the results.

  • When the microphone is open: while a reply to a voice message plays, and for 3 s after. Never for a typed turn. The mic button shows a ring (.barge-listening). Off with Toggle voice interrupt in the palette (localStorage ghost-barge-in, per browser).
  • Detecting speech: a level above the room, not a speech model. It measures the room for 300 ms, needs 220 ms above 3.5 times that level to start and 900 ms below half that bar to end. Echo cancellation is on for this microphone; push-to-talk keeps it off.
  • What happens: hearing speech pauses the audio. Under 280 ms voiced (a bare trigger), an empty transcript or a failed transcription resumes it. Three empty results in one reply stop the listening until the next reply, with a note, because the microphone is probably hearing the speakers. Words go out as a 16-bit WAV to /api/stt, with 500 ms of lead-in so the first word survives, and the reply stops.
  • What stays cut (_speechCut): only reply text already on the stream, checked in queueTTS. A retract removes that text and ends the cut, and so does a new turn. A resume replays the stream from the start, so content and retracts at or behind the furthest point already reached count as history (_streamChars, _replayUpTo): they are not said again and don't touch what is playing. Pressing or speaking before any reply text cuts nothing, so the answer is still heard. Reasoning is never read out, and nothing plays while the mic button is held.
  • Where the words go (_voiceWords, for the button and for voice): to the running turn's inbox if a turn runs, as Enter does, else a new turn with a spoken reply. A message waiting for after the turn, or one the turn never read, still gets a spoken reply unless the speaker button was turned off since. A bare stop word with no turn running only ends the speech (isStopWord, twin of core/queued_messages.py, one test table for both).
  • Words are kept: a mic press sends what was already said. Stop, a typed message, the speaker button, a new chat or another session end the listening; words already being transcribed then go to the tray, and so do words from another conversation. So do words being said at that moment, unless too short to be words.

The handheld: no voice interruption, by decision: its microphone hears the speaker about 13 times above the room, and audio through PipeWire's echo canceller sounded distorted. Shift+Esc interrupts, and the rest of a streaming reply then stays unsaid, by the same rule as above.

Not covered: real speakers and microphones. The tests use Chromium's fake microphone, which has no echo, so the thresholds are untuned against a real room, and iOS is untried. The agent's history keeps the whole reply, so it doesn't know how much was heard. Speech that continues after a 0.9 s pause is treated as a new utterance and lost while the first is transcribed. Pinned by tests/test_interface_bargein.py and tests/test_interface_bargein_page.py.

GHOST_TTS_VOICE_ELMelina (el_GR, stock macOS)The voice for Greek text (2026-11-02). Ava cannot read Greek script, so Greek replies used to be spoken by an English voice. tts_voice_for() picks a voice per /api/tts chunk. A chunk is usually one sentence, but the end of a streamed reply can arrive as one larger chunk, which then gets one voice. The rule counts words (tokens with at least 2 letters) after dropping URLs, which app.js leaves in the text. A Greek word has at least 2 Greek letters. The rule picks this voice when a chunk has at least 2 Greek words, or when Greek words are at least 30 % of its words. It leans Greek on purpose: Melina reading an English name only sounds accented, while Ava reading Greek can't be understood. So "In Greek, good morning is καλή μέρα." is spoken by Melina, while symbols like μ, σ², Ω and ΔG in English maths don't count. A chunk with no words (2., 19°C) uses GHOST_TTS_VOICE. The choice depends on nothing else, so clients never affect each other. Empty turns the switch off. ⚠ On macOS 27, say -v <unknown name> exits 0 and quietly uses a default voice, so a typo in either voice variable produces the wrong voice and no warning. The fallback below only fires when say exits non-zero. Check names with say -v '?'. Pins: tests/test_interface_voice.py (Greek voice block).

⚠ The launchd PATH trap (cost every STT request a 503)

launchd hands a service a minimal PATH — /usr/bin:/bin:/usr/sbin:/sbin — which does not include Homebrew. say lives in /usr/bin so TTS worked, but ffmpeg and ffprobe live in /opt/homebrew/bin, so a bare shutil.which("ffmpeg") returned None and every STT request 503'd under the daemon while working perfectly from a shell — which is precisely why it survived testing. It presented as a Safari-only failure; it was not browser-related at all.

Both call sites now use resolve_binary(): explicit GHOST_<NAME>_BIN override → PATH → known install prefixes (/opt/homebrew/bin, /usr/local/bin, /usr/bin, /bin). The error text names launchd and the override rather than the misleading "not installed". memory/audio_ingest.py had the identical latent bug — the agent is also a LaunchDaemon — and was fixed with it. Standing checklist item: anything a daemon shells out to must not trust the inherited PATH.

Two traps, both measured

  1. The empty-response trap. Gemma 4 emits thinking blocks that its chat template strips. With max_tokens too low the entire budget goes to thinking and the API returns empty content with finish_reason="length" — no error, just nothing. Measured: 256 tokens → ''; 1024 → correct. transcribe() detects that exact shape and raises, because a silent "" would be auto-sent to the agent as an empty prompt.
  2. The dialect trap. Audio must ride an input_audio part. The audio_url data-URI shape tools/vision.py uses for images is rejected with 400 unsupported content[].type — so this is deliberately not a copy of the vision payload builder.

Measured characteristics (live, 2026-08-02)

  • 25.0 audio tokens per second — constant across 3.2 s, 38.9 s and 377 s clips.
  • ~11× faster than real-time — a 6.3-minute clip processed in 33.6 s.
  • No encoder window limit — codewords at the start, middle and very end of a 6.3-minute clip were all recovered. Chunking is a context-budget concern only.
  • Push-to-talk round trip (3.6 s clip, browser-shaped WebM/Opus): ~6 s.

Design notes

  • Verbatim transcription, not intent extraction. The transcript goes straight to the main model, which is the thing that should interpret intent — summarising on the small model would discard information before the smart model sees it. Verbatim also preserves the spoken language (no forced translation).
  • Text reaches say through a file (-f), never argv or a shell string: agent replies routinely contain quotes, backticks and newlines.
  • Errors carry their own HTTP status. VoiceError distinguishes an unusable upload (4xx) from a backend failure (5xx), so a client mistake is never reported as a 502.
  • Privacy. Audio never leaves the tailnet. Keyless local processing is the only speech path compatible with the no-identity-egress rule — this capability cannot be bought, only built.

Four guards added 2026-08-03, all aimed at the same failure mode — speech that keeps working while quietly using the wrong voice, which no ordinary assertion catches because the endpoint still returns 200 and valid audio:

  • test_configured_voice_is_passed_to_say_as_one_argv_element — the name contains a space and parentheses. Split across argv, say would see Ava and (Premium) as separate arguments, exit non-zero, and drop onto the fallback.

§4ML (2026-10-08)

  • A clip under 0.35 s is silence (GHOST_STT_MIN_SECONDS; was 0.05 s). At 0.2 s the audio model answered "The quick brown fox jumps over the lazy dog." 12 times, and twice that reached the agent as the owner's words.
  • Bounded voice work, per kind. STT and TTS each run at most 2 requests (GHOST_VOICE_MAX_CONCURRENT), in separate pools, so a reply being spoken is never refused because someone is dictating. Each kind has a short wait list: 4 waiters (GHOST_VOICE_MAX_WAITING), who wait 10 s for STT and 30 s for TTS (GHOST_STT_SLOT_WAIT_S, GHOST_TTS_SLOT_WAIT_S). The next TTS sentence therefore queues behind the last one instead of being refused (the uConsole drops a reply's remaining speech on a 429). Past the wait list, a request gets 429 at once. Before this, one held key on the uConsole ran the server out of file descriptors: 135 × "Too many open files", and chat failed with it.
  • A cancelled request kills its child (ffmpeg, say): on server shutdown or a cancelled caller. uvicorn does not cancel a handler when the client merely hangs up; that case is bounded by the timeout and the pools.
